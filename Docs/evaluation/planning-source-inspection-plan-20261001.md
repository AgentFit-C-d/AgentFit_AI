# 새 기획서 후보 로컬 검수 계획

## 목적과 범위

확보한 MD 4개·PDF 5개·DOCX 1개가 새로운 실제 기획서 평가 자료로 적합한지 검수한다. 후보 확보를 최종 평가 준비 완료로 취급하지 않는다. 원문/획득 기록을 보존하고 별도 추출물·검수 기록을 추가한다. 현재 제품 분석 코드와 모델 평가 기준은 바꾸지 않는다.

## 순서

1. 고정 원문 SHA-256을 다시 대조하고 페이지/문단/표 위치를 가진 로컬 텍스트를 추출한다. PDF의 빈 페이지·깨진 글자·이미지 중심 페이지와 DOCX의 표/그림/변경 기록을 집계한다.
2. 렌더링과 본문 읽기로 추출 순서·표·이미지 내 정보 누락을 점검한다. 정규식 개인정보 후보 탐색은 보조 수단이며 검수 완료의 근거로 단독 사용하지 않는다.
3. 개인정보가 있으면 평가용 텍스트에서 제거하고 원문 위치 대응과 제거 이유를 로컬에 기록한다. 원문·개인정보·비밀 값은 Git/진단 로그에 넣지 않는다.
4. 기존 튜닝 문서와 문서 계열/원문/내용 중복을 확인한다. 기획서+결과보고서 혼합 문서는 범위를 사전에 정하고 근거를 기록한다. 모델 성능을 보고 자료를 제외하거나 교체하지 않는다.
5. 변환이 검증된 자료만 임시 정답 작성과 사람 검토 대상으로 넘긴다. 정답·코드·모델을 고정하기 전 실제 평가를 실행하지 않는다.

## 상한과 완료 근거

이번 작업의 모델 호출·재시도는 0회다. 로컬 추출/렌더는 명령당 180초, 실패 시 원인 확인 후 최대 1회 수정 실행한다. 처음 10문서 검수는 1,800초 이내에서 수행하고 남은 것은 미검증으로 남긴다. 외부 모델 전송 승인·무료 확인 조건은 후속 평가에서도 그대로 적용한다.

문서별 원문/추출물 해시, 페이지/문단 수, 개인정보 검수 범위, 시각 확인 페이지, 누락/변환 문제, 평가 적합성 및 보류 사유를 기록한다. 사람이 정답을 검토하지 않은 상태는 `human_reviewed=false`로 유지한다. DOCX 원문 입력을 서비스가 지원한다고 주장하지 않는다.
