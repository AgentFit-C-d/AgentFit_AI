## 선정과 중복 처리

- 문서 계열당 한 파일. 최종 기획서 명칭을 우선했고 MD 4개·PDF 5개·DOCX 1개를 후보로 기록했다.
- 기존 specs/Docs/work 기록의 저장소명 검색에서 ORDER101이 기존 튜닝 자료로 확인돼 제외했다. 원문 내용/해시·포크 계보까지의 중복 검사는 남아 있다.
- 의료 영상 산출물 통합본은 제안/기획/완료보고가 섞인 후보다. 사용 가능 구간과 전체 입력의 적합성을 모델 실행 전에 정하고 기록한다.
- 기술 정보가 부족하거나 모호하다는 이유로 쉬운 문서만 골라 남기지 않는다. 목표의 10필드 양성 정답 포함 여부는 전체 자료의 주석 검토에서 확인한다.

## 다음 절차

1. 고정 커밋의 원문을 별도 로컬 폴더에 확보하고 SHA-256·파일 형식·크기를 검증한다.
2. 개인정보·비밀 정보, 실제 기획서 여부, 지원 형식의 텍스트 변환과 표/페이지 근거 보존을 확인한다. 부적합 후보 교체 사유는 모델 출력 확인 전에 기록한다.
3. 기존 전체 튜닝 계열·원문과 중복 검사를 마친 뒤 최종 코퍼스를 고정한다. 파서 실패·문서 부족은 제외로 숨기지 않고 별도 보고한다.
4. 원문 근거·미정·부정·대표 기능의 임시 정답을 작성하고 사람 검토를 받는다. 에이전트 정답만으로 정확도 기준 충족을 선언하지 않는다.
5. 코드·모델·정답을 고정해 문서별3회 평가한다. 결과를 보고 수정한 자료는 튜닝용으로 전환하고 최종 검증용으로 재사용하지 않는다.

현재 실행 중인 classification-full-batch15-v1의 코드/자료/정답/호출 예산에는 변경이 없다. 이 후보들의 모델 전송은 0회이며 실제 Spring·사람 수정 부담·운영 검증도 미완료다.
