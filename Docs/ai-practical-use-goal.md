# AgentFit AI 실사용 목표와 완료 기준

2026-10-01 사용자의 “다른 문서에도 사용할 수 있는 수준을 기준으로 목표 설정” 요청을 기존 활성 목표에 반영한다. 목표 상태는 진행 중이다.

## 목표

**처음 보는 기획서에서도 원문 근거가 있는 분석 초안을 만들고, 사용자가 적은 수정으로 확인·확정한 뒤 저장할 수 있는 수준으로 구현한다.**

핵심 흐름은 문서 입력 → 분석 초안 → 근거와 확인 필요 사항 표시 → 사용자 확인·수정 → 버전 검증 후 저장이다. 정보가 없거나 모호하면 미정/확인 필요로 남긴다. 대표 기능은 30개 이하로 요약한다. 사용자 확인 단계가 있더라도 낮은 추출 품질을 완료로 처리하지 않는다.

## 완료 기준

기존 [초안 평가 기준](../specs/ai-developer/04-analysis-provider/draft-readiness/spec.md)과 [독립 평가 계약](../specs/ai-developer/04-analysis-provider/independent-profile-evaluation/spec.md)의 품질 문턱을 유지한다.

| 영역 | 통과 조건 | 현재 상태 |
|---|---|---|
| 새 문서 일반화 | 튜닝에 쓰지 않은 서로 다른 실제 기획서 10개 이상, 문서별 3회 평가. 10개 필드에 양성 정답 포함 | 미검증 |
| 추출 품질 | 사람이 검토한 의미 단위로 전체·각 평가 필드 precision 95% 이상, recall 90% 이상. 문서별 반복 실행에서도 기준 충족 | 미검증 |
| 근거·의미 안전성 | 반환 항목의 근거 검증 100%, 부정·미정·타제품 사실의 잘못된 확정 0건 | 로컬 회귀와 실제 문서 검증 구분 필요 |
| 실패 처리 | 요청 실패율 5% 이하. 실패도 누락 분모에 포함. 시간 초과·취소·중복·버전 충돌에서 잘못된 결과를 저장하지 않음 | 로컬 검증 마련, 실제 모델 평가는 미완료 |
| 사용자 부담 | 첫 실행에서 사람이 추가·삭제·수정한 횟수/정답 단위 수의 평균 10% 이하. 사람의 검토·수정 시간 중앙값 120초 이하, p95 300초 이하 | 미측정 |
| 확인·저장 | 사용자 확인 전에 확정하지 않으며 변경 버전·저장 실패·재시도·삭제를 검증 | mock·계약 검증, 실제 Spring 미검증 |
| 개인정보·운영 | 로그의 비밀·원문 노출 방지, 삭제 후 복구 방지, 실패 원본만 7일 보관 정책 검증 | 로컬 검증과 운영 검증 구분 필요 |

precision은 제안한 항목 중 올바른 비율, recall은 정답 항목 중 찾아낸 비율이다. 위 수치는 달성된 결과가 아니라 기존 목표값이며 제한된 파일럿 기준이다. 모든 종류의 문서에 대한 통계적 보장이 아니다.

사용자의 시간 제한 유예를 유지한다. **현재 품질 튜닝에서는 모델 처리 시간을 기록하되 품질 통과 문턱으로 쓰지 않는다.** 실행 안전을 위한 요청·호출·재시도 예산은 유지한다. 위의 사람 검토 시간과 모델 처리 시간은 별도다. 과거 v1 결과의 60초 판정은 소급 변경하지 않는다.

## 평가 원칙

- 문서를 고른 뒤 결과를 보기 전에 정답과 코드·모델·설정을 고정한다. 사람이 검토하지 않은 정답은 임시 기준으로 표시한다.
- 문서 계열·원문 해시로 튜닝/최종 검증 중복을 막는다. 검증 결과를 보고 수정했다면 해당 자료를 튜닝용으로 전환한다.
- 현재 공개 README 10개와 에이전트 작성 gold207개는 비교·진단용이다. 사람이 검토한 새로운 실제 기획서 세트나 한국어/PDF 분포의 검증을 대신하지 못한다.
- 반복·부정·검토안·타제품·개발 전용·모호한 역할·근거 오류를 자동 회귀에 포함한다. 합성 테스트의 통과율을 실제 문서 정확도로 표현하지 않는다.
- 평균뿐 아니라 문서별·필드별 누락, 잘못된 제안, 미평가 항목, 질문 수, 실패, 반복 편차와 사람 수정량을 공개한다.
- 사람이 확인하기 어려운 초안은 확인 버튼이 있다는 이유로 실사용 가능 판정을 받지 못한다.

## 범위와 단계

1. 현재 자율 진행: 선택 모델 비교, 관측된 원인 수정, 로컬 통합·mock·계약 검증, 평가 및 사람이 검토할 자료 준비.
2. AI 파일럿 준비 판정: 새 실제 기획서 품질 기준과 사람 수정 부담을 충족하고 로컬 핵심 흐름이 통과해야 한다.
3. 실제 서비스 판정: Spring·DB·사용자 화면·접근 제어·운영 삭제까지 연결한 뒤 별도로 검증한다. Spring 저장소는 현재 제공 불가이므로 필요한 계약·검증 항목을 인계하고 미검증으로 남긴다.

각 작업은 SDD와 feature 브랜치·push를 유지한다. 무료 확인 범위 안에서만 NVIDIA를 호출하고 한도 초과 시 중단한다. 유료 전환·개인 문서의 추가 외부 전송·운영 배포는 기존 승인 범위를 넘겨 실행하지 않는다. 전체 완료 선언은 증거가 갖춰졌을 때만 한다.

## 현재 우선순위

선택형 DeepSeek 검토 경로의 전체 검증 → 고정된 조건에서 실제 분석 완주 여부와 품질 측정 → 관측된 누락·오확정 원인 보완 → 새 문서·사람 검토로 일반화와 수정 부담 검증 순서로 진행한다. 구현 진행률과 모델 정확도는 따로 보고한다.
