# 통합 분석기의 서비스 연결 사전 점검

2026-09-30 현재 코드에 근거한 후속 작업 메모다. 실측 중 제품 코드는 변경하지 않았다. 아래 항목은 구현 완료나 Spring 팀의 계약 승인을 뜻하지 않는다.

## 순서와 남은 품질 기준

1. 현재 고정 H02 실측의 최종 결과와 실패/재시도/미평가 분모를 감사한다.
2. 첫 후속 기능에서 확인된 입력 검사 누락을 수정한다. 의미 오류가 남으면 해당 단계를 근거로 수정한다. 전송 복구를 의미 품질 개선으로 계산하지 않는다.
3. 최종 분석 흐름을 고정한 뒤 노출하지 않은 문서의 기준을 먼저 작성하고 독립 평가한다. 이미 튜닝에 사용한 H02와 부분 검사 6개는 전체 정확도를 입증하지 않는다.
4. 위 결과 어댑터·요청 수명주기·설치 경로를 별도 SDD feature로 구현하고 실제 서버 연결을 검증한다.

개인 문서 발췌 열람 승인은 별도로 대기 중이다. 이 메모에는 문서 본문·파생 문구·키가 없다.

## 결과·질문 어댑터 설계 방향

이는 후속 명세를 위한 설계안이며 아직 API에 적용하지 않았다. 사용자는 목표 내 설계·계획·구현을 자율 진행하도록 승인했다. Spring의 실제 합의·구현 검증은 별도로 남는다.

### 비교와 선택

1. 기존 `project_draft`만 사용하면 미해결 필드의 유효한 제안 값도 사라진다. 부분 기능 목록이나 이름 표현을 사용자가 참고하기 어려워진다.
2. `unresolved` 상태에 non-null Profile 값을 그대로 허용하면 기존 확인 계약과 FR-010/012의 미정 일관성을 바꾼다. 기존 소비자가 확정 초안으로 오해할 수 있다.
3. **선택:** 기존 Profile의 미정 일관성은 유지하고, 내부 확인 응답의 별도 `proposals`에 해당 제안 값·근거 위치를 담는다. 사용자는 제안을 참고해 확인·수정하고, Spring은 명시적인 확인 전 저장된 확정 Profile에 합치지 않는다.

### 구체적 경계

- 새 선택형 통합 모드와 별도의 확인 계약 헤더를 사용한다. 기존 `confirmation-v1`의 응답 형식을 묵시적으로 바꾸지 않는다.
- 원래 통합 결과의 `unresolvedFields`를 기존 `project_draft`에 전달해 Profile의 해당 값·근거를 비운다. 원래 값이 non-null이고 Profile 검증을 통과했다면 `proposals[field] = {value, evidence}`로 복사한다. 제안은 10개 필드·기존 값 길이·배열 최대30개·근거 위치 한도를 그대로 따른다. 새 원문 인용 필드는 만들지 않는다.
- `fieldStates`는 기존 suggested/unknown/unresolved 의미를 유지한다. 모든 suggested/unresolved 필드에 정확히 하나의 `confirm_<field>` 질문을 둔다. 미해결 사유는 `ANALYSIS_UNRESOLVED`, 검토를 마친 제안 확인은 `CONFIRM_SUGGESTION`, 응답 error는 기존 안전 코드 `REVIEW_CONFIRMATION_REQUIRED`를 사용한다.
- field 매핑이 없는 후보 거절·후보0으로 검토가 끝나지 못했는데 모든 값이 null인 경우, 질문0으로 끝내지 않는다. 확정 판단이 불가능한 unknown 항목을 unresolved로 표시하는 규칙을 명세에 고정한다. 누락 후보를 지어내지는 않는다.
- `candidate_profile`은 기존 complete 후보 형식으로 변환할 수 있으나, 이는 DB 저장 또는 사용자 확인 완료가 아니다. `needs_confirmation`을 complete로 승격하지 않는다.
- 입력 Profile·문서 ID·근거 범위·unresolved 필드·카운터의 형식과 불일치를 검사한다. 원래 분석 결과를 변경하지 않는 순수 변환을 먼저 구현하고 HTTP/worker 연결은 뒤에 한다.

### 필요한 검증

부분 배열 제안 보존, 반복 이름 표현 보존, null 일관성, 근거 범위 재검증, 모든 질문 완전성, 잘못된 계약의 거절, 원 객체 변이 없음, 검사 실패가 자동 완료로 바뀌지 않음을 합성 전체 경로 테스트로 고정한다. 실제 문서 제안 정확도와 Spring 확인·저장은 이 어댑터 테스트로 입증하지 않는다.
