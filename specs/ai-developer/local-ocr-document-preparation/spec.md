# 한국어 OCR 기반 기획서 변환 가능성 검증

## 목표와 현재 근거

새 기획서의 이미지 속 기능표·기술명·상태 표현을 원문 위치와 함께 복구하고, 정답 작성에 사용할 수 있는지 확인한다. 문서 입력 완전성을 보완하기 위한 로컬 실험이며, 이 실험의 성공만으로 서비스가 실사용 가능하다고 판정하지 않는다.

현재 pypdf 입력기는 글자가 있는 모든 페이지를 수락한다. 후보06은 DB/UI 이미지 내용을 놓친 채 수락됐다. 기존 선택형 표준 Docling도 `do_ocr=False`다. 후보05의 이미지 기능표, 후보06의 DB/UI, 후보07의 그림, 후보08 DOCX의 표/그림이 검수 대상으로 남아 있다.

## 접근 선택

1. **선택: 로컬 Docling + 한국어 RapidOCR.** 기존 Docling의 표/페이지 구조를 활용하고 OCR을 추가한다. CPU 시간·OCR 오인식·행 관계 오류를 별도로 측정해야 한다.
2. 외부 시각 모델: 문서 외부 전송과 비용 확인이 추가로 필요해 이번 로컬 실험에 포함하지 않는다.
3. 텍스트만 추출: 관측된 이미지 정보 누락을 복구하지 못하므로 성공 기준을 만족하지 않는다.

이번은 `brainstorming`의 가능성 검증(spike)이다. 사용자 SDD 요구에 따라 명세·계획·결과를 남긴다. 임시 실행 코드는 실험용으로만 보존하며 제품 모듈로 채택하지 않는다. 계획/실행에 대한 기존 자율 승인을 적용한다.

## 검증 요구사항

- 합성 자료에 한국어 대표 기능, 영문 기술명, `확정`/`검토 중`/`도입하지 않음`, 반복 인용, 이미지 표와 네이티브 텍스트를 넣는다. 기대 항목/행 관계를 변환 전에 고정한다.
- Docling·RapidOCR·Torch 버전과 OCR 언어/모델·설정을 고정한다. 로컬 모델 파일은 익명 공개 다운로드만 허용하고 배포자가 제공한 SHA-256과 대조한다. 사전 해시가 없는 사전 파일은 출처와 획득 해시를 기록한다.
- 문서 내용은 OCR·추출 과정에서 네트워크로 보내지 않는다. 추론 API 호출 0회. 모델 다운로드와 문서 변환을 분리하고 변환 프로세스의 외부 소켓 연결을 차단한다.
- 페이지별 텍스트와 Docling 원본 구조(표 셀·bbox·페이지)를 로컬에 보관한다. 변환문과 원문에서 근거 위치를 혼동하지 않는다.
- 합성 자료의 한국어/영문/부정·보류 표현과 표 행 연결을 확인한 뒤 같은 설정을 실제 후보에 적용한다. OCR 결과를 정답이나 사람 검토 결과로 자동 인정하지 않는다.
- DOCX는 원문 OOXML 표 셀/병합 관계를 보존하는 검토용 표현과 내장 그림 OCR 결과를 분리한다. DOCX 전체 페이지 배치는 렌더링 미실행 상태를 유지한다.
- 개인정보는 후속 변환 텍스트에서도 다시 제거한다. 원본 OCR 텍스트는 로컬 검수 전용이며 Git·공용 로그·모델 API에 넣지 않는다.
- 원문·기존 평가·골드·동결 자료를 덮어쓰지 않는다. 새 출력은 독립 디렉터리에 배타적으로 생성한다.

## 판정

실험 결과에는 복구 여부, 누락/오인식, 표 행 관계, 페이지 대응, 실행 시간, 실제 지원 범위, 미검증 부분을 기록한다. OCR이 성공해도 정보 완전성을 증명한 것은 아니다. 원문 대조가 끝나지 않은 자료는 모델 평가에 사용할 수 없다.

실제 API/Profile/기본 입력기·분석기는 변경하지 않는다. 유효한 변환이 확보되면 후속 SDD에서 자원 제한·실패 처리·부분 결과 표시를 갖춘 서비스 통합을 설계한다. 변환이 실패하면 그 자료를 쉬운 자료로 교체하지 않고 실패 근거를 보존한다.
