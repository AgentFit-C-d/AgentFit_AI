# FastAPI 분석 요청 수용 제한

상태: AI 서비스의 운영 안정화 기능. Spring Boot 내부 HTTP 계약은 팀 합의 전 제안이다.

## 문제

현재 FastAPI는 인증된 요청마다 최대 10 MiB body와 PDF 추출·Solar 분석을 병렬로 시작한다. 클라이언트가 body를 천천히 보내거나 요청을 집중하면 메모리와 worker가 계속 누적될 수 있다.

## 요구사항

- 한 서비스 프로세스에서 body 읽기부터 분석 응답 완성까지 동시에 수용하는 요청 수를 제한한다. 기본값은 2, `AGENTFIT_MAX_INFLIGHT_ANALYSES` 환경 변수로 1~8 범위에서 설정한다.
- 인증·헤더·`Content-Length`의 빠른 거절은 슬롯을 차지하지 않는다. 슬롯이 없으면 body를 읽거나 추출·Provider 호출을 시작하지 않고 `503 {"error":"SERVICE_BUSY"}`와 `Retry-After: 1`을 반환한다.
- 슬롯은 정상·입력 실패·분석 실패·예상 밖 예외에서도 해제된다.
- 인증 후 수용된 요청의 body 스트림에는 기본 10초의 전체 업로드 기한을 적용한다. `AGENTFIT_UPLOAD_TIMEOUT_SECONDS`로 1~30초 사이 설정할 수 있다. 초과 시 `408 {"error":"DOCUMENT_UPLOAD_TIMEOUT"}`를 반환하고 슬롯을 해제한다.
- 잘못된 설정은 서버 시작 시 실패한다. 원문·키·LLM 응답을 오류나 일반 로그에 넣지 않는다.

## 수용 기준

1. 병렬 요청이 제한값에 도달하면 추가 요청이 즉시 503이며 분석기 호출이 증가하지 않는다.
2. 첫 요청 종료 후 새 요청을 수용한다. 실패·업로드 시간 초과 후에도 같다.
3. 기존 문서 크기 제한, 인증, 성공·실패 응답과 전체 테스트가 유지된다.

## 남은 위험

프로세스별 제한이며 여러 Uvicorn worker 전체의 전역 상한은 아니다. 이미 시작한 동기 분석은 Spring 연결 종료만으로 취소되지 않는다. PDF worker의 OS 메모리 제한과 Spring 재시도 정책도 별도 과제다.
