## 결론

v1은 기능을 복구하는 대신 다른 필드와 누락 검토에 영향을 줬고, v2는 배포를 보존하는 대신 기능 손실이 재발했다. 두 문구 모두 기본 서비스에 적용하지 않는다. 이 결과만으로 모델 자체의 능력 한계라고 단정하지 않는다.

다음 설계는 필드별 검토 경계다. 각 후보 검토 요청은 한 필드의 후보만 허용하고, 기능 규칙은 기능 요청에만 넣는다. 누락 검토도 필드별로 수행해 10개 필드의 응답을 서버가 모은다. 한 필드의 프롬프트가 다른 필드의 후보를 삭제할 수 없는 응답 범위를 강제한다. 새 호출량·중복/누락 검토·모호한 근거·오확정 위험을 별도 검증한다.

목표 기준은 유지한다. 임시 gold, 기존 점수, source freeze, 기존 결과를 수정하지 않았다. 새로운 실제 기획서/사람 정답·수정 부담/실제 Spring·운영은 미검증이다.
