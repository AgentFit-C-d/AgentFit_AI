# 제품 용도와 기술 이름 구분 실험

## 근거와 가설

고정 후보 재검토에서 기술 목록에 명시된 제품 기능4개가 두 번 모두 wrong_field로 제외됐다. 기술 이름과 그 기술로 제공하는 제품 동작을 구분하는 공통 지침이 누락의 원인인지 확인한다. 제품별 이름·후보ID·정답은 새 지침에 넣지 않는다.

## 한 변수

기존 explicit-v1 프롬프트 끝에 제품의 명시적 실행 중 용도와 기술 이름/개발 작업/배포 절차를 구분하는 `runtime-purpose-v1` 설명만 추가한다. 기존 확정/부정/검토안/타제품 기준은 유지한다. 검토 대상·모델·배치·응답 계약·검증기는 유지한다. 모델에 추론으로 없는 기능을 만들도록 요구하지 않는다.

## 단계

1. PUBLIC-01의 동일 후보 snapshot을 새 설명으로2회 재검토한다. 직전 두 baseline을 보존해 비교한다.
2. PUBLIC-07의 동일 후보 snapshot을 새 설명으로2회 재검토해 명시적 기능의 과도한 삭제를 확인한다.
3. 원문에 채택 기능·개발/배포 용도·부정/검토안·타제품·반복 인용을 함께 넣은 고정 합성 문서에서 기존/새 설명 각1회 비교한다. 에이전트의 합성 기대값은 사람이 검토한 실제 정답이 아니다.

모든 입력/스크립트/설명/소스 hash를 먼저 고정한다. 최대6요청×13호출=78호출, 요청1200초/전체7200초/재시도0. 현재 무료 확인 원본을 각 호출 검증하며 실패/한도/확인불가 때 즉시 중단한다. 이전 결과/gold 변경0, 개인 문서/유료/배포0.

## 판정과 한계

명시적 제품 용도4개 유지, 비기능 안내2개 제외, PUBLIC-07 명시적 기능 유지, 합성 음성 사례의 잘못된 유지0을 확인한다. 유효성 오류/비기능 오확정/명시적 기능 손실이 있으면 기본 적용하지 않는다. 세대별 프롬프트 비교이며 새 문서 일반화·정확도95% 달성 증거가 아니다. 유효할 때만 별도 회귀 검증과 opt-in 서비스 연결을 진행한다.
