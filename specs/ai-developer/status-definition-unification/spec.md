# Status 정의 통일 비교

2026-10-02 KST. 사용자가 이전 최소 수정안을 승인하고 이 한 쌍의 비교를 요청했다.

## 목적과 변경 경계

기존 U+C의 실제 system 지침에서 중복된 status 설명만 하나로 통합한다.
confirmed는 유효한10개 출력 필드에 속하는 현재 대상 프로젝트의 긍정 사실이다.
범위 밖이 명확하면 other/irrelevant, 필드 판단 불가면 other/tentative다.
명시적 거절·부재·미제공은 해당 필드와 negated를 유지한다.
미정·해결되지 않은 상충은 tentative이며 원시 후보를 없애지 않는다.

다른 의미 분류 문장, 스키마, 모델·생성 설정, 원문·32개 후보·정답·서버 gate는 그대로 둔다.
제품 서비스는 변경하지 않고 별도 실험에만 연결한다. 큰 goal은 paused 유지.
기존 파일을 덮어쓰지 않으며 기존 U+C 원본 응답은 과거 결과로 보존한다.

## 고정 비교

- 기준선 UC: 저장된 classification-instruction-v1의 실제 U+C payload4개를 재사용하여 새로4회 호출.
- 변경 US: 각 기준 payload의 system에서 사전에 명시한 status 문장만 교체하여 새로4회 호출.
- FR: UC2→US2. LS: US2→UC2. 모델 deepseek-ai/deepseek-v4.1-flash, 기존 endpoint/설정 동일.
- 양쪽 전체 원문·앞뒤240자·모든 원문 줄 단위 ID·8개 배치 동일. 정답은 전송하지 않는다.
- 명확30개 주 점수, FR16/LS15는 별도 보고. 모델 오확정·gate 통과 오확정·정상 누락·올바른 제외·보류·인용 결함·시간 각각 집계.
- other/confirmed는 주30개와 전체32개를 따로 집계한다. LS07의 field/status/verdict와
  LS15의 실제 지지/상충 원문 단위 및230행 선택 여부를 추가 관측한다. 기존 주 점수 정의를 바꾸지 않는다.

## 안전과 완료 기준

로컬 구현·검증 최대60분, 호출 전체최대90분·요청당600초·총8회·재시도0.
현재 유효한 무료 계정 확인을 호출 전 매번 검사한다. 무료 확인 만료·한도 거절·통신/파싱/계약 실패 시 전체 중단.
입력·프롬프트·코드 hash를 호출 전에 고정한다. 첫 실행 마커로 재실행을 차단한다.
기존 gate의 other/confirmed 보류와 원시 응답 보존을 유지한다.
로컬 고정 응답 테스트와 실제 모델 성능은 따로 보고한다. 결과 확인 후 정의나 정답을 수정하지 않고 종료한다.
