# 분류 단계 모델·묶음 선택

## 목적과 근거

15후보 파일럿 4호출은 모두 완료했고 지정 기능은 GLM 5/5, DeepSeek 4/5였다. 이전 30후보 GLM 실행은 세 번째 호출에서 종료됐다. 단회·부분 결과이므로 전체 품질이나 인과를 확정하지 않는다. 같은 전체 원문·후보를 대상으로 분류 설정을 비교할 수 있는 내부 옵션을 제공한다.

## 요구사항

1. `classify_profile_candidates(..., batch_size=30)`은 엄격한 int 15 또는 30만 허용한다. 빈 후보여도 잘못된 설정은 전송 전에 거절한다. 기본30과 기존 Solar/NVIDIA 모델 선택은 유지한다.
2. 각 묶음은 원래 후보 순서·ID·근거 위치와 전체 원문을 보존한다. 마지막 잔여 묶음을 포함해 모든 ID가 정확히 한 번 라벨을 받는다. 묶음 경계를 넘은 ID/누락/중복/제공자 실패는 부분 결과 없이 실패한다. 지침·출력8192·호출600초·other 정규화는 유지한다.
3. 통합 분석과 NVIDIA 전용 진입점은 `classification_model=None`, `classification_batch_size=30`을 받는다. None은 기존 후보 추출 경로를 상속한다. 명시한 모델은 기존 NVIDIA 허용 목록만 허용하며 NVIDIA 키·전송을 사용한다. 추출/기능/검토 모델 설정은 그대로다. 혼합 경로에서도 분류만 NVIDIA로 선택할 수 있다.
4. 두 옵션은 추출·외부 호출 이전에 검증한다. NVIDIA 전용 실패는 재시도·대체 없이 중단한다. 혼합 경로는 기존 재시도 정책을 유지한다. 분류 호출도 전체 공유 예산과 안전 진단에 포함하며 마지막 묶음 실패 시 후속 검토·저장을 진행하지 않는다.
5. 공개 Profile/HTTP/환경변수/Spring 계약에 옵션을 노출하지 않는다. 실제 품질 향상 판정은 새로 고정한 전체 문서 비교와 후속 사람 검토에서 수행한다.

## Global Constraints

- 기본 모델 상속·묶음30 유지. 공개 HTTP/Profile/Spring 변경0. 후보 최대240·문서100000자·대표기능30 이하 유지.
- 전체64회 공유예산·분류 호출600초·NVIDIA-only retry0 유지. 로컬 suite별180초, 이 구현 단계 실제API0. 실제 비교는 코드/자료/모델을 새 freeze로 고정하고 별도 호출·시간 예산 등록 후 실행한다.
- 비밀·원문·원본 응답 로그0. 이전 결과/gold/freeze/scratch 삭제·덮어쓰기0. feature 브랜치 commit/push, 병합·배포0. 무료 확인된 모델/엔드포인트만 실호출한다.

## 수용 기준

- 기본 및 15묶음에서 31/240후보 전체 ID와 원문 위치가 보존되고 입력이 변하지 않는다.
- 유효하지 않은 모델/묶음은 외부 작업0으로 거절한다. 분류 실패와 공유 예산 초과는 CLASSIFICATION_FAILED로 종료한다.
- 혼합/NVIDIA-only 경로에서 분류 모델만 교체해도 같은 합성 입력의 최종 Profile·근거는 유지한다. 기본 모델/호출 경로도 기존 테스트로 검증한다.
- 로컬 전체 unit/runtime/contract/core와 독립 최종 리뷰를 통과하고 새 브랜치를 push한다. 새 문서·사람 수정량·실제 Spring·운영은 미검증으로 남긴다.
