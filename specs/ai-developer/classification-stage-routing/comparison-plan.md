# 전체 후보15묶음 분류 비교 사전등록

## 목적

부분15후보 파일럿의 결과가 같은 문서의 전체 후보에서도 유지되는지 비교한다. 분류만 실행하며 과거 검토를 새 라벨에 적용하지 않는다. 새문서·사람 검토·최종 Profile 정확도는 이 실험으로 판정하지 않는다.

## 입력·설정

- 기존 capability-occurrences-full-v1의 PUBLIC-01(173후보), PUBLIC-07(36후보)와 runtime-purpose-review/mixed-synthetic.json(16후보). 원문·후보·ID·정답을 바꾸지 않는다.
- 순서: PUBLIC-01 DeepSeek→GLM, PUBLIC-07 DeepSeek→GLM, 합성 DeepSeek→GLM,각1회. 분류 batch15/explicit-v1/출력8192/모델 호출600초. 모델별 기존 adapter 설정까지 포함한 비교다.
- 추출에서 거절된 수(PUBLIC-01=1)는 별도 메타데이터로 유지한다. 분류에는 정확한 후보만 전달하며 이전 오류의 원인을 복원하거나 이전 라벨을 모델에 보내지 않는다.
- 신규 source-validation-freeze.json은 현재 코드와 기존 corpus/gold를 검증하는 용도다. 실행 조건은 별도 comparison-freeze.json에 등록한다. 과거 freeze를 갱신하거나 현재 결과를 과거 조건에 이어 기록하지 않는다.
- 새 출력 classification-full-batch15-v1. 기존 JSON의 내용 hash를 시작·종료에 대조한다. 키/원문/자유 예외/원본응답 기록0, 라벨ID·field·status와 안전한 호출 메타데이터만 보관한다.

## 비교 항목

1. PUBLIC-01 지정6기능 C059/C061/C066/C069/C071/C073의 features/confirmed, 비기능 C019/C026의 확정 여부, Docker C113/C115의 deployment/confirmed를 각기 집계한다.
2. PUBLIC-07 기존14기능의 보존과 모든 후보의 라벨 변화. 이전 라벨 전체를 정답으로 취급하지 않는다.
3. 합성 keep8/reject8의 지정필드 판정과 다른 필드로 확정한 거절항목을 별도로 집계한다. 제품명 누락은 후보 밖이므로 미평가다.
4. 모델별 구조 완주·실패 코드·실제 호출·시간·반복 차이. 부분 실패는 성공으로 합치지 않는다. 과거30묶음과의 차이는 실행시점·묶음크기 변경을 포함한다.

## 상한과 중단

- 문서별 최대12/3/2호출,전체34호출·재시도0. 각 모델 호출은 기존 subprocess timeout600초 이내. 문서별 예정호출수×600+60초(7260/1860/1260초), 전체20760초 이내이며 매 전송 전 남은 시간을 확인·적용한다. 파싱/집계는 제한된 후보·응답 크기 내 로컬 작업이다.
- 기존 무료 확인의 만료·허용모델·엔드포인트·예산을 매 전송 직전에 재검증한다. 무료 여부를 새로 추정하거나 만료를 연장하지 않는다. 제공자/구조/자료변경/시간/무료 한도 오류가 하나라도 나면 후속 호출을 중단하고 결과를 보존한다.
- 로컬 helper 검사 각180초/API0:전체원문/후보동일·모델간입력동일,34호출계산,마지막묶음실패 보존,무료거절0호출,비밀비노출,결과덮어쓰기차단,후보·코드변경 거절. 새 구현의 독립리뷰·push·CI 이후 실제 실행한다.

## 후속 결정

지정 회귀 항목 개선과 전체 분류 완주를 함께 확인한 경로에만 새 추출→분류→검토→초안 평가를 수행한다. 의미 기준은 사람 검토 전의 임시 기준임을 유지하고, 새문서10×3·precision95/recall90·수정량·실제Spring/운영 목표는 낮추지 않는다.
