# 문서 입력부터 확인 저장까지 검증

## 목적과 범위

기존 핵심 흐름에 PDF·Markdown 입력을 연결한 로컬 통합 검증을 추가한다.
기본 서비스, 공개 API, 모델, 평가 자료와 의존성은 바꾸지 않는다.
사용자가 승인한 실사용 목표의 범위에서 직접 구현한다.

## 계약

- 실제 공개 mock HTTP → AI ASGI → 실제 문서 파서 → 실제 분석 자식 프로세스·LangExtract → 합성 loopback NVIDIA → DRAFT → 사용자 수정 → CONFIRMED → 재조회·삭제를 실행한다.
- Markdown은 UTF-8 BOM만 제거하고 한글·이모지·CRLF를 보존한다. 근거는 Unicode code point 기준이다.
- 텍스트가 있는 두 페이지 PDF는 실제 pypdf 자식 프로세스로 추출한다. 페이지 사이 줄바꿈을 포함한 근거가 저장 이후에도 유지되어야 한다.
- 잘못된 UTF-8, 빈 Markdown, 100,000자 초과, 손상·암호화·전체 빈 페이지·일부 빈 페이지·100쪽 초과 PDF는 기존 413/422 코드로 거절한다. 분석 모델을 호출하지 않고 이전 초안·확정 값·버전을 유지한다. 유효한 다음 입력은 처리 가능해야 한다.
- 원문 전체·비밀 키·실패 원문은 mock 저장소와 공개 오류에 남기지 않는다. Profile의 명시적 추출 값 저장은 허용된다.
- PDF pageCount/characterCount는 현행 내부 응답 계약에서 전달되지 않아 공개 mock에서는 null이다. 이를 실제 측정 완료로 표시하지 않는다.

## 증거와 한계

합성 PDF와 Markdown의 통합 동작을 검증한다. 외부 모델의 의미 판단 정확도, 실제 Spring·DB, OCR·복잡한 PDF 레이아웃, 운영 로그·백업 삭제는 증명하지 않는다.
같은 시점의 NVIDIA 실제 30건 평가는 별도 작업트리에 고정하며 그 소스·입력·실행은 수정하지 않는다.

## 예산

이번 작업의 추가 외부 모델 호출 0, 유료 사용 0, 자동 재시도 0, 배포 0.
로컬 HTTP는 기존 30초 AI/45초 mock/50초 client 상한을 사용한다.
대상 검사 120초, 최종 로컬 네 개 suite 각각 180초, CI 관찰 10분 상한이다.
기존 실제 평가의 호출 예산과 결과에 합산하지 않는다.
