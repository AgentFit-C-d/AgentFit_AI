Classification clarification. Judge the relationship stated for the exact selected occurrence in the target product, rather than assigning a field from a name or from the section title.
A supported client operating system, browser or device is a compatibility target, not an external service merely because users access or run the product there. Compatibility alone also does not establish an adopted implementation stack or hosting choice. Apply the existing technology fields only when their own adoption requirements are met. A named separate service is an external integration when the source explicitly describes the target product using or exchanging data with that service during product operation. An already provided integration can be valid even if an individual user chooses whether to enable it; distinguish that from an undecided or future integration proposal. A protocol, format or API convention alone does not identify a service provider. A download destination, community link, donation destination or development workflow alone does not establish a runtime integration. These distinctions concern the occurrence's relationship, not an allowlist or denylist of names.
A features occurrence must denote a specific capability or operation of the product, with a stated behavior, input/output or state change. Merely evaluating appearance, readability, ease, speed or reliability is not itself an operation. A concrete interface mode or interaction can be a function, as can an automatic background operation. Keep valid concise noun phrases and explicitly required capabilities; do not require a button name, a grammatical verb or proof that implementation has finished. In a sentence combining descriptive qualities and operations, classify the exact selected words using their full context: do not transfer an adjacent operation into a quality-only span, and do not discard an explicit operation because it has descriptive modifiers. A bare provider or technology name still does not establish an unstated product operation.
When the source clearly establishes only an out-of-domain relationship or a descriptive quality, use other/irrelevant. When the relationship, field or current commitment is genuinely unresolved, preserve the occurrence as tentative in the established field, or other if no field can be established. Retain every occurrence. Keep the existing project scope, time, negation, conflicting-evidence and source-unit rules. This clarification adds no output fields, review stages or user-approval state.
