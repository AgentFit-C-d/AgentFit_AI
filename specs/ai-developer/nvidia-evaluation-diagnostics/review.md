## 판정과 수정

- Critical 0 / Important 1 / Minor 0. 최초 판정 `With fixes`.
- Important/P2: 부모 `analysis_process.accept()`는 정상 `needs_confirmation`에 `unavailable` 진단이 붙어도 수락했지만, 평가 저장 검증기는 거절했다. 따라서 성공 응답이 평가 단계에서 `INVALID_CHECKPOINT`가 되어 시작 기록만 남았다.
- 담당자 판단: 실제 사용자 영향은 진단 실험의 실패 기록 유실과 원인 파악 지연이다. 중요한 경계 오류로 수용한다. 기본 서비스는 이 진단 옵션을 사용하지 않는다.
- 수정: 부모에서 `unavailable + 비실패 결과`를 `ANALYSIS_WORKER_FAILED`로 거절한다. 수집기는 초기 unavailable 상태를 보존한다. 실패 결과의 unavailable은 계속 허용한다.
- 검증: 실제 합성 자식으로 부모의 미거절과 저장기의 `INVALID_CHECKPOINT` 두 실패를 재현(RED2). 수정 후 관련 모듈14/14 통과(8.365초). 안전한 `ANALYSIS_FAILURE` terminal 저장·추가 실행 차단·재개 시 파일 불변도 확인한다. 최초 테스트 삽입의 들여쓰기 오류는 구문 수정 후 재현했으며 RED 근거로 집계하지 않는다.
- 한 번의 중요 수정만 적용했다. 새 진단 실험은 실제 호출 전이므로 해당 freeze만 갱신했으며 이전 평가 freeze·gold·결과 파일은 보존했다.
