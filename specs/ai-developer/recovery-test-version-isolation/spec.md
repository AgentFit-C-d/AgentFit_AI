# 복구 테스트 버전 격리

## 승인 범위

현재 서버의 tentative/proposed 수정은 유지한다. 과거 실행을 현재 코드로 복구할 수 없다는 검사를 보존하면서, 같은 버전에서의 기존 복구 검증을 끝까지 실행한다. 테스트·fixture 구성·오프라인 실행 도구·문서만 수정한다. 모델·외부 전송·실제 재개·서비스/계약/골드 변경·배포·Spring 저장은 0, 큰 Goal은 paused.

## 완료 조건

- CODE_MISMATCH에 막힌 11개가 검증하려던 조건을 기록한다.
- 구 fixture zip/manifest 및 그 안의 원문·응답·코드·해시·기대값을 변경하지 않는다.
- 동일 버전 동작은 hash 검증한 snapshot을 새 임시 경로에 복사하고 별도 Python에서 실행한다. 기존 assertion을 유지하고 개별 성공/실패/skip을 부모 suite에 전달한다.
- 현재 코드/옛 실행의 CODE_MISMATCH는 별도 회귀로 확인한다. 옛 파생 decision 거부, 같은 raw 재판정 후 별도 결과 보존도 확인한다.
- 유효한 시작 상태에서 결함을 넣는 검사들이 실제 의도된 오류에 도달하는지 검증한다. blanket skip/expectedFailure 전환/해시 완화는 금지한다.
- 전체 unit suite를 재실행하고 나머지 로컬 실행 가능한 CI 회귀도 구분해 보고한다.

## 제약

정확한 과거 Python 바이너리·의존성을 바꾸어 맞춘 것으로 가장하지 않는다. 기존 플랫폼 불일치 skip 조건을 보존하고 발생 여부를 보고한다. 새로운 현재 코드용 실제 실행 fixture는 만들지 않으며 합성 시험은 표시한다.
