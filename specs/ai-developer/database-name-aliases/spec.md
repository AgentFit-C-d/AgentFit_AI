# DB 이름 별칭 충돌 수정

## 범위와 원인

저장된 Documenso 응답의 `Postgres SQL Database`와 `postgres database`는 모두
database/confirmed이지만 `project_candidate_profile`이 원문 문자열을 비교해
복수 scalar 값으로 처리한다. 최초 오류 지점은 분류 이후 Profile 후처리다.
이번 수정은 이 동등성 판정 하나에 한정한다. 큰 goal은 paused를 유지한다.

## 동등성 기준

- database 필드의 confirmed 후보에만 적용한다. 분류·의미 판단·사용자 승인은 바꾸지 않는다.
- 허용 이름은 `Postgres`, `PostgreSQL`, `Postgres SQL`이다. 대소문자와 이름 사이의
  수평 공백은 구분하지 않는다. 뒤의 `DB`/`Database`는 설명 접미사로 허용한다.
- 이름 다음의 숫자 버전(예: `16`, `16.1`, 선택적인 `v` 접두사)은 그대로 비교한다.
  양쪽 모두 버전 미지정이거나 버전 문자열이 정확히 같을 때만 병합한다.
- `16`/`16.0`, `15`/`16`, 버전 지정/미지정은 병합하지 않는다. 범위·부등식·최신 버전
  표현, 호환 제품, 공급자/배포 방식 수식, 둘 이상의 DB를 담은 문장도 추론하여 합치지 않는다.
- MySQL/MariaDB, PostgreSQL/CockroachDB/Aurora 등 서로 다른 제품은 그대로 충돌 처리한다.
  허용 목록에 없는 값은 기존 원문 일치 기준을 유지한다. 유사도·부분 문자열 매칭은 금지한다.
- 후보가 단어 중간에서 잘렸거나 바로 뒤에 후보에서 빠진 버전 표기가 있으면 병합을
  보류한다. 알려진 수식 이름(Aurora, AlloyDB, RDS, Cloud SQL, Azure Database) 뒤에서
  PostgreSQL 부분만 추출한 경우도 병합하지 않는다. 이 보호는 인접 80자 내 표기 확인이며
  원거리 문맥의 버전/제품 추론을 대신하지 않는다. 후보에 포함된 미등록 수식은 전체 일치에서 거부한다.
- 하나의 DB로 묶이면 원문에서 가장 먼저 등장한 후보의 **원문 값과 그 값의 정확한 근거**를
  Profile 대표로 사용한다. 원문에 없는 표준 이름을 만들지 않는다.
  시작 위치가 같으면 더 긴 원문 표기를 선택해 후보 배열 순서의 영향을 없앤다.
  모든 후보·label·modelDecisions 기록은 보존한다. 입력을 수정하지 않는다.
- 버전/제품 충돌, 의미 검토에서 발생한 확인 필요, 거부 후보로 인한 최종 확인 요구는 유지한다.

## 완료 기준

1. 기존 응답 원본을 변경하지 않고 해시·후보 위치를 기록하여 충돌을 재현한다.
2. 동일 저장 응답을 변경 전/후 코드로 재생하여 DB 누락과 충돌을 비교한다.
3. 이름·대소문자·후보 순서·동일 버전 변형과 다른 제품·다른 버전·수식 문구를 회귀 검증한다.
4. 원문 근거 및 confirmation-v2 검증을 통과하고 사용자 승인으로 승격하지 않는다.
5. 새 모델/API 호출 0회. 유료 실험·Luna·운영 배포·실제 Spring 연결은 실행하지 않는다.
6. 이번 변경 파일만 feature 브랜치에 commit/push하고 결과·제약을 보고한 뒤 종료한다.
