# B의 근거 표현만 비교하는 한 쌍 실험

2026-10-01 사용자 승인: 기존 B 인용문 vs 원문 단위 ID 선택, 로컬 검증 후 무료 NVIDIA 최대18회,
재시도0, 결과 보고 후 종료. 서비스/큰 goal/관계 검증기는 범위 밖.
이전 E1·E2 결과의 후속 최소 변경을 채택한다. 추가 설계 재승인을 요구하지 않는다.

## 고정 조건

- 두 arm 모두 기존 B 직접 field/status 분류, 동일한 분류 문장·필드 설명·status enum·정답10개.
- 원본 `output/direct-field-comparison-v1/inputs.json`의 원문4558자, 후보68개/순서, rejected24개,
  승인 정답10개/양성6개를 고정한다. 새 추출/정답 수정/모델 이름별 예외 없음.
- DeepSeek V4.1 Flash, NVIDIA 동일 endpoint, temperature0, thinking=false, max_tokens8192.
- Q(내부 gate A)=인용문, U(내부 gate B)=unit ID. 과거 다축 A와 혼동하지 않도록 결과에 Q/U로 명시.
- 동일 user message: 원문 전체 + 각 후보의 기존 앞뒤240자 + E1의 전체132줄 단위와 후보 위치 연결.
  Q에도 같은 단위 목록을 제공한다. 따라서 이전 저장 B와 입력 직렬화까지 동일한 실험은 아니며
  이번에 새로 실행한 Q와 U끼리만 효과를 비교한다.
- 동일 batch8(마지막4), 9호출씩 Q→U 순서. 원문·후보·정답·payload·코드·무료 기록을 실행 전에 hash 동결.

## 유일한 실험 요인과 서버 처리

- Q: 기존 B의 quote/occurrence 근거 지시·응답 계약·validate_direct를 유지한다.
- U: 분류 지시는 그대로 두고 근거 복사 지시만 unit ID 선택으로 바꾼다.
  supportUnitIds/counterUnitIds를 E1 resolve_units로 검증한 후 기존 B와 같은 판정 규칙을 적용한다.
- 형식별 근거 제한은 기존 계약을 따른다: Q support/counter 각각 최대4인용·인용당2000자;
  U 각각 최대8줄 단위·합계4000자. 단위별 길이·제목 단독/전체 후보 coverage 검증은 E1 계약이다.
  이 표현별 제약도 결과의 해석 한계에 포함한다. 분류 기준이나 별도 의미 gate는 추가하지 않는다.
- U의 잘못된 참조/상한 초과/후보 미포함/제목만 선택은 citation defect와 보류로 남긴다.
  원래 모델의 field/status와 선택 ID는 보존한다. 잘못된 근거 때문에 원모델 오확정이 채점에서 사라지지 않는다.
- 구조상 파싱 불가·field/status 계약 오류·모델/입력/무료 확인 오류·provider 실패는 한 쌍 전체 중단.
  불완전 arm은 점수 null, 부분 결과·원응답·시작 기록은 보존한다.
- 서버 통과란 **격리 실험의 B 판정 gate** 통과다. 실제 서비스/저장까지 통과했다는 뜻이 아니다.

## 측정

- 인용 결함: 전체68개 중 유효한 해당 후보 근거를 제공하지 못한 수, 사유별 분리.
- 모델 자체 오확정: 승인 gold10개에서 raw status=confirmed, 유효 출력 field이나 정답 field와 다름.
- 서버 통과 오확정: 같은 gold10개에서 verdict=supported이나 정답 field와 다름.
- 정상 누락: 양성6개 중 올바른 field로 supported 되지 못한 수; 보류/제외/오필드 원인을 분리.
- 보류: 전체68개/주 평가10개/정상6개 각각 집계. 후보 유실·호출 수·시간·토큰 별도 기록.
- 특히 태그 정리 C005는 field=features/supported 복구 여부, Clean UI C004는 raw confirmed 및
  supported로 오확정이 통과하는지 원문·선택 근거와 함께 보고한다.
- gold 밖58개를 맞았다고 세지 않는다. 새 사람 검토나 S1–S3 없이 정답 범위를 확장하지 않는다.
