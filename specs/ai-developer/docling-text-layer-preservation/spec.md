# Docling 텍스트 영역 보존

## 목적과 근거

처음 보는 기획서를 분석할 때 머리말·꼬리말이라는 레이아웃 분류 때문에 서비스명·조건·부정 문장을 잃지 않도록 한다. 로컬 OCR 합성 mixed 문서에서 `Native metadata: Project Birch`가 Docling JSON에는 남고 기본 export/iterate에서 제외되는 오류가 재현됐다. 변환 결과가 의미적으로 정확하다는 보장과는 별개다.

## 요구사항

1. 선택형 `convert_structured_pdf_bytes(raw, converter=...)`는 Docling의 body/furniture/background/invisible/notes 텍스트 영역을 명시적으로 순회하고 같은 범위로 내보낸다. 모델이 레이아웃을 잘못 분류해도 저장된 텍스트를 자동 삭제하지 않는다.
2. 원본 `document.texts` 목록과 순회 결과를 대조한다. 텍스트 객체가 구조에서 도달 불가능하거나 알려지지 않은 영역으로 제외됐으면 `PDF_PARTIAL_TEXT`로 거절한다. 별도 텍스트를 임의로 끝에 붙여 복원하지 않는다.
3. 머리말·꼬리말도 본문과 동일하게 단일 페이지 근거·텍스트 포함·반복 횟수를 검증한다. 표의 행/열 표현, Unicode 문자 위치, 파일·문자·페이지 상한, 안전한 오류를 유지한다.
4. Docling 미설치 환경에서도 모듈 import와 가짜 변환기를 이용한 테스트가 동작한다. 기본 HTTP 입력기·Profile·LLM 호출은 변경하지 않는다.
5. 기존 실험 원문·기대값·결과는 보존한다. 수정된 변환 결과는 별도 보고서로 기록하며 OCR 품질 실패를 성공으로 바꾸지 않는다.

## 한계와 후속 작업

숨김/주석 등 원문 텍스트도 포함하므로 이 텍스트 자체를 제품 기능의 확정 근거로 자동 채택해서는 안 된다. 기존 사용자 확인과 의미 검토 정책을 유지한다. 여기서 보장하는 범위는 Docling 구조에 남은 텍스트의 보존이다. Docling 이전의 native 추출 누락, 이미지 글자 미인식, OCR 오인식은 별도로 검증해야 한다.

사용자 목표의 계획/변경/구현 자율 승인을 적용한다. 구현은 직접 수행하고 마지막에 독립 코드 리뷰를 받는다. 운영 배포·실제 문서 모델 전송은 이번 변경에 없다.
