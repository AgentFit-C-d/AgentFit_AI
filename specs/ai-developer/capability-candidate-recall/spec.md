# 기능 후보 누락 가설 검증

## 목적과 범위

처음 보는 기획서에서 기능 후보를 빠뜨리지 않으면서, 부정·검토안·다른 제품의 기능을 현재 제품의 확정 기능으로 승격하지 않는 것이 목표다. 이번 작업은 동작 추출 안내 문구 한 가지를 비교하는 제한된 실험이다. 기본 서비스와 기존 평가 자료·정답·freeze는 변경하지 않는다.

## 관측과 가설

- 직전 진단에서 PUBLIC-01의 임시 기능 정답 7개, PUBLIC-09의 3개가 첫 관측 후보에 없었다. PUBLIC-07은 11개 모두 있었다.
- 현재 동작 추출 안내는 action+object를 선호하고 capability nickname/heading label을 피하도록 한다. 짧은 명사형 기능까지 배제하는 것이 원인일 수 있으나 아직 입증되지 않았다.
- PUBLIC-01의 임시 정답에는 기술 목록의 용도와 당위형 소개 문장이 있다. PUBLIC-09의 세 기능은 Pro 제품 안내에 있다. 따라서 이들을 **추출 후보에 포함하는 것**과 **현재 제품의 확정 기능으로 판단하는 것**을 따로 측정한다. 임시 gold를 수정하거나 사람 정답으로 승격하지 않는다.

## 비교 설계

1. PUBLIC-01, PUBLIC-09, PUBLIC-07 원문 전체를 각각 기존 안내와 새 안내로 동작 추출한다. 순서는 문서별 A/B, B/A, A/B다. 각 조건 1회다.
2. 새 안내는 본문·목록·표·제목·기술 용도에 쓰인 짧은 기능 표현도 후보로 수집한다. 부정·예정·다른 제품 문맥도 보존하며 기능을 발명하거나 확정하지 않는다.
3. 동일 DeepSeek 모델·온도·토큰·근거 계약을 유지한다. 추출 결과를 같은 explicit-v1 분류기로 판단한다. 전체 분석기의 일반 후보 추출·검토·Profile 투영은 이번 분리 실험의 대상이 아니다.
4. 후보 위치의 정확/포함 도달, 분류 field/status, 거절 수, 호출 수·시간을 기록한다. 정답 원문이나 정답 값은 모델에 전달하지 않는다.
5. 사전 판단 기준: PUBLIC-01/09 합계 후보 도달이 증가하고 PUBLIC-07의 기존 도달을 보존하면 전체 파이프라인 비교 대상으로 채택한다. 단계별 후보 도달은 의미 정확도·출시 통과율이 아니다. 분류가 의심스러우면 별도로 기록한다.

## 실행 제한과 보존

- 사용자 승인된 공개 문서만 사용한다. 기존 무료 확인 파일과 DeepSeek endpoint 범위만 사용한다. 확인 만료/한도/제공자 오류에 즉시 중단하며 재시도·유료 대체는 0회다.
- 요청 6개, 요청당 모델 최대 3회(추출 1 + 후보 60개 분류 최대 2), 전체 최대 18회. 요청당 600초, 전체 3600초. 이전 예약을 계정 잔여 할당량으로 해석하지 않는다.
- 기존 원래 소스 freeze와 문서·gold hash를 매 요청 전후 확인한다. 실험 스크립트와 안내 문구도 별도 hash로 고정한다. 새 결과 폴더만 허용하고 중단 후 자동 재개하지 않는다.
- 키는 메모리/자식 stdin만 사용한다. 저장 결과는 ID·위치·enum·개수·hash·시간과 고정 오류 코드로 제한한다. 원문·인용·API 응답·키는 새 결과에 저장하지 않는다.
- 실패도 결과로 남기고 다음 호출을 중단한다. 기존 결과를 소급 수정하지 않는다. 코드 채택은 실제 비교 이후 별도 구현 단계에서 결정한다.

## 완료 증거

사전 등록 조건, 실제 실행 종료 상태, 6개 조건별 결과 또는 중단 사유, 후보 단계와 의미 판단의 한계, 다음 구현 결정이 있어야 한다. 새 실제 기획서 일반화·사람 수정량·실제 Spring/운영 검증은 계속 미완료다.
