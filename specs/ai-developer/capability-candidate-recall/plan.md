# 기능 후보 누락 가설 검증 계획

**Goal:** 동작 추출 안내의 표현 범위가 후보 누락 원인인지 동일 조건으로 확인한다.
**Spec:** [spec.md](spec.md)
**Execution:** brainstorming의 제한된 spike. 사용자의 자율 설계·실행 승인을 적용한다. SDD 요청에 따라 실험 명세·계획을 먼저 기록한다. 임시 스크립트는 이 실험만 실행하며 서비스 코드로 채택하지 않는다.

## 절차

- [x] 기존 freeze와 실제 Git 상태를 확인하고 새 feature 브랜치에 명세·계획·안내를 커밋한다.
- [x] 새 계획 전용 scratch에 단발성 실행 스크립트를 작성한다. 기존 키 로더·무료 검증·추출·분류·근거 검증을 재사용한다. 코드나 문서 변경, 기존 출력 경로, 민감정보, 예산/제공자 실패에서 중단한다.
- [x] 모델 호출 없이 원래 freeze·문서·정답·안내·스크립트 hash, 출력 경로와 무료 확인 유효성을 점검한다. 이 점검은 API 품질 검증이 아니다.
- [x] 승인 범위의 6요청/18모델 호출/3600초/재시도0으로 실행한다. 실제 handle을 추적하며 관찰 시간 초과를 실행 종료로 해석하지 않는다.
- [x] 원문 위치를 임시 정답과 로컬 대조하고 분류 결과를 분리해서 보고한다. 기존 결과 불변을 확인한다.
- [ ] 결과와 후속 결정을 커밋·push한다. 성공해도 전체 흐름 품질 개선으로 표현하지 않는다. 서비스 코드 채택은 다음 SDD 구현에서 진행한다.

## 판단 규칙

PUBLIC-01/09 후보 도달 증가 + PUBLIC-07 기존 도달 보존이 다음 전체 흐름 비교 조건이다. 불충족이면 안내만 바꾸는 가설을 채택하지 않는다. Pro 범위·기술 용도·당위 문장은 사람 검토 전 확정 정답으로 취급하지 않는다.

## 예산과 검증 범위

로컬 사전 점검 180초, 실제 요청당 600초/최대3호출, 전체 3600초/최대18호출, 재시도0. 새 제품 코드 변경은 없으므로 기존 전체 테스트를 단순 재실행해 의미 개선 증거로 삼지 않는다. 실행 스크립트는 임시 연구 도구이며 독립 최종 기획서 평가는 아니다.
