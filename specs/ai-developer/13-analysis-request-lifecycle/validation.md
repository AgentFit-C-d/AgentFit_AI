# 검증 기록

- TDD: Worker 전송·출력 5건, 프로세스 기한·취소·오류 5건, HTTP 기본 경로·기한·연결 종료·PDF 사전 검사 테스트를 각각 실패 상태에서 확인한 뒤 구현했다.
- 실제 프로세스 기한 초과와 태스크 취소 테스트에서 반환 후 자식의 `returncode`가 확정됐고 3초 이내에 끝났다.
- ASGI 및 로컬 TCP 연결 종료 테스트에서 Worker가 취소되고 응답 전송을 시도하지 않았다. 최초 구현은 정상 연결 종료를 Uvicorn 예외로 기록해, 전송 없는 종료 응답으로 수정했다.
- 이미 끊긴 요청에서 Worker가 먼저 시작되는 경합을 실패 테스트로 재현했다. 분석 전 `request.is_disconnected()` 확인을 추가해 수정했다.
- 요청 기한이 PDF Worker 최대 실행 시간보다 짧으면 추출을 시작하지 않는 실패 테스트를 추가해 수정했다.
- 전체 AI 테스트 500건 통과. 평가 CLI의 `--live required` 문구는 기존 예상 출력이며 테스트 종료 코드는 0이었다.
- 로컬 Uvicorn health·인증·분석 응답 smoke 통과.
- 합성 문서의 실제 Solar 호출: 격리 Worker 직접 2회 `complete`, 로컬 FastAPI HTTP 경유 2회 `200 complete`, 1회 `502 PROVIDER_TIMEOUT`. 재실행에서는 완료됐다. 이 한 번의 실패 원인은 확정되지 않았으며 공급자 지연 가능성을 후속 관측 대상으로 남긴다.
- 독립 코드 리뷰를 두 차례 요청했지만 리뷰어의 셸 환경이 동일한 setup 오류로 파일을 읽지 못했다. 독립 리뷰 완료로 간주하지 않는다.

## 남은 위험

- PDF 추출 자체는 기존 별도 Worker와 스레드 경계를 사용한다. OS 수준 메모리 상한과 프로세스 생성 지연까지 엄밀한 전체 기한 보장은 후속 과제다.
- Spring 계약·저장·사용자 확인 흐름 및 의미 정확도는 이 기능의 검증 범위 밖이다.
