# 분석 요청 수명주기 명세

## 목적

FastAPI가 받은 유효한 문서 요청은 업로드 시작부터 분석 결과 생성까지 한 번의 전체 기한과 취소 경계를 갖는다. Spring 연결이 끊기거나 기한이 지나면 Solar 호출을 포함한 해당 요청의 실행을 끝내고 동시 수용 슬롯을 돌려준다. 공개 Profile 및 기존 내부 HTTP 성공 형식은 유지한다.

## 현재 문제와 선택

현재 `run_in_threadpool(analyze_document, ...)`는 동기 분석을 실행한다. ASGI 요청 태스크가 취소되어도 실행 중인 스레드와 그 안의 Provider 호출을 즉시 종료할 수 없다. 스레드 작업을 단순히 백그라운드로 버리면 수용 슬롯·호출 비용·CPU 사용량의 실제 상한이 어긋난다.

기본 Solar 분석만 요청별 단일 자식 프로세스로 옮긴다. 이 프로세스는 기존 `SolarAnalyzer`와 동일한 Provider HTTP 계약을 프로세스 내부에서 직접 수행한다. 즉 Provider 호출을 위한 두 번째 자식 프로세스는 생성하지 않는다. 부모는 요청 종료 시 해당 단일 프로세스를 종료·회수한다. 테스트용 `create_app(analyze=...)` 주입은 기존과 같이 프로세스를 거치지 않는다.

## 계약

- 인증·헤더·크기 검증과 동시 수용 제한을 통과한 시점부터 결과 객체 생성까지 기본 60초 기한을 적용한다. `AGENTFIT_REQUEST_TIMEOUT_SECONDS`로 1~120초를 설정할 수 있고 잘못된 값은 앱 생성 시 거부한다. 응답 전송 중에는 기존 수용 슬롯을 계속 점유하며, 네트워크 전송 시간은 분석 기한에 넣지 않는다.
- 업로드에는 기존 10초 기본 기한과 요청 전체 남은 시간을 함께 적용한다. 문서 추출과 분석에도 같은 전체 남은 시간을 적용한다. 기한이 끝나면 HTTP 504 `ANALYSIS_DEADLINE_EXCEEDED`를 반환한다. 업로드 자체의 짧은 기한이 먼저 끝나면 기존 HTTP 408 `DOCUMENT_UPLOAD_TIMEOUT`을 유지한다.
- PDF 추출 Worker의 최대 15초 실행 시간을 확보할 수 없으면 추출을 시작하지 않고 504를 반환한다. PDF Worker의 프로세스 생성 지연까지 OS가 엄밀히 보장하지는 않으므로 실제 측정으로 기본 60초 기한을 검증한다.
- 본문 수신 뒤 `http.disconnect`를 관측하면 분석 프로세스를 종료·회수한다. 연결이 끊긴 요청에는 새 HTTP 응답을 시도하지 않는다. 자식 종료가 확인되기 전에는 수용 슬롯을 해제하지 않는다.
- 부모 ASGI 태스크가 취소되어도 자식을 종료·회수한 후 취소를 전파한다. 정상 완료·분석 오류·출력 오류·기한 초과·연결 종료 모두 자식이 남지 않아야 한다.
- 부모에서 Worker에는 UTF-8 JSON으로 `document`, `documentId`, `key`만 전달한다. 환경 변수는 Python 실행에 필요한 최소값만 전달하며 API 키·원문·Provider 원본 응답을 파일·일반 로그·표준 오류에 기록하지 않는다.
- Worker 출력은 안전한 JSON 결과 한 건이며 최대 1,500,000 bytes다. 부모는 실제 읽은 바이트 수로 제한하고, 초과·형식 오류·비정상 종료를 원문 없는 `ANALYSIS_WORKER_FAILED`로 반환한다. Provider 오류는 기존 `AnalysisError` 코드와 서비스 매핑을 유지한다.
- 기존 `post_solar`의 독립 호출 API와 평가 도구의 동작은 유지한다. 요청 Worker 내부 전용 Provider 전송만 인라인으로 실행한다.

## 검증

- 실제 로컬 ASGI 요청에서 느린 분석 Worker가 전체 기한 후 종료되는지, 응답 코드가 504인지, 이어지는 요청이 수용되는지 확인한다.
- 실제 소켓 연결을 끊었을 때 Worker가 종료되고 슬롯이 회수되는지 확인한다. 연결 종료 감지 전·후 경합도 확인한다.
- Worker 정상 Profile, Provider 오류, 잘못된 출력, 과대 출력, 프로세스 실행 실패를 테스트한다. 원문·키가 오류 응답 및 로그에 없는지 검사한다.
- 기본 분석 요청이 더는 별도 Provider 자식 프로세스를 만들지 않는지 검증한다. 전체 AI 테스트와 로컬 Uvicorn HTTP 검증을 실행한다.

## 제외와 남은 과제

PDF 추출 Worker의 OS 메모리 상한은 별도 기능이다. Spring의 실제 재시도·저장·확인 질문 UI와 의미 정확도 기준 충족도 별도 검증이 필요하다.
