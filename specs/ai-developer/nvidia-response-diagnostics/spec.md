# NVIDIA INVALID_RESPONSE 최소 진단

## 범위 / 승인
2026-10-02 사용자 요청에 따른 오프라인 관측 개선. 기존 HTTP/SSE 거절 조건,
분류 지침, 출력 스키마, 응답 해석, 서버 판정, 재시도 정책은 유지한다.
새 모델 호출·서비스 배포·큰 goal 재개는 하지 않는다.

## 계약
- INVALID_RESPONSE에 한해 HTTP 상태와 Content-Type, 실패 검증 위치,
  SSE data 이벤트 순번(1부터), 실패 이벤트 data 원문 바이트 수와 제한 발췌를 전달한다.
- JSON 문법 오류에는 가능한 경우 data 기준 문자 위치·줄·열을 추가한다.
  중복 키·의미 구조 오류는 검증 위치만 기록하며 위치를 추정하지 않는다.
- 실패 data 발췌는 UTF-8 최대 2048바이트, Content-Type은 최대 128바이트,
  진단 JSON 전체는 최대 8192바이트. 자격 증명 또는 NUL 포함 표현 감지 시
  해당 발췌 전체를 숨긴다(UTF-16/32 등에서 키 문자열 분리 방지).
  인증 헤더, 요청 객체, API 키, 예외 메시지, 전체 스트림은 저장하지 않는다.
- 워커→부모는 실패 진단만 추가 전달하고, 부모는 같은 INVALID_RESPONSE를 발생시킨다.
  진단 생성 실패는 기존 오류 코드로 복귀한다. 정상 출력 바이트는 동일해야 한다.
- 비교 harness의 기존 finished 기록에 선택적 response_diagnostic을 추가한다.
  이전 저장 자료와 동결 manifest는 덮어쓰지 않는다. 새 소스 revision은 별도 기록한다.
- HTTP 단계 거절은 body를 읽지 않고 event를 null로 기록한다.
  정상 SSE 조립 이후의 분류/스키마 실패는 이번 전송 진단의 범위 밖이다.

## 검증
합성 로컬 HTTP/SSE로 상태·MIME·프레이밍·JSON·구조 오류, 잘린 발췌,
분할 UTF-8와 자격 증명 제거, 워커 전달·파일 저장, 정상/오류 계약을 검증한다.
기존 성공 4건은 저장된 조립 응답에서 SSE를 재구성해 오프라인 재생한다.
이 재구성은 실제 원본 SSE가 아니다. 이전 5번 실패는 원본 이벤트와 헤더가 없어
소급 원인 확정이 불가능하며 미확인으로 남긴다.
