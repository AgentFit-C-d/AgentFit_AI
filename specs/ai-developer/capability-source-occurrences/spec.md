# 기능 인용의 서버 위치 계산

## 목적과 근거

기능 명칭을 추출할 때 긴 원문 문맥(anchor)까지 모델이 다시 복사하면서 후보 전체가 거절되는 손실을 줄인다. 직전 capabilities-v2 실험에서 PUBLIC-01의46개 후보가 모두 ambiguous_anchor로 거절됐다. 인용문 자체가 정확했는지는 당시 응답을 저장하지 않아 미확인이다. 이번 선택형 구현의 개선 효과는 실제 비교로 판단한다.

## 계약

- `extract_capability_candidates(document, key, *, model=MODEL, transport=None) -> dict`는 새 내부 응답 `{"quotes": ["원문 인용", ...]}`를 받는다. 최대60항목, 각1~200 Unicode code point의 비공백 문자열, 추가필드/잘못된 타입/초과는 실패한다.
- 모델은 문장·목록·표·제목·기술 용도의 기능 표현을 인용한다. 명사형도 허용한다. 부정·미정·다른 제품·과거 문맥도 후보에 포함하며 field/status를 출력하지 않는다.
- 서버는 기존 `freeze_candidate_occurrences`로 원문과 정확히 일치하는 모든 등장 위치를 찾는다. 모델 offset, normalization, fuzzy matching은 사용하지 않는다. 중복 인용은 한 번만 확장하고 서로 다른 위치는 유지한다. 원문 부재는 rejected로 남긴다. 고유 후보240개 초과는 부분 결과 없이 실패한다.
- 통합 분석기의 새 `capability_candidates: bool=False`가 true일 때만 기존 동작 추출을 교체한다. bool 이외 값은 호출 전 거절한다. 일반 추출·merge·explicit-v1 독립 분류·검토·대표 기능30개 이하·Profile·HTTP 계약은 그대로다.
- 기존과 같은 OPERATION_EXTRACTION_FAILED 단계, 동일 provider meter·최대64호출·취소/기한·NVIDIA 단독 경로 재시도0을 사용한다. 기존 혼합 경로는 호출자가 지정한 기존 재시도 설정을 유지한다. 숨은 네트워크 호출이나 오류 시 이전 추출기로 fallback하지 않는다.
- 이 옵션은 Python 내부 분석 API에만 추가한다. 기본 HTTP 서비스에는 자동 적용하지 않는다. 전 구간 평가 후 서비스 적용을 판단한다.

## 검증과 위험

반복한 같은 인용의 확정/부정/다른제품 문맥을 위치별로 보존하고 분류·검토 결과를 각각 적용한다. 모델 판단이 맞다는 보장은 로컬 가짜 응답 테스트로 주장하지 않는다. 짧고 흔한 인용은 후보 수를 늘려240개 제한에 걸릴 수 있으며 이를 숨기지 않는다. 문서에 없는 기능을 발명하면 rejected가 남아 확인 필요로 처리된다.

실제 비교는 구현·최종리뷰·CI 이후 새 freeze/출력 폴더에 PUBLIC-01/09/07 각1회, 최대192모델호출/5400초, 요청1800초/64호출, 재시도0으로 등록한다. 기존 결과·gold·freeze는 보존한다. 확인된 무료 NVIDIA DeepSeek 범위만 사용하며 만료/한도/제공자 오류에 중단한다. 임시 gold 도달과 확정 의미 판단을 구분하고, 새 기획서 일반화와 실제 Spring/운영 검증은 계속 미완료로 둔다.
