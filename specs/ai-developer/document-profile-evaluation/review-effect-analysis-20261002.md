## 2. 제외 6개를 의미 기준으로 다시 대조

### PDF·Markdown 입력 — 정상 의미2개, 최종 보류

- C120 Markdown `[5191,5199)`, C121 PDF `[5233,5236)`는 [입력 한도 L136](E:/AgentFit/output/document-profile-baseline-live-20261002-v1/source.md:136)에 있다: “PDF·Markdown 파일 … PDF 100쪽 이하”. [입력 흐름 L59](E:/AgentFit/output/document-profile-baseline-live-20261002-v1/source.md:59)도 “PDF · Markdown · 텍스트 입력”을 명시한다.
- 요청24는 두 후보에 `insufficient_evidence`를 반환했다. 그러나 입력에 전체 원문이 정확히 들어 있고, before/after에도 입력 한도·파일·쪽수 문맥이 포함돼 있다. 원문 미전달이나 후보 위치 오류는 이 두 후보의 검토 실패 원인이 아니다.
- 실제 지침은 문맥이 동작을 명시하면 짧은 명사구도 기능으로 허용한다. 동시에 맥락 없는 도구·입력 문서 이름으로 동작을 추론하지 말라고 한다. **확인된 것은 문맥상 정상 의미가 제외됐다는 결과**다. 짧은 값만 과도하게 중시했는지, 지침의 두 조건을 잘못 적용했는지는 이유 코드만으로 확정할 수 없다.
- 검토 후 두 형식은 Profile에서 사라진다. PDF C042/C119와 Markdown C043이 검토 이전부터 needs_confirmation이어서 최종 보류로 남는다. 이 후보들은 자체 인용 문제가 있어 앞선 분류에서 이미 보류된 것이며, GLM이 보류로 전환한 것은 아니다.
- 고정 의미 F03.01·F03.02는 각각1개씩 계수한다. 형식 이름만 검사한 결과가 아니라 입력 동작 문맥까지 대조한 기존 기준을 유지했다.

### 재접속 후 유지 — 정상 의미1개 누락

- C077 `[3636,3667)`은 [이번 학기 필수 범위 표 L109](E:/AgentFit/output/document-profile-baseline-live-20261002-v1/source.md:109)의 완료 결과다: “실제 문서를 분석하고 수정·저장한 값이 재접속 후 유지됨”.
- 요청24의 사유는 `not_product_fact`다. 입력 before에는 “이번 학기에 만들 범위”, “필수 범위”, “완료 후 보여줄 데모”가 모두 포함된다. 전체 문서도 전달됐다.
- 고정 골드 F04.03은 저장 및 재접속 후 유지를 요구한다. 이것은 현재 구현 완료 주장과 다르며, 실제 지침도 기획서의 필수 요구는 미구현이어도 confirmed로 허용한다.
- **추정:** 데모/완료 조건이라는 형식을 제품 동작이 아닌 팀 활동·목표로 과잉 배제했을 수 있다. 저장 이유 코드가 이 가설과 맞지만 내부 판단 근거는 미확인이다.
- C075의 “Profile 수정·확인 저장”은 남지만 재접속 유지 조건까지 담지 않는다. 다른 최종 값·명시 보류 후보로 복구되지 않았다. C077의 supported 감사 기록만 남으므로 F04.03은 누락으로 유지한다.

### 예시 안의 AgentFit 동작 — 중복 보존 및 사람 검토1개

- C052와 C055는 [L82](E:/AgentFit/output/document-profile-baseline-live-20261002-v1/source.md:82)·[L83](E:/AgentFit/output/document-profile-baseline-live-20261002-v1/source.md:83)의 예시다. 요청23은 둘 다 `not_current`를 반환했다. “팀 설명에 사용할 예시/가상의 운동 기록 서비스” 문맥은 입력에 명시돼 있다.

- **추정:** 예시 구역 전체를 일괄적으로 비현재 사실로 처리하면서 가상 입력 프로젝트와 그 입력을 처리하는 대상 서비스의 주어·역할을 구분하지 못했을 수 있다. `not_current`는 부정·미정·과거·예시·다른 프로젝트를 합친 코드라 어느 하위 이유였는지는 미확인이다.

- C055의 역할·실제 업무 수집은 C078 “Profile 수집”과 보류 C006에 의해 얼마나 보존됐는지 애매하다. 기존 F06.01의 **사람 검토 필요** 판정을 유지한다. 전체 감사의 다른 애매한 항목 F08.01(Catalog 검토)은 이번6개 제외에 의한 새 변화가 아니다.

## 3. Codex 오답 통과와 검토 이전 문제

### Codex: 의미 분류에서 발생, GLM이 놓침

- 원문 [L115](E:/AgentFit/output/document-profile-baseline-live-20261002-v1/source.md:115): “초기 지원 Client는 Codex 중심”. C082 `[4020,4025)`.
- 요청14의 의미 분류는 `external_service / external_integrations / confirmed`, scope=target, time=current, commitment=adopted, decision=supported를 만들었다. 이름의 존재는 맞지만 **지원 대상 Client라는 관계를 외부 연동 채택으로 바꾼 것**이 고정 정답과의 최초 불일치다.

- 지침은 외부 서비스/제공자 연동을 요구하고 내부 모듈·저장소·일반 표준을 배제하지만, 외부 연동 필드의 설명에서 지원 Client와 실제 연동 관계를 직접 대비하지는 않는다. **관계 구분 적용이 불충분했다는 결과는 확인**되나, 지침 보완만으로 해결될지·특정 모델의 능력 문제인지는 이번 기록만으로 알 수 없다.
- 최종 external_integrations는 GitHub/Codex다. 후속 투영이 새로 만든 오답이 아니다. 실제 GitHub 로그인 C039/C073은 정상 대조군이다.

### 프로젝트명: 검토 대상에 오르기 전에 보류

### 텍스트 입력: 동작 추출의 위치 연결 실패

- 요청3 응답의 mention index18에는 “PDF · Markdown · 텍스트 입력”이 있다. 그러나 anchor는 원문 ASCII 큰따옴표를 곡선 따옴표로 바꿨다. 저장된 operations_grounded에서 index18은 `ambiguous_anchor`로 탈락했다.
