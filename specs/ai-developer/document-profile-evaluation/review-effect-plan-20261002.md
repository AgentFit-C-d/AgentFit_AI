# 의미 검토 불일치 후보 보존 — 최소 수정·회귀 계획

**상태: 제안만 작성, 미구현·미실행.** 이번 요청은 저장 기록 분석에서 종료한다. 실제 코드 수정·모델 호출·서비스 적용 권한으로 해석하지 않는다. 큰 Goal은 일시중지 상태다.

**목적:** 검토에서 이견이 생긴 원문 연결 후보가 긍정 값에서도 빠지고 사용자 확인 대상으로도 남지 않는 문제를 줄인다.

**근거:** [오프라인 분석](E:/AgentFit/tmp/worktrees/document-input-runtime/specs/ai-developer/document-profile-evaluation/review-effect-analysis-20261002.md)의 6개 후보 status 변경과 최종 감사 기록/확인 대상의 불일치. 사유 코드만으로 의미적 제외의 정당성을 보장할 수 없다.

**범위:** 기존 후보 검토 결과 적용 → 최종 확인 응답 구성 경계. 추출·모델·프롬프트·스키마·의미 골드·출력 개수 기준·비용 설정·Spring 저장은 그대로 둔다. 새 관계 검증기나 모델 단계도 추가하지 않는다. 구현 시에는 현재 코드의 실제 함수를 다시 확인한다. 이번 분석은 저장 자료만 사용했으므로 수정 파일·함수 시그니처를 새로 확인했다고 주장하지 않는다.

## 제안 규칙

1. 원문 위치가 검증된 후보가 검토에서 거절되면 긍정 Profile 값에는 자동 복귀시키지 않는다. 검토 이전 분류와 거절 사유를 보존하고, 실제 해결 전에는 해당 후보를 명시적인 확인 대상으로 남긴다.
2. 모델의 원시 confirmed/supported 기록을 사용자의 직접 확정으로 바꾸지 않는다. 검토 전 원시 기록은 불변으로 두고, 검토 후 최종 처리와 근거를 연결한다. 현재 최종 응답 계약 안에서 표현 가능한지부터 확인한다. 공개 계약을 변경해야 한다면 구현 전에 별도 영향 검토가 필요하다.
3. 이미 tentative/irrelevant인 미검토112개와 검토를 통과한27개는 이 변경으로 재분류하지 않는다. 기존 명시적 부정·다른 프로젝트 사실을 긍정 값으로 되살리지 않는다. 검토의 단일 enum만으로 `not_current` 하위 이유(부정/예시/과거/미정)를 확정하지 않는다.
4. 확인 의미는 후보 문자열 개수가 아닌 고정 골드 기준으로 감사한다. 중복 후보/기능의 일반 표현을 새 의미로 세지 않는다. 확인 질문을 모두에게 늘리는 해결은 허용하지 않는다.
5. Codex처럼 검토가 잘못 유지한 후보는 이 변경의 해결 실적으로 계산하지 않는다. 관계 판단 오류는 다음 원인으로 남긴다. 특정 ID·이름·문구 조건은 구현에 넣지 않는다.

## 최소 작업 순서 — 후속 승인 시에만

- [ ] 저장 trace/원문/골드 해시를 고정한 재현 fixture를 구성한다. 모델 호출은 막고 검토23·24 응답을 그대로 재생한다. 실행 전 원본 대비 별도 폴더를 사용한다.
- [ ] 검토 결과 적용과 최종 확인 응답 경계를 실제 코드에서 확인한다. “원시 분류 보존”, “검토 후 보류”, “사용자 직접 확정”이 섞이지 않는 작은 변경 범위를 확정한다.
- [ ] 아래 R1–R6의 실패 조건을 먼저 재현한 뒤 해당 경계만 수정한다. 모델 응답을 다시 생성하거나 다른 지침을 주입하지 않는다.
- [ ] 같은145후보/40정상 의미를 대조하여 긍정 오답·보존·보류·누락·사람 검토를 별도 보고한다. 원본 모델 결과와 수정 후 고정 응답 재생 결과를 구분한다.
- [ ] 확인 후보 증가가 불일치6개에만 한정되는지, 기존 긍정 값26개(오답1개 포함)와 확인 후보52개가 유실되지 않는지 확인한다. UI에서의 질문 병합·부담 감소는 관측 전까지 주장하지 않는다.
- [ ] 결과 보고 후 멈춘다. 실제 모델 검증·운영 서비스 적용·큰 Goal 재개는 후속 범위다.

## 가설과 한계

- **검증할 가설:** 검토 모델의 불일치만으로 명시 확인 후보까지 제외하는 경계를 바꾸면, 현재 완전히 누락된 정상 의미2개를 사용자 확인 가능한 상태로 보존할 수 있다. 수정 후 기대이며 이번의 관측 성과가 아니다.
- 긍정 오답을 줄이는 실험은 아니다. 예상상 Codex 오류는 남고 확인 부담은 늘 수 있다. 후보6개가 보류로 추가되더라도 고유 정상 의미·질문 수는 같은 증가량이 아니다. 두 지표를 따로 측정해야 한다.
- 이 저장 기록에는 GLM이 실제 오답을 옳게 거절한 사례가 없다. 수정이 그런 경우에도 자동 확정을 막는지는 새 합성 대조 또는 독립 기록으로 후속 검증해야 한다. 현재 자료만으로 통과했다고 표시하지 않는다.
- 검토 범위 축소나 제거의 전체 성능·시간은 미실행이다. 이번 산술 시간 절감치를 품질 유지 증거로 쓰지 않는다.
