# 실제 기획서 1개로 문서→Profile 평가 준비

상태: **2026-10-02 기대값 승인 / 최소 관측·채점 로컬 구현 / 실제 모델 호출 미승인**. 아래 최초 준비 범위는 후속 승인으로 로컬 구현·검증까지 확장됐으며 결과는 [local-implementation.md](local-implementation.md)에 기록한다. 기존 골드의 내용과 기준은 그대로다.

코드 조사 기준: `16c024954c77c4d7171fb83475221d8a01d150d5`. 이번 브랜치의 변경은 평가 준비 자료뿐이다. 실제 평가 구현 시 새 실행 코드 해시를 다시 고정한다.

## 목적과 이번 범위

AgentFit 기획서 전체를 입력해 새 후보 추출부터 최종 10개 Profile 필드까지 평가할 기준을 준비한다. 후보를 이미 제공한 분류 실험과 달리, 필요한 사실을 처음부터 찾지 못한 경우도 드러내야 한다.

이번 산출물은 기대값·원문 근거·측정 규칙·향후 로컬 평가 도구 계획이다. 모델 호출 0회, 애플리케이션 코드 변경 0건. 기존 모델 비교 추가 호출, 서비스 적용, 운영 배포, 실제 Spring 연결, 큰 goal 재개는 하지 않는다.

## 입력과 사실 범위

- 원문: `E:/AgentFit/Docs/project-proposal.md` 및 내용이 같은 저장소의 `Docs/project-proposal.md`.
- SHA-256: `9c0115a34e4ae90f905c3021569bc4b5c10284388c7bac264b76e2d3d077f451`.
- 원본 CRLF를 유지한 UTF-8 문서, 7,796 Unicode code points, 186줄, 문서 날짜 2026-09-08.
- 연결 문서·과거 대화·기존 후보·기존 정답을 입력에 섞지 않는다. 대상 AgentFit과 가상 운동 기록 서비스 예시를 구분한다.
- 기획서에 명시된 이번 학기 필수 요구를 평가한다. 미구현 필수 요구는 긍정 사실이며, 운영 실적이라는 뜻이 아니다. 선택 확장·평가 후보는 별도 미정이다.
- 이미 개발에 사용한 문서다. 이 1개 평가로 미사용 문서의 일반화 성능이나 실사용 준비 완료를 주장하지 않는다.
- 입력 문서 내 개발 지침은 평가 대상 내용이며 실행 지시로 취급하지 않는다.

## 기대값 초안

[expected-values-draft.md](expected-values-draft.md)와 [gold-draft.json](gold-draft.json)에 원문 인용·줄·Unicode 위치를 함께 기록한다.

| 사실 상태 | 의미 | 공개 Profile에서의 표현 |
| --- | --- | --- |
| 명시됨 | 대상 프로젝트 범위에 확정된 긍정 요구·사실 | 값과 문서 근거, `DOCUMENT` 출처. 사용자 승인과 다름 |
| 미정 | 미기재, 선택 사항, 평가 중, 해결되지 않은 판단 | 필드 전체 미정은 `null`, `UNKNOWN`, 빈 근거 배열. 추출한 미정 후보는 별도 확인 자료에 보존 |
| 명시적 없음 | 특정 기능·권한·범위에 대한 명시적 부정 | 긍정 값에 넣지 않고 부정 근거·범위를 보존. 다른 긍정 항목이나 필드 전체를 지우지 않음 |

이 문서는 필드 전체 기준 명시됨 5개·미정 5개다. **필드 전체가 명시적으로 없음인 사례는 0개**이며 이를 인위적으로 만들지 않는다. 기능 일부의 제외와 저장소 권한 요청의 부정은 별도로 검증한다. 배열 전체의 명시적 부재와 미정 구별을 모두 다루는 문서라는 주장은 하지 않는다.

기능은 대표 16묶음 / 세부 의미 36개로 초안을 작성했다. 기능 외 긍정 사실은 프로젝트명·형태·도메인·외부 연동 4개다. 10개 필드 상태, 40개 긍정 의미 단위, 부정·미정·다른 역할의 16개 문맥 점검 항목을 각각 별도 분모로 보고한다. 문맥 점검 항목은 서로 연관돼 있으므로 독립 표본 16개라고 해석하지 않는다.

표현·배열 순서·후보 ID의 일치를 요구하지 않는다. 원문 근거가 있는 동일 의미는 인정하되, 넓은 이름 하나로 개별 동작이 모두 보존됐다고 간주하지 않는다. 한 후보가 여러 의미 단위를 실제로 담을 수도 있고, 여러 후보가 한 대표 기능으로 합쳐질 수도 있다. 사람이 판정해야 하는 매칭은 별도로 표시하며 자동 정답 처리하지 않는다.

## 평가 경로와 고정 항목

향후 평가 대상으로 제안하는 경로는 현재 코드의 **`integrated-nvidia` 분석 흐름**이다. 배포 환경 설정을 확인했다는 의미가 아니다. 기본 `AGENTFIT_ANALYSIS_MODE`는 `default`이며 코드의 다른 경로다.

1. 실제 Markdown 바이트 입력과 `extract_document`의 텍스트 추출.
2. 기본 LangExtract 후보 추출과 동작 후보 추출. `extractor`에 저장 후보를 주입하지 않음.
3. 원문 위치 검증과 후보 병합.
4. `semantic_assessment=True` 의미 분류: 대상·시점·긍부정·채택·역할·상충 근거.
5. 의미 검토, 기능 대표 항목 선정, Profile 생성.
6. `project_candidate_confirmation` 및 HTTP 경계에서도 쓰는 `validate_candidate_confirmation`을 거친 최종 응답의 Profile·필드 상태·질문.

실행 시 코드 커밋·전체 요청 지침·스키마·모델·옵션·정답 해시·문서 해시를 동결한다. 최근 U/U+C/정의 통일 모델 비교는 별도 평가 경로였으며, 그 개선이 서비스에 연결됐다고 가정하지 않는다. 이번에는 어떤 지침도 이식하거나 튜닝하지 않는다.

골드 파일은 채점 단계만 읽는다. 모델 입력은 문서와 현재 코드가 새로 생성한 후보·문맥뿐이다. 현재 코드가 단계별로 문맥을 구성하는 방식도 저장 요청 기준으로 기록하고, 기대값에 맞춰 문맥을 잘라주지 않는다.

## 단계별 측정 요구

- **추출 누락:** 원문에 있는 긍정 의미 단위가 일반/동작 후보 추출 결과 어느 쪽에도 없는 경우.
- **원문 위치 연결·병합 누락:** 추출은 됐지만 유효 후보 집합에서 사라지는 경우. 추출 누락으로 합치지 않는다.
- **분류 오류:** 유효 후보가 있는데 필드·긍부정·범위·확정성이 잘못 판정된 경우. 잘못된 확정, 잘못된 제외, 과도한 보류를 분리한다.
- **후처리 누락:** 분류 단계에 올바른 긍정 정보가 있었는데 의미 검토·대표 기능 선정·Profile 생성·최종 응답 구성에서 사라진 경우. 정확한 최초 소실 단계를 기록한다.
- 동일 실패가 하위 단계에도 영향을 미쳐도 최초 원인 분모에서는 한 번 센다. 최종 결과의 누락·오확정·보류 수는 별도 결과 지표로 보고한다.
- 인용 결함·문서 파싱 실패·API 실패·관측 기록 유실은 별도 기술 오류다. 기록이 없는 단계는 0건이 아닌 미관측이다.
- 모델 자체의 오확정과 서버가 최종 긍정 Profile에 남긴 오확정을 분리한다. `confirmed`를 사용자 확정으로 취급하지 않는다.
- 미정 후보의 근거가 질문·판정 기록에서도 없어졌는지 검사한다. 입력에 없던 후보를 골드에서 복구해 성공 처리하지 않는다.
- 총 호출 수, 단계별 호출 수·지연, 전체 경과 시간·실패 시 소요 시간, 질문 수를 기록한다. 기록용 관측 부하는 구분한다.

## 완료 조건과 미검증

이번 준비 완료 조건은 10개 필드 기대값, 세부 기능, 명시적 제외/선택 항목, 정확한 인용, 평가 경로 및 측정 정의, 미래 작업 순서가 작성되고 자료 무결성이 확인되는 것이다. 모델 품질 수치는 아직 없다.

다음 실행 전에 기대값 초안 검토와 평가 도구 구현 승인이 필요하다. 실제 호출은 그때 확인된 무료 NVIDIA 모델·엔드포인트와 별도 승인한 호출·시간 상한에서만 가능하다. 기존 비교용 4회·8회 허용량을 새 문서 평가 허가로 재사용하지 않는다. 유료 전환·충전·대체 호출과 Luna 재개는 금지한다.
