# 검토 사유 재현 조사 계획

**분류:** 제한 조사(spike). 직접 수행. 사용자 자율 계획·실행 승인에 따라 재승인을 요청하지 않는다.

**Spec:** [spec.md](spec.md)

- [ ] 새 scratch 실행기가 기존 입력/trace/free-access 검증기 및 검토 함수를 사용하도록 작성한다. snapshot을 검증한 뒤 후보·labels만 child stdin으로 전달한다. 모델 외부 호출은 명시적 --live에서만 실행한다.
- [ ] 외부 호출0으로 실행기 검증: 원문 hash 불일치·변조 labels·잘못된 제외사유 거절, 무료 미확인과 제공자 오류 후 추가 호출0, 두 사유 수집/ID 대응, bounded budget 및 원문/키 미출력을 확인한다. 실행시간180초 상한.
- [ ] 코드·source·trace·script·기존 JSON hash를 manifest로 고정하고 두 요청을 순서대로 실행한다. 요청1200초/전체2400초/총26호출/재시도0.
- [ ] 원본 결과와 replay의 유지/제외 차이, 사유, 의미 검토 쟁점을 기록한다. source-only audit은 사람이 검토한 정답으로 취급하지 않는다.
- [ ] 결과·상태를 검증 후 commit/push한다. 제품 동작 변경과 일반화 주장은 하지 않는다.

이 조사는 제품 기능 구현이 아니라 실패 원인 관측이며, 구현 단계의 독립 리뷰를 새로운 제품 변경 없이 반복하지 않는다. 원인이 확인되면 별도 명세와 회귀 검증으로 수정한다.
