# GLM 검토 경로 비교 사전등록

## 가설과 범위

DeepSeek는 기능/배포 근거를 제외하고 합성 제품명 누락을 놓쳤다. 후보·원문을 고정했으므로 현재 오답은 검토 경계에서 발생했다. GLM5.3의 기존 검토 경로에서 같은 문제가 남는지 확인해 특정 모델 운용 경로와 공통 계약 문제를 구분한다. 결과를 보기 전에 항목과 예산을 고정한다. 구조·제품 코드·기본 서비스는 수정하지 않는다.

## 변경 변수와 통제

- 기존 `review_model` 선택만 GLM5.3(`z-ai/glm-5.3`)으로 바꾼다. 원문, 후보, 라벨, system/user 지침, 스키마, 배치20, 순서, 문서3개,1회씩, 출력8192토큰, 재시도0은 유지한다.
- 모델별 기존 adapter 설정은 다르다: DeepSeek temperature0/thinking=false, GLM temperature0.5/reasoning_effort=low/clear_thinking=true. 따라서 **모델과 기존 운용 설정의 비교**이며 가중치만의 순수 성능 비교라고 해석하지 않는다. 이 설정은 이번에 변경하지 않는다.
- 공개01의 기능4/4·비기능 제외2/2·Docker2/2, 공개07 기능14/14, 합성16/16와 제품명 누락 검출을 같은 기준으로 평가한다.
- 새 `freeze-glm.json`, 별도 실행기 `review_probe_glm.py`, 별도 출력 `field-local-candidate-review-glm-v1`을 사용한다. 기존 DeepSeek 결과·실행기·freeze는 변경하지 않는다.
- 동일 입력·지침·스키마와 운용 설정 차이를 로컬 fake transport로 검사한다. 무료 거절0호출/제공자 오류1회 중단/31회 경계/키와 원문 비노출 검증을 그대로 재사용한다.

## 순서와 예산

1. DeepSeek 결과 감사·보존 완료(session2563 exit0).
2. GLM 실행기와 단회 freeze 생성, 외부0 안전·동일조건 검사.
3. 무료 확인 파일을 각 호출 전에 확인한다. 계정 무료 범위/만료를 자의적으로 변경하지 않는다.
4. 공개01→공개07→혼합합성 각1회, 요청31호출/1800초, 전체93호출/5400초. 실패 시 후속 요청 중단, 유료 대체·재시도 없음.
5. 이전 결과 hash와 결과 계약을 검증하고 위 사전등록 항목·시간·호출·실패를 비교한다. 품질 미달이면 기본 적용하지 않는다.

로컬 각180초 상한, 실제 모델 최대5400초. 최신 제품 코드는 이미 독립 리뷰와 Linux CI를 통과했으며 추가 제품 변경은0이다. 성공하더라도 전체 추출/분류 파이프라인, 반복성과 새 문서·사람 검토는 별도 gate다.
