# 필드별 후보·누락 검토

## 목적과 근거

실사용 목표의 근거 있는 초안과 적은 수정 부담을 위해, 한 필드의 규칙이 다른 필드 후보를 삭제하는 문제를 줄인다. 고정 PUBLIC-01 후보의 기능4개는 일반 runtime-purpose 설명으로 복구됐지만 배포 후보가 삭제됐고, 설명을 features로 한정하자 기능이 다시 누락됐다. 따라서 프롬프트 문구에 더해 서버가 검토 범위를 분리한다. 모델의 의미 정확도를 코드로 보장한다고 주장하지 않는다.

## 선택한 구조

기존 혼합 검토 함수를 수정해 기본 동작을 바꾸는 대신, 별도 `candidate_field_review.py`에 NVIDIA 전용 `review_candidates_by_field`를 추가한다. 파이프라인의 `field_local_review=False` 옵션이 true일 때만 선택한다. 기존 기본 경로·HTTP 설정·Profile·확인 응답·Spring 계약은 유지한다. 사용자는 자율 설계·계획·직접 구현을 승인했다.

### 후보 검토

- 입력 원문(최대100000자), frozen(최대240개), labels를 기존 공통 검증기로 확인한다. transport/collectors/model/key도 호출 전에 검증한다.
- FIELDS 순서로 confirmed 후보를 모으고, 필드 안에서 기존 순서를 보존해 최대20개씩 분할한다. 각 confirmed ID는 정확히 한 번 검토한다. non-confirmed 후보를 자동 승격하지 않는다.
- 모델 입력은 document, targetField, selections. 전체 원문·정확 위치·주변 문맥을 유지한다. 허용 응답 ID는 그 요청의 후보뿐이다. checkedCandidateIds는 입력 순서와 완전히 같아야 한다.
- wrongCandidateIds와 rejectionReasons는 기존 엄격 계약(허용 ID·중복 없음·사유1:1·4개 enum)으로 검증한다. 다른 필드/배치 ID가 오면 전체 검토가 실패하며 부분 Profile을 반환하지 않는다.
- explicit-v1 의미와 확정/부정/검토안 기준을 유지한다. features 요청에만 앞선 runtime-purpose-v1의 제품 용도 구분 설명을 넣는다. 그 설명은 다른 필드 요청에 넣지 않는다.

### 누락 검토

- 후보 검토를 모두 통과한 뒤, FIELDS의 10개 필드를 각각 정확히 한 번 요청한다. 후보가 없는 필드도 생략하지 않는다.
- 입력은 document, targetField, confirmedValues(해당 필드에서 살아남은 중복 없는 값). 다른 필드의 값이나 임시 gold는 전달하지 않는다.
- 응답은 `{field: 요청한 필드, missing: bool}`만 허용한다. 잘못된 필드, 문자열/숫자 bool, 누락/여분 키는 실패다.
- features 누락 검토에만 기능 설명을 적용한다. 나머지는 explicit-v1 원래 정의를 유지한다.
- 10개 응답이 모두 검증된 경우에만 서버가 기존 `{checkedFields, missingFields, wrongCandidateIds}`로 합친다. 누락·실패 시 자동 완료하지 않는다.

### 예산·실패·관측

20개 고정 배치에서 후보240개/10필드의 후보 검토는 최대21회, 누락 검토10회로 이 단계 최대31회다. 전체 분석의 공유64회 상한은 유지하며 초과 시 고정 실패 코드를 반환한다. NVIDIA-only 재시도0·제공자 실패 후 중단·외부 부모 기한(기존 평가1800초)은 유지한다. 함수 자체가 전체 hard deadline을 제공한다고 주장하지 않는다.

기존 안전한 call_trace는 유지한다. 선택형 review_calls/review_reasons에는 필드 enum과 고정 ID/사유만 추가하며 키·원문·모델 설명을 저장하지 않는다. diagnostic 실패와 실제 의미 오답을 구분한다. 소스·코드·모델·자료를 고정한 뒤 별도 실평가를 등록한다. 현재 단계의 실제 호출0, 로컬 suite당180초. 초기 실평가는 공개2문서와 고정 혼합 합성의 검토-only 각1회로 최대93호출/5400초/재시도0이며 무료 확인 유효 때만 수행한다. 실제 호출 전에 별도 freeze와 실행 조건을 확인한다.

## 완료 및 유보 기준

구현 완료는 입력 검증·필드/ID 경계·빈 필드 누락 검사·전체10필드 완료·공유예산·기본 경로 불변·부분결과 금지의 회귀와 최종 독립 리뷰, CI로 판단한다. 실제 비교에서는 기능4개 유지와 비기능2개 제외, Docker 유지, PUBLIC-07 기능 유지, 합성의 부정/검토안/타제품/반복/다른 필드/빠진 제품명 검출을 함께 확인한다.

하나라도 품질 기준에 미달하면 기본 적용을 보류한다. 임시 gold·과거 점수·기존 freeze는 수정하지 않는다. 새 기획서 일반화·사람 정답·수정량/시간·실제 Spring/운영은 별도 미완료 gate다.
