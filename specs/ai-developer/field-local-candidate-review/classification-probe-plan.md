# 후속 진단 계획: 고정 후보의 분류 모델 비교

상태: 사전등록 준비. 기존 GLM 검토 session91923이 종료하고 결과를 보존한 뒤에만 실제 호출한다. 서비스 변경이 없는 진단 실험이며, 사용자 목표의 자율 설계·실행 승인을 적용한다.

## 질문과 근거

공개01의 C059/C061은 정확한 원문 후보이지만 other/irrelevant로 분류돼 검토에 도달하지 않았다. 같은 분류 입력에서 기존 DeepSeek 경로를 재현하고 GLM 경로와 비교해, 검토 이전의 누락을 줄일 가능성을 확인한다. 분류와 검토의 지침을 동시에 바꾸지 않는다. 기존 관측과 이번 재현의 차이도 별도로 기록한다.

대안은 분류 지침에 제품 동작 보완 문구를 추가하거나 재분류 단계를 추가하는 것이다. 우선 기존 함수의 모델 선택만 비교한다. 이 진단은 새 제품 API·서비스 구조를 추가하지 않으며, 효과가 확인돼도 전체 파이프라인 검증 전에 기본 적용하지 않는다.

## 고정 조건

- 원문과 후보: 기존 capability-occurrences-full-v1의 PUBLIC-01 173개, PUBLIC-07 36개와 기존 mixed-synthetic.json의 16개. 추출·근거 위치·순서·정답 자료를 수정하지 않는다.
- 함수: classify_profile_candidates, field_semantics=explicit-v1, 후보30개/묶음, 출력8192토큰, 호출 timeout600초. 기존 분류 라벨이나 기대값은 모델 입력에 넣지 않는다.
- 모델: deepseek-ai/deepseek-v4.1-flash, z-ai/glm-5.3. 기존 adapter 설정까지 포함한 경로 비교다. 모델별 temperature/추론 차이를 제거했다고 주장하지 않는다.
- 순서: 공개01 DeepSeek→GLM, 공개07 DeepSeek→GLM, 합성 DeepSeek→GLM, 각1회. 동시 실행·재시도·유료 대체0.
- 신규 freeze-classification.json, classification_probe.py와 별도 classification-model-probe-v1 출력. 실행 전 코드·자료·helper·조건의 hash를 고정하고 매 요청 전후 확인한다. 이전 JSON 결과는 보존한다.

## 사전 지정 관측 항목

1. PUBLIC-01: C059/C061의 features/confirmed 복구2개, C066/C069/C071/C073의 features/confirmed 보존4개를 각각 집계한다. C019/C026이 features/confirmed인지도 기록한다. Docker C113/C115의 deployment/confirmed 여부는 기존 임시 해석하의 회귀 항목이다.
2. PUBLIC-07: 기존 features/confirmed 14개 보존 여부, 나머지 모든 라벨 변화. 원래 라벨 전체를 정답으로 간주하지 않는다.
3. 합성: 기존 keep 8개는 원래 지정 field/confirmed인지, reject 8개는 해당 field/confirmed로 오확정되지 않았는지 확인한다. 거절 항목을 다른 필드로 확정한 경우 별도 표시해 숨기지 않는다. 미정·부정·다른 제품·과거 사례의 실제 status도 보고한다. 분류 대상에 없는 제품명 누락 검사는 이 실험 범위가 아니다.
4. 모든 후보의 ID·field·status 변화, 구조 실패, 실제 호출 수, 처리 시간. 모델이 쓴 자유 텍스트·원문·키는 결과에 기록하지 않는다.

위 항목은 사람 검토 전의 진단 기준이다. 기술 목록의 기능·지원 배포 방식·ORM 범위에 대한 사용자 답변이 와도 진행 중 조건과 점수를 소급 변경하지 않는다. 새 문서 일반화·전체207개 gold·사용자 수정 부담의 사람 검토를 대신하지 않는다.

## 실행 예산과 중단

- 모델별 예상6+2+1=9호출, 전체18호출 상한. 건별 후보 수에서 계산한6/2/1회만 허용한다. 요청당1800초, 전체10800초 상한, 재시도0.
- 현재 두 모델에 대한 무료 확인을 매 호출 전에 검사한다. 확인 만료·파일 변경·한도 거절·제공자 오류·계약 오류 시 전체 중단한다. 만료를 임의로 연장하지 않는다. 키는 기존 loader로 메모리에서 읽어 자식 stdin으로만 전달한다.
- 관측 대기 timeout은 재시작 사유가 아니다. 실행 timeout은 실패로 보존하며 완료되지 않은 호출 수를0으로 단정하지 않는다.
- 로컬 안전 검사 각180초/API0: 무료 거절0호출, 제공자 실패1회 중단, 입력 변조 차단, 묶음별 상한, 출력 ID 계약·비밀 비노출, 두 모델의 입력/스키마 동일성 및 허용 adapter 차이.

## 다음 결정

관측된 누락이 줄고 기존 비교 항목에 퇴보가 없는 경로만 전체 분석의 후속 평가 후보로 삼는다. 원문 후보가 있는데 양쪽 모두 누락하면 지침 차이 가설을 새 실험으로 분리한다. 성공 수치를 위해 공개 Profile, 정답, 시간/호출 상한을 도중에 바꾸지 않는다.
