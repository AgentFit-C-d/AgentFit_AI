# 계획
원인: v27 MABC 실패 호출2·3에서 quote는 모두 지정 줄에 존재했으나, 서로 다른 quote에 occurrence2~6을 부여했다. 현재 수정 요청은 INVALID_FEATURE_SPAN만 전달해 어느 항목을 어떻게 재확인할지 부족하다.
1. 기존 API 변경 없이 인용별 occurrence 설명과 대조 예시를 강화한다.
2. 실패한 features의 최대30개 span에 대해 숫자·고정 오류 코드만 담은 spanIssues를 계산해 기존 correction errors에 추가한다. 겹치는 문자열도 기존 find(start+1) 검증과 동일하게 센다.
3. 순번 범위를 서버에서 고치거나 잘못된 항목을 버리지 않는다. 모델 수정 뒤 동일 검증을 다시 적용한다.
4. 단위 회귀 후 고정된 실패 초안 수정 실험을 실행한다. 과거 v27과 새 v28 각각 동일 초안 1회, 고정 합성3사례 각1회. 프롬프트 변화와 진단 개선의 묶음 효과이며 개별 인과를 단정하지 않는다.
5. 정상 검토 파이프라인은 유지한다. 의미 품질·지연의 구조적 재설계는 별도 검토한다.
