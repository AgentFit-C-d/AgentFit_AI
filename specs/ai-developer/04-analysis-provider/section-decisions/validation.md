# 검증 결과 — section-v2

## 변경
후보마다 selected 또는 제외 사유 하나만 출력한다. 서버가 필드와 배열 순서를 구성한다. 선택/제외 두 목록 사이의 모순을 표현할 수 없게 했다. 중복 JSON 키·잘못된 역할 등은 계속 거절한다.

## 검증
- 전체 unittest: 166/166 통과. 신규 테스트 RED 후 구현 GREEN 확인.
- 독립 리뷰: 주요 결함 없음. 중복 JSON 키 거부를 직접 확인했다.
- Minor 보류: decisions 중복 키 전용 영구 회귀 테스트는 아직 없으며 공통 파서에서 차단한다.

## 실제 Solar 평가
기존 section-v1과 같은 7개 입력·임시 정답 기준. 추출 프롬프트는 변경하지 않았다. 기존 입력은 이미 튜닝에 사용돼 일반화 평가가 아니다.

section-v1: 정답0/7, 오답반환0, 오류7. section-v2: 정답0/7, 오답반환0, 오류7. 이번에는 모두 첫 추출에서 실패해 통합 단계에 도달하지 않았다. 통합 계약 변경의 종단 간 개선은 입증되지 않았다.

## 고정 후보 통합 검사
이전 성공 추출 응답은 보관 정책상 없어, ROLE-002 문서에서 후보8개를 수작업 구성했다. 원래 후보 풀 재생이 아니다. 동일 입력으로 총2회 호출했으며 두 번 모두 SECTION_MERGE였다. 첫 호출은 상세 판정을 기록하지 않았고, 두 번째는 원인 확인을 위해 ID/판정만 계측했다. 두 번째에서 개발 도구 후보까지 전부 selected로 나와 기존 역할 검증이 차단했다. 성공한 시도만 선별하거나 첫 실패를 제외하지 않았다.

## 판단과 다음 작업
이번 구현은 모순 없는 내부 판정 형식을 제공하지만 의미 품질 개선에 성공하지 못했다. 기본 SolarAnalyzer를 교체하거나 운영 채택하지 않는다.
다음 실험에서는 값과 인용을 별도로 생성하는 추출 계약을 줄이는 안부터 검토해야 한다. 짧은 정확 인용 하나로 값을 복원할 경우 기능 단위와 명시적 없음의 근거를 어떻게 보존할지 먼저 명세/검증해야 한다. AgentFit의 INCOMPLETE_RESPONSE와 제공자 timeout도 별도 원인 분석이 필요하다. 응답 길이만 무작정 늘려 60초 예산을 넘기지 않는다.
공개 Profile, 기본 분석기, 최대6호출/60초 협력적 예산, 실패 응답7일 정책은 유지했다. 60초 하드 반환 보장은 기존과 같이 미해결이다.
