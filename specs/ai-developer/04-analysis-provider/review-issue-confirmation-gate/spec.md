# 검토 이슈 이후 자동 확정 차단

## 문제

합성 진단에서 의미 검토가 오류를 지적했는데도 수정·재검토를 거쳐 잘못된 `complete`가 반환된 사례가 있었다. 재검토의 빈 이슈 목록만으로 최초 오류가 실제 해결됐다는 독립 증거가 되지 않는다. 이 기능은 해당 경로를 선택형 복구 분석에서 사용자 확인 상태로 낮춘다.

## 계약

- `require_issue_free_review`를 켠 복구형 분석에서 의미 검토 또는 재검토가 한 번이라도 이슈를 반환하면, 최종 분석기가 성공했더라도 `complete` 대신 `needs_confirmation`을 반환한다.
- 최종 Profile은 기존 서버 검증을 통과한 구조·근거 그대로 제안으로 보존한다. 값이 있는 필드는 `suggested`, 값이 없는 필드는 `unknown`이며 자동 확정되지 않는다. `questions`는 빈 배열이다. 클라이언트는 이 상태의 모든 제안을 확인 대상으로 취급해야 한다.
- 오류 코드는 고정된 `REVIEW_CONFIRMATION_REQUIRED`다. 이슈 문장, 원문, 모델 원본 응답은 결과에 포함하지 않는다.
- 이슈가 없고 분석이 성공하면 기존 `complete`를 유지한다. 분석 실패 처리와 기본 `analyze()` 및 기본 `analyze_recoverable()` 동작은 유지한다.
- 분석 호출 수·6회 제공자 호출 상한·60초 기한은 늘리지 않는다. 호출별 이슈 상태는 재사용되지 않는다.

## 검증

- 결정적 가짜 제공자로 초기 이슈→수정→재검토 통과가 `needs_confirmation`이 되는지 검증한다. 이슈 없는 성공, 실패 복구, 연속 호출, 기본 옵션 회귀도 확인한다.
- 동일 실행의 합성 사례에서 이 게이트로 막힌 자동 확정과 남은 오확정, 확인 부담, 지연·호출 수를 기록한다. 게이트로 오확정을 숨긴 결과를 모델 정확도 향상으로 주장하지 않는다.
- 실제 서비스로 승격하려면 사용자 확인 UI와 저장 금지 상태 계약, 독립 문서 및 사람 검증이 추가로 필요하다.
