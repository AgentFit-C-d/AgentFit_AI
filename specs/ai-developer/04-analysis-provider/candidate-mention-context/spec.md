# 후보별 원문 위치·문맥 전달

## 문제

후보 고정 단계는 ID마다 정확한 원문 start/end를 보존하지만, 판정과 커버리지 검토 요청은 ID와 값만 전달한다. 서로 다른 위치에 같은 값이 반복되면 모델이 ID를 해당 언급과 연결할 수 없다. 후보 배열 순서는 원문 위치의 대체물이 아니다.

## 변경과 제한

- 선택형 후보 우선 분석기의 판정·검토 입력에 동일한 서버 생성 언급 표현을 쓴다: ID, 값, 원문 start/end, 앞뒤 최대 240 Unicode code point 문맥.
- start/end는 Python 원문 문자열의 0부터 시작하는 반개구간이다. 문맥은 원문을 자르기만 하며 재작성하지 않는다. 모델은 해당 위치의 언급을 판정하고 다른 언급의 확정 여부를 전이하지 않는다. 전체 문서는 제품 관계와 명시적 결정 변경을 해석하는 데 계속 제공한다.
- 잘못된 위치는 모델 호출 전에 거절한다. 모델의 출력 계약은 ID·field·status로 유지한다.
- 추론 none에서는 위치를 줘도 합성 판정이 6/16에 그쳤다. 고정 후보 비교로 medium 설정을 검증하고, 통과하면 선택형 판정 단계에 사용한다. 정확도 검증을 위해 이 단계의 호출 대기는 최대 600초로 두며 기존 서비스의 기한과는 별개다.
- 기본 서비스 승격 여부는 별도 실제 정확도·통합 검증으로 판단한다. 원문 값과 문맥은 기존 승인된 API 요청에만 포함하고 공유 평가 결과에는 기록하지 않는다.

## 검증

1. 원문 순서와 후보 순서가 반대여도 같은 값의 각 언급을 구별할 정보가 판정·검토 요청에 존재한다.
2. 한글·이모지·CRLF·긴 문맥에서 위치와 원문이 일치하고, 문맥은 각 방향 최대 240자다.
3. 음수·초과·역전·bool 위치는 API 요청 전에 실패한다.
4. 실제 모델에서 반복·부정·검토안·다른 제품 사례를 고정 후보로 평가하고, 비식별 실문서에서도 제안 일치·보류 사유를 확인한다. 단위 테스트 통과를 모델 정확도 증거로 대신하지 않는다.
