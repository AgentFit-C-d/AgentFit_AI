# 원문 언급 문맥 검증

## 재현된 결함과 수정

- 후보의 원문 위치는 고정 단계에서만 보존되고 의미 판정·검토에는 ID와 값만 전달됐다. 동일 값의 후보 순서를 바꾸면 각 ID의 지시 대상이 입력에서 사라지는 결함이다.
- 회귀 테스트 세 개(하위 사례 포함 여섯 실패)로 위치 손실과 검토 입력의 잘못된 위치 허용을 재현했다. 원문 위치·앞뒤 문맥을 두 단계에 공통 전달하도록 수정한 뒤 관련 테스트 20개가 통과했다.

## 추론 끔 비교

합성 문서 네 개의 동일 기술명 두 언급을 원문 순서 및 역순 ID로 배치해 총 8개 입력·16개 언급을 판정했다. 정답은 API 호출 전에 고정했고, 두 구성의 호출 순서를 교차했다. 모델은 Solar Pro4, 추론은 none이다.

| 입력 | 판정 일치 | 잘못된 confirmed | 실패 호출 |
| --- | ---: | ---: | ---: |
| 기존 ID·값 | 5/16 | 2 | 0/8 |
| 위치·문맥 추가 | 6/16 | 3 | 0/8 |

위치 전달 결함을 고쳤지만, 추론을 끈 모델의 의미 판정은 충분하지 않았다. 작은 합성 사례의 단일 실행이므로 일반 정확도로 해석하지 않는다. 후보 생성·최종 검토를 제외한 판정 단계 수치다.

## 실문서 관찰

H02의 비식별 입력으로 위치·문맥 추가와 추론 none을 실행했다. 고정 후보 51개, 보류 후보 40개(모호한 anchor 37, 정렬 충돌 3), 검토 문제 11개였다. 확인 필요 제안은 6개 정답 중 2개 일치했고 자동 완료되지 않았다. 실행 시간은 약 324초다. 이전 실행의 4/6보다 낮지만 후보 생성부터 다시 실행했으므로 문맥 추가의 인과 효과로 단정할 수 없다.

## 추론 medium 비교

동일한 네 문서·정답·8개 후보 배열로 비교했다. 결과 다섯 행 저장 후 실행 핸들이 사라져 저장된 조합을 건너뛰고 남은 11개 조합을 이어 실행했다.

| 입력 | 판정 일치 | 잘못된 confirmed | 실패 호출 |
| --- | ---: | ---: | ---: |
| 기존 ID·값 | 7/16 | 4 | 0/8 |
| 위치·문맥 추가 | 16/16 | 0 | 0/8 |

이 제한된 사례에서 위치 정보와 추론을 함께 사용하는 구성이 유효했다. 선택형 판정 단계는 medium과 최대 600초 호출 기한을 사용하도록 바꿨다. 합성 프로브는 모두 이전 120초 호출 기한 안에 완료됐고, 위치·문맥 구성의 가장 느린 호출은 약 58초였다. 긴 실제 입력 평가를 위해 기한을 늘렸으며 처리 속도 개선 주장은 하지 않는다.

재현 도구는 이 폴더의 `probe.py`다. AI 서비스가 설치된 환경에서 `python ../specs/ai-developer/04-analysis-provider/candidate-mention-context/probe.py --live --env-file <로컬-env-경로> --output <새-결과-경로> --reasoning-effort medium`을 실행한다. 추론 끔 비교는 마지막 인자를 `none`으로 바꾼다. 합성 문서만 사용하고 API 키·문서 텍스트·모델 원본 출력은 결과에 기록하지 않는다.

## 최종 실문서 관찰과 남은 일

- 최종 medium 구성의 H02: 고정 후보 53개, 보류 후보 43개(정렬 충돌 6, 모호한 anchor 37), 검토 문제 12개. 확인 필요 제안 4/6 일치, 자동 완료 0/1, 약 162초. 최초 후보 추출부터 새로 실행한 한 건이므로 앞선 2/6 대비 인과적 개선이나 일반 성능으로 단정하지 않는다.
- 원문 없는 세부 진단: 모호한 anchor 37개 중 원문에 없는 anchor 35개, 반복 anchor 2개였다. 37개 중 후보 인용 자체는 원문에 있는 것이 34개, 없는 것이 3개였다. 주된 실패가 단순 반복보다 모델이 재작성한 주변 문맥의 불일치임을 확인했다.
- 기존 `candidate-occurrence-expansion`은 서버가 모든 원문 일치 위치를 열거하는 구현을 이미 갖고 있다. 당시 none 설정의 고정 판정은 13/27이어서 전체 의미 정확도를 해결하지 못했다. 다음 작업은 이 구현 원리를 후보 우선 분석기에 재사용해 모델이 주변 인용을 다시 쓰는 요구를 줄이고, 이번 위치 문맥·medium 판정과 결합해 검증하는 것이다. 없는 후보 인용을 임의 생성하거나 검토 실패를 자동 완료로 바꾸면 안 된다.
- 최종 코드 전체 테스트: 810개 실행, 6개 건너뜀, 나머지 통과. diff 공백 검사 통과. 코드 커밋 `7fa6b9e` push와 Linux CI 실행 36609820787 성공을 확인했다.
- 서비스 승격·독립 실제 문서 검증·Spring 저장 연동을 포함한 실사용 목표는 아직 완료되지 않았다.
