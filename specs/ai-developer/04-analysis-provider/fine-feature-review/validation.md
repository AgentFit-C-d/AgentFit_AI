# 기능 검토 구역 세분화 검증 기록

## 로컬 검증

- 선택형 `fine_feature_review=True`에서 기능 추출은 기존 120줄 구역을 사용하고 기능 의미 검토는 50줄 구역을 사용한다. 전체 줄 커버리지와 최대 21개 구역을 검증한다.
- 모의 평가에서 마지막 검토 구역의 범위 오류는 자동 완료하지 않으며, 22개 구역은 제공자 호출 전에 거부한다.
- 새 옵션에서만 최대 36호출·2,400초를 허용한다. 옵션이 꺼지면 기존 22호출·1,200초 상한을 유지한다.
- Windows 로컬 전체 `unittest discover -s tests -q`: 695건 통과 (2026-09-29). Linux CI `36562334892` 통과. GitHub 변경분의 독립 리뷰에서 P1/P2를 찾지 못했지만, 리뷰어의 로컬 도구 오류로 테스트 재실행은 못 했다.

## 실제 평가

Campfire PRD(547줄) 1건을 Solar Pro 4로 한 번 평가했다. 안전 결과는 ignored 로컬 `tmp/fine-feature-review-campfire-20260929-1/{plan,results,summary}.json`에 있다. 원문·키·원본 응답·Profile 내용은 저장하지 않았다.

| 항목 | 50줄 기능 검토 | 이전 120줄 기능 검토 |
|---|---:|---:|
| 기능 후보 / 대표 기능 | 128 / 30 | 128 / 30 |
| 기능 검토 구역 | 14 | 6 |
| 제공자 호출 / 전체 시간 | 25/36 / 1,046,829ms | 14/22 / 627,898ms |
| 최종 상태 | `needs_confirmation(INCOMPLETE_RESPONSE)` | `needs_confirmation(INCOMPLETE_RESPONSE)` |
| 부분 정답 일치 | 6/7 | 6/7 |
| 잘못된 근거 | 0 | 0 |
| 미평가 값 | 30 | 32 |
| 명시적 미정 필드 보존 | 0/1 | 0/1 |

비기능 검토 5회가 완료되고 기능 검토 14구역 중 11구역은 응답했다. 12번째 기능 구역 검토는 입력 1,081토큰에서도 출력 8,192토큰 상한에 닿아 미완료였으며 마지막 2구역은 시작되지 않았다. 완료된 기능 검토에서도 여러 의미 이슈를 발견했다. 구역을 120줄에서 50줄로 줄이면 검토 진행 범위는 넓어지지만, 출력을 안정적으로 완료하거나 정확도를 높이지는 못했다. 각 설정은 한 번씩 실행했으므로 점수 차이를 일반화하지 않는다.

## 적용 판단

선택형 실험으로만 유지한다. 작은 입력에서도 출력 상한이 반복되므로 구역을 더 잘게 나누는 방식은 다음 단계로 채택하지 않는다. 검토 모델·추론 예산 또는 서버/사용자 확인 흐름을 구조적으로 재검토한다. 튜닝에 사용한 공개 문서의 부분 정답만으로 실사용 가능성을 주장하지 않는다.
