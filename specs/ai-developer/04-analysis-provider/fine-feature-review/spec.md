# 기능 검토 구역 세분화 실험 명세

## 목적과 관찰

필드별 의미 검토 실험은 Campfire PRD의 비기능 필드 검토를 모두 끝냈지만 첫 기능 구역 검토에서 `INCOMPLETE_RESPONSE`로 멈췄다. 그 호출은 120줄 범위, 입력 3,291토큰, 출력 상한 8,192토큰, 약 419초였다. 547줄 문서의 기존 기능 검토 구역은 6개다. 기능 구역 입력을 줄여 검토 완주 여부를 확인한다. 부분 정답이 6/7이고 미정 필드도 잘못 채워졌으므로, 완주만으로 정확도 개선을 주장하지 않는다.

## 선택한 방식

- 선택형 `fine_feature_review=False`가 기본이다. `fieldwise_review=True`인 구역 추출·대표 기능 선택 실험에서만 켠다.
- 기능 **추출** 구역은 기존 120줄 이하·최대 7개로 유지한다. 기능 **검토** 구역만 제목 경계를 보존해 50줄 이하로 다시 나눈다. 전체 원문의 각 줄을 한 번씩 빠짐없이 검토하고 최대 21개 검토 구역을 허용한다. 초과하면 제공자 호출 전에 `CALL_LIMIT`으로 안전 실패한다.
- 검토 요청의 원문·초안·근거·이슈 스키마, Solar Pro 4, 의미 검토 추론 설정과 출력 상한 8,192토큰은 바꾸지 않는다. 검토 범위만 바꾸는 실험이다. Campfire 문서는 14개 검토 구역이 된다.
- 1 core + 최대 7 기능 추출 + 최대 1 대표 기능 선택 + 최대 1 근거 수정 + 5 비기능 검토 + 최대 21 기능 검토 = 최대 36호출. 전체 기한은 이 실험에서만 최대 2,400초다. 완료 조건은 비기능 필드 전체와 모든 기능 구역의 유효 검토이며, 한 호출이라도 미완료·형식 오류·기한 초과면 자동 완료하지 않는다.
- 평가 CLI `--fine-feature-review`는 `--fieldwise-semantic-review`를 요구한다. plan에 두 구역 크기·최대 호출·기한을 기록하고 실제 응답의 안전 수치만 저장한다. 기본 서비스·공개 Profile·FastAPI 계약은 바꾸지 않는다.

## 대안과 검증

- 기능 검토 상한만 올리는 방법은 요청의 과도한 범위를 그대로 둔다. 모델을 바꾸면 원인 분리가 어렵다. 이번에는 한 변수인 검토 구역 크기를 줄인다.
- 모의 테스트로 추출/검토 범위 분리, 각 검토 줄의 정확한 한 번 커버리지, 최대 36회, 마지막 구역 실패, 22회 기존 모드 불변, 2,400초 실험 제한을 확인한다.
- Campfire 1건을 같은 모델·문서·정답으로 한 번 실행해 검토 완주, 부분 정답·미정 보존·근거 오류·미평가 값·호출/시간을 기록한다. 실제 검토에서 의미 이슈가 발견되면 `needs_confirmation`이 올바른 결과다. 독립 실제 문서의 사람 검토와 Spring/Frontend 확인 후 저장 E2E 전에는 실서비스 기본값으로 승격하지 않는다.
