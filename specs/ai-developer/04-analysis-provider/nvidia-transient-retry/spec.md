# NVIDIA 제공자 오류의 제한적 재시도

## 목적과 근거

H02 스트리밍 평가는 17호출·약 44분 후 마지막 GLM 원문 누락 검사에서 `PROVIDER_UNAVAILABLE`로 실패했다. 해당 요청은 302,710ms 후 끝났고 앞선 추출·분류·후보 검토는 완료됐다. 정확한 5xx 번호와 원인은 미확인이다. 실패 요청은 43,130bytes로 성공한 검토 요청보다 작았다. 전송을 바꾸는 것만으로 전체 완료가 보장되지 않았다.

지속적인 장애일 수도 있으므로 재시도가 반드시 복구한다고 가정하지 않는다. 동일 요청 1회만 다시 보내는 방법은 이미 완료된 단계와 판단 정책을 유지하면서 일시적 제공자 실패를 복구할 기회를 준다. 모델 교체는 의미 판단 조건을 바꾸므로 이번 범위에서 선택하지 않는다. 기존 실패 결과와 미평가 분모는 보존한다.

## 계약

- 선택형 내부 함수 `analyze_integrated_candidates`에 `nvidia_retry_limit=1`을 추가한다. 정확한 int 0 또는 1만 허용하고 bool·float·음수·2 이상은 I/O 전에 거절한다. 0이면 자동 재시도를 끈다.
- NVIDIA transport가 `AnalysisError('PROVIDER_UNAVAILABLE')`를 낸 경우만 적용한다. 논리 요청당 최대 2시도이며 두 번째 실패 후 세 번째 전송은 없다. 첫 시도가 종료된 뒤 2초 대기하고 같은 요청을 보낸다.
- Solar, 인증, 429, timeout, network, redirect, 모델 불일치, 크기·JSON·스키마·의미 실패와 일반 예외는 재시도하지 않는다. 유효한 결과에서 의미 오류를 찾아도 다른 출력을 뽑기 위해 다시 보내지 않는다.
- 요청 model/messages/schema/options와 key/timeout을 유지한다. 주입한 transport가 전달받은 dict를 수정하더라도 두 번째 시도에는 최초 요청의 깊은 복사본을 사용한다. 앞서 끝난 추출·분류·검토는 재실행하지 않는다.
- 기존 `max_calls` 1~64는 모든 실제 transport 시도를 센다. 재시도할 예산이 없으면 대기·추가 전송 없이 기존 `CALL_BUDGET_EXCEEDED`로 종료한다. 부분 결과를 자동 확정하지 않는다.
- 각 시도의 기존 `call_trace` 행에 `attempt`(1 또는 2), `retry_of_call_index`(최초 행은 null, 재시도는 최초 call_index), `provider_error`(허용 코드 또는 null)를 추가한다. `call_index`는 실제 전송마다 증가한다. 외부 collector의 기존 행 수는 예산이나 인덱스에 영향을 주지 않는다.
- 실패 행을 성공 행으로 덮어쓰지 않는다. `transport_completed`는 bytes 수신 여부이며 최종 JSON·의미 성공과 구분한다. 최초 전송 성공, 전송 복구, 전체 분석 결과를 따로 집계한다.
- 키·본문·기능명·Provider 오류 원문은 계측에 넣지 않는다. 재시도 대기 시간은 전체 평가 시간에 포함되고, 각 행의 `elapsed_ms`는 해당 transport 실행 시간이다.
- 공개 Profile·기본 HTTP 서비스·NVIDIA streaming transport 자체는 유지한다. 이 함수에는 아직 전체 요청 기한 보장이 없으며 HTTP 연결은 별도 작업이다. 추가 시도의 시간·비용은 기존 호출 상한 안에서만 증가한다.

## 검증과 실측

외부 transport에 5xx를 주입하고 실제 추출 이후 분류·검토·대표 구성·최종 검증 코드를 실행한다. 마지막 누락 검사 실패 뒤 해당 요청만 복구되는지, 반복 실패와 다른 오류의 종료, 예산 경계, 원 요청 보존, 비밀 값 없는 시도별 기록을 확인한다. 기존 전체 테스트를 실행한다.

독립 코드 리뷰 후 제품 코드를 고정하고 H02를 새 추출부터 한 번 평가한다. source/manifest/redacted 해시는 이전과 같고 새 driver/report를 사용한다. 최초 실패·재시도·복구·최종 성공/확인/실패 및 미평가를 분리한다. 실제 5xx가 없었다면 이 실행에서 재시도 효과가 검증됐다고 주장하지 않는다. 단일 문서의 6개 부분 검사를 전체 정확도로 확대하지 않는다.

## 자체 검토

재시도는 기존 계측 바깥의 transport 안에 숨기지 않고 실제 전송을 세는 위치에 둔다. 각 요청은 최대 두 번만 시도하며 데이터·모델·검증 기준을 바꾸지 않는다. 이전 실패 보고서를 보존한다. 사용자 자율 설계·계획·구현 승인에 따라 직접 진행한다.
