# NVIDIA 원문 선택자 전체 분석 비교 구현 계획

**목표:** 선택형 원문 선택자 분석의 모든 모델 호출을 NVIDIA NIM으로 라우팅해 Solar와 동일한 공개 평가를 수행한다.

**구조:** `NvidiaSourceSelectorAnalyzer`가 `SourceSelectorSolarAnalyzer`의 파이프라인을 재사용하고 `_send_payload`만 기존 `NvidiaAnalyzer`에 위임한다. 평가 CLI는 모델에 따라 키와 전송 함수를 선택한다. 기본 FastAPI 분석기는 변경하지 않는다.

**대상:** `ai_service/agentfit_ai/nvidia_source_selector.py`, `public_holdout_evaluation.py`, 관련 테스트와 이 폴더의 검증 기록.

## 작업 0: 평가 전용 긴 기한

- [ ] 실패 테스트: 기본 분석은 전체 60초·필드 호출 40초이고 일반 설정의 121초는 거부된다. 명시적 평가 옵션만 전체 300초·필드 호출 120초를 허용한다.
- [ ] SolarAnalyzer의 호출 기한 계산에 선택형 한도를 연결한다. 기본 FastAPI Worker 설정은 바꾸지 않는다.

## 작업 1: 전송 라우팅

- [ ] 실패 테스트: core/features/의미 검토가 지정 모델로 변환되고 NIM 응답 모델명 불일치·지원하지 않는 모델을 거부한다.
- [ ] 기존 선택자 분석기·NVIDIA 어댑터를 결합하고 키·진단 모델명이 일치하게 한다.

## 작업 2: 평가 CLI

- [ ] 실패 테스트: NVIDIA 플래그는 선택자 모드에서만 가능하고 키 로더·전송·plan 모델명이 맞으며 기본 경로는 불변이다.
- [ ] `--source-selector-model` 플래그와 모델별 안전한 키/전송 선택을 구현한다.

## 작업 3: 실제 비교

- [ ] 전체 회귀 테스트와 합성 1건 실호출을 통과한다.
- [ ] 이미 튜닝에 쓴 공개 PRD 5건을 선택자·전체 300초·필드 120초 조건에서 실행한다. 필요하면 같은 긴 기한에서 Solar도 실행하고 지표·응답 시간을 함께 기록한다.
- [ ] 원문·키 비저장과 브랜치 push·Linux CI를 확인한다. 결과가 미달하면 기본값을 유지한다.

## 작업 4: 의미 검토 미완료 원인 조사

- [ ] 실패 테스트로 안전 평가 결과에 숫자형 prompt·completion·상한만 남기고 원본 응답은 제외한다.
- [ ] 미완료 사례 1건을 재실행해 출력 토큰 상한 도달 여부를 확인한다.
- [ ] 명시적 평가 옵션에서만 검토 출력 상한을 16,384로 늘리고 같은 사례를 재시험한다. 완료 여부와 시간·다음 실패를 기록한다.

## 검토 초점

- NVIDIA 키가 입력 원문이나 문서 ID에 있으면 첫 호출 전 차단해야 한다.
- 응답 모델명 일치 확인을 거치지 않은 데이터를 채점하지 않는다.
- 제공자 옵션 변환이 strict JSON schema와 40초 제한을 없애면 안 된다.
- NVIDIA 모드에 Solar 키를 요구하거나 반대로 기본 모드에 NVIDIA 키를 요구하면 안 된다.
- 실패 호출에서 원본 응답·키가 결과 파일에 남으면 안 된다.
