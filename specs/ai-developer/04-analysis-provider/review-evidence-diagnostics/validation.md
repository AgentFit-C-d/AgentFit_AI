# 근거 오류 세분화와 단일 원인 보완 결과

## 재현과 원인

- 이전 실패 사례 N-004·E06·E07의 첫 재실행(`results/run1`)에서는 근거 형식 오류가 재현되지 않았다.
- 선택형 계약 20건 재실행은 중단되어 18건까지만 `results/run2`에 저장됐다. 남은 E07·E08은 같은 설정으로 `results/run3`에서 재실행했다. 따라서 두 파일을 한 번의 연속 실행 결과로 해석하지 않는다.
- 안전 진단에서 E02(`run2`)와 E07(`run3`)이 `COMPACT_EXISTING_SOURCE_UNEXPECTED`였다. 모델이 기존 항목 이슈에 불필요한 원문 줄 번호를 포함한 경우다. 원본 응답은 저장하지 않았다.
- 이 유형에 한해, 모델의 줄 번호가 형식·범위 검증을 통과하면 버리고 서버가 검증된 Profile의 근거 span에서 줄을 다시 계산하도록 바꿨다. 누락 이슈의 근거 줄, 잘못된 줄 범위·대상 ID 거부는 유지한다.

## 수정 후 교차 평가

`results/run4`에서 기존 방식과 수정된 선택형 방식을 동일 합성 20건에 교차 적용했다. Solar Pro4, 전체 60초·의미 검토 호출별 40초 상한, 최대 6회 호출을 사용했다.

| 지표 | 기존 | 수정된 선택형 |
|---|---:|---:|
| 전체 Profile 완전 일치 | 5/12 | 5/12 |
| 다구역 지정 사실 성공 | 0/8 | 1/8 |
| 전체 성공 | 5/20 | 6/20 |
| 검토·재검토 시간 초과 호출 | 6 | 2 |
| 검토 형식 오류 호출 | 1 (`ARRAY_INDEX`) | 3 (`COMPACT_MISSING_SOURCE_EMPTY` 2, `DUPLICATE_TARGET` 1) |
| 검증 계열 오류 | 9 | 12 |
| 오확정 | 0 | 0 |
| 검토 요청 중앙 크기 | 10,432바이트 | 5,054바이트 |

**적용 관문 실패.** 형식 오류와 검증 오류가 증가했다. 기존 방식의 일부 관측 시간이 설정 60초를 약 63ms 초과해 `observed_60s_limit`도 거짓이다. 수정된 선택형의 관측 시간은 60초 이하였다. 다른 실패 관문만으로도 결론은 같다. 기본 분석기는 유지한다.

이번 재평가에는 보완 대상 오류가 다시 발생하지 않았다. 따라서 회귀 테스트는 서버 변환 동작을 증명하지만, 라이브 정확도 개선이 그 수정 때문이라고 주장할 수 없다. `누락 이슈의 근거 줄 없음`과 `대상 ID 중복`은 별도 원인이다. 다음 변경은 이 원인의 실제 응답 경로를 먼저 확인해야 한다. 이미 튜닝에 사용한 합성 자료는 실서비스 성능 근거가 아니다.
