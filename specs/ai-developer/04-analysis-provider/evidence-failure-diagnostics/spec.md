# 최종 근거 검증 실패의 안전한 진단

## 문제

공개 문서 첫 평가에서 Mealie·Immich가 모두 `INVALID_EVIDENCE`로 실패했다. 1·2번째 호출의 필드/사유는 로컬 조사로 확인했지만, 3번째 수정 호출 후 마지막 투영 실패의 필드/사유는 기존 진단에 빠진다. 이 상태에서는 수정 단계의 오류가 최초 오류와 같은지 판단할 수 없다.

## 요구

- 근거 투영이 수정 호출 뒤 실패하면 마지막 호출 진단에 `field`, 고정된 근거 오류 `reason`, 선택적 `itemIndex`·`matchCount`만 기록한다. 원문·인용·값은 기록하지 않는다.
- 최초 추출 검증과 의미 수정 재투영에서도 같은 안전 형식을 사용한다.
- 공개 Profile, FastAPI 응답, 모델 프롬프트, 호출 횟수·시간 제한은 바꾸지 않는다.
- 공개 문서 평가 CLI는 실패 사례의 안전한 호출 단계·근거 검증 사유를 결과에 포함한다. 기존 평가 결과 파일에는 원문·응답·Profile·키를 저장하지 않는다.
- 실제 실패 두 건을 재실행해 마지막 수정 오류의 필드/사유를 관측한다. 이 문서들은 관측 후 튜닝 자료로 간주하고 최종 독립 검증으로 재사용하지 않는다.

## 수용 기준

1. 잘못된 인용을 두 번 반환하는 가짜 Provider 테스트에서 마지막 수정 실패의 필드·사유를 얻는다.
2. 안전하지 않은 임의 오류 상세는 진단에 포함하지 않는다.
3. 전체 AI 테스트 및 공개 문서 평가의 비밀·원문 비저장 검증을 통과한다.
