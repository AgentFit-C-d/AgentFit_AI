# 후보 내부 원문 구간 판단 실험

## 문제

후보 생성이 제품 요구사항이 든 문장 전체를 반환하면, 현재 판단 단계는 그 후보를 하나의 값으로 선택하거나 버릴 수만 있다. `N-004`의 모델 이름과 `N-006`의 기능 표현은 후보 안에 있지만 전체 문장 선택 때문에 값 채점에서 오확정됐다. `Q-001`처럼 두 동작이 한 후보에 묶이면 후보당 판단 하나라는 제약으로 둘을 모두 담을 수 없다.

## 선택형 내부 계약

- `judgment_subspans=True`인 경우에만 판단 응답을 후보 ID별 `facts[]`로 받는다. 각 fact는 기존 field·role·status·scope·decision과 `quote`를 가진다. 빈 배열은 무관한 후보다.
- `quote`는 해당 후보의 원문 구간 안에 정확히 한 번 나타나는 연속 부분 문자열이어야 한다. 서버가 후보의 절대 위치를 기준으로 새 근거 구간을 계산한다. 문장을 새로 쓰거나 다른 후보/문서 위치에서 값을 가져올 수 없다.
- 후보당 최대 5개, 전체 최대 120개 fact를 허용한다. 같은 후보의 fact 구간은 서로 겹치지 않는다. 모호한 반복, 중복, 부분 응답, 역할·상태·선택 충돌은 기존 검증 또는 새 계약 검증에서 전체 실패시킨다.
- 선택된 fact만 기존 `merge_profile`로 보내며 값·근거는 서버에서 재검증한다. 원래 후보·판단·검토·수정의 호출 수와 6회·60초 상한은 그대로다.
- 기본 `judgment_subspans=False`는 기존과 동일하다. 공개 Profile, 기본 분석기, 서비스 API, 실패 원본 정책은 변경하지 않는다.

## 평가와 한계

- 가짜 제공자로 복수 동작 분리, 문장 속 모델명 선택, 후보 밖 인용·모호한 인용·겹침·중복·부분 응답 거부를 먼저 검증한다.
- 합성 `Q-001`, `N-004`, `N-006`을 포함한 고정 평가에서 최종 값·근거, 오확정, 시간·호출, 형식 실패를 기록한다. 이 실험의 기존 `candidate_gap` 단계 진단은 원래 후보와 파생 fact를 구별해야 하므로, 잘못 확정된 결과의 단계명은 지원 전까지 `undetermined`로 표시한다.
- 안전 관문(오확정 0·구조 근거 오류 0·6회·60초)을 통과하더라도 독립 실제 문서와 사람 검증 없이는 서비스 적용을 선언하지 않는다.
