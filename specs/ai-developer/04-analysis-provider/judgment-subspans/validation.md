# 후보 내부 원문 구간 판단 검증

## 결정적 테스트

- 후보 하나의 “장소 확인과 후보 선택”을 두 개의 독립 값·근거 구간으로 만들고, 문장 후보에서 `Lyra`만 고르는 가짜 제공자 테스트가 통과했다.
- 후보 밖 인용, 같은 후보 내 반복 인용, 겹치는 fact, 누락된 후보 ID, 잘못된 필드·상태는 전체 실패로 처리한다. `selected`는 스키마에서 현재 확정 또는 명시적 범주 부재만 허용한다.
- 최종 전체 단위 테스트 **439건 통과**, `git diff --check` 통과.

## 실제 모델을 사용한 합성 대상 3건

후보는 DeepSeek V4.1 Flash, 판단·의미 검토는 Solar Pro4, 검토 이슈 확인 게이트는 켠 상태다. 사례당 한 분석 호출로 실행했다. 모델 응답은 실행마다 달라지므로 각 실행 간 수치 차이를 인과 개선량으로 해석하지 않는다.

`N-004`는 제약 후 잘못된 값이 자동 확정되지는 않았지만 확인이 필요한 제안으로 남았다. `N-006`은 아직 유용한 Profile을 만들지 못했다. `Q-001`의 실제 모델 실행에서는 앞 단계의 DeepSeek가 이미 두 후보로 나눴으므로, 이 실행만으로 판단 단계의 복수 하위 구간 능력을 입증하지 않는다. 그 동작은 결정적 가짜 응답에서만 확인했다.

**판정:** 세 사례 사전 관문을 통과하지 못했다. 합성 20건으로 확대하지 않고 기본 분석기·서비스 API에도 적용하지 않는다. 다음에는 판단이 생성한 하위 값의 역할·확정 상태와 의미 검토 재거부를 더 좁혀야 한다.

## 독립 리뷰 반영

- 하위 구간에서 오확정의 최초 불일치 단계는 계속 `undetermined`로 둔다. 다만 필드별 후보·정답·최종 근거 위치는 보존한다. 여러 오확정 필드도 각각 기록한다.
- 평가 `passed`에는 실패 사례 0건을 추가했다. 기존 결과 JSON은 당시 코드의 기록으로 유지한다. 특히 `q001-n006-constrained-run1/summary.json`의 `passed=true`는 구 관문 판정이며, 현재 기준에서는 N-006 실패 때문에 통과할 수 없다.
- 수정 후 전체 단위 테스트 **441건 통과**, `git diff --check` 통과. 이 수정은 평가와 진단의 정확도만 다루며 모델 품질의 개선 증거는 아니다.

결과 JSON 12개에서 합성 문서 전체 문자열과 Upstage·NVIDIA 키를 검사해 검출되지 않았다. 원본 응답·Profile 전체를 기록하지 않는다. 독립 실제 문서·사람 검증·사용자 확인 UI는 아직 없다.
