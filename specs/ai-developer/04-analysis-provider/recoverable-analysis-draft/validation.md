# 실패 복구형 분석 초안 검증

## 범위

- 선택형 `analyze_recoverable()`을 이전 튜닝에 사용한 합성 20건에서 사례당 한 번씩 실행했다. Solar Pro4, `v2` 판단, 후보 등장 확장·keyed 후보·compact review와 기존 6회/60초 예산을 사용했다.
- [run1](results/run1/summary.json)은 최초 구현, [run2](results/run2/summary.json)는 리뷰 1차 수정, [run3](results/run3/summary.json)는 최종 코드의 실행이다. 모델 응답이 매번 달라 세 실행은 사례별 개선 효과를 비교하는 실험이 아니다.
- 각 실행의 `plan.json`에 자료·코드 SHA-256을 기록했다. `results.json`은 사례 ID, 상태, 안전한 오류 코드와 수치만 담는다. 독립 기획서 검증이나 서비스 사용성 검증은 아니다.

focus의 목표 일치 10건은 **제안 전체의 정답 수가 아니다**. focus 자료는 일부 목표 구간과 금지 문자열만 제공하므로 그 밖의 제안은 정오를 판정할 수 없다. full 자료는 필드 값 전체를 채점하지만 의미상 올바른 근거 구간을 독립적으로 주석화하지 않았다. `validate_profile` 통과는 구간과 문자열 포함을 보장할 뿐, 해당 인용이 필드 주장을 실제로 뒷받침한다는 증거가 아니다. 따라서 오제안·잘못된 의미 근거가 0건이라고 주장할 수 없다.

실패 유형별 보존 제안·목표 일치·금지 문자열·질문·완전 실패의 집계는 [run3 요약](results/run3/summary.json)의 `failure_types`에 있다. 시간 초과 4건 중 2건은 제안을 남겼고 2건은 복구할 제안 없이 실패했다. 세 실행 모두 오류와 실패 사례를 20건 분모에 포함했다.

## 판정과 남은 일

- 단일 분석 실행, 최대 6회 호출, 구조적 근거 검증은 통과했다.
- 관측 지연 60초, 감지된 오확정 0건, 전체 제안의 의미 채점, 의미상 근거 0오류 입증 관문은 통과하지 못했다. `run3` 평가 프로세스 종료 코드 1은 이 판정을 반영한다.
- 값 제안이 없는 실패는 `failed`로 내리도록 수정했다. 질문이 28개 남았고, 사용자 확인 화면의 사용성은 아직 검증하지 않았다.
- **기본 분석기나 서비스 API로 승격하지 않는다.** 다음 단계는 기존 성공 경로의 오확정 방지, 목표 외 제안과 의미 근거의 독립 주석 평가, 질문 수 축소, 제공자 시간 초과 시 관측 지연 관리다. 새 독립 문서가 없으므로 합성 점수만으로 실사용 가능 판정을 내릴 수 없다.

- 단위 테스트: `python -m unittest discover -s tests` — 최종 코드 408건 통과.
- `git diff --check` 통과.
- 결과 폴더에서 `document`, `profile`, `raw`, `response`, `UPSTAGE_API_KEY` 항목 검색 결과 없음. API 키·원문·원본 응답은 평가 산출물에 기록하지 않는다.
