# 실패 복구형 분석 초안 검증

## 범위

- `feature/recoverable-analysis-draft`의 선택형 `analyze_recoverable()`을 합성 20건에서 사례당 한 번씩 실행했다.
- Solar Pro4, `v2` 판단, 후보 등장 확장·keyed 후보·compact review, 기존 6회/60초 예산을 사용했다.
- 자료는 이전 튜닝에 사용한 합성 사례다. 독립 문서 검증이나 서비스 사용성 검증이 아니다.
- 실행 코드·자료 해시는 [plan.json](results/run1/plan.json)에, 원문 없는 사례별 수치는 [results.json](results/run1/results.json)에 보관했다.

## 판정

- 단일 분석 실행, 6회 호출, 원문 구간의 구조 검증은 통과했다.
- 60초 관측 지연과 오확정 0건 관문은 실패했다. N-004의 기존 성공 경로에서 오확정 1건이 나왔으며, E02·E06·E07에서 관측 지연이 60초를 조금 넘었다.
- 일부 결과는 값 제안 없이 다수의 질문만 남겼다. 질문 97개는 현재 방식 그대로 사용하기에 부담이 크다.
- **기본 분석기나 서비스 API로 승격하지 않는다.** 다음 개선은 오확정 방지, 가치 없는 빈 초안의 실패 처리, 질문 범위 축소, 관측 지연의 경계 정리다. 이후 독립 기획서로 검증해야 실사용 판단이 가능하다.

## 검증 방법

- 단위 테스트: `python -m unittest discover -s tests` — 구현 시 405건 통과.
- `git diff --check` 통과.
- 결과 폴더에서 `document`, `profile`, `raw`, `response`, `UPSTAGE_API_KEY` 항목 검색 결과 없음. 산출물은 사례 ID, 상태, 집계 수치, 안전한 오류 코드와 SHA-256만 기록한다.
- 실제 호출의 오류와 실패 사례도 분모에 포함했다. 평가 프로세스 종료 코드는 안전 관문 실패를 반영해 1이다.
