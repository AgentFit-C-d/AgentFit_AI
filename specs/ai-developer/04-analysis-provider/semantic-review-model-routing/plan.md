# 구현·검증 계획

1. 기존 모델 전달 경로와 NVIDIA 어댑터를 확인하고 각 방식의 차이를 의미 검토 제공자·모델 하나로 고정한다.
2. 표준·compact 검토의 payload 모델과 후보·판단·수정 모델이 분리되는 테스트를 먼저 작성한다. 미지정 기본값과 지원하지 않는 모델 거부도 확인한다.
3. 내부 선택형 `review_model`·`review_api_key`를 구현하고 호출 진단의 실제 모델 기록을 검증한다. 전체 비교 전에 DeepSeek·GLM·Kimi를 합성 한 건씩 호출해 응답 계약과 시간 제한을 확인한다.
4. 호환 모델을 동일 합성 20건에서 Pro4 검토와 비교하는 평가기를 작성한다. 자료·코드·평가기 해시를 저장하고 안전 진단만 기록한다. 키 사전 차단 수정 후 현재 코드로 한 번 더 교차 실행해 변동을 확인한다.
5. 전체 회귀 테스트, 평가 산출물 보안 점검, 품질 관문을 실행해 `validation.md`에 결과와 한계를 기록한다. 관련 파일만 기능 브랜치에 commit/push한다.
