# 의미 검토 단계 모델 분리 명세

## 목적

분석 파이프라인의 후보 추출·판단은 Solar Pro4로 유지하고, 독립 의미 검토·재검토만 NVIDIA 제공 모델로 실행했을 때 품질·형식 오류·시간을 비교한다. 후보는 DeepSeek V4.1 Flash, GLM 5.3, Kimi K3다. 이전 DeepSeek 고정 후보 판단 실험은 의미 검토 단계의 효과를 측정하지 않았다.

## 선택형 동작

- `AnchoredAnalyzer`에 선택형 `review_model`과 `review_api_key`를 추가한다. 미지정 시 모든 호출은 기존 Solar `model`을 사용한다.
- `review_model`은 `deepseek-ai/deepseek-v4.1-flash`, `z-ai/glm-5.3`, `moonshotai/kimi-k3` 중 하나일 수 있다. 이때 의미 검토와 재검토 호출만 NVIDIA 어댑터로 보내고, 후보 추출·필드 판단·수정 호출은 Solar Pro4를 사용한다. NVIDIA 키가 없거나 지원하지 않는 검토 모델이면 호출 전에 거부한다.
- DeepSeek는 기존 비추론 설정, GLM은 공식 문서의 낮은 추론 노력과 `clear_thinking=true`, Kimi는 낮은 추론 노력으로 호환성을 시험한다. 제공자별로 지원하지 않는 Solar 전용 필드를 제거한다. 검토 프롬프트·JSON Schema와 채점 데이터는 동일하다.
- 기존 표준 검토 계약과 선택형 compact 검토 계약 모두에서 모델 분리가 작동한다. 공개 Profile과 기본 서비스 설정, 프롬프트, 스키마, 최대 6회 호출·60초 제한은 유지한다.
- 호출 진단에는 제공자가 반환한 모델명이 기존 방식대로 기록된다. 키·원문·원본 응답은 평가 산출물에 저장하지 않는다.
- NVIDIA 키 자체가 입력 문서·문서 ID에 포함되면 첫 Solar 호출 전에 민감 입력 오류로 거부한다.

## 비교와 판정

- 합성 한 건의 호환성 검사에서 JSON Schema 응답과 40초 호출 제한을 통과한 후보만 20건 비교에 포함한다. 현재 compact 검토 계약을 고정하고 `Pro4 후보·판단 + Pro4 검토`와 각 호환 NVIDIA 검토 모델을 같은 합성 20건에서 비교한다. 모든 방식의 검토 호출별 상한은 40초다.
- 전체 Profile 완전 일치, 다구역 지정 사실, 오확정, 검증 오류, 검토 형식 오류, 시간 초과, 단계별 모델·호출 수·지연을 고정 분모로 보고한다.
- 새 방식에서 정확도가 떨어지거나 오확정·검증 오류가 늘면 기본값으로 적용하지 않는다. 성공 건수가 증가하고 오류·시간 지표도 악화되지 않을 때만 후속 실제 문서 검증 후보로 본다.
- 합성 자료는 튜닝에 사용됐다. 한 번의 교차 실행은 모델 우열이나 실서비스 성능을 증명하지 않는다. 서로 다른 제공자의 토큰 사용량은 직접 비용 비교하지 않는다.
- 앞단 후보·판단을 두 방식에서 독립 재호출하므로 반복 실행으로 변동을 확인하고, 성공 차이를 검토 모델만의 인과 효과로 단정하지 않는다.
