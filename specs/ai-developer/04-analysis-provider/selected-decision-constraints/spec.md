# 선택 판정 스키마 일치 보완
## 근거
9e3fa8b의 전체27건 중 S03/S08/O08이 SELECTED_STATUS로 실패했다. judgment_schema는 field-role-status만 결합하며 decision의 selected를 모든 상태/범위/역할 분기에 허용한다. 서버 merge_profile은 selected에 current, confirmed 또는 absent, 정상 role을 요구한다.

## 범위 판단
기존 서버가 이미 요구하는 규칙을 요청 스키마에도 적용하는 되돌릴 수 있는 보완이다. 응답의5개 키·필드 의미·서비스 경계·공개Profile·호출 흐름은 변하지 않는다. 사용자 지침의 사소한 구현 선택 자율 진행 범위로 판단했다. 새 복구 단계나 추가 호출은 이 작업에 포함하지 않는다.

## 요구사항
- selected_constraints=False 기본인 opt-in. AnchoredAnalyzer의v2에서만 허용한다.
- selected 분기: scope=current, status=confirmed 또는 배열 필드의 absent, 해당 field 정상role.
- 기존 각 field/status 분기를 복제하여 selected와 비선택 결정들을 구분한다. 비선택 및 단독irrelevant 표현력은 그대로다.
- 공급된 모든 후보ID 필수·추가키금지·서버의 기존 classify/merge 검증을 유지한다.
- 최초 판정과 후보 기반 의미 수정에 동일한 스키마를 적용한다.
- 다른 프롬프트·모델·추론·토큰·60초/6회·원문 수정 계약은 변경하지 않는다.
- 구조적으로 올바르지만 의미적으로 틀린 confirmed를 생성할 위험을 평가한다. 단위 테스트나 구조 오류 감소를 품질 향상으로 간주하지 않는다.
