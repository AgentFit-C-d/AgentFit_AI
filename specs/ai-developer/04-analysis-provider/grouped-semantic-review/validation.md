# 묶음별 의미 검토 실험 기록

## 구현·검증

- 3개 고정 필드 묶음의 검토 요청과 `checkedFields`·오류 대상 ID·근거 줄의 서버 검증을 구현했다. 세 묶음 모두 정상일 때만 자동 완료한다. 의미 이슈가 있으면 추가 의미 수정 없이 확인 필요로 보류한다.
- 기본 단일 검토·공개 Profile·최대 6호출·FastAPI 설정은 유지한다. 평가 CLI의 `--grouped-review`에서만 활성화된다.
- 전체 `python -m unittest discover -s tests -q`: 최종 637건 통과. 모의 테스트는 5호출 정상 완료, 구조 수정 포함 6호출 정상 완료, 의미 이슈·마지막 묶음 오류 시 자동 완료 금지, NVIDIA 전송을 확인했다.
- 자체 명세 대조에서 묶음 요청에 전체 초안을 보내던 불일치를 찾았다. 해당 묶음 초안만 보내도록 수정하고 회귀 테스트를 추가했다. 실제 출력의 `SCALAR_INDEX`를 보고 필드별 허용 대상 ID만 schema에 남기고 서버 검증은 유지했다.

## 이미 튜닝에 사용한 Campfire PRD 1건

- Solar Pro4, 원문 선택자, 그룹 검토, 전체 600초, 각 그룹 출력 상한 4,096토큰으로 단계별 수정 후 총 3회 실행했다. 세 실행은 서로 다른 확률적 응답이어서 변화량을 코드의 인과 효과로 해석하지 않는다.

| 실행 | 최초 검토 응답 | 최종 결과 | 호출·경과 | 부분 정답 / 미평가 값 |
|---|---|---|---:|---:|
| 전체 초안 전달 | 첫 묶음 4,096/4,096토큰 미완료 | 확인 필요, `INCOMPLETE_RESPONSE` | 3회·79,706ms | 7/7 · 33 |
| 묶음 초안 전달 | 첫 묶음 1,402토큰 완성, `SCALAR_INDEX` | 확인 필요, `SEMANTIC_REVIEW_INVALID` | 3회·41,287ms | 7/7 · 33 |
| 필드별 대상 ID 제약 | 첫 묶음 1,737토큰 검증 통과·의미 이슈, 둘째 묶음 4,096/4,096토큰 미완료 | 확인 필요, `INCOMPLETE_RESPONSE` | 4회·85,344ms | 7/7 · 33 |

- 세 번 모두 세 묶음 완주에 실패해 5문서 확대 조건을 충족하지 못했다. 첫 묶음의 유효한 이슈가 있었어도 뒤 묶음 실패 시 자동 확정하지 않았다. 묶음 분할만으로 출력 상한 문제를 해결했다고 볼 수 없어 기본값으로 승격하지 않는다. 부분 정답 일치는 정답 밖 값의 정확성을 증명하지 않는다.
- ignored 로컬 `tmp/public-prd-grouped-review-campfire-20260929`, `tmp/public-prd-grouped-scoped-campfire-20260929`, `tmp/public-prd-grouped-targets-campfire-20260929`의 plan/results/summary SHA-256 앞 8자리: 각각 `ed575ad9/3312904f/4962d968`, `ed575ad9/ce368af4/934bbb45`, `ed575ad9/831fdb67/eb4722f6`. 평가 저장 함수는 키·문서 전체 포함 시 쓰기를 거부하고 원본 응답·Profile을 저장하지 않는다.

## 남은 문제

- 세 그룹을 끝까지 검토하지 못해 실제 모델의 전체 형식 안정성과 의미 검토 정확도를 평가하지 못했다. 출력 상한 확대 또는 원문 범위 축소에는 누락·오확정 검증이 필요하다.
- 독립 실제 문서의 사람 검토, 정답 밖 값 확인, Spring/Frontend의 사용자 확인 전 저장 금지 E2E는 미완료다. 실사용 가능 판정은 보류한다.
