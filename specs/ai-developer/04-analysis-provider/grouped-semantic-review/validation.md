# 묶음별 의미 검토 실험 기록

## 구현·검증

- 3개 고정 필드 묶음의 검토 요청과 `checkedFields`·오류 대상 ID·근거 줄의 서버 검증을 구현했다. 세 묶음 모두 정상일 때만 자동 완료한다. 의미 이슈가 있으면 추가 의미 수정 없이 확인 필요로 보류한다.
- 기본 단일 검토·공개 Profile·최대 6호출·FastAPI 설정은 유지한다. 평가 CLI의 `--grouped-review`에서만 활성화된다.
- 전체 `python -m unittest discover -s tests -q`: 636건 통과. 모의 테스트는 5호출 정상 완료, 구조 수정 포함 6호출 정상 완료, 의미 이슈·마지막 묶음 오류 시 자동 완료 금지, NVIDIA 전송을 확인했다.

## 이미 튜닝에 사용한 Campfire PRD 1건

- Solar Pro4, 원문 선택자, 그룹 검토, 전체 600초, 각 그룹 출력 상한 4,096토큰으로 1회 실행했다.
- 결과는 `needs_confirmation`·`INCOMPLETE_RESPONSE`, 부분 정답 7/7, 정답 밖 값 33개 미검토, 3 Provider 호출, 총 79,706ms였다. core·features는 구조 검증을 통과했고 첫 의미 검토 묶음에서 `completion_tokens=4096/4096`으로 미완료됐다. 뒤 묶음은 호출되지 않았다.
- 첫 묶음이 완성되지 않아 5문서 확대 조건을 충족하지 못했다. 필드 묶음만으로 출력 상한 문제를 해결했다고 볼 수 없어 기본값으로 승격하지 않는다. 부분 정답 일치는 정답 밖 값의 정확성을 증명하지 않는다.
- ignored 로컬 `tmp/public-prd-grouped-review-campfire-20260929`의 plan/results/summary SHA-256 앞 8자리: `ed575ad9/3312904f/4962d968`. 평가 저장 함수는 키·문서 전체 포함 시 쓰기를 거부하고 원본 응답·Profile을 저장하지 않는다.

## 남은 문제

- 첫 그룹도 완성되지 않아 세 그룹 집계의 실제 모델 형식 안정성과 의미 검토 정확도를 평가하지 못했다. 출력 상한 확대 또는 원문 범위 축소에는 누락·오확정 검증이 필요하다.
- 독립 실제 문서의 사람 검토, 정답 밖 값 확인, Spring/Frontend의 사용자 확인 전 저장 금지 E2E는 미완료다. 실사용 가능 판정은 보류한다.
