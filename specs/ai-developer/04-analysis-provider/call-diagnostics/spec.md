# 분석 호출별 진단과 오류 기록
사용자 승인: 시간 초과 원인 확인부터 SDD 구현. 실패 원본은 실패 건만7일 보관이라는 기존 정책 적용.
기준 f43e96a/profile-v18. 브랜치 feature/analysis-call-diagnostics.
- 각 core/features/repair 호출별 번호, 요청 필드, 입력 길이·줄수·요청 bytes, provider 대기 시간·전체 시간, 응답 bytes, 토큰수, 결과·안전 오류코드를 기록한다.
- 진단은 결과/오류 객체의 추가 메타데이터이며 Profile 계약과 프롬프트/모델/timeout/무재시도/최대3호출은 그대로 유지한다.
- run UUID 사용. 진단 메타데이터에는 원문/문서ID/후보/키/임의 예외문자열을 넣지 않는다.
- 기본 라이브러리는 디스크에 쓰지 않음. 로컬 평가 CLI가 --diagnostics-dir 지정 시 저장. 성공은 메타데이터만, 최종 실패는 실패 응답만 저장. 수정으로 성공한 분석의 원문은 저장하지 않는다.
- 비밀 패턴·현재 API키 발견, 파싱 불가/과대 응답은 원문 보관 제외. 응답 없는 timeout은 메타데이터만. 로깅 실패가 분석 결과/원래 오류를 바꾸면 안 된다.
- 모든 로컬 진단은7일 만료. 읽기/쓰기/명시적 purge 때 만료 파일 삭제. 정지한 로컬 프로그램의 정확한 시각 삭제는 보장하지 않으며 배포 시 정기 purge 운영 필요.
