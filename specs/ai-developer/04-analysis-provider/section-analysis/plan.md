# 구현 계획
## 대안과 선택
- 구역마다1호출: 단순하지만 현재 두 문서만으로6/15회가 필요해 기존 상한과 충돌한다.
- 검색 상위구역만 선택: 비용은 적지만 전체 요구사항 누락 위험이 있어 이번 목적에 맞지 않는다.
- 최대2묶음에서 전체구역별 결과 추출: 구역별문맥과포괄성검사를 유지하며 기존6회 상한에 맞춘다. 첫 실험으로 선택한다.
## 단계
1. sections.py: 순수 함수로 원문 범위·제목 계층·원자블록을 분할하고 빈틈·겹침·복원 가능성을 검사한다.
2. 원문 순서를 유지한 최대2개 묶음 배정. 묶음12000자 상한과 긴원자블록은 명시적실패. 제목·메타데이터와 원문위치는 별도 보존.
3. section_analysis.py: 모든 구역ID를 확인하는 추출 계약과 사실 후보 검증을 구현한다. 사실 후보는 출처·역할·확정상태·원문인용을 보유한다.
4. 후보ID기반 통합: 서버가 검증한 후보만 선택해 기존Profile에 투영하고 충돌을 무시한 선택을 거절한다. 이는 원문 모든부분의 N제곱후보를 열거했던v23과 달리 실제 추출된 사실 후보만 다룬다.
5. 기존 의미 검토와 최종 공통 근거 검증을 연결한다. 호출 예산과실패 정책은spec대로 별도 상태전이 테스트.
6. 먼저 실패 테스트→구현→140개 기존회귀 포함 검증. 구조/누락/문맥 사례와 실제2문서의 정답을 호출 전에 고정한다.
7. 기존 결과와 작은 비교. 기본 경로는 유지한다. 결과·제약·SDD를 feature/section-document-analysis에 push한다.
## 구현 확인 대상
6회 상한을 유지하는 대신 새실험의 구조오류는 추가수정없이실패한다. 새실험 입력상한은총24000자이며 원자블록 제한이 있다. 이 두 제한과새추출/통합흐름을 확인한 후 구현한다.

## 구현·검증 기록
구역당30후보,전체120후보 상한을 두고 초과는 명시적오류로 처리한다. 독립리뷰 Setext문맥 문제를 실패 재현 후 수정했고, 기존 평가7건 입력해시는 변하지 않았다. 전체163테스트통과,실호출0/7. 기본 분석기는 유지한다.
