# 동일 초안 기능 검토 모델 비교 명세

## 목적과 근거

Campfire PRD의 기능 의미 검토는 120줄 구역에서 첫 호출, 50줄 구역에서 12번째 호출이 Solar Pro 4의 출력 8,192토큰 상한에 닿았다. 후자는 입력 1,081토큰에 불과했다. 구역을 더 쪼개는 방향은 중단하고 추론 설정·모델이 완료율에 주는 영향을 같은 초안·같은 원문 구역에서 분리해 측정한다. 모델 완료만으로 의미 정확도는 입증되지 않는다.

## 평가 계약

- 고정 공개 튜닝 문서 Campfire PRD 1건의 원문 선택자 첫 단계만 Solar Pro 4로 실행해, 검토 직전 서버가 근거를 검증한 Profile을 메모리에 얻는다. 기능 후보 선택까지 완료한 뒤 훅에서 의도적으로 중단하므로 전체 의미 검토를 반복하지 않는다.
- 50줄 검토 구역 중 직전 실패가 있던 12번째(1부터 셈)를 고른다. 그 원문·초안·서버 부여 ID와 JSON schema는 모든 비교군에서 같다.
- Solar Pro 4의 검토 추론 `medium`, `low`, `none`과 NVIDIA 제공 `deepseek-ai/deepseek-v4.1-flash`, `z-ai/glm-5.3`, `moonshotai/kimi-k3`를 각 1회 실행한다. NVIDIA 요청은 기존 모델별 payload 변환을 사용한다. 호출 순서와 결과를 기록하며, 제공자 오류가 나면 다음 비교군을 계속 실행한다.
- 응답은 공통 파서와 `normalize_section_review`로 검증한다. 결과에는 고정 모델명, 설정, 구역 번호·줄 범위, 완료/안전 오류 코드, 프롬프트·출력 토큰, 경과 시간, 검증된 이슈 개수만 둔다. 원문·초안·Profile·인용·키·원본 응답은 출력·파일·로그에 저장하지 않는다. 결과 파일은 기존 `write_safe_json`의 금지 문자열 검사 후 작성한다.
- 실제 API 호출은 `--live`가 있을 때만 한다. 입력 문서 해시와 고정 케이스 ID를 확인한다. 결과 경로가 이미 존재하면 덮어쓰지 않는다. 실패해도 원본 응답을 보관하지 않는다.

## 판단 기준

- 유효 응답과 출력 토큰 여유가 있는 모델/설정만 전체 파이프라인 검증 후보가 된다. 검증된 이슈 수 0이 정확함을 뜻하지 않는다.
- 1회 비교는 모델의 안정적 성공률을 추정할 수 없다. 후보가 있으면 별도 선택형 라우팅 설계 후 Campfire 전체·정답 밖 값·미정 필드 안전성을 검증한다. 후보가 없으면 자동 의미 검토에 기대는 구조를 재검토한다.
- 공개 튜닝 문서만으로 실사용 가능 판정을 하지 않는다.
