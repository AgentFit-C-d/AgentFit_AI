# 실행 계획

1. `AnchoredAnalyzer`에 기본값이 꺼진 ID별 후보 옵션을 추가한다. v2·반복 후보 확장 설정에서만 허용한다. 두 묶음의 응답을 모은 뒤 기존 `normalize_keyed_candidates`로 검증하고 동일한 후보 풀을 후속 판단에 전달한다.
2. 테스트를 먼저 작성해 옵션 제약, 두 묶음의 정상 경로, 원자적 오류, 기존 배열 경로, 6회 호출 제한을 검증한다.
3. 합성 12건의 기존 전체 Profile 정답과 다구역 8건의 고정 사실 정답을 읽는 비교기를 만든다. 같은 Solar Pro4·v2·반복 후보 확장·동일 판단/검토 옵션으로 문서별 순서를 교차한다.
4. 외부 호출 전 plan.json에 자료·코드 해시와 판정 기준을 기록한다. 결과에는 안전한 점수와 진단 값만 쓴다. 실행 중 중단돼도 사례별 결과를 보존한다.
5. 테스트와 실제 비교를 실행하고 수용 기준을 기록한다. 기본값 변경 없이 기능 브랜치에 커밋하고 push한다.

## 고정 판정 기준

- **실험 유효성:** 양쪽 모두 동일한 20건·설정으로 시도하고, 각각 호출 수 6회와 60초를 초과하지 않아야 한다.
- **품질:** 전체 Profile 12건의 완전 일치 수, 필드 일치 수, 오확정 수와 다구역 8건의 지정 사실 회수·오확정 수를 병렬 비교한다. ID별 방식의 오확정·검증 오류가 기준선보다 많으면 승격 실패다.
- **한계:** 자료는 튜닝에 사용된 합성 사례이므로 비교 결과는 선택형 실험 판단에만 사용한다. 기본 서비스 적용과 실사용 가능 판정은 별도 결정이다.
