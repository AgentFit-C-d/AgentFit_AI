# ID별 후보 계약의 전체 Profile 비교 명세

## 목적

기존 배열 후보 응답과 이미 검증한 ID별 후보 응답을 동일한 전체 분석 흐름에 넣어, 후보 회수 개선이 최종 Profile의 필드·역할·확정 여부 개선으로 이어지는지 확인한다. 이번 기능은 선택형 실험 경로이며 기본 분석기와 공개 Profile을 바꾸지 않는다.

## 비교 계약

- 같은 원문, 모델, 판단·검토 설정, 시간·호출 한도를 사용한다. 문서별 실행 순서는 두 방식을 번갈아 배치한다.
- ID별 후보는 모든 묶음이 도착한 뒤 함께 검증한다. 한 묶음이라도 실패하면 부분 Profile을 반환하지 않는다. 기존 원문 위치·모호성·120개 제한을 따른다.
- 후보 이후의 판단, 의미 검토, 수정 흐름은 두 방식에서 동일하다. 문서당 최대 6회 호출·60초를 유지한다.
- 기존 전체 Profile 정답 12건에서 모든 필드의 값과 미정·부재 상태를 채점한다. 다구역 합성 8건에서는 사전 지정된 현재 제품 사실의 필드·값·원문 근거, 배제해야 할 과거·예시·개발 전용 사실의 오확정을 채점한다.
- 결과는 사례 ID, 점수, 오류 코드, 호출 수, 지연, 코드·자료 해시만 기록한다. API 키, 문서 원문, 인용 문자열, 모델 원본 응답은 저장하지 않는다.

## 판정

- 두 방식의 최종 성공·오확정·검증 오류·호출 수·지연을 나란히 보고한다. 전체 Profile 12건의 필드 일치율과 완전 일치 사례 수, 다구역 8건의 지정 사실 정확도와 오확정을 별도로 표시한다.
- ID별 방식에 잘못된 확정 또는 검증 오류가 늘면 기본값 승격을 권장하지 않는다. 정확도 상승만으로 실사용 가능 판정을 내리지 않는다.
- 모든 사례는 이미 튜닝에 사용된 합성 자료다. 성공하더라도 실제 신규 문서의 일반화 성능은 미확인으로 표시하고 기본 분석기를 자동 변경하지 않는다.

## 수용 기준

1. 선택형 설정에서 기존 배열과 ID별 계약을 각각 전체 분석으로 실행할 수 있다. 기존 설정의 동작은 유지된다.
2. 다구역 두 묶음의 ID별 후보를 원자적으로 검증하고 판단 단계에 동일한 형식으로 전달한다. 오류 시 부분 성공이 없다.
3. 비교 실행 전에 평가 자료·설정·채점·판정 기준을 파일로 고정한다. 결과에는 비밀 값과 원본문서가 없다.
4. 두 방식의 필드·역할·확정 여부 품질, 오류, 최대 호출 수와 지연을 재현 가능한 요약으로 확인할 수 있다.
