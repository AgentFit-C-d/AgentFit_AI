# 계획
1. 기존 지시를 공통/기술/기능으로 구분한다. 사실 판단 기준을 추가하거나 평가 기준을 변경하지 않는다.
2. 실제 전송 payload의 지시 분리, 기능전용/기술전용/혼합 수정 분기를 회귀 테스트로 먼저 검증한다.
3. profile-v17 적용. 스키마/검증/호출수는 기존 코드 유지.
4. 전체 단위 및 동일 합성26·실제4 평가. 기존v16은 역사적 기준이며 동시 무작위 대조는 아님을 명시한다.
5. 실패 원인이 남으면 구체적 증거를 수집하고 범위를 벗어난 수정을 누적하지 않는다.
6. 결과/한계 기록, 비밀 검사 후 기능 브랜치 commit/push.

## v17 진단 및 v18
v17 기존합성12/24. 진단 재호출에서 기술선택 문장이 features로 출력되고, 가계부 앱 이름이 null이었다. 원래 이름 추출 예시가 분리 중 제거되었다. 기술에 해당 예시를 현재 줄 형식으로 복원하고 기능에는 기술/연동 선택은 동작이 아니라는 음성·양성 예시를 추가한다. 고정 정답이나 검증기는 변경하지 않는다. v17 결과 보존.
