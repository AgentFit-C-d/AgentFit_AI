# 통합 판정 구현·대조 결과
사용자 ‘설계대로 진행’ 승인에 따라 opt-in 구현했다. 기본 분석기는 변경하지 않았다.

## 구현
후보별5키 객체 대신18개 라벨 중 하나를 반환하고, 서버가 기존 classify/merge 입력으로 변환한다. 모든ID·라벨을 먼저 검증하고 conflict가 있으면 부분 결과 없이 실패한다.
value/absent/omit 변환은 후보 quote와 기존 전역근거를 그대로 사용한다. 중복값·선택개수·선택된 존재/부재 충돌 검증을 유지한다.
atomic_verdict=True는v2+candidate_occurrences=True에서만 가능하며 selected_constraints와 동시 사용을 거부한다. 최초·후속 판정 계약은 동일하고 추가 호출은 없다.
제외 후보의 세부 분류 정보가 줄어드는 승인된 위험은 남아 있다. 기존 모든 충돌 보호와 동등하다고 주장하지 않는다.

## 동일 시점 교차 비교
기존27건과 새 대조6건, 총33건을 두 조건으로66회 요청했다. 모두 합성 튜닝 자료이며 원문 후보는 사전 고정했다.
Solar Pro4/none/4096/40초, 같은 위치focus와 허용근거를 사용했다. 사례별 기존먼저/신규먼저 순서를 교차했다. 정답은 API에 보내지 않았다.

| 지표 | 기존5키+선택제약 | 통합18라벨 |
|---|---:|---:|
| 일반 값·근거 정답 |18/31|17/31|
| 명시적 충돌 인식 |0/2|2/2|
| 대조6건 전체 정답 |4/6|4/6|
| 오확정 사례(잘못된 근거 포함) |7|4|
| 서버 판정 검증 실패 |3|4|
| 중앙값 지연 |1,375ms|812ms|
| p95 지연 |6,641ms|6,703ms|
| 생성 토큰 합계 |2,799|902|

단순합계는18/33→19/33이지만 충돌 인식 개선이 포함된 수치다. 일반 초안 정확도가 개선됐다는 근거가 아니다.
오확정은 틀린 값·잘못된 부재·근거 없는 확정을 뜻한다. 허용되는 사실 일부를 빠뜨린 순수 누락은 정답 점수에서 실패시키되 오확정과 구분했다.
신규 실패는 CONFLICTING_FACTS1, DUPLICATE_VALUE2, SELECTED_COUNT1이다. API 전송/JSON 형식 실패는 없었지만 서버 의미 계약 검증은 통과하지 못했다.
AC01·AC02의 충돌 인식은 모든 지정 후보의 정확한 conflict 판정을 확인했다. 일반 예외 코드나 조용한 전체null을 충돌 정답으로 인정하지 않았다.
AC04·AC05에서는 과거/예시를 배제하고 현재 사실을 고르는 회귀가 발생했다. 새 통합 계약에서도 역할·시점·대상 판단은 해결되지 않았다.

## 사전 관문과 결정
일반 정확도 증가, 오확정0, 대조6/6, 검증오류0 모두 충족하지 못했다. results/summary.json의gate는false다.
명세대로 전체 흐름27건과 기존12건3회·추가 위치 반복을 수행하지 않았다. 기본값으로 승격하지 않는다.
짧은 응답·충돌2건 인식만으로 모델 품질을 달성했다고 판단하지 않는다. 각 조건1회이며 통계적 안정성이나 새로운 실제 문서의 성능을 검증한 결과가 아니다.

## 코드·보관 검증
회귀 테스트323건 통과. 라벨18개, 전체형식 우선검증, 중복JSON키, 부분실패금지, 기존merge보호, 초기/재판정5호출, 잘못된 옵션, 충돌 채점, 순수누락 구분, 정답 비전송·원본응답 미기록을 확인했다.
독립 검토에서 차단 이슈 없음. 관련19건과diff 검사를 검토자가 직접 통과시켰다. 별도API호출/파일수정은 없었다.
평가 원본응답·reasoning·키는 저장하지 않았다. 안전한 점수·오류코드·근거offset·토큰·시간·코드와자료해시를 기록했다.
예약 공개문서와 실제 사용자 문서는 읽거나 전송하지 않았다. 실사용 목표와 독립 실제문서·사용자 수정부담 검증은 미완료다.
