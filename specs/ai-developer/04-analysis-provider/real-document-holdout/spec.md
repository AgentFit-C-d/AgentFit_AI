# 새 실문서 비식별 검증 명세

## 목적

기존 AgentFit·MABC·Handoff와 합성 문서는 개발·원인 조사에 사용됐다. 새로 제공된 Markdown·DOCX·PDF 세 문서로 현재 서비스 Profile 분석기의 일반화와 문서 입력 경계를 독립 확인한다. 사용자는 2026-09-30에 개인 정보를 제거한 평가용 추출 텍스트의 외부 모델 API 전송을 승인했다.

## 자료 경계

- 승인된 원본은 SHA-256이 각각 `57f13a242906bb5037b7fc65c5dbc30e42687436b27f9349699198449fc31239`(Markdown), `2a290fff891ac850a03ea715629a8d9fef1fb1628776eec8e852c8175b2bb24d`(DOCX), `a6ef17b02d392865c8251e0adb81c6dadab5781e57e53c418a4ddcf609b1136f`(PDF)인 세 파일이다. 경로는 로컬 비공개 manifest에서 받되 세 해시가 모두 일치해야 한다.
- Markdown은 팀원 표 구역을 제거한다. PDF는 팀장·팀원 이름·학번·연락처가 있는 머리말을 버리고 프로젝트 본문 시작 표시 이후만 사용한다. DOCX는 읽기 전용으로 문단 순서대로 추출한다. 모든 결과에 전화번호·이메일·8자리 학번 패턴이 남으면 전송하지 않고 실패한다.
- 추출·비식별 텍스트와 원본 경로, 모델 응답, Profile 값, 키를 저장하거나 일반 출력하지 않는다. 원본과 비식별 텍스트의 SHA-256, 길이, 구조 개수, 오류 코드, 골드 채점 수치만 기록한다. 원본 파일은 수정하지 않는다.
- PDF Docling 변환은 로컬에서만 수행한다. DOCX는 현재 공개 서비스 입력 형식이 아니므로 실험용 문단 추출 결과를 TEXT로 평가하되, DOCX 업로드가 지원된다고 주장하지 않는다.

## 평가

- 최초 모델 호출 전에 세 원본 해시, 비식별 텍스트 해시, 각 문서의 소수 핵심 필드 골드를 고정한다. 골드는 현재 모델 결과를 보지 않고 기획서의 확정·검토·예시 표현을 구분해 작성한다.
- 실제 서비스의 기본 `SolarAnalyzer` 설정(40초 제한, Profile 10필드)으로 문서별 분석을 한 번 실행한다. 실패도 분모에 남긴다. Profile 값·근거가 원문에 있고 상태가 확정인지 독립 골드 체크로 평가한다. 모델의 출력 원문이나 근거 내용은 결과에 저장하지 않는다.
- 기본 제한에서 완주하지 못하면 동일한 고정 텍스트·골드를 120초, 최대 600초의 명시적 진단 설정으로 재실행할 수 있다. 600초 설정에서는 개별 필드 호출도 120초까지 기다린다. 이 결과는 기본 서비스 성공률과 합산하지 않는다. 실패 단계·안전 오류 코드·경과 시간만 기록한다.
- 필요하면 선택형 Docling·LangExtract·규칙 경로는 별도 실험으로 측정하며 기본 서비스 결과와 섞지 않는다. 이 세 문서는 지시문 수정에 쓰지 않고 holdout으로 유지한다.
- 3문서의 결과만으로 실서비스 가능을 선언하지 않는다. 실패 필드와 처리 시간·메모리·입력 형식 미지원은 별도 관문으로 남긴다.
