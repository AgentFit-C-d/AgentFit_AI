# 새 실문서 비식별 검증 계획

**목표:** 승인된 새 문서 세 개를 개인정보 제거 후 고정 골드로 실제 서비스 분석기에 평가한다.

**경계:** 로컬 비공개 manifest는 `E:/AgentFit/tmp`에 두고 Git에 추가하지 않는다. 공유 저장소에는 코드·테스트·해시·안전 수치만 기록한다.

## 1. 입력과 비식별

- [ ] 원본 세 SHA-256과 형식·개수를 검증하고 다른 파일은 모델 호출 전에 거절하는 실패 테스트를 쓴다.
- [ ] Markdown 팀원 구역, PDF 개인 정보 머리말을 제거하고 DOCX 문단을 읽는 로컬 추출기를 구현한다.
- [ ] 전화번호·이메일·8자리 학번 패턴이 남거나 필수 경계 표시를 못 찾으면 전송하지 않는 테스트를 쓴다.
- [ ] 비식별 텍스트의 해시·길이와 구조 수를 모델 호출 전에 고정하고 비공개 골드를 검토한다.

## 2. 안전한 서비스 분석 평가

- [ ] `--live`와 manifest·골드·비식별 선검증 전에는 키를 읽지 않는 CLI 테스트를 쓴다.
- [ ] 40초 기본 설정의 `SolarAnalyzer`를 문서당 한 번 호출하고 Profile의 선택 필드를 독립 골드로 채점한다. 실패는 안전 코드로 집계한다.
- [ ] 원문·개인정보·키·응답·Profile 값이 결과 파일과 로그에 남지 않는 테스트를 쓴다.

## 3. 결과

- [ ] 세 실문서를 승인 범위 내에서 라이브 평가하고 실험 결과의 한계를 `validation.md`에 기록한다.
- [ ] 로컬·Linux 테스트와 diff를 확인하고 `feature/real-document-holdout-evaluation` 브랜치에 push한다.
