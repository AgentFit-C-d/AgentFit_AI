# 새 실문서 비식별 검증 결과 (2026-09-30)

## 입력과 개인정보 처리

- 사용자 승인에 따라 새 Markdown·DOCX·PDF 세 문서의 평가용 추출 텍스트만 Solar API에 보냈다. Markdown 팀원 구역과 PDF의 이름·학번·연락처 머리말을 제거했다. 해시·길이·전화번호·이메일·8자리 번호 패턴을 전송 전에 확인했다.
- 모델 호출 전 고정한 비공개 골드는 세 문서 합계 19개 선택 필드 체크다. 결과 파일에는 원문·키·응답·Profile 값이 없고 문서 ID, 해시, 길이, 오류 코드, 호출 단계만 있다. 원본 파일은 수정하지 않았다.
- DOCX는 실험에서 문단을 추출해 TEXT로 전달했다. 공개 서비스가 DOCX 업로드를 지원한다는 의미는 아니다.

## 실제 모델 실행

| 설정 | H01 Markdown | H02 DOCX | H03 PDF | Profile 완료 |
|---|---|---|---|---:|
| 기본 분석기, 전체 40초·필드당 최대 40초 | `PROVIDER_TIMEOUT` | `PROVIDER_TIMEOUT` | `INVALID_EVIDENCE` | 0/3 |
| 전체 120초·필드당 최대 40초 | `INVALID_EVIDENCE` | `PROVIDER_TIMEOUT` | `INVALID_EVIDENCE` | 0/3 |
| 진단, 전체 600초·필드당 최대 40초 | `INVALID_EVIDENCE` | `PROVIDER_TIMEOUT` | `INVALID_EVIDENCE` | 0/3 |
| H02 단독 진단, 전체 600초·필드당 최대 120초 | — | `INVALID_EVIDENCE` | — | 0/1 |

600초 진단의 안전한 호출 단계 요약에서 H01은 `core` 검증, `features` 검증 실패, `repair` 근거 검증 실패였다. H03은 의미 검토 후 `semantic_repair`에서 근거 검증에 실패했다. H02의 개별 호출을 120초로 늘린 진단에서는 `core`와 `features` 모두 검증 실패, `repair`도 근거 검증 실패였다. 이 진단은 서비스 기본 성공률과 합치지 않는다.

Profile을 반환한 건이 없어 고정 골드 19개는 **0개 채점**했다. 따라서 0/19 정확도라는 주장은 성립하지 않는다. 현재 확인된 수치는 기본 설정 완료율 0/3과 진단 설정 완료율 0/3이다. 세 문서는 이 평가 이후 프롬프트나 규칙 수정에 사용하지 않는다.

## 문서 변환과 범위의 한계

- PDF Docling 변환은 `46`개 셀 중 `36`개를 표의 행·열에 매칭하지 못했다는 경고를 냈다. 제거된 개인정보 머리말의 셀일 수 있지만 이 경고만으로 본문 손실이 없다고 증명할 수 없다.
- 세 문서는 새 입력이지만 표본이 작고 모두 Profile 완료에 실패했다. 현재 경로의 실사용 가능성을 입증하지 못한다. 다음 개발은 근거 인용·수정 오류를 재현 가능한 비공개 진단으로 분류하고, 별도 튜닝 자료에서 보완한 뒤 독립 자료로 재검증해야 한다.
- 비식별화는 특정 구역 제거와 번호·이메일 패턴 검사에 의존한다. 일반 목적의 개인정보 탐지 기능으로 취급하지 않는다.

## 검증

- 서비스 단위 테스트: 전체 실행 성공 (`6`건 건너뜀).
- 평가기 단위 테스트: `9`건 통과.
- 실제 Docling 의존 환경의 관련 테스트: `47`건 통과.
- diff 검사와 원격 CI는 최종 커밋 전에 별도 확인한다.
