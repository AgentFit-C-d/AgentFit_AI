# 비교 결과

- Solar Mini4 alias, medium/low 각각 고정 합성6건 1회. 전체 단위 테스트248건 통과.
- 후보/판단/검토 프롬프트와 정답, 검토8192토큰, 최대6회/60초 동일.
- 성공/실패 단계의 시간·사용량·이슈 종류를 허용 목록으로 기록했다. 응답·추론·Profile 원문 저장 없음.
- 두 실행 모두 기준 미달로 exit1. 추가 반복/실제 문서 확대는 하지 않았다.

## 관측과 한계
- 검토 단계 Q-001:33.594→28.954초, Q-004:52.735→54.437초, Q-005:14.000→8.250초.
- Q-006 low는 시간 내 종료했지만 features 골드와 다르다. 모델 자체 검토 통과는 정답 보장이 아니다.
- Q-002는 검토 전 결과부터 달라졌다. 전체 평균/중앙값 차이는 조기 실패 효과와 모델 변동을 포함하므로 추론 설정의 인과 효과로 해석하지 않는다.
- 각1회이며 API 응답 지연/비결정성 영향이 있다. 시간 단축의 재현성은 미확인.
- medium Q-006 실제60.047초:60초는 협력적 네트워크 예산이며 하드 중단 보장이 아니다.
- 누락 방어가 잘못된 성공을 차단했지만 누락 자체를 고친 것은 아니다.
- 후보를 고정하고 기존 후보 분류만 다시 하는 수정 단계는, 후보에 필요한 분리된 동작이 없으면 복구할 수 없다(코드상 한계).
- SECTION_MERGE는 여러 검증 원인을 합친 코드다. 이번 metadata만으로 정확한 위반 유형은 확정할 수 없다.
- 기존 검토 프롬프트는 짧은 동작을 요구하고 일부 문장 범위를 overbroad로 본다. 의미 골드의 전체 동작문 허용과 충돌할 수 있으나 이번에는 변경하지 않았다.

## 다음 보완 순서
1. 합친 검증 오류를 안전한 원인 코드로 세분화하여 판단 단계 실패를 재현한다.
2. 후보 생성의 동작 분리·명시적 부재 보존을 별도 평가한다. 후보 수정 없이 해결 가능한지 먼저 확인한다.
3. 필요하면 원문 내 후보 분리/보완까지 가능한 수정 계약을 구체화하고 주요 계약 변경 승인을 받는다.
4. 검토 기준과 의미 골드의 표현 범위 차이를 별도 실험으로 해결한다.
공개 검증 자료는 아직 모델에 보내지 않았다. 실사용 목표는 미달이며 사람의 수정 부담도 미측정이다.
