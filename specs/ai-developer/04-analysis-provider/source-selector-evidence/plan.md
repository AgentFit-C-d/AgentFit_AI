# 원문 구조 선택자 근거 실험 구현 계획

**목표:** 모델이 값 문자열을 복사하지 않고 원문 줄과 구조 선택자만 반환하도록 한다.

**구조:** `source_selector.py`가 줄별 결정적 span 생성·선택자 schema·Profile 투영을 맡는다. 선택형 분석기는 `LineEvidenceSolarAnalyzer`의 Provider, 수정, 의미 검토, 복구 흐름을 재사용하고 프롬프트·schema·투영만 바꾼다. 공개 평가 CLI는 플래그로만 이 분석기를 사용한다.

**대상:** `ai_service/agentfit_ai/source_selector.py`, `source_selector_analysis.py`, 공개 평가 CLI, 관련 테스트 및 이 폴더의 검증 기록.

## 작업 1: 원문 선택자와 투영

- [ ] 실패 테스트로 제목·목록·표·강조·코드·구분자 span, CRLF·Unicode, 빈·중복·긴 후보, 잘못된 줄·역할·배열 중복을 고정한다.
- [ ] `source_selector.py`에서 줄별 선택자를 결정적으로 만들고, `{lineId,selector,role}`을 기존 Profile로 투영한다.
- [ ] 관련 테스트와 기존 줄 근거 테스트를 실행한다.

## 작업 2: 선택형 분석기

- [ ] 실패 테스트로 core/features/수정 요청이 새 계약을 쓰고 기본 분석기는 변하지 않음을 확인한다.
- [ ] 기존 분석기 상속으로 전용 prompt/schema/투영을 구현하고 안전 진단 버전을 기록한다.

## 작업 3: 공개 튜닝 평가

- [ ] CLI 선택 플래그 테스트를 추가하고 opt-in 경로를 연결한다.
- [ ] 전체 테스트, 고정 PRD 5건 실제 실행, 결과의 원문·키 누출 확인을 수행한다.
- [ ] 결과를 `validation.md`에 기록하고 feature 브랜치를 push하며 Linux CI를 확인한다.

## 검토 초점

- 모델이 존재하지 않는 선택자를 선택하면 첫 후보로 대체하지 않는다.
- 같은 텍스트가 줄에 여러 번 있어도 선택자 span은 유일하게 지정되어야 한다.
- 표의 빈 셀 때문에 셀 인덱스가 밀리지 않아야 한다.
- 원문에서 Markdown 표식을 제거할 때 값과 근거 span이 동일한 위치를 가리켜야 한다.
- 선택자 오류가 의미 검토를 우회해 자동 확정으로 이어지면 안 된다.
