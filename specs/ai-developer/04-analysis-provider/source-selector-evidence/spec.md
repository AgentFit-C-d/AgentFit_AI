# 원문 구조 선택자 근거 실험

## 목적

Solar가 정확한 `value` 문자열을 다시 쓰다가 실패하는 경로를 제거한다. 운영 기본값과 공개 Profile은 유지하며, 선택형 분석에서 모델은 원문 줄 ID와 서버가 계산할 구조 선택자만 고른다. 성공 기준은 기존 공개 PRD 튜닝 자료에서 근거 투영 오류와 완료율·시간을 관찰하고, 오류가 줄더라도 의미 정확도와 독립 검증 없이는 기본값을 바꾸지 않는 것이다.

## 현재 근거

- `line-evidence-v1`은 `VALUE_NOT_IN_LINE`이 반복돼 5개 PRD 자동 완료가 0건이었다.
- 같은 5개 PRD의 정답 근거 35개 모두 단일 원문 줄 안에 있다. 표 셀만 사용하면 일부 정답을 놓친다.
- 줄 전체·표 셀·강조·코드·구분자 뒤를 모두 전개한 후보는 문서별 397~3,586개, 약 12,480~149,580자의 추가 후보 payload가 된다. 따라서 후보 목록 전체를 모델에 중복 전송하지 않는다.

## 내부 계약

- 기존 번호가 붙은 원문 줄을 한 번 전송한다. 확정 항목은 `{lineId,selector,role}`만 반환하며 `value`, 인용문, 오프셋을 생성하지 않는다. 미정은 `null`, 명시적 부재는 기존 `absent` 형식을 쓴다.
- 선택자는 줄 전체와 구문적으로 식별 가능한 원문 일부를 가리킨다. 최소 범위는 제목·목록 표식을 뗀 본문, 표 셀, Markdown 강조·코드, 첫 콜론·등호·긴 대시 앞뒤다. 서버가 선택자별 정확한 원문 span과 값을 계산한다. 구조가 없거나 공백·200자 초과·중복 결과이면 안전하게 거부한다. 의미를 추론하거나 원문을 수정하지 않는다.
- 필드별 role, 배열 한도·중복, 확정성 및 기존 Profile 검증·의미 검토를 재사용한다. 잘못된 선택자는 필드·항목 인덱스와 안전한 고정 사유로 수정 요청에 전달한다. 수정 뒤에도 실패하면 기존 확인 필요/실패 흐름을 따른다.
- 기본 SolarAnalyzer와 FastAPI 요청·응답, 기존 6회 호출/전체 기한, 실패 원본 보관 정책은 변경하지 않는다. opt-in 평가 플래그만 추가한다.

## 검증 기준

- 원문 span 보존: CRLF, Unicode, 표의 빈 셀, 반복 문자열, 인용부호·Markdown 표식, 선택자 범위 오류를 테스트한다.
- 서버 생성 후보가 고정 정답 35개를 포괄하는지 확인하고, 실제 모델 실행에서는 자동 완료·확인 필요·실패, 정답 일치·누락·판정 불가, 구조 오류, 단계별 시간과 총 기한을 기록한다.
- 새 모델 실행 결과는 이미 튜닝에 쓴 문서에서 나온다. 다른 확률적 응답과의 수치 차이를 인과 개선으로 단정하지 않는다.
