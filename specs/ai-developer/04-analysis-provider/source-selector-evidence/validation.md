# 원문 구조 선택자 실험 검증 기록

## 구현 전 탐색, 2026-09-29

- `public-prd-holdout/manifest.json`의 이미 튜닝에 사용한 공개 PRD 5건을 고정 커밋·SHA-256으로 다시 읽었다. 전체 정답 근거 35개 모두 하나의 원문 줄 안에 있었다.
- 비어 있지 않은 줄은 문서별 170·284·460·1,131·238개다. 가장 긴 줄은 509자이며 300자 초과 줄은 총 4개다.
- 표 셀만으로 별칭이 들어간 후보를 얻는 경우는 문서별 3/6·4/5·6/7·7/8·8/9다. 제목·문장·목록 등 비표 구조가 필수다.
- 줄 전체·표 셀·강조·코드·구분자 뒤를 풀어 나열한 임시 탐색은 문서별 397·586·1,346·3,586·634개 후보, 대략 12,480·27,398·46,789·149,580·30,729자 payload를 만들었다. 200자 이하의 후보에 정답 별칭이 들어가는 포함률은 35/35였다. 이는 모델의 올바른 선택 가능성이나 Profile 값의 의미 정확도를 입증하지 않는다.
- 실험 스크립트는 ignored `ai_service/tmp/candidate_coverage_probe.py`에만 있다. 제품 코드·API 키·문서 원문은 이 기록에 넣지 않았다.

## 현재 판단

후보 전체를 펼쳐 보내는 방식은 특히 58KB PRD에서 입력을 크게 늘리므로 채택하지 않는다. 줄 본문은 한 번만 보내고, 모델 응답은 줄 ID와 구문 선택자로 한정하는 구현을 진행한다. 실제 모델 결과와 시간·의미 정확도는 아직 미확인이다.
