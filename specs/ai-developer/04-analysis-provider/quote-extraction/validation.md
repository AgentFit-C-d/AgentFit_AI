# 단일 인용 추출 실험 결과

## 구현
quote_only=True인 구역 분석에서 value를 받지 않고, 정확한 quote의 원문 위치에서 값을 복원합니다. 공개 Profile과 Mini4/Jev 호출 흐름은 유지했습니다.
일반 인용은 200자 이하, 명시적 없음의 인용은 2000자 이하입니다. 문장 전체를 기능명으로 고르는 오류까지 길이 검사로 보장하지는 않습니다.
기존 오류 코드를 유지하고 candidate_error에 원문 없는 reason/sectionId/itemIndex를 추가했습니다.

## 검증
신규 계약 테스트 8건의 실패를 먼저 확인한 뒤 구현했습니다. 통합 흐름과 리뷰 수정 회귀까지 전체 **191/191 통과**했습니다.

## 실제 짧은 구역 평가
- Mini4 6호출: 정확한 인용·문맥 및 응답 구조 **6/6 통과**.
- 사전 고정한 의미 정답 조건 **0/6 통과**.
- Q-001/Q-002/Q-006은 필드·값·역할·상태·범위의 정확한 집합을 검사했습니다.
- Q-003은 개발 후보의 값/역할 및 운영 AI 확정 금지, Q-004는 명시적 없음, Q-005는 후보 없음을 검사했습니다. Q-003은 전체 필드·상태의 완전한 정답 평가가 아닙니다.
- 같은 6사례로 기존 value+quote 방식을 이번에 호출하지 않았으므로 구조 통과가 계약 변경만의 인과 효과라고 단정하지 않습니다.

## 원인 확인용 추가 1호출
Q-001을 한 번 추가 호출했습니다. 장소 확인·후보 선택의 값은 정확했으나 둘 다 user_action 대신 product_fact로 분류했습니다.
이 호출은 최초 6개 평가를 대체하지 않습니다. 다른 5건의 구체적인 실패 원인까지 확인한 것은 아닙니다. 최초 6개는 원본 응답을 저장하지 않아 후보 수·구조·정답 여부만 남았습니다.

## 리뷰 및 평가 기준 수정
리뷰에서 두 가지 거짓 통과 가능성을 발견했습니다.
1. Q-002의 서로 다른 역할이 같은 원문 위치를 인용해도 평가가 통과할 수 있었습니다.
2. Q-004의 명시적 없음 후보에 잘못된 역할을 붙여도 평가가 통과할 수 있었습니다.

두 회귀 테스트에서 실패를 재현하고 기대 문맥의 위치 및 필드별 역할 검사를 추가했습니다. 전체 191개 테스트가 통과했습니다.
최초 실험의 기준은 scoring_revision=1이며 quote-extraction-cases-v1.json에 보존했습니다. 강화된 revision=2는 실제 API로 재실행하지 않았습니다. 조건이 강화됐으므로 기존 0/6을 성공으로 바꿀 수 없으며 원본이 없어 상세 재채점도 하지 않았습니다. 비교 보고서에는 이 차이를 명시했습니다.

## 게이트와 다음 과제
짧은 6개를 모두 통과한 뒤 전체 문서로 확대한다는 승인 계획에 따라 **전체 7문서 평가는 미실행**입니다. 이번 계약은 실험 옵션으로 남깁니다.
다음 검토 대상은 추출 시 붙이는 역할과 후속 Jev 판정의 경계입니다. 현재 Jev는 추출 역할을 입력으로 검증하므로 잘못된 역할을 자동 수정하지 않습니다. 이를 바꾸려면 별도의 구체적인 명세와 평가가 필요합니다.

SectionAnalyzer(key, model="solar-mini4", jev_merge=True, quote_only=True)

기본 분석기는 변경하지 않았습니다. 기존 실패 원본 7일 정책은 유지하며, 짧은 단독 평가는 원본 응답을 저장하지 않습니다.
