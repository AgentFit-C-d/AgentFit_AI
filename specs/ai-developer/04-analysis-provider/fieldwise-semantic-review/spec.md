# 필드별 의미 검토 실험 명세

## 목적과 근거

AgentFit AI의 선택형 구역 추출·대표 기능 선택 흐름에서 Campfire PRD(547줄)의 기능 후보 128개를 30개로 줄였다. 그러나 `ai`, `database`, `deployment`, `external_integrations`를 함께 검토하는 응답이 8,192 출력 토큰 상한에 닿아 10번째 제공자 호출에서 멈췄다. 의미 검토와 기능 구역 검토가 완료되지 않아 실서비스 승격 근거가 없다. 목표는 모든 필드의 검토 완료를 증명하면서 해당 요청의 출력 범위를 줄이는 것이다.

## 설계 선택

- 선택형 `fieldwise_review=False`를 기본으로 두고, `section_feature_curation=True`인 실험에서만 켠다. 이때 비기능 검토 순서는 기존 A 묶음(`project_name`, `project_type`, `domain`, `frontend`, `backend`) 다음 `ai`, `database`, `deployment`, `external_integrations` 각 1필드다. `features`는 기존 구역별 검토를 유지한다.
- 대안인 B 묶음 출력 상한 증가는 이미 8,192에서 실패했고, 모델 변경은 여러 변수를 동시에 바꾼다. 이번에는 묶음 크기만 변경한다. 전체 원문, 초안 값·근거, Solar Pro 4, 추론 설정, 각 검토 8,192토큰은 유지한다.
- 단일 필드 호출도 전체 원문을 포함하므로 완주를 보장하지 않는다. 미완료·형식 오류·기한 초과는 기존처럼 `needs_confirmation`으로 보류한다.

## 내부 계약과 안전 경계

- 서버는 각 호출의 `checkedFields`가 요청 필드와 정확히 같고 `issues`가 해당 필드만 가리키는지 검증한다. 여섯 고정 묶음의 합집합은 공개 Profile의 10개 필드와 정확히 같다. 구역별 `features` 검토가 끝나야 완료 판정한다.
- 한 검토가 의미 오류를 찾으면 나머지 호출도 수행해 가능한 전체 이슈를 수집하되 자동 완료하지 않는다. 한 호출이라도 불완전하거나 검증에 실패하면 앞서 통과한 필드만으로 완료하지 않는다.
- 구역 추출 최대 7회, core 1회, 대표 기능 선택 최대 1회, 구조 근거 수정 최대 1회, 비기능 의미 검토 5회, 기능 구역 검토 최대 7회로 최대 22회다. 전체 기한은 1,200초다. 기존 선택형 모드 최대 19회와 기본 분석기·공개 Profile·FastAPI 계약은 그대로다.
- 평가 CLI에는 독립 `--fieldwise-semantic-review` 플래그를 추가하고 `--section-feature-curation`을 요구한다. plan에 모드와 최대 22회를 기록한다. 원문·원본 응답·키·Profile 내용은 평가 파일에 기록하지 않는다.

## 검증과 승격 기준

- 모의 테스트에서 여섯 묶음의 정확한 필드 순서, 요청별 스키마, 22회 상한, 마지막 필드·구역 실패 시 자동 완료 금지, 오류 한 건의 확인 필요 전환, 기본 모드 불변을 확인한다.
- Campfire 1건을 같은 모델·문서·정답으로 한 번 평가한다. 검토 완주, 부분 정답 7개, 잘못된 근거, 미평가 값, 선택 기능 30개의 사람 확인 필요성, 호출·시간을 분리해 보고한다. 결과가 유효하지 않으면 다른 문서로 확대하지 않는다.
- 이 튜닝 문서의 부분 정답만으로 일반 정확도나 실사용 가능성을 주장하지 않는다. 독립 새 문서의 사람 검토와 Spring/Frontend 확인 후 저장 E2E는 별도 관문이다.
