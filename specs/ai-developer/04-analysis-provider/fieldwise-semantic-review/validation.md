# 필드별 의미 검토 검증 기록

## 로컬 구현 검증

- `fieldwise_review=True`는 기존 구역 추출·대표 기능 선택 실험에서만 허용한다. 기본값은 `False`다.
- 검토 순서는 기존 A 묶음 다음 `ai`, `database`, `deployment`, `external_integrations` 각 단일 필드, 마지막 `features` 구역 검토다. 서버는 10개 필드 전체 커버리지를 확인한다.
- 7개 기능 구역·대표 기능 선택·근거 수정·필드별 검토의 최대 경로가 22호출 안에서 완료되는 모의 테스트를 통과했다. 마지막 필드·구역 검토가 잘못되면 자동 완료하지 않는다.
- Windows 로컬 전체 `unittest discover -s tests -q`: 690건 통과 (2026-09-29). Linux CI `36560800615` 통과. 독립 리뷰는 GitHub 변경분에서 P1/P2를 찾지 못했지만 리뷰어의 로컬 실행 환경 오류로 테스트를 직접 재실행하지 못했다.

## 실제 튜닝 문서 평가

Campfire PRD(547줄) 1건을 Solar Pro 4로 한 번 평가했다. 안전 결과는 ignored 로컬 `tmp/fieldwise-review-campfire-20260929-1/{plan,results,summary}.json`에 있다. 원문·키·원본 응답·Profile 내용은 저장하지 않았다.

| 항목 | 이번 필드별 검토 | 이전 4필드 묶음 |
|---|---:|---:|
| 후보 / 대표 기능 | 128 / 30 | 128 / 30 |
| 제공자 호출 / 전체 시간 | 14/22 / 627,898ms | 10/19 / 152,343ms |
| 최종 상태 | `needs_confirmation(INCOMPLETE_RESPONSE)` | `needs_confirmation(INCOMPLETE_RESPONSE)` |
| 부분 정답 일치 | 6/7 | 7/7 |
| 잘못된 근거 | 0 | 0 |
| 미평가 값 | 32 | 33 |
| 미정 필드 보존 | 0/1 | 1/1 |

기존 실행은 두 번째 의미 검토 묶음의 8,192토큰 상한에서 멈췄다. 이번에는 A 묶음과 4개 단일 필드 검토가 모두 응답했지만, 첫 번째 기능 구역 검토가 8,192토큰 상한에 닿았다(입력 3,291토큰, 출력 8,192토큰, 해당 호출 약 419초). 일부 의미 검토는 초안 문제를 보고했으므로, 기능 구역 검토만 완주해도 자동 완료가 된다는 뜻은 아니다.

이번 실행에서 부분 정답 하나가 불확정 근거로 바뀌었고 명시적 미정 필드에 값이 들어갔다. 한 번씩 실행한 두 설정의 점수 차이를 일반화하거나 필드 분리의 정확도 개선으로 해석하지 않는다.

## 적용 판단

선택형 실험으로만 유지한다. 다음 병목은 기능 구역 검토의 120줄 범위다. 출력 토큰과 이슈의 유효성을 함께 추적하며 구역을 더 잘게 나누는 별도 실험을 설계한다. 공개 튜닝 문서의 부분 정답만으로 일반 정확도는 입증할 수 없고, 독립 자료·사람 검토·Spring/Frontend 저장 전 확인 E2E가 남아 있다.
