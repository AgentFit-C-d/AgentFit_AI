# 검증 결과
T07 재현3회 모두 개발 검증 이름을 operating_model/confirmed/current로 채택했다. 운영 미정은 별도 tentative 사실로 반환했다. 이전 보관 결과의 구체적 값은 소급 확정하지 않는다.

## 비교
빠른 기준선은 마지막2회에 PROVIDER_RATE_LIMIT이 발생해 별도로 보존했다. 이후2초 간격의 동일13건3회 비교를 수행했다. 평가 대기시간은 elapsed_ms 밖이며 서비스 지연으로 주장하지 않는다.
자세한 통과 수는 summary.json 및 원본 결과에 보존한다.
v1은 개발/운영 목적 우선 판단, v2는 전체 부재/특정 거부와 반복 이름의 context 예시를 보완했다.
- T07/S01 개발용 모델 오분류는 v1/v2 모두3회씩 통과했다.
- S03 전체 AI 부재는 v2에서3회 통과했다.
- S02는 v1/v2 모두3회 실패했다. 추가 진단에서 quote가2번인데 context=null 또는 quote를2번 포함한 context를 선택했다.
- S10의 INVALID_RESPONSE는 간헐적이다. 별도 형식 진단3회에서는 모두 통과해 원인은 미확인이다. 재현되지 않았다고 해결로 처리하지 않는다.

## 범위
전체 unittest282건 통과. 평가 도구와 선택적 프롬프트 실험만 변경했으며 아직 분석기 기본 경로에 통합하지 않았다. 공개 Profile/검증/호출 한도는 유지했다. 성공 원문·추론·키는 보관하지 않았다. 동일 합성 세트의 개선이며 실사용 품질 달성은 아니다.

## 후속
사용자가 repair-evidence-units/spec.md·plan.md의 수정 근거 단위 세분화 실험을 승인했다. 상태 v2를 고정한 채 문장·줄 단위로 나눈 경우와 기존 구역을 비교한다. S10 형식 오류는 관측을 유지한다.
