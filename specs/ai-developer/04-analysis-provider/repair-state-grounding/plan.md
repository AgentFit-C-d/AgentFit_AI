# 계획
1. 수정 결과의 역할/상태/범위 enum과 최종 값 상태를 안전하게 관측한다.
2. 동일 T07을 현재 v2 설정에서3회 재현해 원인을 좁힌다. 이전 실패의 값을 소급 단정하지 않는다.
3. 원인에 따라 원문 우선 판단 규칙을 고정하고, 새 대조 사례(미정/부재/부분 부정/개발 전용/확정)를 사전 등록해 비교한다.
4. 개선이 확인될 때 기본False 옵션으로 통합하여 고정 전체 흐름 및 회귀를 검증한다.
5. 결과·한계·다음 행동을 기록하고 commit/push한다.

## 재현 근거와 비교 고정
T07은3회 모두 개발 검증 이름의 원문 위치7~12를 operating_model/confirmed/current로 분류했다. 같은 응답의 운영 미정 항목은 tentative였다. 역할을 요청 필드로 자동 배정하는 오류로 좁혔다. 원문 역할·상태 우선 규칙과 상반된 AI 예시2개를 고정한다. T07+새12건을 기준선/v2+상태규칙 각3회(39회씩) 비교한다. 미정·부재·부분 부정뿐 아니라 확정 양성 사례를 함께 검증한다.

## 호출 한도 관측
빠른 기준선39회 마지막2회가 PROVIDER_RATE_LIMIT이었다. 실패 결과는 보존한다. 잠시 대기 후 기준선과 변경안 모두 호출 사이2초 간격으로39회씩 실행한다. 간격은 처리시간(elapsed_ms) 밖의 평가용 속도 제한이며 서비스 지연 개선으로 주장하지 않는다. 최초 빠른 기준선을 버리지 않고 진단 참고로 별도 집계한다.

## v2 근거
v1이 T07/S01 개발용 모델 오분류를 막았지만 S03 전체 부재를 negated로 처리했고 S07 부분 부정에서도 병합 실패1건이 남았다. S02는 재진단에서 quote가2번, context=null인 것을 확인했다. 기존 결정 계약을 바꾸지 않고 전체 부재/특정 거부 예시 및 같은 모델의 개발·운영 문맥 구분 예시를 v2에 추가한다. 동일13건3회/2초간격으로 비교한다.
