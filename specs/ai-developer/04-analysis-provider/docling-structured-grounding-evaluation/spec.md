# Docling 구조 문서 근거 결합 평가 명세

## 목적

실사용 가능한 AgentFit Profile 분석을 위해 PDF의 제목·표·페이지 문맥이 후보 추출과 상태 판단까지 보존되는지 확인한다. 지금까지의 LangExtract 18건은 튜닝에 사용한 텍스트 사례이며, Docling native 경로는 표·제목·읽기 순서 모델을 사용하지 않았다. 세 요소를 함께 쓴다는 이유만으로 품질 향상을 가정하지 않는다.

## 선택한 흐름

1. 표준 Docling PDF 파이프라인이 로컬에서 PDF를 구조화한다. 원격 문서 처리 서비스는 끈다. native 결과는 구조화 성공으로 집계하지 않는다.
2. 페이지별 본문을 하나의 정규 텍스트로 연결하고, 코드포인트 기준 `[start,end)`와 페이지 번호를 만든다. 제목과 표가 빠졌거나 페이지가 비었거나 출처가 모호하면 부분 결과를 버리고 실패로 기록한다.
3. 기존 선택형 LangExtract 후보 추출과 `candidate_attributes.anchor`를 정규 텍스트에 적용한다. 서버가 문맥·인용·중복·정확 위치를 재검증한다.
4. 기존 `guard_candidate`가 부정·검토안·확정 상태를 보수적으로 판단한다. 자동 허용 후보의 근거가 한 페이지의 정확한 원문 구간에 들어갈 때만 평가상 확정으로 센다.

## 리뷰 후 평가 보강

- 표 셀의 문자열 존재만으로 표 보존을 인정하지 않는다. Docling 표의 행·열 Markdown 직렬화가 해당 페이지의 정규 텍스트에 연속해서 존재해야 한다. 이 검증이 실패하면 문서 전체를 보류한다.
- 기존 12건의 점수는 골드 필드와 `present` 상태를 규칙에 넣은 조건부 근거 평가로만 표시한다. 모델 자체 판단은 별도 Solar 분류 호출이 후보별 `database/features/other`와 `confirmed/negated/tentative/irrelevant`를 골드 없이 반환하게 하여 측정한다. 필드가 틀린 자동 허용은 오확정과 허용 누락 양쪽에 기록한다.
- 표·제목을 실제로 포함한 고정 합성 PDF 1개에서 네 가지 기능 상태를 추가 검증한다. 세 입력 경로에 같은 PDF와 골드를 쓰되 독립 모델 호출의 변동은 비교 한계로 기록한다.
- 사례의 목표 후보만 점수화한다. 추가 후보의 전수 Profile 정확도와 독립 실제 문서 일반화는 이 실험의 통과 주장에 포함하지 않는다.

## 경계와 실패 처리

- 이 기능은 평가 CLI와 별도 실험 의존성에만 적용한다. 공개 Profile, Spring 계약, 기본 FastAPI/PDF worker는 승격 평가 전까지 변경하지 않는다.
- 실제 PDF는 로컬에서만 변환한다. API 호출은 고정한 합성 문서에만 허용하며 `--live`가 있어야 한다. 원문, 후보, 문맥, 모델 응답, 키는 평가 JSON·일반 로그에 남기지 않는다.
- 표준 파이프라인의 모델 자산 부재, 실패/부분 성공, 표·제목 누락, 여러 페이지에 걸친 근거, 페이지 매핑 불일치, 100쪽/10 MiB/10만 코드포인트 초과는 안전 오류 또는 확인 필요로 구분한다. 실패를 `pypdf`나 native 결과로 조용히 대체하지 않는다.
- 실험의 처리 시간·메모리 최고값을 기록한다. 현행 PDF worker의 15초 제한 안에 들어간다고 가정하지 않는다.

## 자동 평가

- 기존 반복·부정·검토안 18건은 회귀용 튜닝셋으로 유지한다. 별도의 새 합성 사례에 같은 문장 내 여러 대상, 반복 이름, 부정 범위, 검토 후 확정, 철회 후 재확정을 넣고 골드·파일 SHA-256을 최초 호출 전에 고정한다.
- 동일한 합성 PDF를 `pypdf`, Docling native, 표준 Docling으로 각각 변환해 텍스트 누락, 제목·표 구조, 페이지와 문자 위치, 처리 시간·메모리를 비교한다. 포맷별 정규 텍스트가 다르면 각 텍스트의 골드 위치를 별도로 계산하고 동일 오프셋을 재사용하지 않는다.
- 기준선, Docling만, LangExtract만, 규칙만, 세 단계 결합을 동일 골드로 비교할 수 있는 항목만 비교한다. 불가능한 조합은 `미평가`로 남긴다. 결과는 자동 오확정, 허용 누락, 정확 근거 위치, 중복·모호·실패, 카테고리별 건수로 분리한다.
- 자동 오확정 0과 자동 확정 근거 위치 100%는 필수 관문이다. 그 결과만으로 실서비스 가능성을 선언하지 않는다. 독립 실제 문서 골드와 Spring 연동, 처리 한도까지 통과해야 승격을 논의한다.
