# Docling 구조 문서 근거 결합 평가 계획

**범위:** `feature/docling-structured-grounding-evaluation`의 선택형 평가기. 공개 API와 기본 PDF worker는 유지한다.

## 1. 실험 환경과 PDF 구조 검증

- [x] 실험 전용 의존성을 고정하고 표준 Docling 파이프라인의 로컬 실행 가능 여부를 확인한다. 모델 자산 다운로드와 문서 외부 전송을 구분해 기록한다.
- [x] 제목·표·2쪽 페이지가 있는 합성 PDF와 기존 실제 PDF 1건을 로컬에서 변환한다. 텍스트 원문은 저장하지 않고 구조 개수·누락·시간·메모리만 기록한다.
- [x] 실패/부분 성공, 빈 페이지, 표 누락, 다중 페이지 출처가 전체 결과를 보류하는 테스트를 먼저 작성한다.

## 2. 정규 텍스트와 근거 위치

- [x] 표준 Docling 본문 순서와 페이지별 텍스트를 `ExtractedDocument`와 구조 요약으로 변환한다. `export_to_text(page_no=..., traverse_pictures=True)`의 기본 본문 계층을 쓰며 헤더/푸터는 본문으로 강제 포함하지 않는다.
- [x] PDF별 코드포인트 오프셋, 제목·표 포함 여부, 모든 추출 근거의 단일 페이지 포함 여부를 테스트한다.
- [x] 기존 `pypdf`/native/표준 Docling의 같은 PDF 비교를 안전한 수치 결과로 기록했다.

## 3. LangExtract·규칙 결합과 평가

- [x] 새 합성 골드를 반복·부정·검토안의 여러 대상/상태 경계까지 확장하고 SHA-256으로 고정한다. 기존 18건은 회귀셋으로만 쓴다.
- [x] 정규 텍스트에 기존 anchored LangExtract 추출과 규칙 검증을 연결한다. 제공자 호출은 합성 입력과 `--live`에서만 실행한다.
- [ ] 세 PDF 입력 경로의 결합 결과는 같은 골드로 채점했다. 후보/규칙 단계별 제거 실험과 실제 분석기 기준선은 아직 미평가다. 골드 수정 후 수치를 같은 실행으로 제시하지 않는다.

## 4. 검증과 판정

- [x] 전체 로컬 테스트, 실험 의존성의 실제 파서 테스트, Linux CI, 독립 코드 리뷰를 수행했다. 리뷰에서 추가된 세 결함은 아래 5단계로 보완한다.
- [x] 1차 실험 결과와 미평가 항목을 `validation.md`에 기록하고 브랜치를 push했다. 서비스 승격 조건을 충족하지 못해 선택형으로 유지한다.

## 5. 독립 리뷰 후 보완

- [x] 표 셀은 남지만 행·열이 평탄화되는 실패 테스트를 작성하고, 실제 표 Markdown이 페이지에 연속해 있는지 검증한다.
- [x] 골드 필드·상태를 모델 출력 대신 쓰지 않도록 별도 분류 호출과 안전 점수를 구현한다. 잘못된 필드의 자동 허용도 오확정으로 센다.
- [x] 제목·표·확정·부정·검토안이 있는 별도 합성 PDF를 모델 호출 전 SHA-256으로 고정한다. 실제 Docling으로 표 1개·제목 1개와 고유 근거 위치를 확인한다.
- [x] 고정 합성 사례에서 표준 Docling과 두 기존 입력 경로를 라이브 비교하고, 기존 12건의 모델 자체 분류도 평가한다.
- [ ] 최종 로컬 검증·Linux CI를 다시 실행하고 `validation.md`의 결과와 한계를 갱신한 뒤 feature 브랜치에 push한다.
