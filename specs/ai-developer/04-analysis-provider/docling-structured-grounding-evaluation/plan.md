# Docling 구조 문서 근거 결합 평가 계획

**범위:** `feature/docling-structured-grounding-evaluation`의 선택형 평가기. 공개 API와 기본 PDF worker는 유지한다.

## 1. 실험 환경과 PDF 구조 검증

- [ ] 실험 전용 의존성을 고정하고 표준 Docling 파이프라인의 로컬 실행 가능 여부를 확인한다. 모델 자산 다운로드와 문서 외부 전송을 구분해 기록한다.
- [ ] 제목·표·2쪽 페이지가 있는 합성 PDF와 기존 실제 PDF 1건을 로컬에서 변환한다. 텍스트 원문은 저장하지 않고 구조 개수·누락·시간·메모리만 기록한다.
- [ ] 실패/부분 성공, 빈 페이지, 표 누락, 다중 페이지 출처가 전체 결과를 보류하는 테스트를 먼저 작성한다.

## 2. 정규 텍스트와 근거 위치

- [ ] 표준 Docling 본문 순서와 페이지별 텍스트를 `ExtractedDocument`와 구조 요약으로 변환한다. 헤더/푸터 처리와 표 표현을 명시한다.
- [ ] PDF별 코드포인트 오프셋, 제목·표 포함 여부, 모든 추출 근거의 단일 페이지 포함 여부를 테스트한다.
- [ ] 기존 `pypdf`/native/표준 Docling의 같은 PDF 비교를 안전한 수치 결과로 저장한다.

## 3. LangExtract·규칙 결합과 평가

- [ ] 새 합성 골드를 반복·부정·검토안의 여러 대상/상태 경계까지 확장하고 SHA-256으로 고정한다. 기존 18건은 회귀셋으로만 쓴다.
- [ ] 정규 텍스트에 기존 anchored LangExtract 추출과 규칙 검증을 연결한다. 제공자 호출은 합성 입력과 `--live`에서만 실행한다.
- [ ] 기준선과 단계별/결합 결과에서 오확정·누락·위치·보류·실패를 같은 골드로 채점한다. 골드 수정 후 수치를 같은 실행으로 제시하지 않는다.

## 4. 검증과 판정

- [ ] 전체 로컬 테스트, 실험 의존성의 실제 파서 테스트, Linux CI, 독립 코드 리뷰를 수행한다.
- [ ] 실험 결과와 미평가 항목을 `validation.md`에 기록하고 브랜치를 push한다. 서비스 승격 조건을 충족하지 못하면 선택형으로 유지한다.
