# 수정 호출의 근거 문맥 선택지 실험

## 관찰과 가설

한국어 공개 문서에서 `AMBIGUOUS_QUOTE`, `AMBIGUOUS_CONTEXT`, `CONTEXT_NOT_FOUND`, `QUOTE_NOT_IN_CONTEXT`가 수정 호출 뒤에도 남았다. 기존 등장 순서 실험은 모델이 숫자 위치를 계산해야 해서 잘못된 순서·중복이 발생했고, 문장 분할은 약어를 끊었다. **가설:** 서버가 원문에서 해당 인용의 실제 등장마다 짧고 유일한 정확 문맥을 만들어 수정 모델에 제시하면, 모델이 문맥 문자열을 새로 작성할 때보다 근거 검증 실패가 줄어든다.

## 동작

- opt-in `RecoverableSolarAnalyzer(repair_context_options=True)`에서만 사용한다. 기본 Solar·복구형 기본값·FastAPI 계약은 유지한다.
- 최초 필드별 검증 오류 중 위 네 위치 사유에만 후보를 만든다. 모델이 이미 출력한 해당 항목의 `quote`를 원문에서 정확 검색한다. 원문 등장 수가 1~8개이고, 각 등장에 대해 인용을 한 번만 포함하는 유일한 문맥을 240자 이내에서 만들 수 있을 때만 모든 후보를 제공한다. 하나라도 만들 수 없으면 해당 필드의 후보를 생략한다.
- 후보는 `field`/`itemIndex`별 `{quote, context}` 목록이다. 후보 선택·복사 지침을 수정 호출의 시스템 목적에 추가한다. 모델 응답 스키마는 기존 `evidence-v1`이며 서버는 반환된 값·인용·문맥을 기존 검증기로 다시 검사한다. 서버가 후보를 임의로 선택하거나 실패 필드를 확정하지 않는다.
- 원문과 모델 응답을 추가 저장하지 않는다. 안전 평가 산출물은 옵션 사용 여부·제공한 필드와 선택지의 개수, 성공/확인 필요/실패, 안전한 오류 코드·정답 수치만 기록한다.
- 새 API 호출 없음. 기존 최대 6회, 수정 호출 최대 40초, 서비스 60초 경계를 유지한다.

## 검증

1. 중복 이름의 각 등장에 서로 다른 정확 문맥이 생성되고, 한 문맥 안 인용은 1회다. CRLF·한글 오프셋도 안전하다.
2. 유일 문맥을 만들 수 없거나 인용이 원문에 없거나 등장 수가 8개를 넘으면 후보를 제공하지 않는다. 비위치 오류에는 후보를 제공하지 않는다.
3. 실제 수정 요청에 후보와 선택 지침이 들어가며, 응답의 잘못된 문맥은 여전히 거부된다. opt-out 요청은 기존 payload와 동일하다.
4. 사용한 한국어 공개 문서로 튜닝 관찰을 하고, 기존 실행과 확률적 응답 차이를 개선량으로 단정하지 않는다. 실패가 줄어도 새 독립 문서·Spring 확인 흐름 전에는 운영 기본값을 바꾸지 않는다.
