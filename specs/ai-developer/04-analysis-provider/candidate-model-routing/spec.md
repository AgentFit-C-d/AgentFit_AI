# 후보 생성 모델 라우팅 실험

## 문제와 가설

합성 `Q-001`에서 후보 모델은 “장소 확인과 후보 선택”을 하나의 후보로 반환했다. 후보 ID당 판단 하나인 현재 계약에서는 두 동작을 모두 Profile에 담을 수 없다. 기존 프롬프트는 이미 나열된 동작을 각각 인용하라고 요구하므로, 프롬프트 문구 반복보다 후보 생성 모델 교체를 먼저 측정한다.

## 선택형 계약

- `candidate_model`과 `candidate_api_key`를 함께 제공한 경우에만 후보 생성 호출을 NVIDIA 모델로 보낸다. 판단·검토·수정은 기존 Solar 경로를 유지한다. 허용 모델은 현재 NVIDIA 어댑터가 검증한 모델 목록이다.
- 후보 응답은 기존 ID별 스키마, 원문 위치 복원, 120개 상한, 부분 결과 거부를 그대로 통과해야 한다. 후보 모델의 원본 응답·키는 산출물에 남기지 않는다.
- 모든 제공자 호출을 같은 6회·60초 예산과 평가 호출 수에 포함한다. 네트워크 오류·시간 초과는 기존 실패/복구 규칙을 따른다.
- 기본값은 `None`; 기본 분석기, 공개 Profile, 결과 계약, 서버 서비스 경계는 바꾸지 않는다.

## 평가

1. 합성 `Q-001`을 포함한 고정 사례로 원자 후보 회수, 최종 Profile 채점, 오확정, 실패 코드, 호출·지연을 측정한다.
2. 같은 실행의 안전한 위치 메타데이터와 독립 정답을 사용한다. 다른 시점의 Solar 실행과 인과 개선량을 주장하지 않는다.
3. 후보 두 개가 회수되어도 최종 `complete`의 값·근거와 6회·60초 관문을 별도로 검증한다. 하나라도 실패하면 기본값이나 서비스에 승격하지 않는다.
4. 실사용 판정에는 독립 실제 문서, 사람 검증, 사용자 확인 경로가 추가로 필요하다.
