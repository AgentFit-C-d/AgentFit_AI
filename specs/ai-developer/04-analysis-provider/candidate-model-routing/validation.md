# 후보 생성 모델 라우팅 검증

## 구현 범위

`candidate_model`이 지정된 선택형 분석에서만 후보 생성 호출을 NVIDIA 모델로 보낸다. 판단·검토·수정은 Solar이며, 모든 호출을 같은 6회·60초 예산에 포함한다. 기존 후보의 ID별 JSON·원문 검증과 기본 서비스 경로는 유지한다. 평가기는 Solar와 NVIDIA 키를 같은 명시적 `.env`에서 읽되 산출물에는 기록하지 않는다.

## 합성 결과

NVIDIA의 [DeepSeek V4.1 Flash](https://build.nvidia.com/deepseek-ai/deepseek-v4.1-flash)를 후보 생성에 사용했다. Solar만 사용한 앞선 검토 이슈 게이트 실행과 이번 실행은 서로 다른 모델 응답이므로 직접적인 개선량으로 해석하지 않는다.

| 항목 | DeepSeek 후보 생성 20건 | 앞선 Solar 후보 생성 20건 |
| --- | ---: | ---: |
| `complete` / `needs_confirmation` / `failed` | 9 / 5 / 6 | 8 / 6 / 6 |
| 기존 값 채점의 잘못된 자동 확정 | 2 (`N-004`, `N-006`) | 1 (`Q-001`) |
| 검토 이슈 게이트가 확인 상태로 낮춘 사례 | 0 | 0 |
| 관측 60초 초과 | 2 | 2 |
| 최대 제공자 호출 | 6 | 6 |
| 평가 관문 | 실패 | 실패 |

`Q-001` 단독 시험은 3회 호출·8.595초·오확정 0건이었다. [전체 실행 결과](results/deepseek-full20-run1/summary.json)에서 `Q-001`의 후보는 정답 동작 두 곳과 일치하는 별도 구간 `11..16`, `18..23`으로 분리됐고 최종 오확정이 없었다. 그러나 `N-004`는 후보가 존재해도 최초 판단이 잘못됐고, `N-006`도 잘못된 값을 확정했다. 두 사례의 의미 검토가 해당 필드를 지적하지 않았다. `E05`의 후보 호출은 40초 시간 초과였고 전체 60초 초과도 2건이었다.

**판정:** 후보 모델 교체가 특정 복수 동작 사례의 후보 누락을 줄였지만 전체 안전 관문은 실패했다. 기본 분석기나 서비스 API에 적용하지 않는다. 다음 개선은 후보가 맞아도 잘못 판단된 필드와 검토 누락을 다뤄야 한다.

결과 JSON 6개에서 합성 문서 전체 문자열, Upstage·NVIDIA 키, 원본 응답·Profile 필드를 검사해 검출되지 않았다. 실제 문서와 사람 검증, 의미 근거 정확도, 사용자 확인 UI는 검증되지 않았다.
