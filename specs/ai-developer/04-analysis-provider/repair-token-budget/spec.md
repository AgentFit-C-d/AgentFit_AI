# 수정 응답 토큰 예산 비교
목표: low 추론에서 수정 응답 미완료를 줄이면서 기존 시간 한도를 유지할 수 있는지 확인한다.
관측: 전체 흐름 N-004 수정 호출이 completion_tokens=4096/max_tokens=4096, INCOMPLETE_RESPONSE였다.
가설: 응답 예산 부족이 원인 중 하나이며 8192가 완결률을 높일 수 있다. 추론 지연으로40초에 실패할 가능성도 있다.
범위: 단독 평가 CLI에 max_tokens 4096/8192 선택만 추가한다. 서비스 기본 분석기, 공개 Profile, 검증, 전체6회60초는 변경하지 않는다. 성공 응답 원문과 추론은 저장하지 않는다.
판정: N-004를 동일프롬프트·low·원래구역·40초에서 각3회 비교한다. 예산 확대 통과만으로 채택하지 않고 실제 전체 흐름 평가가 필요하다.
