# 원문 기반 수정 경로 구현·실험 결과
## 구현
사용자 승인에 따라 source_repair=True 옵션을 추가했다. 기본 False, 기본 prompt v1 및 기본 검토medium은 유지했다.
문제 필드의 사실을 원문 단위에서 다시 추출하고 정확 인용/context/역할/상태/범위/상한을 검증한다.
검증 완료 후에만 대상 필드를 원자적으로 교체한다. 비대상 필드와 공개Profile을 보존한다.
missing 수정 후 값·근거가 변하지 않거나 재검토가 실패하면 전체 실패다.
최대6회/60초 협력예산과 실패 원본7일 정책을 유지한다. 하드 네트워크 중단 보장은 기존과 동일하게 없다.
## 검증
- 전체 단위 테스트264건 통과.
- 신규 회귀: 후보 밖 동작 복구/동작 분리, 비대상 필드 보존, 부재[]와 미정null 구별, 모호·허구 인용, 잘못된 역할, context 유일성, 중복, 후보총120, 6회/시간예산, 재검토 실패.
- 독립 리뷰 P2 2건: 무변경 수정 응답이 실패 원문에서 누락, 실패 repaired_fields에서 새 단계 누락. 재현 테스트 후 수정.
- 추가로 새 후보와 유지된 사실을 합한120개 상한을 회귀 테스트로 보완.
## 실제 Solar 비교
고정 기존6+새6. Mini4, promptv2, reviewlow, 동일 골드/예산. 각12건1회 순차 실행.
기준선은 진단 보관 수정 전 시작됐다. 해당 수정은 실패 메타데이터만 바꾸며 기존 경로 의미 판단을 바꾸지 않았다.
새 경로 코드 해시는 실행 시작 후 완료 전에 기록했다. 사전 기록이라고 주장하지 않는다.

|결과|기존 경로|원문 수정|
|---|---:|---:|
|최종 골드 통과|4/12|3/12|
|시간 초과|1|2|
|누락 수정 불가/무변경|5|2|
|의미 재검토 거절|1|4|
|검토 응답 구조 오류|1|0|
|모델 검토 통과했지만 골드 불일치|0|1|

- 원문 수정 실행6건(Q001/Q002/Q004/Q006/N002/N005), 최종 정답으로 복구된 사례0.
- Q001/Q002/Q006/N005: 수정 후 값이 생겼지만 재검토에서 features overbroad로 거절.
- Q004/N002: 명시적 외부연동 부재를 수정해도 누락이 그대로라 거절.
- N004: 검토가 이슈 없다고 판단했지만 ai 골드와 불일치. 검토 통과가 정답을 뜻하지 않는다.
- Q003은 원래 초안이 맞았지만 새 경로 실행에서 검토 시간 초과. 최종 통과수 감소를 수정 로직 자체의 인과 효과로 단정하지 않는다.
- 최종 통과3건은 최초 초안부터 맞은 사례다. 이번 변경으로 모델 품질이 개선됐다는 근거는 없다.
- 재검토 직전 초안의 골드 점수는 별도 보존하지 않았다. overbroad 거절이 모두 올바른지/표현 허용 범위 불일치인지 이번 기록만으로 확정하지 않는다.
- 두 실행 exit1. 최초12건 통과 gate 미달이므로 추가2회 반복/실제 문서/공개 최종 corpus 확대하지 않았다.

## 남은 작업
1. 재검토 전후 초안을 메모리에서 같은 골드로 각각 채점해 수정 오류와 검토 오판을 구분한다.
2. 명시적 부재를 빈 후보/미정으로 처리하는 오류를 집중 진단한다.
3. 검토 지연과 잘못된 통과를 함께 개선해야 한다.
새 경로는 opt-in 실험 상태다. 실사용 목표는 미달이고 사람의 수정 부담도 아직 미측정이다.
