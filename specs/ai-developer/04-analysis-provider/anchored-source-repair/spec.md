# 원문 기반 필드 수정 경로 — 승인 대기
## 근거와 범위
현재 수정은 이미 생성된 후보만 재분류한다. 후보에 없는 사실·독립 동작은 복구할 수 없다.
승인된 anchored spec 6항의 '없는 후보를 추가하지 않는다'를 바꾸는 내부 계약 변경이다.
기본 분석기와 공개Profile, Spring/API/DB는 변경하지 않는다. opt-in 실험만 추가한다.
## 구체적 변경
1. 기존 후보 생성→판단→전체 의미 검토는 유지한다.
2. 의미 검토가 문제를 지적한 필드만 수정 대상으로 정한다. 원문 전체와 서버 원문 단위ID/위치, 기존Profile, 이슈를 제공한다.
3. 수정 응답은 대상 필드마다 facts 배열을 반환한다. fact는 unitId, 정확 quote, 구분 context, role, status, scope다.
   기존 후보 ID를 재사용할 필요가 없다. 새 후보·여러 독립 동작을 같은 원문에서 제시할 수 있다.
4. 서버는 대상 필드 집합 일치, 인용의 단위 내 유일성, 필드-역할/상태 제약, 길이/개수/충돌을 검증한다.
   current + confirmed/absent만 채택한다. 부재는 []+근거, 미정/미언급은 null+근거 없음.
   대상 필드의 결과를 원자적으로 교체하고 비대상 필드와 근거는 유지한다.
5. missing으로 지적된 필드가 수정 전과 동일하면 실패한다. 새로운 값도 원문 근거 검증 및 전체 재검토를 통과해야 한다.
6. 수정 실패나 재검토 이슈는 전체 실패로 남긴다. 임의 첫일치·자동값합성·골드 기반 패치·부분성공은 허용하지 않는다.
## 예산과 실패 경로
기존 판단수정1회를 원문필드수정1회로 대체한다. 추출최대2+판단1+검토1+수정1+재검토1=최대6회.
60초 협력 예산 유지. 원문 최대2묶음/각12000자, 후보 총120, 필드별 기존 공개 제한 유지.
구조가 깨진 첫 추출/판단은 이 경로로 우회하지 않는다. 우선 의미 검토 이후의 누락·과도한 범위·역할 오류 수정에 한정한다.
성공 원본 보관 없음, 실패 원본만7일. 보고에는 안전한 메타데이터만 기록한다.
## 영향과 위험
수정 단계가 새 사실 후보를 만들 수 있어 환각·부정 오판 가능성이 늘 수 있다. 서버의 정확 인용만으로 의미 진실성을 증명할 수 없다.
전체 재검토는 필요하지만 이전 실험에서 오통과가 있었으므로 외부 고정 골드로 평가한다.
지연과 토큰 증가 가능성이 있으며 60초 안에 효과가 없으면 채택하지 않는다.
빈 후보에서 검토가 누락을 찾지 못하는 문제는 이 변경만으로 해결되지 않는다. 초안/검토/수정 이후를 따로 측정한다.
개선 효과는 미확인이다.
