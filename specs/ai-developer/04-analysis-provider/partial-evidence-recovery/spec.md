# 필드별 근거 검증 실패 복구

## 관찰한 문제

공개 문서 Mealie·Immich에서 `project_name` 인용 검증이 수정 후에도 실패했다. 다른 필드의 후보가 유효해도 전체 Profile 투영이 중단되어 복구형 분석기가 `failed`를 반환한다. 현재 복구형 스냅샷은 전체 Profile 투영이 성공한 뒤에만 만들어진다.

## 목표와 범위

- 선택형 `RecoverableSolarAnalyzer`에서 전체 투영 전 필드별 구조·근거 검증을 수행한다. 각 필드는 단독 Profile로 기존 `_project`를 통과해야 임시 초안에 포함된다.
- 초기 추출의 일부 필드가 실패해 수정 호출이 시작되기 전에도 검증된 필드를 메모리에 보관한다. 수정 호출 뒤 전체 투영이 또 실패하면 수정된 후보를 필드별로 재검증해 스냅샷을 갱신한다.
- 실패 필드는 값·근거를 버리고 `unresolved`와 `ANALYSIS_UNRESOLVED` 질문으로 보낸다. 검증된 제안값도 의미 검토가 완료되지 않았다면 `REVIEW_UNAVAILABLE` 확인 질문을 요구한다.
- 유효한 비 null 필드가 하나도 없으면 기존처럼 `failed`다. 모든 필드가 검증되고 의미 검토까지 통과하면 기존 `complete`다.
- 기본 `SolarAnalyzer`, 공개 Profile/HTTP 형식, 6회 호출·40초 내부 분석·60초 서비스 기한은 변경하지 않는다. 문서·모델 응답을 새로 저장하지 않는다.

## 안전 규칙

1. 각 필드의 구조 검증은 기존 `evidence_to_profile` 및 `validate_profile`을 사용한다. 임의 인용 보정·값 추측·필드 간 근거 차용은 없다.
2. 의미 검토 전에 만들어진 초안은 자동 확정이 아니다. 사용자 확인 전 Spring의 CONFIRMED 저장을 허용하지 않는 기존 복구 모드 계약을 유지한다.
3. 수정 전후 스냅샷은 요청별로 격리한다. 다른 요청의 필드·질문을 섞지 않는다.
4. 실패 원인과 확인 질문은 고정 안전 코드만 노출한다.

## 수용 기준

- 잘못된 `project_name`과 검증 가능한 다른 필드를 가진 후보에서 수정 실패 시 다른 필드만 `suggested`, 이름은 `unresolved`가 된다.
- 수정 호출 자체가 시간 초과해도 초기 검증 필드를 보존한다.
- 검증되지 않은 값만 있으면 `failed`이며, 정상 분석 성공은 기존 `complete`다.
- 서비스 확인 계약 재검증과 전체 테스트를 통과한다. 실제 공개 튜닝 문서 재실험은 효과 관찰일 뿐 독립 검증으로 세지 않는다.
