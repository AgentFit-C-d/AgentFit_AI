# 구현 계획

1. `SolarAnalyzer`에 기본 동작이 없는 초기/수정 후보 관측 훅을 추가한다. 기존 검증과 모델 호출 순서는 유지한다.
2. 복구형 분석기에서 후보의 각 필드를 기존 `_project`로 단독 검증하고 하나의 Profile로 재검증해 메모리 스냅샷을 만든다. invalid 필드 집합도 함께 보관한다.
3. 오류 시 invalid 필드를 `ANALYSIS_UNRESOLVED`로 투영하고, 의미 검토 미완료 제안값에는 `REVIEW_UNAVAILABLE` 질문을 만든다.
4. 가짜 Provider 기반으로 수정 오류·수정 시간 초과·유효 필드 0·정상 성공·요청 격리를 실패 테스트부터 검증한다.
5. 전체 테스트와 FastAPI 내부 계약 테스트 후, 공개 튜닝 문서로 1회 관찰한다. 오확정 여부는 별도로 검토하고 운영 모드 변경은 하지 않는다.
