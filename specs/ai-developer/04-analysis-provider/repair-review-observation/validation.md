# 수정·검토 분리 관측과 예시 실험
## 구현
평가 전용 repair_observation 모듈을 추가했다. 초기 검토 입력/원문 수정 직후/재검토 입력을 메모리에서 같은 골드로 채점한다.
골드를 API에 보내지 않고 필드명·일치 여부·개수만 저장한다. 성공Profile/인용/추론 저장 없음.
scoped patch를 사용하는 단일 프로세스 진단 도구이며 서비스 경로에서 사용하지 않는다. 관측 비용도 기존60초에 포함된다.
예시 프롬프트는 repair_examples=True 옵션으로 수정 호출에만 적용한다. 기본False, 공개Profile/모델/호출상한은 유지한다.
## 회귀 검증
전체269건 통과. 겹치는 별칭의 일대일 채점, 부재/미정/스칼라, 골드 비노출, 정답 수정 후 오거절 분리, 옵션 단계 격리를 검증했다.
## 기존4건 관측
Mini4/v2/reviewlow/source-repairon, 기존 예시 없음. 최종0/4, exit1.
- Q001: 초기/수정 후 모두 한 항목 안에 두 정답 동작을 포함. 정확한 독립 항목0/2. 재검토 시간 초과. 실제 수정 초안 자체가 틀렸음.
- Q002: features 비어 있음에도 검토 통과. 최종 골드 실패. 수정 미실행.
- Q004: 명시적 외부연동 부재가 수정 후에도 누락.
- N004: ai 골드와 다른 초안을 검토가 통과. 수정 미실행.
이번 관측에서 정답인 수정 초안을 검토가 잘못 거절한 사례는 확인되지 않았다. 지난 실행의 거절을 소급해서 정당화하는 근거로 쓰지 않는다.
## 수정 호출만 분리한 비교
null초안+고정 missing 이슈를 제공한 단독 호출이다. 검토 탐지가 정확하다는 가정을 둔 조건이며 전체 분석 점수가 아니다.
같은4건: 기본0/4 → 일반 예시3/4. N004는 여전히 ai 오답.
프롬프트를 바꾸지 않고 새8건과 골드를 먼저 고정해 비교: 기본2/8 → 예시6/8.
예시는 동작 나열/동사 동작/전체부재/미정/개발vs운영을 다른 단어로 보여준다.
새8건 실패: R002 부분 연동 거부와 채택의 구별, R008 다른제품 예시 제외.
두 비교 모두 각1회. 새8건도 개발자 합성 자료이며 실제 고객문서 holdout이 아니다.
## 예시 옵션을 연결한 전체4건 관측
같은4건에서 최종2/4, exit1.
- Q001: 잘못된 최초 초안 → 올바른 수정 → 재검토/골드 통과(29.750초).
- Q004: 부재 누락 → []+근거로 올바른 수정 → 재검토/골드 통과(48.469초).
- Q002: 최초 초안 오답을 검토가 통과시켜 수정되지 않음(28.781초).
- N004: 수정도 오답, 재검토 시간 초과(60.062초).
기존0/4 대비2/4라는 개선 신호가 있으나, 각1회이며 최초 추출/검토의 비결정성 및 지연 영향이 있다.
수정 단계 개선을 확인했지만 실사용 목표 달성/일반화/반복 안정성을 입증하지 못했다. 기본 설정을 바꾸지 않았다.
## 다음
검토의 누락 탐지 실패와 특정 기술 거부/실제 채택·다른제품 예시 구분을 각각 분리해 보완한다.
고정12건 전체/반복 gate와 실제문서, 공개 최종검증, 사람 수정 부담은 아직 미달 또는 미실행이다.
## 재현
저장소 ai_service에서 python -m agentfit_ai.repair_observation --live --output 새경로.
예시군은 --repair-examples 추가. 기존 출력 경로 재사용은 거절된다.
실제 실행에서는 번들Python과 rtk proxy를 사용했다. 키 값은 .env에서만 읽는다.
