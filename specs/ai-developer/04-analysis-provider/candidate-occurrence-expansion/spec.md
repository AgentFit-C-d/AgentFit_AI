# 위치별 후보 확장 — 승인 대기
## 목적과 근거
현재 CANDIDATE_PROMPT_V2는 인용이 unit 안에서 한 번만 등장하도록 요구한다. validate_quotes도 resolve_quote(..., None)를 호출한다. “개발 모델은 Kestrel이다. 운영 모델도 Kestrel이다.”의 quotes=["Kestrel"]이 ANCHORED_CANDIDATE로 거부됨을 로컬 재현했다.
수정 모델에 등장 순서를 계산시킨 실험도 오판과 지연을 남겼다. 이번에는 초기 단계에서 서버가 모든 위치를 후보 ID로 제공한다.

## 변경 계약
- candidate_occurrences=False 기본인 opt-in 옵션이며 prompt_revision=v2에서만 허용한다.
- 추출 응답 units/unitId/quotes 형식은 유지한다. 모델은 같은 문자열을 목록에 한 번만 쓰되 원문 내 반복은 허용한다. 위치·역할·상태는 추출 단계에서 계산하지 않는다.
- 서버가 인용의 정확한 모든 등장 위치를 열거한다. 기존 근거 탐색처럼 중첩 일치도 포함한다. 배치별 전역 start/end/quote 순으로 정렬하여 각 위치에 별도 F ID와 전역 span을 부여한다. 배치 간 start_index를 유지한다.
- 최초 위치 임의 선택이나 부분 생략은 금지한다. 목록의 중복 문자열·없는 인용·공백 인용·누락 unit은 기존대로 거부한다.
- 확장 후 전체120개 한도를 적용한다.121번째가 나오면 SECTION_LIMIT으로 실패하며 부분 성공을 반환하지 않는다. 단위당 인용30개, 원문24000자 한도는 유지한다.
- 판정 입력의 후보에 focus={before,selected,after}, headingPath, 앞뒤 잘림 여부를 추가한다. before/after는 해당 unit 안에서 최대160자씩이며 selected는 정확한 인용이다. 원문 전체도 제공한다.
- 모델은 위치별 문맥을 보고 기존 field/role/status/scope/decision을 후보 ID별로 반환한다. 문자 오프셋이나 등장 순서를 계산하지 않는다. 같은 이름의 개발·과거·예시·현재 운영을 별도 판정한다.
- duplicate는 적격 여부를 판단한 뒤 같은 최종 사실의 중복에만 쓴다. 서버의 역할·상태·중복 선택·충돌 검증은 유지하고 임의로 수정하지 않는다.

## 영향과 한도
초기 후보의 내부 해석과 판정 입력이 바뀌므로 구현 전 확인이 필요하다. 공개 Profile·Spring 계약·저장 정책·기본 모델은 변경하지 않는다.
추출1~2회, 판정1회, 검토1회, 기존 수정·재검토 최대2회로6회/60초를 유지한다. 추가 호출은 없다. 기존 source_repair 흐름은 그대로다. 새 비교에서는 문장 분리와 occurrenceIndex 수정 옵션을 끈다.

## 위험
반복이 많은 문서는120개 한도에 빨리 도달하며 후보·문맥 증가로 토큰과 지연이 늘 수 있다.160자 문맥 밖 조건은 원문 전체와 제목으로 보완하지만 정확도를 보장하지 않는다. 추출에서 빠진 인용은 확장할 수 없다. ID가 정확해도 의미 판단이 틀릴 수 있어 값과 근거 위치를 함께 채점한다.

## 평가 범위
기존 상태13건·위치 대조14건·전체12건은 이미 사용한 튜닝 자료다. 부재 O08의 유효한 [34,50), [24,50) 두 경계는 별도 평가 버전에 사전 허용하고 양쪽 계약에 동일 적용한다. 기존 정답·결과는 보존한다. 문서 전체를 허용하는 단순 포함 검사는 금지한다.
실험 통과만으로 기본값 승격이나 실사용 목표 달성을 선언하지 않는다.
