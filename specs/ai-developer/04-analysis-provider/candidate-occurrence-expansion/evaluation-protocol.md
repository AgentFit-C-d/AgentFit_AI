# 사전 고정 평가 자료 v1
승인 대기 중 서비스 코드나 프롬프트를 변경하지 않고 평가 입력·정답만 준비했다.
evaluation-cases.json은 기존 상태13건과 위치14건, 총27건의 튜닝 자료다. 독립 최종 검증 자료가 아니다. 원본 파일의 SHA256을 기록하고 기존 파일은 수정하지 않았다.

## 두 평가 단계
- 판정만 비교: fixed_extraction_reply는 현재·예시·과거·개발·미정 후보를 포함한 사람이 준비한 인용 목록이다. expected_occurrences는 모든 정확한 위치의 정답이며 필드/역할 판단을 미리 결정하지 않는다. 이 경로는 모델 추출 누락을 측정하지 않는다.
- 전체 흐름: API에는 document만 실제 입력 자료로 주고 모델이 후보를 추출한다. 고정 후보·gold·accepted_evidence_sets·expected_occurrences를 API에 보내지 않는다. gold가 후보 생성에 유출되지 않도록 두 경로를 분리한다.

## 근거 채점
값의 기존 정답 일치와 함께 accepted_evidence_sets 중 한 개 전체와 출력 evidence가 일치해야 한다. 목록은 한 근거의 개별 허용 조각이 아니라 전체 Profile 근거의 대안이다. 없는 필드는 빈 evidence여야 한다. 여러 대안의 span을 섞거나 모두 선택하면 실패다.
O08만 원래 짧은 부재 문장과 현재 정책 접두사를 포함한 문장 두 가지를 사전 허용한다. 예시 문장이나 문서 전체를 포함한 span은 허용하지 않는다. 같은 버전을 모든 비교 조건에 적용한다.
다른 유효 경계가 발견되면 자동으로 점수를 고치지 않는다. 원래 결과와 정답을 보존하고 별도 판정 후 새로운 평가 버전에서 양쪽 조건을 다시 측정한다.

## 검증
자료 생성 시 모든 고정 인용이 원래 unit에 실제 존재함, 모든 허용 span의 범위, O08 두 문장의 정확한 내용, 문서 전체 미허용을 로컬 확인했다. 후보 생성·판정 구현과 실제 API 평가는 승인 후 진행한다.
