# 동일 후보의 검토 모델 비교

## 목적과 고정 조건

이전 goal turn은 코드2063f0b·실제 동일 후보 비교를 완료하여 progress다. 사유 계약만으로는 의미 품질 우위가 확인되지 않았다. 이번에는 이미 구현된 검토 경로에서 모델/해당 모델 어댑터 설정만 바꿔 의미 판정 차이를 측정한다. 제품 코드는 변경하지 않는다.

- 승인 H02 문서와 해시, 병합183개 후보·원래 분류, explicit-v1, reasoned_review=True를 고정한다.
- 모델: z-ai/glm-5.3, moonshotai/kimi-k3. 기존 DeepSeek 사유 결과는 비교 기준으로 사용하되 다른 시점 실행임을 표시한다.
- 각 최대7호출(확정 후보6묶음+원문 커버리지), 출력8192, 요청timeout600초. 재시도·수정·후보 추가 없음. 토큰 상한/요청 오류를 의미 실패와 분리해 기록한다.
- 기존 어댑터 설정 사용: GLM low/temperature0.5/clear_thinking=true; Kimi low/temperature1. 설정이 다르므로 모델 가중치만의 인과 비교라고 부르지 않는다.
- 결과에는 원문·키·모델 응답 전문을 저장하지 않는다. PID·시작시각·호출 단계·종료 상태·후보 ID/위치·사유 enum·집계만 기록한다. 새 파일명을 사용하고 종료되지 않은 실행을 중복 시작하지 않는다.

## 실행 순서·다음 판단

1. preflight에서 승인 원문과 snapshot hash/183개 위치를 확인한다.
2. GLM→Kimi 순서로 전체 검토·최종 Profile 변환을 실행한다. 실패 모드도 저장하고 완료된 실행만 비교한다.
3. 사전16개 관찰, 지정6개 검사, 원문 근거 대조, 자동 완료 여부를 보고한다.
4. 의미 개선 신호가 있는 모델은 반복/다른 문서로 검증한다. 계약 실패 모델은 원인 한 가지를 확인한 후 필요할 때만 설정을 바꾼 별도 실험을 설계한다. 어떤 경우에도 이번 단일 문서 결과로 기본 서비스를 승격하지 않는다.

## GLM 완료 결과와 추가 원문 대조

GLM의7호출은 모델 identity와 응답 계약 검증을 모두 통과했고 finish_reason=stop이었다. 총1,133,914ms, 확인 필요 결과다. 아래는 완료된 GLM 행과 기존 DeepSeek 완료 실행의 비교이며, 유효 출력이 없는 Kimi는 점수 비교에서 제외했다.

GLM의 사전16개 불일치는 C156의 명시된 개인정보 블라인드 동작을 not_product_fact로 제외한 것이다. C165의 MVP 발급 동작은 보존했고 C153/C154의 기대효과는 제외했다.

16개 밖의 원문 대조에서 backend로 남은 C016/C150은 내부/오픈소스 서버 모듈이다. explicit-v1의 백엔드 구현 언어·프레임워크·런타임 정의를 만족하지 않으며 기존 검사 C03도 실패했다. 따라서15/16만으로 모델 채택을 결정하지 않는다. 외부 연동·배포 후보 전체 정확성은 이번 제한 대조로 입증되지 않았다.

37개 기능 표현에는 같은 동작의 별칭·반복·짧은 표현과 구체 동작 표현이 함께 있다. `project_candidate_profile`은 문자열 동일성만 합치고30개를 넘으면 features를 null로 남기므로 기존 검사 C06도 실패했다. 이는 사용자가 요구한 대표 기능30개 이하 구성을 아직 충족하지 못한 상태다. 후보 검토에서 유효한 반복을 오답으로 지우거나 상한을 올리는 방식으로 감추지 않는다. 기존 section-feature-curation 구현의 재사용 가능성과 대표 선택→후보 의미 커버리지 검증을 다음 설계에서 검토한다.

누락 검토는 현재 필드 이름만 반환한다. backend의 누락 지목도 어떤 원문 사실을 말하는지 응답으로는 확인할 수 없다. 따라서 원문에 없는 기술과 실제 누락의 구분은 사유 enum 및 구조 검증만으로 해결됐다고 할 수 없다. 다음 보완 후보는 근거가 있는 누락 주장과 대표 기능 구성이다. Kimi 전송 실패로 이 판단을 보완할 의미 출력은 확보하지 못했다.

## 공식 설정 확인

2026-09-30에 [NVIDIA GLM 문서](https://docs.api.nvidia.com/nim/reference/z-ai-glm-5-3)와 [Kimi 추론 설정 문서](https://platform.kimi.ai/docs/guide/use-reasoning-effort)를 확인했다. 두 모델은 low/high/max를 지원하고 기본은 max다. GLM의 clear_thinking=true 사용과 Kimi의 항상 활성화된 추론을 확인했다. 현재 low는 기존 어댑터 설정을 유지한 비교 조건이며 모델의 최대 품질을 측정한 것이 아니다. 실행 중 설정은 바꾸지 않는다. 시간보다 품질을 우선한다는 사용자 요구에 따라, 결과가 불충분하면 가장 유망한 모델 또는 실패 묶음에서 추론 강도만 높인 별도 검증을 수행한다.

## 후속 한정 검증: GLM 추론 강도

GLM 전체 검토가 완료됐고 의미 오류가 확인됐으므로, 기존1·5번 후보 묶음(각20개)만 low→max로 비교한다. 이는 재시도가 아니라 설정 변경을 명시한2호출 실험이며, 전체 Profile 평가가 아니다. 제품 코드와 기존 드라이버는 변경하지 않는다. 로컬 run-rejection-reason-effort-h02.py의 사전 검증은 exit0으로 통과했다.

- 원문/183개 후보/원래 분류/explicit-v1/사유 계약/GLM temperature0.5/clear_thinking=true/8192출력/600초 timeout은 동일하다. 기존 함수를 네트워크 없는 캡처 transport로 실행해 해당 두 요청을 재구성하고 실호출 transport에서 reasoning_effort만 max로 바꾼다.
- 실행 전 고정 기준6개: C016/C150은 backend에서 제외, C156/C165는 명시된 제품 동작으로 보존, C153/C154는 기대효과로 제외. 기존 low는3/6이다. 기준은 요청에 추가하지 않는다. 그 밖의40개 전체 판단 변화는 별도 기록하고 이6개를 전체 정확도로 부르지 않는다.
- 정확한20개 checked ID·잘못된 ID 부분집합·사유 일대일·모델 identity·완료 응답을 동일하게 검증한다. 길이/계약/전송 실패를 의미 실패로 점수화하지 않는다. 종료 전 원문/모델 응답 전문을 파일에 저장하지 않는다.
- 새 결과 파일 candidate-rejection-effort-h02-20260930-v1.json을 사용한다. 기존 GLM low는 다른 시점1회이므로 단일 결과로 추론 강도의 인과 효과나 반복 안정성을 입증하지 않는다.
- 개선되면 전체 경로와 다른 문서에서 재검증한다. 개선되지 않으면 max가 무효라고 일반화하지 않고 남은 근거/대표 기능 구성 계약의 보완으로 진행한다.
