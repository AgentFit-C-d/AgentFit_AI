# Mini4 + Jev 통합 평가

## 설정
Mini4로 구역 추출/최종 검토, Jev로 후보 통합/수정. 기존 통합 호출을 대체해 최대6회·60초를 유지했다.
이전 Mini4 평가와 원문7개·정답·추출/검토prompt 해시가 같다. Jev prompt 해시는 별도 기록했다. 실제2문서 전송은 기존 승인 범위다.

| 항목 | Mini4 기존 | Mini4 + Jev |
|---|---:|---:|
| 정답 반환 | 0/7 | 1/7 (14.3%) |
| 오답 반환 | 0 | 0 |
| 오류 | 7 | 6 |
| API 호출 수 | 9 | 11 |
| 총 경과 | 67.015초 | 90.469초 |

## 단계별 결과
- ROLE-003: 추출 → Jev 통합 → Mini4 검토 통과, 정답.
- TEXT-SEM-004: 추출과 Jev 통합 통과, Mini4 의미 검토 응답 형식 오류.
- ROLE-001/002/004, MABC, AgentFit: 추출 단계 실패. 이5건은 Jev를 호출하지 않았다.
- Jev 도달2/7건. 통합 구조 검증2/2 통과가 의미적 정확도2/2를 뜻하지 않는다.

## 해석
관측 성공률은0%→14.3%(+14.3%p)지만 같은 추출 모델의 출력도 달랐다. 특히 ROLE-003은 이전에는 추출 단계에서 실패했다. 따라서 개선1건의 원인을 Jev만으로 분리할 수 없다. 반복/동시 교차 실험도 하지 않았다.
실제 문서2개는 여전히 모두 실패했다. 전체 품질 기준 미충족이며 기본 분석기에 적용하지 않는다.

## 고정 합성 후보 보조 검사
ROLE-002 수작업 후보8개를 Jev에 한 번 전달했다. SDK 후보는 wrong_role로 제외했으나 개발 클라이언트는 selected로 남아 서버 SECTION_MERGE 검증에 실패했다.
이 검사는 추출 후보를 직접 구성한 통합 단위 실험이다. 이전 Chat 통합 검사와는 입력에 전체 원문을 추가한 차이도 있으므로 모델만의 비교로 해석하지 않는다.

## 남은 문제
실패6건 중5건이 추출 단계다. 다음 우선순위는 정확한 인용과 구역 누락을 처리하는 추출 구조 보완이다. Jev를 추가하는 것만으로 그 단계의 실패는 해결되지 않는다.
후보별 choice 판정은 전역 선택 제약을 보장하지 않는다. 기존 서버 충돌/중복/역할검증과 최종 의미검토를 유지한다.
빈 후보풀에서는 Jev 호출을 생략하고 null초안을 검토한다. 누락이 발견되면 후보를 생성할 수 없으므로 실패로 종료한다.

## 최종 리뷰
독립 리뷰에서 비정상 거대 확률 정수가 OverflowError로 실패 진단을 벗어나는 P2를 발견했다.
test_huge_probability_is_a_controlled_failure에서 RED를 재현한 뒤 범위검사를 먼저 하도록 수정, 전체179/179 GREEN.

추가 주요 결함 없음. 보류한 테스트 보강: Jev 전용 raw 보관/7번째 호출 거절 전용 테스트. 기존 공통 경로 테스트와 코드 리뷰로 확인했다.
60초는 기존처럼 호출 전후 예산검사이며 강제 wall-clock 중단을 보장하지 않는다.
