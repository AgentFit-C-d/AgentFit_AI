# 구역별 기능 추출 검증

## 코드 검증

- `--section-feature-extraction`은 구역 검토의 모든 선행 옵션을 요구하며, 기본 분석기와 공개 Profile 형식을 바꾸지 않는다. 최대 호출은 18회, 구역별 출력 상한은 4,096토큰이다.
- 첫 실제 실행에서 평가 CLI의 1,200초 설정이 분석기 생성자의 실험 상한 600초와 충돌했다. 구역 추출 모드에만 1,200초를 허용하도록 수정하고 회귀 테스트를 추가했다. 모델 호출은 이 오류가 해결된 뒤에 시작됐다.
- 첫 통합 오류의 분류가 기존 평가 결과에서 소실돼, 첫 단계의 허용 목록 기반 오류 이유만 기록하도록 했다. 문서·응답·키·Profile 내용은 평가 결과에 저장하지 않는다.
- Windows 로컬 전체 `unittest discover -s tests -q`: 670건 통과 (2026-09-29). 마지막 수정 전 커밋 `5cd3804`의 Linux CI는 통과했으며, 최종 수정 커밋의 CI는 별도 확인한다.

## 실제 문서 1건

고정 튜닝 문서 Campfire PRD(547줄)에서 Solar Pro 4를 사용했다. 안전한 결과 파일은 `tmp/section-feature-extraction-campfire-20260929-3/{plan,results,summary}.json`이다.

| 항목 | 새 구역 추출 | 이전 구역 검토 |
|---|---:|---:|
| 기능 청크 | 6개 | 6개 |
| Provider 호출 | 7/18 | 10/12 |
| 상태 | `failed(INVALID_EVIDENCE)` | `needs_confirmation(SEMANTIC_REJECTED)` |
| 최초 불일치 | `SECTION_FEATURE_OVERFLOW` | 의미 검토 이슈 |
| 부분 정답 | 채점 불가 | 2/7 |
| 미평가 값 | 채점 불가 | 3 |
| 실행 시간 | 30,878ms | 213,952ms |

6개 구역의 추출 호출은 모두 반환됐지만, 통합된 고유 기능 후보가 공개 Profile의 30개 상한을 넘었다. 서버는 임의로 항목을 잘라내지 않고 분석을 실패 처리했다. 의미 검토는 시작하지 않았으며 이 실행에서는 정답률을 비교할 수 없다. 별도 분류 계측을 넣기 전에도 동일한 오류 코드로 7호출·30,486ms에 실패했다.

이는 한 튜닝 문서의 관측값이다. 후보가 과다해진 원인이 실제 기능 수인지, 모델의 세부 항목 분할 또는 잘못된 분류인지는 이 안전 집계만으로 확정할 수 없다. 이전 실행과 호출 수·시간 차이를 품질 향상이나 인과 효과로 해석하지 않는다.

## 확대 및 승격 판단

기존 구역 검토 실험의 Campfire 결과가 `needs_confirmation`이어서 나머지 고정 튜닝 문서 4건 전송은 자동 승인 검토에서 거절됐다. 이 실행도 실패했으므로 확대 조건을 충족하지 못한다. 추가 전송을 시도하지 않았다.

이 모드는 선택형으로 유지한다. 30개 상한을 넘는 긴 기획서에서 유효 Profile을 만들지 못했으며, 독립 문서의 사람 검토와 확인 전 저장 금지 E2E도 없다. 다음 설계에서는 구역 후보의 유형별 개수와 과다 분할 여부를 내용 없이 계측하고, 공개 Profile의 상한 안에 어떤 사실을 담을지 결정해야 한다. 임의의 상위 30개 절단은 누락을 감추므로 적용하지 않는다.
