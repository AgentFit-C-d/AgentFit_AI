# 구역별 기능 추출 선택형 실험 명세

## 문제와 가설

원문 선택자 분석기의 Campfire PRD 최근 두 실행은 기능을 포함한 부분 정답 7개 중 2개만 일치했고, 6개 구역의 후속 기능 검토는 모두 유효하게 끝났으나 의미 이슈로 자동 완료되지 않았다. 이전 실행에서 6/7이 나온 적도 있으므로 두 실행만으로 특정 단계의 결함을 확정할 수는 없다. 전체 547줄을 한 번에 읽는 `features` 추출 호출을 120줄 이하의 구역별 호출로 바꾸면, 긴 문서에서 기능 누락의 변동이 줄어드는지 검증한다.

과거 `SectionAnalyzer`는 다른 인용·후보 계약과 모델 통합 호출로 7건 모두 실패했다. 이 실험은 현재 검증된 `source selector`의 줄 ID·selector·role 계약을 사용하고, 서버가 후보를 결정적으로 통합한다. 과거 실험의 성공으로 간주하지 않는다.

## 동작 계약

- `section_feature_extraction=False`가 기본이다. 이 옵션은 `section_feature_review=True`, 원문 선택자·8K 묶음 검토·정확도 우선 평가에서만 켠다. 기본 분석기, FastAPI, 공개 Profile은 변경하지 않는다.
- 서버는 기존 `split_feature_sections`로 원문 1..N줄을 정확히 덮는 최대 7개 청크를 추출 전에 확정한다. 7개 초과면 외부 호출 전에 안전 실패한다. 청크당 최대 120줄, Markdown 상위 제목은 읽기 전용 문맥이며 selector가 가리킬 수 있는 줄은 해당 청크 안뿐이다.
- core 필드 9개는 기존 전체 원문 호출 1회로 추출한다. `features`는 각 청크에서 정확히 1회씩 순차 추출한다. 각 응답은 기존 source selector의 `null`, `confirmed(items)`, `absent` 중 하나이며 서버가 형식·role·lineId·selector를 검증한다. 한 청크라도 호출·구조·근거 검증에 실패하면 일부 기능만으로 자동 완료하지 않는다.
- `confirmed` 항목은 원문 순서대로 합친다. 동일한 값이 여러 구역에 반복되면 서버가 원문에서 먼저 나오는 항목 하나만 보존한다. 값이 서로 다른 항목의 일부 문자열이라는 이유로 합치지 않는다. 통합 후보가 30개를 넘으면 안전 실패한다. `absent`와 `confirmed`가 함께 나오면 충돌로 보류한다. 모두 `null`이면 `features=null`; `absent`만 있으면 `features=[]`와 해당 근거를 유지한다.
- 통합 후 기존 Profile 구조·근거 검증 및 A/B 전체 검토와 구역별 기능 검토를 그대로 거친다. 검토 이슈가 있으면 자동 완료하지 않는다. 기존 근거 수정 호출 1회는 유지하되, 선택형 최대 호출은 1 core + 최대 7 기능 추출 + 1 구조 수정 + 2 A/B 검토 + 최대 7 기능 검토 = 18회다. 평가 전용 전체 기한은 1,200초이고 각 추출·검토 호출의 기존 상한은 유지한다.
- 진단은 단계·청크 번호·호출 수·오류 종류·수치형 토큰과 시간만 저장한다. 원문·원본 응답·키·Profile을 공개 평가 산출물에 저장하지 않는다.

## 검증·중단 기준

- 오프라인 테스트: 청크 밖 selector 거부, 제목 문맥 선택 거부, 여러 청크의 값 통합/정확 중복 제거, 부분문자열 항목 보존, absent 충돌, 30개 상한, 마지막 청크 실패, 18호출, 기본 경로 불변.
- 동일한 Campfire 튜닝 PRD 1건을 선택형으로 실행하여 구역 완주, 7개 부분 정답과 정답 밖 값, 검토 상태를 보고한다. 현재 2/7 두 실행은 반복 변동의 참고치이지 인과 대조군이 아니다. 유효하고 현저한 개선이 있을 때만 추가 문서 전송 승인을 별도로 확인한다.
- 공개 튜닝 문서의 부분 정답만으로는 실사용 가능성을 확정하지 않는다. 독립 실제 문서의 사람 검토와 Spring/Frontend 확인 전 저장 금지 E2E가 끝나기 전에는 기본값으로 승격하지 않는다.
