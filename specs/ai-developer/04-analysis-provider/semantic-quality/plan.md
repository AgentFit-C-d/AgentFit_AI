# 구현·검증 계획안
상태: 구현 전. 검토 항목: 최대 호출3→6과 최종 의미 오류의 분석 실패 처리.

1. 기존 루브릭을 보존하고 실제3문서 강화루브릭을 별도 작성한다. 키워드 포함만으로 통과시키지 않고 추가 오답과 기능 세분화도 검사한다. 애매한 정답만 사용자에게 확인한다.
2. 새 문서가 전달되면 최종 홀드아웃으로 둔다. 미사용 합성 반례를 평가 전 확정한다.
3. 먼저 실패 테스트: 초안 승인/오답거절/null로 숨긴 누락/잘못된 줄·필드·인덱스/검토 인젝션/수정후재검토/초과호출/전체시간초과/실패7일보관.
4. v21 추출 기반에 독립 semantic_review 모듈을 추가한다. 의미 검토와 수정후 검토를 최대6회 상태전이로 통합한다. 자동 문장축약·추측 보정 없음.
5. 전체60초 deadline에서 호출 timeout을 남은 시간으로 제한하고 후속 호출 전 확인한다. 외부 통신 라이브러리의 하드 deadline 보장 범위를 별도 확인한다.
6. 작은 고정 대조 세트에서 v21단독과 검토추가를 비교한다. 잘못된 성공·누락·올바른 초안 오거절·토큰·지연을 측정한다. 효과가 없으면 큰 평가를 반복하지 않는다.
7. 효과가 확인될 때만 전체고정5회반복→미사용합성→미사용실제→NORMAL30개 검증을 진행한다.
8. 검증 코드·SDD·원문없는 보고서를 feature 브랜치에 push한다. 실패를 빼거나 정답을 바꿔 통과시키지 않는다. 품질기준 통과 전 다른 기능/병합으로 넘어가지 않는다.

제약: Solar 유지, 공개 Profile 유지, 비밀정보·실제문서·전체Profile·원본응답 Git 제외.
