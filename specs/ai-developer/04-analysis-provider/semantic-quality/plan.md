# 구현·검증 계획안
상태: 사용자 승인 후 구현·대조 평가 진행. 검토 항목: 최대 호출3→6과 최종 의미 오류의 분석 실패 처리.

1. 기존 루브릭을 보존하고 실제3문서 강화루브릭을 별도 작성한다. 키워드 포함만으로 통과시키지 않고 추가 오답과 기능 세분화도 검사한다. 애매한 정답만 사용자에게 확인한다.
2. 새 문서가 전달되면 최종 홀드아웃으로 둔다. 미사용 합성 반례를 평가 전 확정한다.
3. 먼저 실패 테스트: 초안 승인/오답거절/null로 숨긴 누락/잘못된 줄·필드·인덱스/검토 인젝션/수정후재검토/초과호출/전체시간초과/실패7일보관.
4. v21 추출 기반에 독립 semantic_review 모듈을 추가한다. 의미 검토와 수정후 검토를 최대6회 상태전이로 통합한다. 자동 문장축약·추측 보정 없음.
5. 전체60초 deadline에서 호출 timeout을 남은 시간으로 제한하고 후속 호출 전 확인한다. 외부 통신 라이브러리의 하드 deadline 보장 범위를 별도 확인한다.
6. 작은 고정 대조 세트에서 v21단독과 검토추가를 비교한다. 잘못된 성공·누락·올바른 초안 오거절·토큰·지연을 측정한다. 효과가 없으면 큰 평가를 반복하지 않는다.
7. 효과가 확인될 때만 전체고정5회반복→미사용합성→미사용실제→NORMAL30개 검증을 진행한다.
8. 검증 코드·SDD·원문없는 보고서를 feature 브랜치에 push한다. 실패를 빼거나 정답을 바꿔 통과시키지 않는다. 품질기준 통과 전 다른 기능/병합으로 넘어가지 않는다.

제약: Solar 유지, 공개 Profile 유지, 비밀정보·실제문서·전체Profile·원본응답 Git 제외.

## 구현 결정 및 v24 진단
사용자 승인 후 v21 추출 복원, 검토/수정/재검토와 최대6회 구현. baseline은 semantic_review=False를 명시하고 semantic_reviewed=False로 표시한다.
v24 실호출 검토가 올바른 null에 uncertainty를 붙이고 미정 문서에 missing을 만들어 오거절했다. 실패 원문을 대조해 확인했다.
v25는 추출/모델설정/정답을 유지하고 검토에서 null/[]가 정답인 반례를 추가한다. 코드 리뷰에서 발견한 실패시 repaired_fields 누락은 두 실패 테스트 확인 후 수정한다.
urllib socket timeout과 호출 전후 deadline 검사는 지연 응답을 성공으로 수용하지 않지만, 블로킹 transport를 중간에 중단하는 하드60초 보장을 하지 않는다. 이는 남은 제약이며 완료로 표시하지 않는다.

## 검토 추론 분리 진단과 v26
정답/오답 초안을 고정한 검토 전용 진단에서 none은 정답초안 오거절, medium은2/2(약39초/24초), low는 정답통과·오답시간초과(약11초/40초)를 보였다. 단2초안이며 일반 성능의 증거가 아니다.
v26은 검토 호출만 medium/8192로 변경한다. 추출/수정은 기존none/4096을 유지한다. 실제 호출 설정은 진단과 평가 보고서에 따로 기록한다.
공식 Solar API https://console.upstage.ai/api/chat (2026-09-25 확인): Solar Pro4 none은 추론끔, low~max는 추론켬. 높은 설정은 지연·비용을 늘리고 품질 향상을 보장하지 않는다.

## v27 시간 배분 수정
v26에서 검토의 40초 개별 제한이 전체60초 예산보다 먼저 만료됐다. v27은 추출의40초 상한을 유지하고 검토에 남은 전체시간을 배분한다. 회귀 테스트에서 [40,40,50]초 배분을 확인했다. 전체117테스트 통과. 하드60초 반환 보장은 여전히 미완료다.
