# 의미 품질 검증 설계안
상태: 구현 전 설계안. 날짜: 2026-09-25.
사용자 목적: 추출 품질을 충분히 보완한 뒤 다음 기능 진행.

## 확인한 문제
- v21도 미완성: 기존합성26/26, 역할5/8, 기존실제3/4, README0/2.
- v23은 구조40/40과 별개로 의미24/40. 원문 ID 복원만으로 역할·누락·과다추출을 해결하지 못했다.
- 실제 문서의 기존 루브릭은 필수 개념 포함 중심이므로 추가된 오답을 충분히 검출하지 못한다.
- AgentFit·HandOff·MABC는 이미 튜닝에 사용했다. 새 문서 일반화의 증거로 표현하지 않는다.
- 인용문 존재와 구조 검증만으로 확정 여부/역할/미언급을 검증할 수 없다.

## 범위
Solar Pro4와 공개 Profile10필드, Spring의 최종 저장 책임을 유지한다.
v21 추출 경로를 기준으로 두고 ID 실험은 채택하지 않는다. 복귀 시 이력을 지우지 않고 추출 코드에만 반영한다.
아래는 구현 제안이며 아직 동작하지 않는다.

## 처리 흐름
1. core와 features 추출: 2회.
2. 구조/근거 오류가 있으면 해당 필드만 1회 수정.
3. 별도 Solar 검토 호출이 원문 전체와 초안을 비교. 추출 호출의 설명을 정답으로 신뢰하지 않는다.
4. 의미 오류가 있으면 해당 필드만 1회 수정.
5. 수정 후 구조검증과 의미검토를 다시 수행.
최소3회, 최대6회. 네트워크 재시도 없음. 검토 스키마 오류를 추가 호출로 무한 복구하지 않는다.

## 검토 계약
값의 원문 지원 여부, 역할, 확정/미정/명시적없음, 현재제품/다른제품/가상예시/개발작업 귀속을 확인한다.
이슈는 field, kind, 기존 항목 인덱스(해당 시), 원문 줄 ID로 표현한다.
kind: unsupported, wrong_role, wrong_scope, uncertainty, missing, overbroad, duplicate.
원문의 필수 사실을 초안과 대조해 누락도 검사한다. null로 비우거나 전부 삭제해서 성공 처리하지 않는다.
서버는 검토의 줄ID·필드·인덱스를 검증한다. 응답에 포함된 명령은 실행하지 않는다.
최종 검토에 문제가 남거나 검토 응답이 유효하지 않으면 분석 오류를 반환한다. 거절 초안을 정상 결과로 반환하지 않는다.
같은 Solar의 검토는 오류가 상관될 수 있다. 모델 검토 통과를 무오류 인증으로 표현하지 않고 독립 정답으로 효과를 검증한다.

## 영향
공개 Profile 모양과 DB/HTTP 경계 변경 없음. 실제 호출 상한은3→6, 새 의미 검토 진단 stage·오류 코드 추가.
사용량·지연·호출 수를 전부 합산한다. 최종 거절된 추출 응답도 실패 보관 정책과 맞춰 테스트한다. 실패 원본7일 정책 유지.
기획서의60초 내 결과/실패안내 목표를 유지한다. 전체 deadline을 도입하고 초과는 실패로 집계한다. 비용·지연 증가를 숨기지 않는다.
호출 상한과 실패 의미 변경은 사용자 검토 대상이며 아직 구현하지 않는다.

## 완료 기준
- 과거 루브릭/점수를 보존한다. 강화 루브릭은 별도 버전으로 작성하고 필수/허용/금지항목·근거·null/[]를 명시한다.
- 고정 사례 반복에서 구조·근거 위반, 잘못된 확정, 예시기술 혼입, 없음 혼동, 개발작업 혼입0건.
- 누락과 과도한 문장도 실패. 모든null·빈배열·전체거절은 정확한 추출 성공이 아니다.
- 대상/정답을 호출 전에 고정하고5회 반복한다. 최초성공/수정후성공/실패를 모두 기록한다.
- 미사용 실제 문서와 독립 합성 반례를 검증한다. 새 문서가 없으면 미검증으로 남긴다.
- 기획서의 FACT9개 이상 정확도90%, SEM12개 이상 대상필드 전부정답, NORMAL30개 이상 첫 요청 정상성공95%도 별도 대조한다. 반복본을 서로 다른30개로 세지 않는다.
- 단위 테스트 통과만으로 품질 완료를 선언하지 않는다. 모든 문서에 대한100%는 약속하지 않는다.

## 제외
사용자 수정/API 연동으로 품질 문제를 대체하지 않는다. OpenAI 비교, 배포, 원문 자동절단, 프로젝트별 이름 필터는 추가하지 않는다.
