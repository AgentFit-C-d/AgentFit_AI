## 고정된 작은 대조 평가

합성5개와 튜닝에 사용된 실제2문서의 총7개를 각 모드에서1회 평가했다. 기존 루브릭을 보존하고 MABC 기능 단위·추가 오답 및 AgentFit 개발업무 혼입 검사를 추가했다. 강화 기준은 임시 정답이며 전체 의미 오류를 포괄하지 않는다. 실패를 제외하거나 정답을 사후 변경하지 않았다.

## 검토 설정 진단

ROLE-003 정답/오답 초안을 고정한 별도 진단: none은 정답 오거절, medium은 두 초안 모두 올바르게 판정(약39초/24초), low는 정답 통과·오답 시간 초과(약11초/40초). 이2초안 결과는 설정 선택의 진단 근거일 뿐 품질 승인 근거가 아니다. 원문 없는 probe JSON을 함께 보관했다.

## 구현 검증

- 전체 단위 테스트117/117 통과. 의미 검토 계약, 구조수정→검토→의미수정→재검토 최대6회, 늦은 응답 거절, 수정 성공 원본 미보관, 최종 실패 원본 보관을 검증했다.
- 독립 코드 리뷰에서 발견한 실패시 repaired_fields 누락을 수정하고 회귀 테스트2건을 추가했다.
- 검토 시간 배분 회귀 테스트의 실패를 확인한 뒤 수정했다. 추출40초, 검토는 남은 전체 예산을 사용한다.
- 공개 Profile10필드와 Solar만 사용한다. 원문·전체Profile·응답·키는 Git 보고서에서 제외했다.

## 남은 기준 및 판단

- v27에서도 의미 검토가 features 오답을 승인했고 시간 초과와 INVALID_FEATURE_SPAN이 남았다. 전체 문서 재검토만으로 품질 개선을 입증하지 못했다.
- urllib의 socket timeout과 호출 전후 검사는 하드60초 반환을 보장하지 않는다. 시간 제한 초과를 성공으로 인정하지 않는다.
- 실제3문서 전체 강화 루브릭,5회 반복,미사용 실제문서,NORMAL30개 검증은 미완료다. 작은 비교 효과가 입증되지 않아 큰 평가를 진행하지 않았다.
- 독립 합성12사례는 예약만 했고 호출하지 않았다. 기존 실제문서는 튜닝 노출 상태다.
- FACT90%, SEM대상필드 전부정답, NORMAL첫성공95%를 충족했다는 근거가 없다.
- 다음 설계 검토는 기능 추출의 근거 선택과 짧은 동작 표현을 우선 다룬다. 전체 문서 검토 반복이나 시간 상한 확대는 자동 채택하지 않는다. 현재 실험은 보존하되 병합·운영 적용하지 않는다.

평가 원문과 임시 실제문서 루브릭, 실행 스크립트는 로컬 output/semantic-quality에 남겼다. Git 보고서는 입력 해시·강화 검사·결과만 포함하므로 저장소만으로 실제문서 평가를 완전히 재현할 수 없다.
