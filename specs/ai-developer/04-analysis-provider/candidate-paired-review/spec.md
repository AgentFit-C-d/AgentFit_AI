# 동일 후보 기반 검토 모델 비교

## 목적과 관찰

H02의 최신 후보 분석은 검토를 완주했지만 지정6항목 중4개만 맞았다. project_name은 검토 후 투영에서 사라졌고 backend는 null 기대를 위반했다. 현재 집계에는 실제 backend 후보가 없어 기술 예시 오판인지, 채택한 서버 모듈의 필드 범위·골드 문제인지 구별할 수 없다. 원문에는 두 종류가 함께 있다. 기존 정답을 임의로 고치거나 특정 기술명을 제거하지 않는다.

실사용 가능한 분석을 만들기 위한 선택형 비교다. 추출·분류는 한 번만 실행해 고정하고, 같은 후보를 Solar Pro4와 NVIDIA DeepSeek V4.1 Flash로 각각 검토한다. GLM5.3·Kimi K3도 명시적 CLI 선택으로 같은 경로를 쓸 수 있다. 첫 실제 평가는 Solar/DeepSeek 두 모델로 한정한다. 사용자는 이번 목표의 설계·구현과 NVIDIA 모델 사용을 자율 진행하도록 승인했다.

## 계약

- `review_candidates_separately(..., review_model="solar-pro4", transport=None)`의 기본 경로는 현재와 같다. NVIDIA는 기존 `NvidiaAnalyzer`와 고정 endpoint/모델 허용 목록을 재사용한다. 제공자별 키를 따로 받으며 반환 모델명 검증을 우회하지 않는다.
- 동일 원문·후보·라벨을 메모리에서 공유하되 각 검토에는 deep copy를 전달한다. 호출자는 추출·분류를 다시 실행하지 않는다. 비교 모델의 순서를 기록한다. 원문·원본 응답·Profile 값·키는 저장하지 않는다.
- 20개 이하 후보 묶음, 전체 원문 누락 검토, ID 완전성, 8192토큰·호출당600초를 유지한다. 모델별 기존 추론 설정 차이는 결과에 명시한다. Solar에서만 length의 제한적 분할 복구를 허용한다. NVIDIA의 실패를 Solar로 위장하거나 재시도하지 않는다.
- 검토 후 Profile 생성 코드를 `finalize_candidate_analysis(document, document_id, frozen, labels, review, *, observer=None)`로 분리해 기존 단일 분석과 비교가 같은 로직을 쓴다. 기본 서비스·공개 Profile은 변경하지 않는다.
- 새 비교기는 모델별 상태·부분 정답·검토 호출 진단·후보 ID/원문 위치/필드/상태만 기록한다. 값·인용·주변 문맥은 제외한다. 필드별 검토 전후 확정 수·고유 값 수·200자 초과 여부·투영 null 여부를 기록해 스칼라 충돌과 오류 잔존을 구분한다. 이 진단은 모델 입력에 들어가지 않는다.
- 한 검토 모델 실패 후에도 동일 고정 입력으로 다음 모델을 평가한다. 공통 추출·분류가 실패하면 모든 모델이 비교 불가다. 관측 실패를 분모에서 빼지 않는다.
- 두 키가 원문 또는 문서ID에 포함되면 어떤 API도 호출하지 않는다. CLI는 기존 승인 문서 manifest/hash/비식별 전처리, 명시적 env-file·live, 기존 출력 덮어쓰기 금지를 유지한다. 부분 결과도 안전한 JSON으로 모델별 기록한다.

## 검증·판정

키와 endpoint 분리, 반환 모델 불일치, NVIDIA length 재분할 부재, 부모 복구의 기존 회귀, 동일 입력과 mutation 격리, 앞선 모델 실패 후 진행, 공통 실패·비밀 사전 차단, 동일 최종 투영, 안전 집계를 테스트한다. 실제 H02로 두 검토를 비교하고 남은 후보 위치를 로컬 원문과 대조한다. 부분6항목을 전체 정확도로 부르지 않는다. 하나의 모델이 우수해도 반복·다문서 평가 전에 기본 서비스로 승격하지 않는다.
