# 프로젝트명 추출 안정화 명세
날짜: 2026-09-25. 승인: 사용자의 “안정화 진행해줘”.
브랜치: feature/project-name-stability. 선행: feature/solar-profile-analysis.

## 시나리오
사용자는 문서에 나타난 현재 프로젝트의 이름을 일관된 초안으로 받는다. 불명확한 이름은 null로 유지한다.

## 요구사항
- NS01: 현재 대상 이름과 과거/비교 대상 이름을 구분한다.
- NS02: 명시한 프로젝트명 또는 현재 개발 대상으로 부르는 명칭을 그대로 추출한다. 일반적인 “프로젝트/이번” 설명과 조사는 이름에 포함하지 않는다. 명시적으로 인용한 이름 안의 단어는 보존한다.
- NS03: 후보 이름만 있거나 서로 충돌하고 우선순위가 없으면 null이다. 없음과 근거 정책은 기존 계약을 유지한다.
- NS04: 기존 6건의 사전 정답을 수정하지 않는다. 진단 5회와 최종 고정 반복 평가의 모든 실패를 보존한다. 성공할 때까지 재시도하지 않는다.
- NS05: 새로운 이름 사례 6건을 수정 전에 고정하고 각각 2회 평가한다. 기존 6건도 각각 2회 평가한다. 총24회에서 이름24/24 및 전체 필드24/24를 목표로 하며 실패 시 달성으로 보고하지 않는다.
- NS06: 실측 보고서는 합성 문서에서 확인 가능한 이름의 문서 위치/기대값과의 차이, 안전한 오류와 설정만 보관한다. 운영 문서·원본 응답/키는 기록하지 않는다.

## 범위
외부 Profile/API/DB 계약은 유지한다. 사용자 확인 UI와 저장, PDF/FastAPI 연동, 실패 원본7일 저장은 포함하지 않는다. 전체 운영 품질 보증은 아니다.

## 승인된 추가 요구사항
NS07: 사용자 “내부 응답 구조 개선 진행” 승인. Provider 응답을 필드별 null 또는 non-null value/evidenceQuotes object로 제한하고, 기존 Profile 검증기로 변환한다. 외부 Profile 계약은 유지한다.
