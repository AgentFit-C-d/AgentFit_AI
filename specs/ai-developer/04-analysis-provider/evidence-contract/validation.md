# 공통 근거 계약 검증

브랜치: feature/shared-evidence-contract. 내부 계약 evidence-v1, 최종 프롬프트 profile-v30.

## 구현한 재발 방어

- 숫자 등장 순서·문자위치를 AI가 출력하지 않는다. 모든10필드가 정확 인용·유일한 문맥을 같은 검증기로 처리한다.
- 동일 값 중복, 값과 자기 근거 불일치, 없는 인용, 모호한 반복, 허용되지 않는 상태·역할은 거절한다. 의미상 중복·역할 정답까지 서버가 증명하는 것은 아니다.
- 공통 수정 오류는 필드·항목 번호·고정 사유·일치 횟수만 담는다. 서버가 값이나 근거를 임의 수정하는 fallback은 없다.
- 공개 Profile10필드, 최대6회·전체60초 예산·실패 원본7일 보관 정책을 유지한다. urllib의 하드60초 반환 보장은 여전히 미완료다.

## 코드 검증

전체140테스트 통과. 공통 계약12개 기본 테스트, 문자·CRLF·결합문자·반복 위치24조합 생성 테스트1개, 새 파이프라인6개를 포함한다. 기존 줄번호 계약 테스트는 evidence_contract=False로 명시하여 보존했다.
독립 코드 리뷰에서 짧은 AI 인용이 주변 미확정 문장을 숨기는 P2를 재현했다. 공개 근거 위치는 그대로 두고 확정성 검사에 해당 원문 줄을 사용하도록 수정했으며, 실패→통과와 다른 줄의 확정 사실 보존을 검증했다.

## 고정 실호출 비교

기존7사례(합성5·튜닝 노출 실제2), 기존 정답과 강화 검사를 유지했다. v27은 저장된 결과와 비교하며 동일 시점의 인과 실험은 아니다.
v29는 새 계약 최초 적용, v30은 JSON null/명시적 없음/반복 문맥의 범용 예시와 리뷰 회귀 수정이다.

## 판단과 미완료 범위

공통 근거 검증 체계와 회귀 방어는 구현했다. 단위 통과가 추출의 의미 정확성이나 모든 미래 입력의 무오류를 보장하지 않는다.
최종 고정 평가의 정답·오답·오류를 모두 보존한다. 품질 완료·운영 채택·다음 기능 진행을 선언하지 않는다.
신규 실제문서, 독립 합성12개, 전체5회 반복,NORMAL30개 검증은 미실행이다. 작은 비교에서 전체 기준을 충족하지 못하여 대규모 실험을 반복하지 않았다.
남은 문제는 Solar의 의미 선택 및 검토 판정과 시간 제한이다. 특정 프로젝트명·예외 문구를 추가하는 방식으로 우회하지 않는다.
실제 원문·전체Profile·응답·키는 Git 보고서에 포함하지 않았다. 로컬 실행 스크립트와 실제문서 루브릭은 output/semantic-quality에 남았으며 원문 없는 보고서만으로 실험 전체를 재현할 수는 없다.
