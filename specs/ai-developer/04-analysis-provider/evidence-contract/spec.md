# 공통 근거 계약과 회귀 방어
상태: 검토할 설계안. 사용자 방향: 특정 문서·항목에 한정하지 않고 재발을 줄인다.
## 확인한 원인
- 모델에 정확한 문자열 복사·줄 선택·등장 순서 계산·의미 분류를 동시에 맡기고 있다.
- features와 다른 필드의 근거 구조가 달라 오류 위치와 수정 정보도 일관되지 않다.
- 전체 문서 의미 검토는 오답을 승인할 수 있고60초 예산을 소모한다.
- v28 순번 설명과 진단 강화만으로 MABC 실패를 해결하지 못했다. 같은 형태의 프롬프트 수정을 반복하지 않는다.
## 공통 계약
FR1: 모델은 사실의 의미·역할·확정 여부와 원문 인용을 선택한다. 문자 오프셋과 등장 횟수 계산은 서버 책임이다.
FR2: 모든10필드에 동일한 항목별 근거 구조를 사용한다. 값과 인용을 한 객체에 묶는다. unknown, 명시적 absent, confirmed를 구분한다. 허용하지 않는 필드의 absent 상태는 거절한다.
FR3: 항목은 원문 value, quote, 필요한 경우 정확한 context를 반환한다. 줄id·occurrence 숫자를 모델이 계산하지 않는다. 문서 전체에서 quote가 유일하면 서버가 정확한 위치를 계산한다. 여러 번이면 유일한 context와 그 안의 유일한 quote를 요구한다. 모호하면 실패하고 재선택을 요청한다. 최초 매치 임의 선택·유사 문자열 매칭·자동 축약 금지.
FR4: quote는 value를 연속 문자열로 포함해야 한다. context는 quote를 연속 문자열로 포함해야 한다. 원문에 없는 문구, 떨어진 문자열 조합, 임의 정규화는 거절한다.
FR5: 중복 값·상충 상태·잘못된 역할·미지원 값·근거 누락을 공통 오류 체계로 표현한다. exact 중복은 서버가 거절하며 삭제로 숨기지 않는다. 의미상 중복·제품 귀속·확정성은 별도 평가 대상이다.
FR6: 오류는 field, itemIndex, reason, matchCount 등 최소 구조 정보로 전달한다. 민감 값과 문서는 진단 메타데이터에 넣지 않는다.
FR7: Profile10필드와 Spring 계약, Solar, 최대6회·60초 예산, 실패 원본7일은 유지한다. 검토를 끄거나 실패 초안을 정상 반환하지 않는다.
## 완료 기준
SC1: 여러 역할·필드·배열·문서 형태에 공통 검증기를 적용하고 동일한 오류 의미를 보장한다.
SC2: 반복 인용, 여러 사실 한 줄, CRLF/Unicode, 같은단어 다른맥락, unknown/absent, 가상예시, 문서내명령, 중복·상충 회귀 테스트.
SC3: 모델 호출과 무관한 검증은 고정/생성 입력으로 테스트한다. 실제 의미 성능은 사전 고정 정답으로 별도 측정한다.
SC4: 실패 사례를 합성 회귀로 전환하고 튜닝에 쓰지 않은 평가군을 유지한다. 정답을 실패 후 변경하지 않는다.
SC5: 잘못된 성공·올바른 초안 거절·누락·중복·시간초과·최초/수정후 성공을 따로 집계한다.
SC6: 작은 비교를 통과한 뒤 확대한다. 새로운 실제문서 미제공 상태는 일반화 미검증으로 남긴다.
## 범위와 한계
내부 Solar 응답 계약과 변환기를 변경하는 설계다. 공개API·DB 변경은 없으나 기존 추출 경로 전체에 영향을 주므로 구현 전 확인한다.
근거 위치의 결정적 검증은 의미 정확성을 증명하지 않는다. 신규 구조의 토큰·지연 증가도 비교해야 한다. 모든 미래 입력의 무오류는 보장할 수 없다.
