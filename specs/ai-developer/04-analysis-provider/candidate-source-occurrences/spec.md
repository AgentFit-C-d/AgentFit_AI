# 후보 원문 등장 위치 확장

## 근거

H02의 모호한 anchor 37개 중 35개는 원문에 없었지만 후보 문구 자체는 34개가 원문에 있었다. 주변 인용의 재작성 오류가 유효한 후보까지 막고 있다. 후보별 원문 문맥과 medium 추론의 합성 판정은 16/16이었으므로 원문 위치를 서버가 확정하는 단계를 보완한다.

## 선택형 계약

- `source_occurrences=True`인 후보 우선 분석에서만 적용한다. 기존 원문 위치·라이브러리 정렬·anchor 판정 경로와 비교할 수 있게 기본 옵션은 false다.
- 추출된 candidate의 문구를 그대로 원문에서 찾는다. 해당 문구의 모든 정확한 등장 위치(중첩 포함)를 열거한다. 공백 정규화, 유사 일치, 최초 위치 선택은 하지 않는다.
- 모델이 작성한 anchor와 라이브러리의 단일 정렬 위치는 이 경로에서 위치 선택 근거로 사용하지 않는다. 서버가 각 위치에서 만든 앞뒤 문맥으로 후속 모델이 대상·상태를 판단한다.
- 같은 문구나 동일 span의 반복 제안은 한 번만 보존한다. 원문 start/end 순으로 정렬한 후 안정 ID를 부여한다. 원문에 없는 문구와 비정상 후보는 고정 오류 사유로 보류하고 자동 완료를 막는다.
- 확장 결과는 최대 240개다. 초과하면 부분 결과나 일부 판정을 반환하지 않고 `CANDIDATE_OCCURRENCE_LIMIT`으로 실패한다. 판정은 기존 30개씩 처리하며, 모든 후보와 10개 필드의 검토를 통과해야 자동 완료가 가능하다.
- 이번 비교는 위치 고정 방식 하나의 효과를 확인하기 위해 후보 생성 요청은 유지한다. 검증 후 불필요해진 anchor 생성 요구를 제거하는 후속 작업을 결정한다.

## 검증 기준

- 잘못된 anchor·단일 정렬 위치가 있어도 원문에 실제 있는 모든 위치를 빠짐없이 보존한다.
- 입력 순서·중복이 달라도 같은 후보 문구 집합의 ID·span은 같다. Unicode·CRLF·겹치는 일치·240 경계를 검증한다.
- 없는 문구는 보류, 241개는 모델 판정 전에 실패, 잘못된 의미 검토는 자동 완료 금지다.
- 동일한 실제 추출 결과를 기존 방식과 새 방식으로 메모리에서 비교해 위치 단계 차이를 측정한다. 원문·후보값·응답 원문은 공유 결과에 기록하지 않는다. 의미 정확도는 전체 분석과 별도로 검증한다.
- 최종 승격은 실제 문서의 정확도·오확정·사용자 확인 부담 및 서비스 연동 검증 후 판단한다.
