# 서버 원문 등장 위치 확장 검증

- `freeze_candidate_occurrences`는 원문 정확 일치만 열거한다. 잘못된 anchor나 외부 라이브러리의 단일 위치 제안은 이 모드에서 사용하지 않는다. 같은 span을 중복 생성하지 않고 원문 순서로 ID를 부여한다.
- 원문에 없는 후보를 보류하고, 240개 초과면 판정 API 호출 전에 실패하는 회귀 테스트를 확인했다. 겹치는 일치·Unicode·CRLF·잘못된 주변 인용·중복 후보도 검증했다.
- 평가 CLI의 `--source-occurrences`가 새 경로를 선택하고 안전 결과에 `grounding_mode`를 남긴다. 기존 옵션 없는 경로는 그대로다.
- 로컬 전체 테스트: 818개 실행, 6개 건너뜀, 나머지 통과. diff 공백 검사 통과.
- 승인된 H02 비식별 입력의 동일 추출 결과를 두 위치 고정 함수에 넣었다. 기존 방식은 위치 37개·보류 47개, 새 방식은 위치 138개·보류 3개였다. 기존 위치 중 사라진 것은 0개다. 보류 항목은 약 93.6% 감소했지만 후보 위치 수 증가를 의미 정확도 향상으로 간주하지 않는다.
- 새 전체 분석은 완료됐다. 확인 필요 제안은 4/6 일치, 자동 완료 0/1, 검토 문제 10개였다. unresolved 필드는 project_name, domain, frontend, backend, ai, database, deployment다. 3개 보류 사유는 모두 `source_quote_absent`였다. 위치 고정은 개선됐지만 이전 실행의 4/6보다 최종 제안 일치가 높아지지는 않았다. 이전 실행과 추출 결과가 달라 최종 점수의 인과 비교도 할 수 없다.
- 전체 분석 시간은 약 315초, 실제 API 호출은 추출 2회·판정 5회·검토 1회로 총 8회였다. 원문·후보 문구·모델 원본 응답은 결과 파일에 기록하지 않았다.
- 코드 커밋 `7b757bd`는 원격 push됐고 Linux CI 실행 36611489353이 성공했다.
- 모델 판정·누락·대표 기능 구성·독립 문서·Spring 저장 연동 검증이 남아 있다. 이 구현만으로 실사용 승격을 주장하지 않는다.
