# 구현·검증 계획

1. 기존 안전 지표에서 실패 단계와 `SEMANTIC_REVIEW_INVALID` 세부 사유를 기록하고 비교 기준을 고정한다.
2. 새 검토 응답 스키마·프롬프트·서버 변환기를 테스트 우선으로 작성한다. 항목 ID의 필드 일치, null 대상, 누락 줄, 기존 span→줄 계산, 중복/부분 실패를 검증한다.
3. `AnchoredAnalyzer`에 기본값이 꺼진 선택형 검토 플래그를 추가한다. 기존 검토와 같은 후속 수정·재검토 경로로 변환된 이슈를 전달한다. 최대 6회·60초를 유지한다.
4. 평가기에서 현행/선택형 검토를 같은 합성 20건과 호출당 40초 상한으로 교차 실행한다. 실행 전 자료·코드·프롬프트 해시와 성공 관문을 보존한다. 결과는 안전한 지표만 저장한다.
5. 독립 코드 검토, 전체 회귀 테스트, 결과 보안 점검 후 `validation.md`를 작성한다. 적용 관문에 실패하면 기본값을 유지한다. 기능 브랜치에 관련 파일만 커밋·push한다.
