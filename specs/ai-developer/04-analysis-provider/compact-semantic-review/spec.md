# 의미 검토 응답 계약 안정화 명세

## 문제와 목적

ID별 후보를 전체 Profile에 연결해도 의미 검토 단계에서 시간 초과와 형식 오류가 반복된다. 최근 60초·120초 비교의 형식 오류는 모두 배열 항목 번호 오류(`ARRAY_INDEX`)였고, 제공자 시간 초과는 의미 검토·재검토 호출에 집중됐다. 모델이 중복해서 출력하는 항목 번호·기존 항목의 근거 줄을 줄이고 서버가 원문 위치를 계산하는 opt-in 계약의 효과를 검증한다.

## 선택형 계약

- 기존의 독립 의미 검토는 유지한다. 모델은 현재 Profile의 10개 필드를 모두 검토하되, 응답은 이슈 목록만 반환한다. 이슈가 없으면 빈 목록이다.
- 배열의 기존 항목을 지적할 때 모델은 서버가 부여한 불변 항목 ID를 선택한다. 서버는 그 ID를 현재 Profile의 필드·인덱스에 매핑하고 다른 필드 ID·없는 ID·중복 매핑을 거부한다. 스칼라·명시적 빈 배열·누락 이슈의 대상 ID는 null이다.
- 기존 항목·스칼라·빈 배열의 근거 줄은 모델이 출력하지 않는다. 서버가 이미 검증한 Profile의 원문 근거 span에서 줄 번호를 계산한다. `missing` 이슈는 원문에서 새 사실을 찾는 것이므로 모델이 근거 줄을 지정해야 한다. 누락 근거가 없거나 범위를 벗어나면 실패한다.
- 서버는 변환한 이슈에 현행 `validate_review` 의미 검증을 적용한다. 변환에 실패하면 부분 성공 없이 `SEMANTIC_REVIEW_INVALID`로 처리한다. 공개 Profile, 기존 기본 계약, 6회 호출·60초 제한은 유지한다.
- 선택형 프롬프트는 현재 필드 역할·현재/미정/부재·타 제품/예시 배제 규칙을 유지하면서 응답 지시와 예시를 간결하게 한다. 두 방식의 호출별 상한은 40초로 맞춘다.

## 사전 비교와 판정

- 기존 튜닝 합성 20건에서 현행 의미 검토와 새 계약을 동일 Solar Pro4·ID별 후보·판단 설정으로 교차 실행한다. 전체 Profile 12건의 필드 일치·완전 일치, 다구역 8건의 지정 사실, 오확정, 검토 형식 오류, 단계별 시간 초과, 호출 수·지연을 고정 분모로 보고한다.
- 새 방식의 완전 일치와 지정 사실 회수가 낮아지거나 오확정·검증 오류가 늘면 기본값으로 승격하지 않는다. 시간 초과가 줄더라도 정답 품질 회귀를 허용하지 않는다.
- 합성 자료는 이미 튜닝에 사용됐다. 성공하더라도 새로운 실제 문서에 대한 일반화 성능이나 실사용 가능성을 주장하지 않는다. 결과에는 원문·키·인용·원본 응답을 저장하지 않는다.
