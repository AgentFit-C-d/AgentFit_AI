# 선택형 의미 검토 계약 검증

## 실행

- 합성 20건(전체 Profile 12건, 다구역 8건)을 Solar Pro4로 교차 비교했다. 양쪽 모두 동일 후보·판단 설정, 전체 60초 및 의미 검토 호출별 40초 상한을 사용했다.
- `results/run1/plan.json`에 자료·코드·평가기 해시와 설정을, `results/run1/results.json` 및 `summary.json`에 원문·키·원본 응답을 제외한 지표를 저장했다.
- 선택형 계약은 기본값이 꺼져 있으며 공개 Profile 형식은 바꾸지 않았다.

## 결과

| 지표 | 기존 | 선택형 |
|---|---:|---:|
| 전체 Profile 완전 일치 | 5/12 | 5/12 |
| 다구역 지정 사실 성공 | 0/8 | 1/8 |
| 전체 성공 건수 | 5/20 | 6/20 |
| 의미 검토·재검토 시간 초과 호출 | 8 | 3 |
| 의미 검토 형식 오류 | 1 (`ARRAY_INDEX`) | 3 (`EVIDENCE_LINES`) |
| 검증 계열 오류 | 7 | 11 |
| 오확정 | 0 | 0 |
| 검토 요청 중앙 크기 | 10,520바이트 | 5,046바이트 |
| 검토 제공자 처리 중앙 시간 | 21,984.5ms | 8,640ms |

선택형에서 N-001은 기존 10/10 대신 `ANCHORED_MISSING_CANDIDATE`로 실패했다. E04는 기존 시간 초과 대신 3/3 지정 사실을 회수했다. 선택형의 `EVIDENCE_LINES` 오류는 N-004의 첫 검토와 E06의 재검토, E07의 첫 검토에서 발생했다. 안전 기록에 원본 응답을 남기지 않아 세부 위반 형태는 확인되지 않았다. 기존 방식의 Q-006·E03·E06·E07 관측 시간은 60,062~60,063ms로 설정값을 62~63ms 초과했다. 선택형의 관측 시간은 모두 60초 이하였다.

## 판정과 후속 과제

적용 관문 **실패**: 형식 오류와 검증 오류가 증가했다. `summary.json`의 `observed_60s_limit=false`는 기존 방식의 경미한 관측 초과에도 영향을 받는다. 다른 실패 관문이 있어 판정은 변하지 않는다. 선택형 계약을 기본 분석기로 승격하지 않는다.

다음 실험에서는 비밀·원문을 기록하지 않는 범위에서 `EVIDENCE_LINES`를 `누락 근거 없음`·`기존 항목에 불필요한 줄 지정`·`줄 범위 오류`·`서버 근거 계산 실패`로 나눠 계측한다. 실제 모델 출력의 위반 유형을 확인한 뒤 한 원인만 수정하고 동일 자료로 재평가한다. 이 자료는 튜닝에 사용됐으므로 실제 신규 기획서에 대한 성능 근거로 사용하지 않는다.
