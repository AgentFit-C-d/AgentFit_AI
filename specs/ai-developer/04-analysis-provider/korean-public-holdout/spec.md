# 한국어 공개 문서 독립 평가

## 목적

기존 영어 공개 문서 3건과 재사용한 합성 문서는 현재 모델의 독립 한국어 기획 문서 성능을 입증하지 못한다. 새 한국어 프로젝트 설명 5건을 모델 결과를 보기 전에 고정하고, 값·근거·확인 필요·지연을 최초 1회 채점한다. 이 문서는 실제 사용자 기획서와 같지 않으므로 출시 게이트를 단독으로 통과시키지 않는다.

## 자료

- 서로 다른 공개 GitHub 프로젝트의 한국어 README 5건: 오늘어디, DevConnect 앱, GitFarm, FestMoment, ORDER101.
- 각 파일은 저장소·40자 커밋·경로·SHA-256으로 고정하고 원본이 100,000바이트 이하인 UTF-8인지 확인한다.
- 모델 호출 전에 사람이 읽고 선택한 필드별 별칭과 원문에 정확히 1회 등장하는 5~200자 인용을 기록한다. 일부 필드만 채점하면 `unassessed_values`를 따로 세며 전체 정확도라고 부르지 않는다.
- 처음에는 `partition=heldout`으로 실행한다. 첫 평가 뒤에는 최초 실행 산출물과 해시를 기록하고 `partition=tuning`으로 바꿔 같은 문서의 후속 실행을 독립 검증으로 표시하지 않는다.

## 평가 흐름

1. 기존 `public_holdout`의 검증·채점 함수를 재사용하되, 호출자가 기대하는 partition을 지정할 수 있게 한다. 기본은 현재 `tuning`이다.
2. 기존 평가 CLI에 명시적인 manifest 경로와 기대 partition을 받는 선택 옵션을 추가한다. 경로가 없으면 기존 영어 코퍼스 동작을 그대로 유지한다.
3. 모든 문서를 먼저 다운로드·해시·인용 검증한다. 하나라도 실패하면 모델 호출이나 결과 디렉터리 생성 전에 중단한다.
4. 동일한 `solar-pro4`, 근거 계약, 의미 검토, 40초 내부 기한으로 문서당 한 번 분석한다. 결과는 원문·키·Profile 없이 상태, 점검 수치, 안전 진단 코드만 저장한다.
5. 자료를 다시 쓴 경우 `partition=tuning`으로 재분류한다. 최초 실행도 한국어 공개 README 5건과 부분 정답만 평가했음을 명확히 보고한다.

## 수용 기준

- 잘못된 partition, 중복 ID, 해시·인용 불일치 문서는 호출 전에 거부한다.
- 새 manifest 5건의 모든 원문·정답 인용 검증이 통과한다.
- 기존 기본 CLI·영어 코퍼스 테스트가 변하지 않는다.
- 최초 실행 결과는 문서별 complete/needs_confirmation/failed, 값·근거 점검, 미평가 값, 호출 수, 시간으로 보고하고 독립 검증의 한계를 적는다.
- 전체 테스트와 Linux CI 통과 후 별도 `feature/korean-public-holdout` 브랜치를 push한다.
