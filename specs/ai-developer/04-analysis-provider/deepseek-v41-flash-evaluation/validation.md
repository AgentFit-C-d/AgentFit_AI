# DeepSeek V4.1 Flash 고정 후보 평가

## 설정과 검증
- NVIDIA 엔드포인트에서 최소 합성 요청을 확인했다. 기본 추론 모드는 답변 본문 없이 종료됐고, `chat_template_kwargs.thinking=false`를 적용한 JSON Schema 요청은 HTTP 200·유효 JSON·정답 라벨을 반환했다. 이는 1건의 호환성 검사일 뿐 성능 근거는 아니다.
- 같은 합성 33건·고정 후보·원자 라벨 프롬프트·서버 검증/채점 계약을 사용했다. 정답은 요청에 포함하지 않았다. DeepSeek는 33건씩 2회, Solar는 이전 실행의 동일 계약 33건 1회이므로 동시 교차 비교는 아니다.
- 첫 실행 후 독립 코드 검토에서 공급자 응답의 모델명 검증 누락을 발견했다. 검증 코드를 추가하고 두 번째 33건에서는 모든 성공 응답의 모델명이 요청 모델과 일치하는지 확인했다. 첫 실행은 출처 미검증 결과로 보존한다. 두 실행 중 유리한 하나를 대표값으로 선택하지 않는다.
- NVIDIA 요청: `deepseek-ai/deepseek-v4.1-flash`, strict JSON Schema, 비추론 모드, 4096 출력 토큰, 40초 호출 제한. 기존 Solar 요청과 공급자별 토큰 계산이 달라 토큰 합계는 직접적인 비용 비교가 아니다.
- 회귀 테스트 325건 통과. 원본 응답·추론·키는 결과 파일에 저장하지 않았다.

| 지표 | Solar Pro4 과거 실행 | DeepSeek 1차·출처 미검증 | DeepSeek 2차·출처 검증 |
|---|---:|---:|---:|
| 전체 정답 | 19/33 | 28/33 | 27/33 |
| 일반 값·근거 정답 | 17/31 | 26/31 | 25/31 |
| 명시적 충돌 인식 | 2/2 | 2/2 | 2/2 |
| 추가 대조 6건 정답 | 4/6 | 4/6 | 4/6 |
| 오확정 사례 | 4 | 2 | 2 |
| 서버 의미 검증 실패 | 4 | 1 | 1 |
| 공급자 시간 초과 | 0 | 0 | 1 |
| 지연 중앙값 | 812ms | 3,563ms | 7,906ms |
| 지연 p95 | 6,703ms | 13,047ms | 37,860ms |
| 지연 최대 | 7,140ms | 18,281ms | 40,109ms |

두 실행에서 공통 실패는 S07의 외부 연동 상충 판정 오류, O02·O04의 backend 근거 위치 오류, AC04·AC05의 현재 AI 누락이다. AC04·AC05는 오확정 없이 빠뜨린 사례다. 두 번째 실행에서는 O14가 40초 호출 제한으로 실패했다. 두 실행의 지연 차이가 크며, 동시 교차 비교와 독립 실제 문서 검증은 수행하지 않았다.

## 결정
고정 후보의 단일 호출 품질 개선 가능성을 확인했다. 그러나 오확정 2건, 서버 검증 실패 1건, 대조 6건 중 2건 실패 및 한 차례 시간 초과가 남아 기존 기본값을 변경하지 않는다. 후보 생성부터 전체 파이프라인의 품질과 실제 문서·사용자 수정 부담은 검증되지 않았다.

다음 단계는 남은 실패의 역할/위치/현재성 원인을 분리하고, 동시·반복 비교 및 독립 실제 문서 평가를 계획하는 것이다. NVIDIA 모델 설명과 API 형식은 [모델 카드](https://build.nvidia.com/deepseek-ai/deepseek-v4.1-flash/modelcard) 및 [API 문서](https://docs.api.nvidia.com/nim/reference/nvidia-deepseek-v4_1-flash-infer)를 참고했다.
