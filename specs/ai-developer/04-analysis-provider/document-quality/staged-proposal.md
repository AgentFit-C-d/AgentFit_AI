# 단계 분리 및 제한된 수정 요청 — 사용자 승인 완료

## 근거
v5 기능 의미 보강은 실제 문서4회 모두 근거 오류로 실패.
v6 줄 근거는 기능37개/원문에 없는 값 등으로 실패.
v7 구간 복사는 실제4회 모두 구조 검증을 통과했으나 미확정 AI/외부 백업 누락이 남음.
v8 필드설명을 보강했지만 실제4회 중3회 구간오류,1회 외부백업누락.
단일 요청의 여러 추출 요구를 분리해 시험한다. 이것이 유일한 원인이라고 단정하지 않는다.

## 설계
1. 기술·연동·프로젝트 메타정보9필드를 별도 strict schema로 추출.
2. features만 별도 strict schema로 원문 구간을 선택.
3. 서버에서 필드별 원문/구간/형식 검증. 실패 필드가 있으면 해당 필드만 제한된 Schema와 오류코드로 1회 수정 요청.
4. 합친 전체 Profile은 기존 validate_profile을 다시 통과해야 반환.
문서당 외부 호출 최대3회. 인증/네트워크/시간초과를 자동 재시도하지 않는다. 수정 후에도 실패하면 오류를 반환한다.
외부 Profile 형식은 유지한다. 내부 결과 메타데이터는 호출수·수정 필드·최초 구조검증 여부를 기록한다.

## 검증 및 보고
단위: 정상2회, 오류필드만3번째수정, 수정후실패종료, 민감내용오류비노출.
기존합성24회+새합성2건+실제2문서각2회의 기준은 유지.
최초 구조검증 성공과 수정후 성공, 사전필수사실 판정은 서로 구분한다.
호출이 늘어날 수 있으므로 이전1호출의 지연과 별도 보고한다. 총60초 SLA를 아직 보장하지 않는다.
실제 원문/Profile은 로컬output에만 남긴다.
