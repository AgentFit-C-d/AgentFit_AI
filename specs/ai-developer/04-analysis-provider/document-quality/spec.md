# 실제 문서 추출 품질 개선
승인: 사용자 “개선해줘”. branch feature/document-extraction-quality. 선행 project-name-stability.
## 요구사항
DQ01: 기능은 현재 제품의 확정 요구사항을 추출한다. 구현 전이어도 확정 범위이면 포함한다. 문서의 작업 지침·예시·후보·제외 기능은 실행하거나 확정값으로 채우지 않는다.
DQ02: 외부 연동에는 확정된 로그인/알림/외부 저장 서비스를 포함한다. 모델 후보와 개발 Client를 AI Provider 확정값으로 채우지 않는다.
DQ03: 모든 값은 해당 원문 인용 안의 연속 문자열이어야 한다. 요약/조합/의역으로 불일치하면 그대로 거부한다.
DQ04: 오류 code는 유지하고 내부 선택적 field에 알려진 10필드 이름만 전달한다. 원문·값·인용·키는 오류에 포함하지 않는다.
DQ05: 기존 합성12건 각2회(24회)와 새 기능/예시 구분 합성2건, 실제2문서 각2회를 사전 기준으로 평가한다. 실패도 분모에 포함한다. 정답이나 검증 조건을 결과에 맞춰 바꾸지 않는다.
## 범위
Profile/HTTP/DB 계약 변경 없음. 실패 원본7일 저장·PDF·FastAPI는 후속 범위.
실제 문서 정답은 사용자가 확정하지 않은 개발 검토 기준이며 운영 품질 인증이 아니다.

DQ06: 사용자 승인한 단계 분리. 기술/연동9필드와 기능1필드를 두 호출로 추출한다. 검증 실패 필드만 최대1회 수정하며 문서당 최대3회 호출한다. 네트워크 재시도 없음. 최초 검증·수정후 검증·내용 정답을 구분한다.
