# 계획
1. 오류 필드를 소실하는 AnalysisError 변환에 안전한 field 메타데이터를 추가한다. 회귀 테스트 먼저.
2. 개선 전 실제 AgentFit 문서를 추가1회 진단한다. 첫 평가와 별도 시도이며 과거 실패를 재구성했다고 주장하지 않는다.
3. features 의미(확정 요구사항, 미구현 포함)와 외부 연동 범위를 명시하고, 각 배열 값의 literal 근거를 지시한다. 기존 구조·검증기는 유지.
4. 고정 합성/실제 평가를 수행한다. 실제 입력·추출 Profile은 output 로컬에만 보관하고 Git에는 코드·합성자료·비식별 결과요약만 포함한다.
5. 단위·실측·SDD 교차 점검 후 관련 파일만 commit/push. 자동 merge/deploy 없음.

## 원인 진단 이후 줄 근거 설계
v5 실제4회 모두 실패. HandOff 추가진단의 기능20개 중11개는 원문에 없는 표현이었다. AgentFit은 반복 인용을 선택했다.
Provider 내부 근거를 evidenceLineIds로 바꾸고 서버가 원문 줄의 code-point 범위를 계산한다. 반복 문구는 명시적 줄 id로 구분한다. id는 존재하는 양의정수, 빈 줄/범위 밖/불일치 값은 거부한다.
Profile과 기존 validate_profile 검증은 유지한다. Quote 기반 이전 어댑터는 호환용으로 유지한다. 기능은 짧은 원문 표현으로 복사하도록 지시한다. profile-v6로 구분하고 같은 기준으로 실제4회/합성26회를 평가한다.

## 기능 생성 구조 개선
v6 기능 배열37개를 진단해 기존30개 한도 위반 확인. HandOff도 원문에 없는 짧은 요약을 계속 생성했다.
features는 {spans:[{lineId,startText,endText}],absenceLineIds:[]}로 모델이 원문 구간만 선택한다. 서버가 정확한 부분문자열을 복사하므로 생성된 기능 요약이 값으로 들어갈 수 없다. 줄·앵커 없음/중복/역순·범위/200자/30개 위반은 거부한다. 명시적 없음은 spans=[]와 유효 absenceLineIds를 사용한다.
다른필드 값/근거줄 계약은 유지한다. JSON Schema에도 기존30개/200자 한도를 넣는다. profile-v7로 구분하고 동일사전정답 평가. 외부Profile은 원래 features 문자열배열이다.

## 승인된 단계 분리 실행
사용자 “단계 분리 방식으로 진행” 승인에 따라 staged-proposal.md 구현. profile-v9에서 2회 분리 추출과 최대1회 필드수정을 도입했다. profile-v10은 미정 판단을 해당 항목에 한정하도록 보완한다. profile-v11의 이름 필드 설명 추가는 회귀 개선 효과가 없어 최종 코드에 채택하지 않았다. 이후 diff에서 이름 규칙 축약을 확인해 v4 규칙을 복원한 profile-v12가 최종 버전이다. 전체 품질 기준은 미달하며 validation.md에 기록한다.
