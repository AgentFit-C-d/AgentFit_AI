# Solar Profile 분석 명세

날짜: 2026-09-25. 브랜치: feature/solar-profile-analysis.
선행 기능: feature/profile-validation (아직 main에 병합되지 않아 해당 커밋에서 분기).

## 사용자 시나리오

- US1(P1): 합성 또는 사용자가 제출한 텍스트에서 10개 Profile 값과 근거를 추출하고, 원문 위치를 검증한 초안 후보를 받는다.
- US2(P1): 빈 입력·한도 초과·명확한 Secret·Provider 오류·거절·잘린 응답·틀린 구조·없는/모호한 근거는 안전한 오류로 받는다.
- US3(P1): 모델 출력 전에 작성한 사전 정답으로 실제 분석의 정확성과 실패를 확인한다.

## 요구사항과 인수 기준

- SA01: 텍스트와 문서 ID를 입력받는다. 공백뿐인 문서와 100,000 code points 초과를 호출 전에 거부한다. 명확한 Credential과 현재 API 키가 문서에 있으면 호출하지 않는다.
- SA02: 단일 외부 호출로 Profile 10개 필드와 필드별 원문 인용을 요구한다. 후보·부정·과거/다른 대상·상충·추론만 가능한 값은 null, 명시적 없음만 []로 둔다.
- SA03: 근거 인용이 원문에서 정확히 한 번 나타날 때 code-point start/end로 변환한다. 없음·중복 발생·잘못된 구조는 오류다.
- SA04: 기존 검증기를 통과한 data/sources/evidence/unknownFields만 결과로 전달한다. 결과에는 원문 인용·모델 전체 응답이 없다.
- SA05: 인증·호출 제한·네트워크·timeout·Provider 장애·거절·불완전 응답·구조/근거 오류를 고정 코드로 구분한다. 자동 재시도하지 않는다. 오류와 평가 로그에 내용/키를 출력하지 않는다.
- SA06: 고정된 합성 사례의 기대값을 사전에 기록하고 실제 평가에서 실패와 첫 호출 결과를 모두 보고한다. 실제 평가와 Mock 검증을 구분한다.
- SA07: 반환된 초안은 의미 정확성을 보증하거나 DB 저장 성공을 뜻하지 않는다.

## 제외 범위와 성공 기준

FastAPI HTTP, PDF 추출, Spring Boot 연동과 진단 응답 저장/7일 삭제는 후속 통합 범위다. 원본 응답 보관을 완료했다고 표시하지 않는다.
단위 테스트에서 정상 후보, 입력 거부, 유일 근거·Unicode, 실패 변환, 키 비노출을 검증한다. 합성 6건의 실제 정답 일치 여부를 기록한다. 이 작은 표본은 FACT9/SEM12/NORMAL30 품질 게이트를 대체하지 않는다.
