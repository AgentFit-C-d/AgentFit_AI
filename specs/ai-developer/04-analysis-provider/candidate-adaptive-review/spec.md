# 토큰 한도에 걸린 후보 묶음의 제한적 분할 검토

## 근거와 목적

H02 진단 실행에서 첫 20개 후보 검토는 stop/3125토큰으로 끝났고 두 번째 20개는 length/8192토큰으로 잘렸다. 전체 누락 검토 전의 후보 판단 부담을 줄인다. 입력·모델·추론 설정을 유지하며 실패한 묶음만 같은 원문과 라벨로 재검토한다.

## 계약

- opt-in `adaptive_review=True`, CLI `--adaptive-review`는 `--split-review`를 요구한다. 기본 모델·서비스·Profile은 유지한다.
- 기본 20개 묶음을 먼저 검토한다. Solar 응답이 INCOMPLETE_RESPONSE이고 안전하게 읽은 finish_reason=length일 때만, 후보 수가 5개를 초과하면 5개 이하의 연속 하위 묶음으로 분할한다.
- 모든 하위 묶음의 checkedCandidateIds·wrongCandidateIds를 기존 계약으로 검증한다. 원래 묶음의 부분 응답은 사용하지 않는다. 원래 후보 집합 전체가 하위 묶음에 정확히 한 번씩 포함된다.
- 하위 묶음은 재분할하지 않는다. 하나라도 미완료·시간 초과·계약 오류이면 전체 분석 실패다. 원문 누락 검사, 다른 오류, 다른 모델 응답에는 분할 복구를 하지 않는다.
- Solar pro4, medium, 8192토큰, 호출당600초 유지. 위치 확장 상한240개의 경로에서는 최악12*(1+4)+1=61개 검토 호출이다. 기본은 기존 최대13개다. 실험의 시간·호출 증가를 결과와 함께 기록한다.
- 진단은 parent batch_index 및 sub_batch_index, 후보 수를 기록한다. 실패한 부모의 validated=false는 보존한다. 모든 하위 검토가 유효할 때만 부모에 recovered=true를 기록한다. 실패하면 recovered=false다.
- 원문·응답·정답·키를 저장하지 않는다. 정상 부모는 재검토하지 않는다. 분할로 원래 완료 조건을 완화하지 않는다.

## 검증과 한계

20개 실패→5개씩4개 유효→누락 검사 순서, 정확한 ID 분할·오류 ID 합집합, 하위 실패 시 누락 검사 미실행, 다른 오류와 기본 모드의 재호출 부재를 테스트한다. 승인된 H02로 실제 완주와 최종 정답·호출 진단을 검증한다. 많은 호출·검토 의미 오류·초기 후보 누락·전체 누락 호출의 길이 제한은 남을 수 있다. 자동 완료나 실사용 품질을 선행 선언하지 않는다.

사용자가 이번 목표의 설계·구현 자율 진행을 승인했다.
