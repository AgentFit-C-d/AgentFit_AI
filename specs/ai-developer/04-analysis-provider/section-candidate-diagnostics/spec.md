# 구역 기능 후보 과다 진단 명세

## 문제

구역별 기능 추출은 Campfire PRD의 6개 구역에서 응답을 모두 받았지만 고유 후보가 공개 Profile의 30개 상한을 넘어 `SECTION_FEATURE_OVERFLOW`로 종료됐다. 현재 안전 결과에는 후보의 구역별 분포와 중복 수가 없어 과다 분할, 구역 편중, 실제 기능 수 중 무엇을 우선 확인해야 할지 판단하기 어렵다. DeepSeek 비교는 두 번째 호출에서 시간 초과돼 같은 기준으로 비교할 수 없었다.

## 목표

선택형 공개 문서 평가에서만 구역별 후보의 **숫자 집계**를 남긴다. 원문, 선택 값, 줄 ID, selector, 근거 span, 모델 응답은 저장하지 않는다. 상한 초과 전에 집계가 생성돼 실패 원인을 분석할 수 있어야 한다.

## 계약

- 기존 `section_feature_extraction=True`인 분석 흐름에서 구역 응답 검증·정규화가 끝난 뒤, 통합 결과의 정확 중복 제거와 30개 상한 검사 전에 관측 훅을 호출한다.
- 집계에는 구역별 후보 수(0~30), confirmed/null/absent 구역 수, 통합 전 총 후보 수(0~210), 정확 중복 수(0~210), 고유 후보 수(0~210)만 포함한다. 원문 순서 및 구역의 시작·끝 줄 번호도 저장하지 않는다.
- 관측 훅이 없는 기본 분석기는 기존 결과와 예외를 그대로 유지한다. 집계는 판단·선택·상한에 영향을 주지 않는다.
- 평가기의 안전 결과 행에만 허용된 키와 정수 범위를 검사한 뒤 `section_candidate_counts`를 기록한다. 비정상/미완료 집계는 버린다.
- 30개 초과나 confirmed/absent 충돌 때도 숫자 집계는 남기되, 자동 완료 또는 잘라낸 Profile을 만들지 않는다.
- 공개 Profile, 서비스 API, 제공자 호출 수(최대 18), 시간 상한(1,200초), 결과 파일의 민감 정보 금지 규칙은 변경하지 않는다.

## 검증

- 합성 두 구역에서 정확 중복을 포함한 집계가 계산되고 기존 merge 결과가 동일하다.
- 31개 이상 후보에서 observer는 상한 예외 이전에 호출되며, 오류는 그대로 유지된다.
- 안전 평가 행에는 숫자만 기록되고 값을 포함한 임의 dict와 범위 밖 숫자는 저장되지 않는다.
- 전체 단위 테스트와 Linux CI를 통과한다.
- 같은 Campfire 튜닝 문서 1건을 Solar로 실행해 실제 숫자 분포를 기록한다. 이 수치만으로 정답성·서비스 준비를 주장하지 않는다.

## 범위 밖

- 후보 절단·요약·클러스터링, 30개 상한 변경, 새 질문·확인 UI, 다른 문서 전송은 이번 기능에 포함하지 않는다.
