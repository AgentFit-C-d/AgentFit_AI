# 구역 기능 후보 과다 진단 결과

## 코드 검증

- 서버의 기존 정확 중복 통합·30개 상한·안전 실패 동작을 유지하면서, 통합 직전 숫자 집계 훅만 추가했다.
- 평가 결과는 구역별 개수와 합계만 허용 목록·정수 범위·합계 일관성으로 재검증한다. 선택 값·근거 줄·원문·응답·키는 저장하지 않는다.
- Windows 로컬 전체 `unittest discover -s tests -q`: 674건 통과 (2026-09-29). 최종 커밋의 Linux CI와 독립 리뷰 결과는 별도로 확인한다.
- 독립 코드 리뷰가 평가 분석기 재사용 시 이전 집계가 사전 실패에 남는 문제 1건을 찾았다. 새 분석 시작에 모든 안전 진단 상태를 초기화하고 재현 테스트를 추가했다. 수정 후 전체 674건이 다시 통과했다.

## 실제 튜닝 문서 관측

동일한 Campfire PRD 1건(547줄)을 Solar Pro 4 구역 추출 모드로 다시 평가했다. 안전 결과는 ignored 로컬 `tmp/section-candidate-diagnostics-campfire-20260929-1/{plan,results,summary}.json`에만 있다.

| 항목 | 관측 |
|---|---:|
| 구역별 후보 수 | 30, 30, 30, 4, 30, 4 |
| 합계 / 정확 중복 / 고유 | 128 / 0 / 128 |
| confirmed / null / absent 구역 | 6 / 0 / 0 |
| Provider 호출 / 경과 | 7 / 42,279ms |
| 결과 | `failed(INVALID_EVIDENCE)`, `SECTION_FEATURE_OVERFLOW` |
| 정답 채점 | Profile 생성 전 실패로 불가 |

네 구역이 구역당 30개 응답 상한에 닿았고 정확히 같은 선택 값은 없었다. **단순 중복 제거로 30개 이하에 도달하지 못한다**는 점은 확인했다. 다만 숫자만으로 128개 중 실제 기능 수, 세부 기준의 과분할, 잘못 분류된 설명의 비율은 알 수 없다. 상한에 닿은 구역에는 반환되지 않은 후보가 더 있을 수도 있다.

같은 경로의 DeepSeek V4.1 Flash 시험은 core 111,578ms 후 첫 기능 구역 호출이 120초에서 `PROVIDER_TIMEOUT`으로 끝나 2호출·231,716ms, 채점 불가였다. 이 실패로 DeepSeek의 후보 과다 여부를 판단하지 않는다. 안전 결과는 ignored `tmp/section-feature-extraction-deepseek-campfire-20260929-1/`에 있다.

## 다음 판단

이 실험은 관측 기능이며 분석 품질 개선이나 서비스 승격 근거가 아니다. 다음 단계에서 ‘독립 제품 기능’의 기준을 명시하고, 선택한 후보의 부분 정답 포함 여부와 잘못된 기능 분류를 별도로 검증해야 한다. 128개에서 임의 30개를 자르면 누락을 감추므로 적용하지 않는다. 추가 공개 문서 4건 전송은 이전 자동 승인 검토의 확대 조건을 충족하지 못해 시도하지 않았다.
