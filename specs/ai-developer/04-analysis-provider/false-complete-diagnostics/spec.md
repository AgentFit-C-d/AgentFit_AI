# 오확정 단계 진단: 선택형 내부 실험 명세

## 목적과 판단 범위

복구형 초안 평가의 합성 20건 세 번째 실행에서 `complete`로 반환된 결과 중 `Q-001`, `N-004`가 기존 정답 채점에 어긋났다. 현재 결과 파일에는 최종 점수만 있어 같은 실행의 후보·판단·검토·수정 중 어디서 불일치가 처음 관측됐는지 알 수 없다. 이 기능은 **새로운 단일 실행**의 단계별 관측치를 연결해 다음 개선 대상을 고른다. 과거 실행의 원인을 사후에 확정하거나 모델 품질이 개선됐다고 주장하지 않는다.

진단은 평가 전용 opt-in이다. 기존 `analyze()`와 `analyze_recoverable()`의 반환값, 공개 Profile, Spring 연동, 기본 분석 동작은 유지한다. 진단은 분석 결과를 자동으로 수정하거나 저장 가능 상태로 승격하지 않는다.

## 내부 데이터 흐름

1. 분석기는 기존 후보 생성·판단·의미 검토·수정 과정에서 관측 훅을 호출한다. 기본 훅은 아무 일도 하지 않는다. 진단 평가기가 opt-in 하위 클래스에서 훅을 받아 **한 분석 호출 동안만** 후보 식별자와 구간, 단계별 Profile의 필드 상태·근거 구간, 검토 이슈의 필드·종류를 보유한다. 실패·예외·종료 시 임시 상태를 해제한다.
2. 이미 존재하는 판단 실패·Profile·검토 이슈 훅을 활용하고, 성공한 판단 및 후보 풀 관측에 필요한 최소 훅만 추가한다. 훅은 제공자 요청·응답을 바꾸지 않고 추가 모델 호출도 하지 않는다.
3. 평가기는 같은 호출의 최종 `outcome`, 단계 관측치, 기존 합성 정답을 결합한다. `complete`이며 기존 채점에서 잘못 확정된 필드만 진단 대상으로 삼는다. `needs_confirmation`과 `failed`는 오확정으로 세지 않고 별도 결과로 남긴다.
4. 결과 파일에는 사례 ID, 필드명, 단계명, 후보 ID·구간, 근거 구간, 상태, 오류 코드, 검토 감지 여부와 집계 수치만 쓴다. 원문, 인용문, 추출값, 원본 모델 응답, 프롬프트, API 키, Profile 전체를 기록하지 않는다. 기존 실패 원본 7일 보관 정책을 변경하지 않는다. 보안 검사는 중첩된 결과에도 금지 키·본문 문자열이 없는지 확인한다.

## 단계 판정 계약

`first_observed_divergence`는 인과 원인이 아니라 **기록된 순서에서 최초로 확인 가능한 불일치**다. 평가기는 오확정된 각 필드에 다음 순서로 하나를 기록한다.

- `candidate_gap`: 정답을 뒷받침하는 **독립적으로 지정된 원문 구간**이 있고, 그 구간을 덮는 후보가 전혀 없다. 단순 문자열 검색 결과나 모호한 중복 인용만으로는 이 판정을 내리지 않는다.
- `judgment_mismatch`: 후보에 정답 근거가 있는데 최초 판단 Profile이 정답과 다르거나, 정답이 명시적 부재·금지값으로 정의되어 후보 누락이 적용되지 않으며 최초 판단부터 틀렸다.
- `repair_regression`: 최초 판단 Profile은 해당 필드의 정답을 만족했으나 후속 수정 Profile에서 틀린 값으로 바뀌었다.
- `undetermined`: 정답 근거 위치·필드 대응·중간 Profile 중 필요한 정보가 없거나 여러 해석이 가능하다. 실패를 다른 범주에 억지로 넣지 않는다.

`review_detected`는 `true`, `false`, `null` 중 하나다. 최초 잘못된 Profile 이후 실행된 의미 검토가 해당 필드의 문제를 명시하면 `true`, 검토가 정상 완료됐지만 해당 필드 지적이 없으면 `false`, 검토가 수행되지 않았거나 결과가 유효하지 않으면 `null`이다. 수정 후 새 불일치는 재검토를 기준으로 한다. 첫 불일치 단계와 검토 감지 여부는 별개로 기록한다. 검토가 지적했어도 최종 오확정이면 해당 사례를 진단에서 제외하지 않는다.

합성 정답의 전체 필드와 초점 필드는 기존 채점 의미를 그대로 따른다. 초점 사례의 금지 문자열이 둘 이상의 필드에 걸쳐 필드를 고를 수 없으면 필드별 단계 판정은 `undetermined`다. 값 정답과 독립 근거 주석이 없는 필드는 `candidate_gap`을 판정하지 않는다. 근거 구간의 구조 검증 통과를 의미적 근거의 정답으로 간주하지 않는다.

## 격리, 예산, 오류 처리

- 진단은 새 환경 변수, 서비스 API, 데이터베이스 테이블을 요구하지 않는다. 기존 평가와 동일한 Solar 설정 및 합성 사례를 사용한다.
- 사례당 분석은 한 번만 실행하고, 기존 최대 6회 제공자 호출·설정상 60초 기한을 늘리지 않는다. 관측된 경과 시간이 60초를 넘으면 별도 위반으로 보고한다.
- 관측 훅이나 진단 채점이 분석의 성공·실패를 바꾸지 않아야 한다. 진단 자체가 예상치 못한 형태를 받으면 `undetermined`와 안전한 진단 오류 코드로 남기되 본래 분석 결과를 보존한다.
- 동시 또는 순차 사례의 임시 관측치가 섞이지 않도록 호출 단위 상태를 격리한다. 평가 후 임시 Profile과 후보 풀 참조를 해제한다.

## 검증 및 완료 기준

1. 결정적인 가짜 제공자 응답으로 후보 누락, 최초 판단 오류, 수정 회귀, 검토 누락·감지, 판정 불가를 같은 호출의 관측치로 검증한다. 기본 분석기와 복구형 결과의 기존 계약 회귀도 확인한다.
2. 산출물 검사에서 원문·값·인용문·API 키·원본 응답이 없고, 호출 수가 늘지 않으며 예외 후 관측 상태가 남지 않아야 한다.
3. 기존 합성 20건을 진단 활성화 상태로 한 번 실행해 오확정 필드별 단계와 `undetermined` 수를 보고한다. `Q-001`·`N-004`가 다시 오확정되지 않으면 해당 실행에서 원인을 단정하지 않고, 결정적 재현 테스트와 관측 한계를 보고한다.
4. 결과는 다음 개선 대상을 고르는 근거일 뿐이다. 독립 기획서 검증이 없고 의미적 근거 채점이 불완전하므로, 이 기능만으로 실사용 가능·오확정 해결을 선언하지 않는다.
