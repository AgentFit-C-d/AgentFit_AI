# 오확정 단계 진단 검증

## 실행 범위

- 기존 튜닝에 사용한 합성 20건을 `Solar Pro4`와 복구형 선택 경로로 사례당 한 번씩 분석했다. 독립 기획서 검증이 아니다.
- [run1](results/run1/summary.json)은 최초 판정 규칙의 실행이다. 이 실행에서 후보 하나가 정답 항목 여러 개를 덮는 경우를 잘못 분류하는 문제가 드러났다. 결과 파일과 코드 SHA-256을 보존했다.
- 후보와 정답 항목을 일대일로 대응시키는 규칙을 추가한 뒤 [run2](results/run2/summary.json)를 새로 실행했다. 두 실행은 서로 다른 모델 응답이므로 품질의 전후 개선량으로 비교하지 않는다.

## 관측 결과

| 항목 | run1 | run2 |
| --- | ---: | ---: |
| 평가 건수 | 20 | 20 |
| `complete` / `needs_confirmation` / `failed` | 8 / 6 / 6 | 7 / 3 / 10 |
| 기존 값 채점의 오확정 | 1 (`Q-001`) | 0 |
| 관측 지연 60초 초과 | 4 | 1 |
| 최대 제공자 호출 | 6 | 6 |
| 중앙 관측 지연 | 16.696초 | 9.813초 |
| 평가 관문 | 실패 | 실패 |

run1의 `Q-001`은 최초 규칙에서 `judgment_mismatch`, `review_detected=true`로 기록됐다. 해당 실행의 안전한 결과에는 후보 ID가 하나(`F0001`)이고 정답 기능은 서로 다른 두 개라고 남아 있다. 현재 판단 계약은 후보 하나당 판단 하나만 할 수 있으므로, 개정된 일대일 대응 규칙을 적용하면 후보 용량이 부족하다. run1 결과의 기존 단계 표시는 **개정 전 규칙의 결과**로 보존하며, 과거 실행 파일을 수정하지 않는다. 의미 검토가 해당 필드를 지적했어도 최종 결과는 잘못된 `complete`였으므로 검토 이후 경로 역시 안전 관문을 통과하지 못했다.

run2에서는 `Q-001`이 제공자 시간 초과로 실패했고 `N-004`는 의미 검토에서 거부됐다. 오확정이 재현되지 않았으므로 개정된 후보 용량 판정의 라이브 발생 빈도나 오확정 해결 효과를 주장할 수 없다. 후보 하나가 두 정답 항목을 덮는 결정적 가짜 제공자 사례는 개정 전 실패·개정 후 통과했다.

## 검증과 한계

- `python -m unittest discover -s tests`의 최종 실행에서 **423건 통과**. 새 관측·단계 판정·평가 테스트는 구현 전 실패를 확인한 뒤 통과시켰다.
- 두 실행 모두 20개의 서로 다른 사례를 각 1회 분석했고 사례당 제공자 호출은 최대 6회였다. `run1`의 오확정 1건과 양 실행의 관측 60초 초과 때문에 각 CLI는 관문 실패 종료 코드 1을 반환했다.
- 두 실행의 `plan.json`, `results.json`, `summary.json`을 별도 검사해 API 키·문서 원문·근거 인용·원본 응답·Profile 전체가 없음을 확인했다. 결과의 후보 ID·근거 위치는 숫자 메타데이터다. 기존 실패 원본 7일 정책은 바꾸지 않았다.
- 의미상 올바른 근거 위치를 독립 채점한 자료가 없어 구조 검증 통과를 의미적 정확도로 해석하지 않는다. focus 사례의 목표 외 제안도 채점되지 않았다. 새 문서가 없어 실사용 준비 상태를 판정할 수 없다.

## 독립 코드 리뷰 후 보완

- 구조 검증에 실패한 `complete`는 오확정 0건으로 기록하지 않고 `scoring_status=unscored_invalid_profile`, `false_confirmations=null`로 남긴다. 집계에서 미채점 완료 사례를 별도로 세고 오확정 0건 관문은 실패시킨다.
- 새 실행의 진단 행에는 후보 ID와 후보·정답 근거 구간의 숫자 좌표를 남겨 후보 부족 판정을 재검토할 수 있게 했다. 기존 run1/run2 파일은 당시 코드의 결과로 보존하므로 새 좌표가 없다.
- 전체 단위 테스트를 다시 실행해 **424건 통과**했고 `git diff --check`도 통과했다. 새 Solar 실험은 실행하지 않았으므로 위 run1/run2 수치는 변경 전 관측이다.
- 초점 사례의 오확정 수는 금지어 적중 수, 단계 분포는 필드 수라는 집계 단위를 요약 설명에 명시했다.

## 다음 개선 대상

이번 진단은 모델 튜닝이 아니라 오확정의 관측 지점을 좁히는 도구다. `Q-001`과 같은 복수 기능 문장에서 후보를 항목별로 분리하고, 의미 검토가 오류를 지적한 뒤에도 잘못된 결과가 `complete`가 되는 경로를 막는 설계를 별도 기능으로 검토한다. 그 전까지 이 선택형 경로를 기본 분석기나 서비스 API로 승격하지 않는다.
