# 대표 기능의 쌍별 포함 관계 검토

## 목적과 근거

실사용 목표의 일부로 대표 정리 뒤의 검토 범위를 명확히 한다. H02 역순 실험은9개 대표 중 하나에22개 동작을 묶었고, 기존 검토기는 대표9개 자신을 포함한41개 전부를 미포함으로 지목했다. 제안이 구조적으로 유효해도 대표 선택 품질과 포함 관계 판단은 별도다. 기존 후보의 오분류·후보 누락·Spring 연동까지 이 기능이 해결한다고 주장하지 않는다.

대안은 프롬프트 강조, 자기 자신을 미포함으로 지목하면 응답 전체 실패, 쌍별 관계 검토다. 첫 두 방식은 결정 가능한 판단까지 모델에 맡긴다. 쌍별 검토를 선택하여 서버는 동일 발생 위치의 자기 포함과 명시적인 미대표를 계산하고, 모델은 서로 다른 발생 위치의 관계만 판단한다. 사용자는 이번 목표의 설계/계획/구현 자율 진행을 승인했다.

## 계약과 흐름

1. 기존 `_feature_candidates`와 엄격 `_validate_partition`으로 검토 후features/confirmed와 정규화된 전체 분할을 검사한다. 제안 생성·중복 대표 정규화는 이전 기능을 그대로 사용한다.
2. 각 그룹의 대표 자신은 구조상 포함이다. unrepresentedIds는 구조상 미포함이다. 두 집합은 모델 판단 대상이 아니다. 다른 모든 그룹 구성원은 `{memberId,representativeId}` 관계1개를 가진다. 입력 후보 순서로 관계 목록을 계산한다.
3. 관계0개이면 외부 호출0회다. 관계가 있으면 최대1회 요청하며 원문, 관계에 참여하는 고유 후보와 정확한 관계를 전달한다. 같은 문구라도 다른 발생 위치이면 모델 판단을 거친다.
4. 응답은 정확히 `assessments=[{memberId,representativeId,coverage}]`다. coverage는 `covered`, `not_covered`, `uncertain` 중 하나다. 모든 요청 관계가 정확히1회 있어야 한다. 행 순서는 자유지만 ID쌍은 서버가 지정한 것과 일치해야 한다. 누락/중복/임의쌍/자기쌍/미대표쌍/추가 키/임의 enum은 거절한다.
5. 서버는 기존 curation의 groups/unrepresentedIds를 보존한다. checkedCandidateIds는 모델의 쌍별 결과와 서버 계산을 합친 전체 검증 후보 목록이다. 모델이 모든 후보를 판단했다는 의미가 아니다. uncoveredIds는 미대표와 not_covered/uncertain 구성원을 합친 입력 순서 목록이다.
6. 기존 `validate_feature_curation`을 통해 최종 결과를 재검증한다. 대표 자기 자신이 uncoveredIds에 있는 입력은 불가능한 관계이므로 거절한다. 원래 4개 결과 키와 공개Profile은 그대로다. 미포함/판단 불가는 features 확인 필요이며 기존의 다른 확인 필요 사유를 해제하지 않는다.
7. `curate_reviewed_features`의 두 번째 단계를 새 helper로 대체한다. 이 함수 자체가 실험용 선택 경로이며 HTTP/기본 분석기에는 아직 연결돼 있지 않다. 새 legacy 플래그를 추가하지 않는다. 이전 전체후보 검토 요청을 유지하지 않는다.
8. 대표로 표시되는 텍스트는 선택한 value다. 문맥은 지시 대상/범위/기존 별칭 정체성을 해석할 수 있지만 value에 없는 다른 절의 동작을 더하지 않는다. 조건절이 후속 처리 전체의 기능을 상속하지 않는다. 다르게 표현된 실제 별칭은 계속 포함 가능하다. 이 일반 규칙은 context-probe.md의 고정 비교로 검증한 뒤 반영한다.

## 인터페이스와 상한

- 새 `candidate_feature_relations.py`의 `review_feature_relations(document, frozen, reviewed_labels, partition, key, *, model=MODEL, transport=None, call_trace=None) -> dict`.
- 독립 검토는0~1호출, 전체대표 구성은0~2호출,자동 재시도0. 문서100,000code point,후보240개,대표30개/200code point,출력8192,timeout600초 및 기존 모델 허용 목록을 유지한다.
- 입력과 판정을 수정하지 않는다. 불변 검토 후 반환되는 curation은 독립 사본이다. 선택 대표의 원문 위치를 바꾸지 않는다.
- 진단은 stage=`feature_relations`,candidate_count,relation_count,server_covered_count,unrepresented_count,validated,error 및 기존 제공자 허용 메타데이터다. 유효 응답에 한해 coverage별 개수를 추가할 수 있다. 원문·키·응답·추론·자유 사유는 기록하지 않는다.
- 모델 identity·완료 상태·응답 JSON·민감 정보 검사는 기존 Solar/NVIDIA 파서를 재사용한다. 구조/제공자 실패 시 완성 curation을 반환하지 않는다.

## 수용 기준

- 자기 포함/미대표만 있는 분할은0호출이며 결정 가능한 상태가 정확하다.
- 서로 다른 위치의 같은 문구는 자동 포함하지 않고 명시적 쌍으로 검토한다.
- covered만 포함으로 취급하며 not_covered/uncertain 모두 확인 필요에 남는다. 원문·대표·다른9개필드·입력 labels는 보존한다.
- 잘못된 쌍/누락/중복/자료형/enum/추가 필드/모델 위장/절단/전송 실패는 실패한다. 최종 입력에 자기 자신 미포함 모순을 주입해도 거절한다.
- 원래 H02 v3와 역순 실험의 완료 분할을 각각 고정해 새 검토만 비교한다. 제안 생성은 다시 호출하지 않는다. 원래 분할은6쌍,역순은32쌍이며 총2호출이다. 기존 검토의 대표 자기 모순과 관계 판정을 별도 측정한다.
- 기존 전체899테스트,새 회귀,독립 코드 리뷰,기능 브랜치push,정확한 Linux CI를 확인한다. 실문서 의미 품질은 구조 통과/테스트 개수와 구분한다.

## 실제 평가의 사전 기준

승인된 H02 원문과 완료 snapshot 해시는 기존과 동일하게 검증한다. 41개 확정 기능에 없는C156 같은 선행 누락은 이번 비교에서 복구할 수 없다. H02는 튜닝 문서이며 독립 정답셋이 아니다.

- 원래v3의6관계(C030→C098, C037→C038/C074/C075, C082→C083/C132)는 로컬 원문 감사상 포함으로 판단한다.
- 역순의C009가 대표인21개 비자기 관계는 제출 동작으로 독립 추출/조립/발급/검증을 대표할 수 없어 미포함으로 판단한다.
- 역순C034→C037/C038/C074/C075, C077→C078, C082→C083/C132/C134, C106→C110의9관계는 포함으로 판단한다.
- 역순C080→C081, C126→C129는 추적/검증과 동작/효과 경계의 모호성이 있어36개 지정 판정에서 제외하고 별도 기록한다.
- 총36개의 사전 지정 판단과2개의 모호 관계를 분리한다. uncertain은 정답 일치로 세지 않고 보류로 보고한다. 사전 판정은 모델 프롬프트에 넣지 않는다. 전체 문서 precision/recall로 부르지 않는다.

후속은 잘못된 그룹의 재구성, 기존 의미 분류/근거 누락 보완, 다문서 반복,HTTP/Spring 확인·저장 검증이다. 관계 검토만으로 전체 실사용 목표를 완료 처리하지 않는다.
