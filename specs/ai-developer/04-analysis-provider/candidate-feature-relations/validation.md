# 쌍별 기능 포함 관계 검증 결과

## 현재 판단

쌍별 검토와 문맥 범위 규칙을 선택형 분석 경로에 구현했다. 구조 검증과 로컬 회귀는 통과했다. 고정한 H02의 관계 판단은 개선됐으나 실사용 품질은 아직 충족했다고 판단하지 않는다. 기본 HTTP 분석 경로로 승격하거나 배포하지 않았다.

## 실제 모델 비교

모델은 NVIDIA의 DeepSeek V4.1 Flash이며, 완료된 GLM 검토의 41개 확정 기능과 두 대표 분할을 고정했다. 후보 생성·대표 생성은 재호출하지 않았다. 각 실험은 원래 분할의 6쌍과 역순 분할의 32쌍에 각각 1회씩 호출했다. 38쌍 중 사전에 명확하다고 정한 36쌍을 집계하고 모호한 2쌍은 제외했다.

| 항목 | 이전 전체 후보 검토 | 쌍별 검토 v1 | 문맥 규칙 추가 v2 |
|---|---:|---:|---:|
| 지정 판단 일치 | 27/36 (75.0%) | 29/36 (80.6%) | 34/36 (94.4%) |
| 원래 분할의 일치 | 6/6 | 6/6 | 6/6 |
| 역순 분할의 일치 | 21/30 | 23/30 | 28/30 |
| 잘못된 포함 판단 | 0 | 7 | 0 |
| 유효 관계를 미포함으로 판단 | 9 | 0 | 2 |
| 대표 자신을 미포함으로 판단 | 9 | 0 | 0 |

이전 검토는 역순 후보를 모두 미포함으로 판단했다. 따라서 v2의 잘못된 포함 0건만으로 전체 개선을 설명할 수 없으며, 유효 관계 누락과 함께 봐야 한다. 자기 대표의 포함 여부는 새 서버 코드가 결정하므로 이 모순 제거는 모델 성능 개선 수치에 넣지 않는다.

- v1: `candidate-feature-relations-h02-20260930-v1.json`, 종료 exit 0, 코드 불변, 40,266ms. 오포함은 C013/C056/C067/C069/C111/C131/C160의 7개다.
- v2: `candidate-feature-relations-h02-20260930-v2.json`, 종료 exit 0, 코드 불변, 33,153ms. 이전 오포함 7개가 없어졌으나 C134/C110의 유효 관계 2개를 미포함으로 판단했다.
- 모호한 C081/C129는 두 실험 모두 포함으로 판단했으며 정답 집계에서 계속 제외했다. 보류 응답은 두 실험 모두 0개다.
- 두 분할 모두 `needs_confirmation`을 유지했다. 다른 9개 필드의 값·근거와 검토된 labels는 변경되지 않았다.
- 원문·키·응답 전문을 Git에 저장하지 않았다. 로컬 결과에는 ID·판정 enum·개수·해시·안전한 메타데이터를 기록했다.

**94.4%는 한 튜닝 문서의 고정 관계 36개에 대한 일치율이다. 전체 서비스 정확도, 전체 문서의 재현율, 개발 진행률을 의미하지 않는다.** 사전 기준은 개발자의 원문 감사이며 독립 평가자 합의 정답이 아니다. 입력 순서에 따른 대표 생성 차이도 이번 검토 비교로 해결되지 않았다.

## 코드 반영 검증

v2는 제품 코드를 동결한 채 transport에서 system 지침만 추가한 실험이었다. 동일한 지침을 제품 helper에 반영한 후 다음을 검증했다.

- 메모리 캡처 transport로 이전 코드 + v2 추가 지침과 새 제품 코드의 최종 요청 전체를 비교했다. 원래 6쌍과 역순 32쌍 모두 정확히 일치했다. 외부 API 호출 0회, 요청 파일 저장 0개다.
- 추가 지침 SHA-256: `303d20016b96a319651109fc7f1b4b9f2945cddd8ab22920562a2e0d2926e9bb`.
- 비교 준비 중 임시 복사본의 바이트 해시가 달랐다. Git 원본과 비교해 CRLF/LF 차이만 있고 텍스트는 같음을 확인했다. LF 정규화 해시는 실제 실험의 원본 코드 해시와 일치했다. 제품 코드는 이 진단에서 변경하지 않았다.
- 최종 코드의 전체 unittest: **907개, 901개 통과, 6개 건너뜀, 실패 0, exit 0, 14.790초**. 로그: `E:/AgentFit/tmp/candidate-feature-relations-context-full-tests.log`.
- 구현 단계의 관련 테스트 22/22, 새 helper 테스트 6/6. 정확한 쌍·전체 응답·0호출·불변 입력·불확실 보존·모델/전송 실패·민감 정보 비노출·자기 대표 모순 거절을 확인했다.
- 독립 리뷰는 `9b583c4..58c8e52` 범위에서 Critical/Important/Minor 발견 0건, 자체 관련 테스트 22/22 통과였다. 이후 변경은 위 문맥 지침 추가이며 독립 리뷰 범위에 포함됐다고 주장하지 않는다. 실제 고정 비교·요청 일치·전체 회귀로 추가 변경을 검증했다.
- 이전 구현 커밋 `58c8e52`의 Linux CI `36648154630`은 성공했다. 문맥 지침을 반영한 `a25965276ee48eb7f28a99694e84698c47261720`을 `feature/candidate-feature-relations`에 push했고, 정확히 그 커밋의 Linux CI `36650027778`도 completed/success를 확인했다. 의존성 호환성 검사·실제 Linux PDF 메모리 제한 검사·전체 테스트가 성공했다. 이후 변경은 이 결과를 기록하는 문서뿐이다.

## 결정과 제한

1. 문맥 지침만 바꾼 고정 비교를 추가했다. 오포함 7개의 공통 대표 주변에 후속 동작이 있어 해석 범위를 점검하기 위해서다. 가설이 틀리면 두 번의 추가 호출과 별칭 오거절 위험이 있었고, 실제로 유효 관계 2개가 남았다.
2. 문맥 지침은 특정 후보 정답을 넣지 않는 일반 규칙으로 반영했다. 문구 존재만 검사하는 단위 테스트 대신 실제 실패·개선 관측과 요청 전체 일치를 근거로 삼았다. 다문서 재현성은 아직 검증하지 않았다.
3. 원문 의미와 지정 정답은 부모 작업에서 감사했다. 독립 코드 리뷰가 의미 정답을 보증하지 않으며 잘못된 로컬 정답일 가능성은 남는다.
4. 공급자별 최대 입력·스키마 성공률은 검증되지 않았다. 구조 검사와 안전한 실패는 테스트했지만 큰 입력이나 다른 모델은 실패할 수 있다.
5. 이 기능의 검증 완료와 전체 서비스 사용 가능 상태를 구분한다. 기존 후보 누락·오분류·대표 선정 및 HTTP/Spring 연동은 전체 목표의 남은 작업이다.
6. 장기 목표 재개를 위해 SDD 진행 기록을 보존한다. 다른 작업 폴더의 사용자 변경은 수정하지 않았다.
