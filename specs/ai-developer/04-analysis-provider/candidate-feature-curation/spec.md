# 후보 기반 대표 기능 구성

## 목적과 근거

사용자는 Profile의 기능을 대표 기능30개 이하로 요약하기로 정했다. 현재 후보 분석은 검토를 통과한 서로 다른 원문 표현을 모두 배열로 만들고,30개를 넘으면 features를 null로 남긴다. H02/GLM 완료 평가에서는41개 발생 위치·37개 표현이 남아 기능 전체가 비워졌다. 다른 문서에도 같은 구조적 문제가 발생한다.

이번 변경은 후보의 의미 검토 뒤에 대표 선택과 포함 관계 검토를 추가한다. 기존 원문 후보 중 표현을 고르므로 새 요약 문구의 근거 위치를 생성하지 않는다. 대표 기능을 직접 문장으로 생성하는 방식은 현재 Profile의 정확한 원문 값·근거 계약과 맞지 않는다. 기존 source-selector용 curation은 ID 부분집합만 반환해 현재 후보 구조에 직접 연결할 수 없고, 선택에서 빠진 동작의 포함 관계도 남기지 않는다.

전체 실사용 목표는 유지한다. 대표 구성만으로 잘못된 최초 분류·후보 누락·사유 검토 오류·Spring 저장 연동·다문서 반복 검증이 해결됐다고 보지 않는다. 사용자는 이 목표의 설계/계획/구현을 추가 승인 없이 진행하도록 명시했다. SDD 문서화와 직접 구현을 적용한다.

## 데이터 흐름

1. 기존 검토 verdict로 확정 후보를 걸러 낸 상태를 입력한다. features/confirmed의 발생 위치만 대표 선택 대상이다. 부정·미정·다른 필드·검토 탈락 후보를 되살리지 않는다.
2. 고유 표현이30개 이하이면 추가 호출 없이 None을 반환하여 기존 투영을 사용한다. 초과하면 선택 요청1회를 실행한다.
3. 선택 응답은 groups=[{representativeId,memberIds}], unrepresentedIds다. 그룹은1~30개다. 각 대표는 해당 그룹의 구성원이어야 한다. 그룹별 구성원과 unrepresentedIds는 입력 후보 전체를 중복·누락 없이 분할해야 한다. 대표의 원문 표현은 공백이 아니고200code point 이하다. 모델 제안에서 동일한 원문 표현의 대표가 반복되면 서버가 해당 그룹의 모든 구성원을 합친다. 대표는 그 그룹들이 제안한 대표 중 입력 후보 순서가 가장 앞선 ID다. 구성원/그룹은 입력 후보 순서로 정렬하고 미대표 후보는 그대로 보존한다. 의미 검토와 최종 결과에는 중복 표현이 없는 이 정규화된 분할만 사용한다.
4. 모델은 같은 동작의 별칭·반복이나 원문 대표 표현이 실제로 포함하는 세부 동작을 묶는다. 독립된 기능을 억지로 한 그룹에 넣어30개를 맞추지 않는다. 표현할 수 없는 후보는 unrepresentedIds에 남긴다.
5. 별도 검토 요청1회에서 같은 원문·후보·제안 그룹을 비교한다. checkedCandidateIds는 제공한 전체 후보 순서와 같아야 하고, uncoveredIds는 원문 대표가 충분히 표현하지 못한 후보 ID의 중복 없는 부분집합이다. 입력 후보 전체를 검토했다고 구조상 확인하더라도 의미 정확성 자체는 실제 문서에서 별도 검증한다.
6. 두 응답이 구조 검증을 통과하면 대표 ID의 원문 값과 근거만 Profile에 투영한다. 기존 검토의 labels는 유지한다. 미대표/미포함 ID의 합집합이 있으면 features를 확인 필요로 표시한다. 기존 missingFields·wrongCandidateIds·근거 오류에 따른 확인 필요 상태는 해제하지 않는다.

## 내부 인터페이스

- 새 모듈 candidate_feature_curation.py.
- `curate_reviewed_features(document, frozen, reviewed_labels, key, *, model='deepseek-ai/deepseek-v4.1-flash', transport=None, call_trace=None) -> dict | None`.
- `validate_feature_curation(document, frozen, reviewed_labels, curation) -> dict`: 선택 ID·미포함 ID·후보 수를 반환하는 공통 검증. 서버 계산 원문 범위와 검토 후 상태를 기준으로 검사한다.
- 완성 curation의 키는 정확히 groups/unrepresentedIds/checkedCandidateIds/uncoveredIds다. IDs와 그룹 외 새 값·인용·오프셋·자유 사유는 허용하지 않는다.
- `finalize_candidate_analysis(..., observer=None, feature_curation=None)`을 선택형으로 확장한다. None은 기존 경로와 동일하다. 유효 curation을 입력하면 features만 대표 ID로 투영하고 확인 필요 판단에 미포함 후보를 반영한다. 내부 결과의 featureCuration에는 후보/대표/미포함 개수만 추가한다.

## 불변식·실패 처리

- 공개 Profile·FastAPI·기본 분석기를 변경하지 않는다. 기존 최종 결과와 검토 관측 labels는 선택 옵션이 없으면 동일하다.
- 다른9개 필드의 값·근거·기존 확인 필요 상태를 유지한다. frozen/labels/verdict 입력은 수정하지 않는다.
- 후보 최대240개, features 대표 최대30개, 대표 값 최대200code point, 요청 출력8192토큰이다. 문서는 공백이 아니며 최대100,000code point다.
- 추가 제공자 호출은0회 또는 최대2회, 자동 재시도는 없다. 모델은 기존 Solar/허용 NVIDIA 검토 모델만 허용한다. 모델 identity·finish_reason·응답 계약은 기존 파서로 확인한다.
- 잘못된 ID, 전체 분할 누락/중복, 대표가 아닌 필드나 부정 후보 포함, 잘못된 구조, 모델/전송 실패는 완료 결과를 만들지 않는다. 단순히 앞30개를 자르지 않는다.
- 선정되지 않은 후보를 의미적으로 틀린 사실이라고 재분류하지 않는다. 대표의 포함 관계 검토와 제품 사실의 검토를 혼동하지 않는다.
- 진단에는 단계·모델·완료·토큰·바이트·시간·개수/ID만 허용한다. 원문·Profile·응답 전문·추론·키는 Git/평가 파일에 저장하지 않는다.

## 수용·검증

1.31개 이상 고유 기능에서 유효 대표 그룹이 있으면 features가30개 이하의 원문 값/정확 근거로 구성된다.
2.30개 이하/빈 기능은 추가 호출이 없고 기존 결과와 같다.
3. 전체 후보 분할,200자/30개 상한, 잘못된 ID/자료형/중복/범위, 서로 다른 발생 위치의 부정/미정/탈락, 대표 포함 관계 검토 실패를 회귀 검증한다.
4. 미대표 또는 미포함 동작은 내부 개수와 features 확인 필요에 남는다. 해당 결과를 자동 완료로 반환하지 않는다.
5. 다른9개 필드와 입력/관측 labels 불변을 검사한다. 공급자 오류·위장·절단은 최대2호출 내 실패한다.
6. H02의 완료 GLM 스냅샷을 원문 해시 검증 후 재사용한다. 원래37개 표현 초과와 새 대표 구성, 후보별 포함 관계, 다른 필드 불변, 기존6개 검사와 실제 원문 동작을 대조한다. 제한된 원문 검토를 전체 정확도로 부르지 않는다.
7. 관련 테스트·전체 단위 테스트·독립 코드 리뷰·기능 브랜치 push·Linux CI를 확인한다. 실문서 결과가 미흡하면 구현 검증과 품질 미달을 구분해 기록한다.

## 2026-09-30 실제 실패에 따른 한정 보완

H02 진단v2는 후보41개가 정확히 한 번씩 배정됐지만 대표30개 중 같은 원문 표현이1회 중복되어 전체가 거절됐다. 프롬프트 반복은 보장을 주지 않으며, 임의 한 그룹 삭제는 구성원을 잃는다. 따라서 중복 대표의 그룹을 서버에서 합친 뒤 원래 두 번째 의미 검토를 실행한다. 이는 텍스트의 의미가 같다는 확정이 아니다. 같은 문구라도 서로 다른 문맥의 동작이면 검토기가 uncoveredIds를 반환해야 하며 확인 필요가 유지된다. 잘못된 ID·겹친 배정·누락·31개 원본 그룹·대표 길이 오류는 계속 거절한다. 최종 curation 입력은 계속 중복 대표를 거절하므로 검토를 우회해 원본 제안을 투영할 수 없다.

추가 검증은 그룹 순서와 무관한 선택, 모든 후보 보존, 입력 불변, 문맥이 다른 중복의 미포함 상태 보존, 정규화 이후 검토 실패, 최종 미정규화 결과 거절이다. 추가 호출/재시도는 없고 공개 계약은 그대로다. 실제v1 실패의 세부 조건은 저장하지 않아 알 수 없으며 v2의 확인된 원인과 구분한다.
