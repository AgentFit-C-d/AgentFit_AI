# 대표 기능 구성 검증

## 범위와 결론

선택형 대표 구성과 중복 대표 정규화는 구현·테스트·실제 H02 실행을 통과했다. 기존 기능 배열 null을 대표29개로 바꿀 수 있다. 이는 실제 문서의 전체 정확도나 서비스 준비 완료를 뜻하지 않는다. 기능 미포함6건, 기존 의미 분류 오류, HTTP/Spring 연결과 여러 문서 반복 검증이 남는다. 기본 분석기와 공개 Profile은 변경하지 않았다.

## 실제 실행

모델은DeepSeek V4.1 Flash, thinking=false,temperature0,max_tokens8192,timeout600초,최대2호출. v2→v3의 입력/프롬프트/모델 설정은 같고 서버 정규화만 변경했다. 별도 호출이므로 출력 자체가 같다는 가정이나 완전한 인과 비교를 하지 않는다.

## 원문 대조

부모가 로컬 감사 스크립트로29개 대표와 모든 구성원/미대표 후보41개를 대조했다. 독립 정답 판정은 아니다. 실제 원문은 이 문서에 복사하지 않는다.

- 다중 구성원3그룹은C030(C098),C037(C038/C074/C075),C082(C083/C132)다. 반복/별칭/해당 구체 동작의 문맥으로 묶였으며 이번 대조에서 서로 다른 독립 동작을 잘못 합친 근거는 찾지 못했다. 정규화된 동일 표현은C030/C098이다.
- 미대표C134/C142/C147/C160/C165/C168은 결과에 남아 확인 필요가 됐다. C142/C147/C165/C168에는 대시보드 입력·원장 검증·발급·검증 시연의 구체 동작이 있어 선정 품질 보완이 필요하다. 이미 있는 기능과 다시 묶을 수 있는지와 독립 동작인지 구분해야 한다.
- 대표에는 중첩된 짧은 표현과 긴 동작 설명이 함께 남고C129 같은 기대효과 성격의 후보도 남는다. 이들의 최초 확정 분류는 이번 구성 전에 존재했다. 정규화가 이를 의미적으로 올바른 사실로 만든 것은 아니다.
- 기존GLM 검토의C016/C150 backend 오분류와C156 명시 동작 제외는 이번 단계가 복구하지 않았다. 미대표6개만 고쳐 전체 의미 문제가 해결됐다고 보고하면 안 된다.
- 미대표가 문서 뒤쪽에 몰리고 앞부분의 중첩 표현은 별도 대표로 남았다. 위치 편향 가설이 생겼지만 이 결과만으로 입증되지 않았다. 고정 모델/입력의 후보 순서만 바꾸는 한정 진단을 다음 실험으로 사용할 수 있다.

## 결정과 제한

1. v1 원인 미저장에 대응해 동일 조건 진단v2를1회 실행했다. 비용은최대2호출이며 반복 성공만 선별하지 않고 실패도 보존했다.
2. 같은 원문 표현의 제안 그룹만 서버가 합친다. 의미상 같은 기능이라고 자동 확정하지 않으며 독립 포함 검토와 확인 필요를 유지한다. 위험은 동일 문구의 다른 문맥을 모델이 놓치는 경우로, 관련 회귀는 상태 보존을 검증하며 실제 모델의 완벽한 판단을 보증하지 않는다.
3. 리뷰어가 제외한 실제 품질은 부모가 위와 같이 대조했고, 최종 기록/push/CI는 부모가 확인한다. HTTP/Spring·다문서 검증은 전체 목표에 남긴다.
4. 독립 리뷰 이후 한정 수정은 재리뷰 대신 회귀와 전체 suite로 검증했다. 독립 리뷰 범위와 수정 검증 범위를 구분한다. 이 기능의 구현 완료를 서비스 승격 승인으로 사용하지 않는다.

후속 우선순위는 대표 선정의 중첩/미포함 개선, 기술 역할 및 명시 동작 의미 오류·근거 없는 누락 주장 보완, 여러 문서 반복 검증, 실제 HTTP/Spring 확인·저장 경로 검증이다. 전체 실사용 목표는 active다.
