# 원문에 함께 적힌 프로젝트명 보존

## 근거와 목적

동일 후보 검토 비교의 공통 입력에서 H02 프로젝트명17개가 영문/한글2개 값으로 분류됐다. 해당 후보만 기존 변환에 넣었을 때 project_name=null, unresolvedFields=[project_name]을 로컬에서 재현했다. 같은 제품의 두 표기를 잃지 않고 사용자가 확인할 수 있는 초안으로 보존한다. 특정 이름이나 정답 문자열을 코드에 넣지 않는다.

## 동작

- 후보 분석의 project_name에 여러 확정값이 있을 때만 적용한다. 다른 scalar 필드와 단일 이름 경로는 유지한다.
- **해당 원문 위치에서 확정된** 두 후보가 같은 줄의 `이름A (이름B)` 또는 `이름A（이름B）`의 두 구성 요소를 이루어야 한다. 괄호 앞뒤의 수평 공백·탭만 허용한다. 다른 위치의 예시·검토안·과거 이름은 사용하지 않는다.
- 현재 확정된 이름의 모든 고유 값이 그 두 구성 요소 또는 같은 구성 요소로 입증된 전체 괄호 표현이어야 한다. 세 번째 별도 이름, 다른 제품명, 여러 줄, 중간 설명·선택지 구분자는 통합하지 않는다.
- 조건을 만족하는 가장 이른 원문 표현을 200 code point 이하에서 그대로 선택하고 그 전체 구간을 근거로 사용한다. 새 표기나 구두점을 생성하지 않는다.
- 괄호만으로 의미적 동의 관계를 확정하지 않는다. 값은 보존하되 project_name은 확인 필요 목록에 남긴다. 기존 자동 완료 조건을 완화하지 않는다. source expression이 없는 충돌은 계속 null·확인 필요다.
- 비교 진단의 projection_reason은 보존된 이름에 source_name_expression을 기록한다. 공개 Profile·FastAPI·제공자 요청·기존 실행 중인 비교 코드는 변경하지 않는다.

## 검증

양언어·반대 표기 순서·공백·전각 괄호·Unicode 위치, 같은 관계의 여러 표기, 실제 충돌/세 번째 이름/미확정·반려 위치/예시 위치/줄 넘김/길이 제한을 검사한다. 다른 scalar 값의 충돌과 단일 이름은 기존 동작이어야 한다. 현재 고정된 원문·후보를 API 호출 없이 재투영해 이름 보존과 근거 일치를 확인한다. 전체 품질과 서비스 준비는 별도로 검증한다.

사용자가 목표 단위로 설계·구현 자율 진행을 승인했다. 기본 검토 분석기 변경이나 새 모델 실험을 한꺼번에 묶지 않는다.
