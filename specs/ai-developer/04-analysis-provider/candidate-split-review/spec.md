# 후보 판단과 누락 검토 분리

## 목적과 근거

실사용 가능한 분석을 위해 후보 우선 실험의 검토 완주율과 판단 품질을 검증한다. H02 최근 실행은 양성 정답 3개가 추출·분류에 남아 있었지만 전체 검토가 INCOMPLETE_RESPONSE로 실패했다. 토큰 소진 여부는 미확인이다. 한 호출에 모든 후보의 판단과 10개 필드 누락을 함께 요구하는 부담이 원인이라는 가설을 시험한다.

## 설계

- 선택형 `split_review=True` / CLI `--split-review`. 기본 분석기와 공개 Profile은 변경하지 않는다.
- 확정 후보만 최대 20개씩 검토한다. 각 요청은 전체 원문과 ID·정확한 위치·주변 문맥·필드·상태를 받는다. 모든 묶음의 `checkedCandidateIds`가 요청 ID 순서와 정확히 같아야 한다. `wrongCandidateIds`는 묶음 내 고유 ID만 허용한다.
- 잘못된 후보를 제외한 뒤 전체 원문과 필드별 확정 값 목록으로 누락만 별도 검토한다. 동일 필드의 동일 문자열만 중복 제거하며 의미·별칭을 합치지 않는다. `checkedFields`는 기존 10개 순서와 일치해야 하고 `missingFields`는 고유한 알려진 필드만 허용한다.
- 미확정 후보는 Profile에 들어가지 않으므로 판단 재검토에서 제외한다. 그중 실제 확정 사실이 있으면 별도 원문 누락 검사에서 잡아야 한다. 이 검사도 모델 판단이므로 완전한 보장은 아니다.
- 전체 결과를 기존 checkedFields/missingFields/wrongCandidateIds로 합친다. 어느 호출이든 미완료·잘못된 계약·다른 모델이면 실패한다. 부분 검토를 성공으로 처리하지 않는다. 기존 보류 조건을 유지한다.
- Solar pro4, medium, 8192 토큰, 호출당 600초를 유지한다. 원문 위치 확장 상한 240개에서 검토는 최대 12+1회다. 빈 후보도 전체 누락 검사는 실행하고 기존 규칙상 자동 완료하지 않는다.
- 모델에 평가 정답은 보내지 않는다. 원문·후보·응답 값은 저장하지 않고 기존 단계 진단과 집계만 남긴다.

## 대안과 판단

출력 상한 증가만으로는 작업 복합성을 검증하지 못한다. 필드별 전체 검토는 기능 필드에 부담이 몰렸던 기존 실험이 있다. 이번에는 후보 묶음과 누락 검사로 책임을 분리한다. 추가 호출·지연과 누락 검사 단일 호출의 실패 가능성은 남는다.

## 완료 기준

계약·경계·실패 회귀 테스트, 전체 테스트 및 CI 통과. 승인된 비식별 H02를 같은 모델로 1회 실행해 검토 완주, 정답 도달 단계, 6개 최종 항목, 자동 완료 여부를 기록한다. 이를 전체 문서 정확도로 표현하지 않으며 검토 완주만으로 서비스 승격하지 않는다. 실제 서비스 목표는 여전히 추가 문서 품질 평가와 Spring 연동·복구 검증을 포함한다.

## 승인

사용자의 이번 목표 내 설계·계획·구현 자율 진행 승인에 따라 별도 재승인 없이 수행한다.
