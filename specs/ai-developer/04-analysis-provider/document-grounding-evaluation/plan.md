# 문서 근거 검증 비교 구현 계획

**목표:** Docling + LangExtract + 규칙 검증이 반복·부정·검토안의 오확정을 실제로 줄이는지 기존 파이프라인과 같은 골드로 평가한다.

**방식:** 기본 서비스 외의 선택형 도구에 입력 정규화, 위치 정렬, 안전 게이트를 독립 모듈로 둔다. 각 단계의 결과와 최종 Profile을 별도 채점하고 성공 및 보류를 구분한다.

## 1. 고정 평가셋과 채점기

- [x] 반복, 부정/부재, 검토안/확정의 쌍별 합성 문서와 `start/end` 골드를 먼저 작성한다. 이미 사용한 이름·문구를 그대로 답으로 옮기지 않는다.
- [ ] 거짓 확정, 누락, 위치 오차, 중복 위치, 확인 필요, 호출 실패를 모두 집계하는 실패 테스트를 작성한다. 후보 허용/보류, 오확정·누락, 중복 위치 및 호출 실패는 완료했다. 위치 오차·확인 필요 집계는 남았다.
- [ ] 채점기를 구현해 현재 분석기의 기준선과 비교할 준비를 한다. 원문·인용을 안전 결과에 기록하지 않는 테스트를 둔다.

## 2. 독립 안전 게이트

- [x] 확정·명시적 부재·미정·제안/검토·과거/타 제품 문맥의 경계 사례를 실패 테스트로 만든다.
- [x] 후보 근거의 주변 문장을 읽는 보수적 게이트를 구현한다. 애매하면 확인 필요로 보류하고 공개 Profile 형식을 바꾸지 않는다. 제목 문맥은 아직 미포함이다.
- [ ] 합성 평가에서 기존 대비 거짓 확정과 정답 누락을 측정한다. 규칙 때문에 생긴 과잉 보류를 별도 기록한다.

## 3. LangExtract 정렬 실험

- [x] 공식 API와 설치 버전을 고정하고 어댑터의 데이터 경계를 정한다. 기존 Solar·키를 쓰는 합성 전용 어댑터를 연결했다.
- [ ] 반복 문구의 여러 등장, 정렬 실패, fuzzy 근거, 문맥상 다른 제품 사례를 실패 테스트로 만든다. 정렬 앞의 세 사례만 완료했다.
- [x] LangExtract 기반 추출/정렬을 opt-in으로 실행하고 서버의 정확 인용·근거 검증을 18개 합성 골드로 채점한다. 라이브 호출은 명시적 플래그에서만 한다. 실사용 관문은 미달이며 현재 기본 서비스와의 직접 기준선 비교는 별도 작업이다.
- [x] 한국어 조사가 붙은 후보의 정렬 실패를 재현하고, 모든 등장 횟수와 추출 횟수가 일치할 때만 원문 위치를 계산하는 선택형 fallback을 테스트한다.
- [x] 합성 사례 파일의 SHA-256을 외부 호출 전에 고정 검증하고 사례별 전체 실행 기한을 둔다.

## 4. Docling PDF 실험

- [ ] 공식 API/패키지 버전을 고정하고 PDF별 텍스트·페이지·문단/표 비교표를 만든다. 버전 및 합성 2쪽 PDF만 완료했다.
- [ ] 페이지 경계와 Profile 문자 오프셋이 Docling 정규 텍스트에 정확히 대응하는지 검사한다. 합성 PDF의 위치 검증만 완료했고 시간/메모리는 남았다.
- [ ] 선택형 PDF 실험의 결과만 평가한다. 15초 worker/메모리 제한과 충돌하면 기본 서비스로 병합하지 않는다.

## 5. 통합 판정

- [ ] 동일 골드에서 기준선/각 단계/조합의 사례별 수치를 저장하고 거짓 확정 0·근거 위치 100%·누락 증가 없음 관문을 평가한다.
- [ ] 전체 테스트, Linux CI, 독립 코드 리뷰를 수행한다.
- [ ] `feature/document-grounding-evaluation`에 검증된 코드·명세·안전 결과를 push한다. 미달 또는 미평가 항목을 명시한다.
