# 문서 구조화·원문 정렬·규칙 검증 비교 명세

## 배경과 목적

현재 PDF 입력은 `pypdf`로 텍스트만 추출하고, 분석기는 원문 줄·인용·등장 순서를 서버에서 검증한다. 일부 반복 표현의 위치 오류와 부정·미정·검토안을 확정으로 읽는 의미 오류가 남았다. Docling의 문서 구조화, LangExtract의 원문 정렬, 결정적 규칙 검증을 각 단계의 역할에 맞게 선택형으로 비교한다. 라이브러리 도입 자체를 품질 개선으로 간주하지 않는다.

## 범위와 불변 조건

- 기본 FastAPI·공개 Profile·Spring 계약과 기본 분석기의 PDF/MARKDOWN/TEXT 경로는 유지한다. DOCX 등 새 입력 형식은 이 실험의 범위 밖이다.
- Docling은 **PDF 입력 전처리 후보**다. 기존 `pypdf` 결과와 같은 PDF에서 문단·표·제목 보존 및 텍스트 누락을 비교한다. PDF의 페이지 및 Profile `start/end`는 선택된 정규 텍스트에 일관되게 매핑되어야 한다. 매핑이 입증되기 전에는 서비스 경로로 승격하지 않는다.
- LangExtract는 **후보 문구를 원문 문자 구간에 정렬하는 후보**다. 추출 문구가 정규 텍스트의 정확한 부분 문자열과 일치하고 위치가 유일하거나 문맥으로 결정되는 경우만 자동 근거로 인정한다. 미정렬, fuzzy만 가능한 결과, 중복 위치 모호성은 `확인 필요`다. 모델 제공자는 기존 키/호출 경계 안에서 어댑터로 연결하며 원문과 응답을 영속화하지 않는다.
- 규칙 검증은 **안전 게이트**다. 확정 후보의 근거 범위에서 부정, 미정, 제안/검토, 과거·타 제품 문맥의 신호가 있으면 자동 확정을 막고 확인 필요로 돌린다. 단어 하나만으로 `사용하지 않기로 확정` 같은 명시적 부재를 긍정 확정으로 바꾸거나 임의 값을 만들어내지 않는다. 기존 원문 위치·필드·역할 검증은 그대로 적용한다.
- 모든 외부 API 실험은 `--live`가 있어야 한다. 원문·키·추출된 인용·원본 응답은 결과 JSON·일반 로그에 남기지 않는다. 합성 골드와 안전한 집계만 버전 관리한다.

## 평가 데이터와 기준

- 자동 평가에는 서로 다른 제품·표현을 쓴 최소 3쌍의 반복 사례, 3쌍의 부정/명시적 부재 사례, 3쌍의 검토안/확정 사례를 먼저 고정한다. 각 쌍은 같은 핵심 명사가 등장하되 상태나 위치만 달라야 한다. 기존 튜닝 사례와 별도 이름·문장을 사용하고 골드 근거 `start/end`를 고정한다.
- 후보/최종 출력을 분리해 **정확 근거 위치**, **중복 위치 선택**, **거짓 확정**, **누락**, **확인 필요**, **완료/실패**를 사례별로 채점한다. `확인 필요`는 거짓 확정은 아니지만 완전 성공도 아니다. 파서·모델 오류도 결과에서 제외하지 않는다.
- 동일 입력·동일 골드로 기존 흐름, 단계별 교체(Docling만/LangExtract만/규칙만), 조합을 비교한다. 단계별 교체가 불가능한 포맷은 `미평가`로 표시한다. 최초 결과를 보고 사례나 골드를 수정하면 새 버전으로 분리한다.
- 승격 후보는 합성 평가의 거짓 확정 0건, 자동 완료된 근거의 정확 위치 100%, 기존 대비 확정 가능한 정답의 누락 증가 없음이 필요하다. 소규모 합성 통과만으로 실서비스 가능을 선언하지 않는다. 실제 비사용 문서와 Spring 통합 검증이 별도로 필요하다.

## 실패 처리

- 문서 변환이 실패하거나 페이지/문자 위치 대응이 무너지면 기존 서비스 경로에 영향을 주지 않고 실험만 실패한다.
- 정렬 불가·중복 모호·규칙 충돌은 자동 확정하지 않는다.
- 의존성/모델 공급자의 기능 차이와 응답 한도는 안전한 오류 코드와 완료 여부만 기록한다.
