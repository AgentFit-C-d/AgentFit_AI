# 역할 분류 실험 검증
날짜: 2026-09-25. 브랜치: feature/profile-role-classification. **품질 게이트 미달, 안정화 완료 아님.**

## 변경
공개 Profile은 유지한다. 내부 후보에 역할을 부여해 사용자/운영 동작과 실제 연동만 투영한다. 클라이언트·시연 모델·폴더·개발 분업을 구분하도록 프롬프트와 스키마 설명을 보완했다.
v21은 반복 인용의 occurrence와 연동 없음의 absenceQuote를 요구한다. 서버는 원문 일치와 범위를 검사하지만, 모델의 의미 해석까지 보장하지는 않는다.

기존 실제 문서 3/4 통과: HandOff 1회는 INVALID_FEATURE_SPAN으로 수정 후에도 실패, 다른 1회는 최초 성공. AgentFit 2회는 각각 수정 후 성공/최초 성공.
모든 실패를 포함했고 네트워크 재시도는 없다. 비교 표본이 작아 일반 성능 향상을 확정할 수 없다. v18 역할 기준은 반복 수가 다르다.

## 남은 문제
- v21 README 첫 실행은 구조 검증에 통과했지만 외부 연동을 []로, 필요한 기능을 null로 출력해 의미 기준에 실패했다.
- 두 번째 실행은 인용 occurrence를 해당 문구의 등장 횟수 대신 목록 순번 2~5로 출력했다. 원문에서 각 문구는 한 번뿐이며 수정 호출에서도 오류가 남았다.
- 명시적 없음의 문장이 원문에 있다는 사실만으로 그 문장의 의미가 없음임을 증명할 수 없다.
- ROLE-002의 정확한 기능명 기준도 실패한다. 문장 전체와 짧은 기능명 차이가 포함된 엄격한 판정이며 정답을 완화하지 않았다.
- v20 README에서는 핵심 동작이 추출됐으나 v21에서 다시 누락/구조 오류가 나타났다. 최종 버전의 README 품질 개선을 주장하지 않는다.

## 검증 범위와 보관
고정된 실제 문서·루브릭을 재사용했다. README 루브릭은 사용자 확정 정답이 아닌 문서 기반 잠정 기준이며, 필수 개념 점수 외 과다 추출은 수동으로 함께 확인했다.
본문·전체 Profile·실패 원문·키는 output/ 아래 로컬에만 둔다. 추적 보고서는 점수/해시/호출 진단만 포함한다. 실패 원문 보관은 기존 7일 정책을 따른다.
연결된 보고서: profile-v21-classification.json, profile-v21-regression.json, profile-v21-mabc-summary.json, profile-v21-real-summary.json.
SDD 계획 범위의 세 변경과 평가를 수행했지만 목표 품질은 충족하지 못했다.
