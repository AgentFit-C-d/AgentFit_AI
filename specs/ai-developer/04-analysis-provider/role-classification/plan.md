## v20 내부 분류 투영
v19 신규합성3/8, README0/2. 프로젝트형태/ai/backend 분류는 개선됐지만 연동에 클라이언트·일반데이터, 기능에 개발업무가 섞임. 반복 진단에서도 기능 인용의 긴 표현이 확인됨.
외부 연동의 각 내부 후보는 name+role(named_service/client/generic_source), 기능 span은 role(user_action/operational_action/development_task/technical_description)를 붙인다.
서버는 역할을 검증하고 실제 서비스/제품 동작만 기존 Profile로 투영한다. 제외 후보만 있으면 미언급null, 명시적 없음의 기존 빈배열 분기는 유지한다.
내부 응답 계약만 변경하며 공개 Profile/근거검증/호출수는 그대로다. 선택된 값은 원문 근거 검증 필수. 특정 프로젝트 이름이나 경로 문자열로 직접 필터링하지 않는다.

## v21 근거로 명시하는 미언급/없음 및 반복인용
v20에서 README 기능은 핵심동작으로 줄었으나 외부연동 []가 두번 남았다. ROLE-004 실패원문은 같은1줄의 두 '야간 백업' 때문에 INVALID_FEATURE_SPAN. 정확한짧은기능명이라는 고정정답과 모호한인용금지가 충돌했다. 정답을 바꾸지 않고 모델이 occurrence(1부터 시작)를 명시하게 한다. 서버는 일치 구간을 열거하고 범위 내의 명시위치만 수용한다. 임의 첫번째매칭/퍼지검색 없음.
연동의 absenceQuote 필드를 추가해 모든후보빈배열+absenceQuote=null은 미언급null, 실제 인용문이 있는 명시적 없음만[]로 변환한다. 남은 후보가 있는데 absenceQuote를 같이 주면 거절. 인용문은 선택근거에 정확히 있어야 한다.
전체단위/고정회귀 후 실패가 남으면 네번째 수정을 누적하지 않고 결과/구조재검토 필요성을 기록한다.
