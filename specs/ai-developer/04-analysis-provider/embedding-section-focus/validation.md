# 임베딩 구역 검색 실험 결과

## 실행
새 합성 다구역 문서 8건, 구역 48개와 금 구역 27개를 고정했다. 기존 33건은 길이가 18~91자여서 구역 검색 평가에 사용하지 않았다. NVIDIA `nvidia/nemotron-3-embed-1b`로 같은 10개 필드 질의를 query 방식, 각 구역을 passage 방식으로 인코딩했다. cosine 최대값 기준 top 4를 선택하고, 단순 키워드 top 4 및 전 구역과 비교했다. 실문서·예약 공개 자료는 전송하지 않았다.

| 조건 | 금 구역 포함 | 완전 포함 문서 |
|---|---:|---:|
| 전 구역(검색 없음) | 27/27 | 8/8 |
| 임베딩 top 4 | 20/27 | 1/8 |
| 키워드 top 4 | 19/27 | 별도 집계 없음 |

임베딩 검색 한 번의 중앙값은 1,125ms였다. 이는 문서별 passage 요청 시간이며 공통 query 인코딩 호출은 포함하지 않는다. 벡터와 원본 API 응답은 저장하지 않았다.

현행 Solar Pro4 후보 생성도 8건의 모든 구역을 보내 측정했다. 유효한 응답 5건에서는 금 문구 17/17개가 후보 span에 포함됐다. 다른 3건은 `ANCHORED_CANDIDATE` 형식 검증에서 실패해 부분 결과 없이 해당 문서 0건으로 기록했다. 총계 17/27은 검증 실패를 포함하므로 모델의 순수 문구 누락률로 해석하면 안 된다. 후보 호출 시간 중앙값은 2,344ms이다. 성공한 문서는 각각 2회 호출했다. 실패한 3건은 최초 집계 코드가 계획된 배치 수를 실제 호출 수로 기록했으므로 해당 필드를 결과에서 제거하고 `calls_unverified_before_fix`로 표시했다. 호출 수 집계 코드를 수정하고 첫 배치 실패 회귀 테스트를 추가했다. 전체 329개 테스트가 통과했다.

## 결정
사전에 정한 두 관문 중 임베딩의 금 구역 전부 포함과 유효 후보 응답에서 실제 문구 누락이 모두 충족되지 않았다. 우선 구역 힌트를 이용한 추가 Solar 호출과 서비스 통합은 실행하지 않았다. 이 설정에서 임베딩으로 6개 구역 중 2개를 제외하면 이미 회수하던 사실을 놓칠 수 있다. 후보 응답 검증 실패의 원인은 별도로 진단할 가치가 있다.

이 자료는 합성 소표본이며 진짜 긴 기획서의 검색 품질을 증명하거나 임베딩 방법 전반을 부정하지 않는다. 서비스의 24,000자 제한을 넘는 문서에도 적용해 보지 않았다. 향후 그 범위로 확장하려면 새 자료와 누락·지연 관문을 먼저 정해야 한다.

임베딩 모델의 한국어 지원과 query/passage 구분은 [NVIDIA 모델 카드](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3-embed-1b)와 [API 문서](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3-embed-1b-infer)를 확인했다.
