# 기본 서비스 분석 기준선 검증

2026-09-29, `SolarAnalyzer`를 Worker와 같은 `solar-pro4`, 근거 계약·의미 검토 활성화, 분석 제한 40초, inline 전송으로 실행했다. 합성 데이터는 기존 평가에 사용한 20건이며 독립 검증 자료가 아니다. 프로세스·HTTP 경로 자체는 실행하지 않았다.

| 범위 | 완료 | 실패 | 정답 일치 | 오확정 관찰 |
| --- | ---: | ---: | ---: | ---: |
| 전체 20건 1회 | 11 | 9 | 완료 11건 중 10건 | 완료 건에서 0 |
| N-004·N-006 별도 1회 | 2 | 0 | 2 | 0 |
| E04 별도 재실행 | 0 | 1 | 해당 없음 | 해당 없음 |

전체 실패는 `PROVIDER_TIMEOUT` 7건, `SEMANTIC_REVIEW_INVALID` 1건, `INVALID_EVIDENCE` 1건이다. 완료 건의 정답 일치는 90/91항목이며, 전체 계획 정답 147항목 중 실패 건은 채점하지 않았다. 최대 5회 호출, 관찰 최대 40,081ms였다. 전체 평가 게이트는 실패 9건 때문에 통과하지 못했다.

N-006은 별도 실행에서 완료했으나 전체 실행에서는 시간 초과했다. E04는 전체 실행에서 완료했지만 정답 1항목을 놓쳤고, 별도 재실행에서는 시간 초과했다. 제공자 응답의 변동성을 확인했으며 누락 원인을 아직 특정하지 못했다.

평가 도구는 완료 Profile과 원문을 산출물에 저장하지 않는다. 전체 평가의 결과 JSON은 작업 폴더의 무시된 `tmp/default-service-quality-20260929/`에 있으며 Git에 포함하지 않는다. 결과는 동일 자료를 재사용한 1회 관찰이고, 의미 근거 위치의 독립 판정 및 실제 문서 검증이 없어 실사용 적합성을 입증하지 않는다.

다음 개선은 우선 40초 제한 내 처리율과 `SEMANTIC_REVIEW_INVALID`/`INVALID_EVIDENCE`를 분리해 조사해야 한다. 시간 제한 완화만으로 정확도가 해결된다고 판단할 근거는 없다.
