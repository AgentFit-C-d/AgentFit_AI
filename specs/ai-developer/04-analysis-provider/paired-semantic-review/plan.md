# 계획
1. 기존 합성4건에서 정답/누락 Profile을 생성해 정확 인용으로 검증한다.
2. 누락 탐지와 정답 오거절을 구분하는 채점 회귀 테스트.
3. none8건, low8건 순차 실행. 두 결과가 모두 부족하면 새 가설과 근거를 먼저 기록한다.
4. 충분히 개선되는 설정만 별도 opt-in 전체 경로에서 재평가한다. 기본 검토 설정은 유지한다.

## 출력 계약 예시 가설
none 설정에서 정답에 무관한 필드 누락을 요구하는 오류가 관측됐다.
checkedFields와 issues의 관계를 명시적 전체 JSON 예시로 보여주는 부록을 고정했다.
같은8건·none·스키마·8192토큰에서 이 부록 유무만 비교한다. 단어는 기존 사례와 다르게 작성했다.
low 기준선 완료 후 실행하고, 기본 검토 설정은 변경하지 않는다.

## 의미 채점 분리와 추가 비교
none+예시의 Q002-missing은 [1,1] 근거로 올바른 missing을 반환했다. 현 validate_review는 중복 줄 번호를 허용한다.
의미 채점revision2에서는 같은 줄의 반복만 중복 제거해 비교하고 기존 완전 일치를 exact_match로 따로 보존한다.
기존 결과 파일은 덮어쓰지 않고 재집계 표를 별도로 작성한다. field/kind/index/실제 근거 줄의 변화는 계속 오답이다.
low+예시8건도 실행해 프롬프트 예시의 지연 효과를 low 기준선과 비교한다. 같은 고정8건, 다른 변수는 유지한다.

## opt-in 전체 파일럿12건
low+예시8/8, 중앙값 약5.5초(기존low8/8 약26.8초)를 관측했다.
review_examples=True로 검토/재검토에만 연결하고 기본False를 유지한다.
고정12건에서 Mini4/promptv2/원문수정on/수정예시on/검토low/검토예시on, 최대6회60초를 평가한다.
전체12건 모두 통과하면 동일 조건2회 추가 반복하며, 실패하면 원인을 보존한다.
이전12건과 비교할 때 수정 예시와 검토 예시가 모두 달라졌다는 점을 밝힌다. 검토 단독 효과는 위 쌍 평가에 한정한다.
