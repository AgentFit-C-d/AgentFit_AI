# 공개 PRD 독립 평가 구현 계획

**목표:** 모델 결과를 보기 전에 새 PRD 5건과 수작업 정답을 고정하고 최초 평가로 실사용 위험을 측정한다.

**구조:** 기존 `public_holdout.py`의 고정 다운로드·검증 및 평가 CLI를 재사용한다. 정답 표현에 필요한 경우에만 스키마와 채점기를 확장한다. 원문은 외부 고정 커밋에서 읽고 로컬 결과에는 집계만 저장한다.

**대상:** 이 폴더의 `sources.json`·`manifest.json`·`validation.md`, 필요하면 `ai_service/agentfit_ai/public_holdout.py`·`public_holdout_evaluation.py`와 관련 테스트.

## 작업 1: 소스 확정과 정답 작성

- [ ] 고정 원문 5건의 SHA-256·UTF-8·100KB 상한을 검증하고 기존 평가 문서와 중복을 확인한다.
- [ ] 원문을 읽어 확정 값, 계획 값, 미정 값 및 원문 인용을 수작업으로 표시한다.
- [ ] 기존 manifest 계약으로 표현할 수 없는 미정 항목을 구분할 최소 확장을 테스트부터 구현한다.
- [ ] `partition=heldout` manifest를 검증하고 모델 호출 전에 커밋한다.

## 작업 2: 최초 평가

- [ ] 기본 분석과 선택형 확인 질문 경로의 모델·기한·옵션을 고정한다.
- [ ] 동일한 고정 문서에서 구성별 최초 1회 라이브 평가를 실행한다.
- [ ] 오확정·누락·확인 질문·근거·지연·호출 수를 문서별로 기록하고 결과 해시를 남긴다.

## 작업 3: 독립 평가 종료

- [ ] manifest를 `tuning`으로 변경하고 한계와 후속 개선 대상을 `validation.md`에 기록한다.
- [ ] 관련 테스트와 전체 AI 테스트를 실행하고 diff·비밀 누출 여부를 점검한다.
- [ ] `feature/public-prd-holdout` 브랜치를 push하고 CI 결과를 확인한다.

## 검토 초점

- 동일 인용이 목차와 본문에 반복되면 평가 시작 전에 거부한다.
- 계획 단계의 기술과 확정 기술을 같은 정답으로 채점하지 않는다.
- 100KB에 가까운 문서는 입력 제한·기한 실패를 별도로 집계한다.
- 부분 정답으로 채점하지 않은 필드의 모델 출력을 정확도 분모에 넣지 않는다.
- 네트워크·원문 검증 실패 시 모델 호출 전에 중단한다.
