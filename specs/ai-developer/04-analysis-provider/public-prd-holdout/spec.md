# 공개 PRD 독립 평가

## 목적

실제 기획 문서에서 분석 결과가 실사용 가능한지 판단할 근거를 확보한다. 기존 AgentFit·MABC·Handoff 문서와 공개 README 코퍼스는 이미 튜닝에 사용했으므로 독립 평가에 재사용하지 않는다.

## 자료와 경계

- 서로 다른 공개 GitHub 저장소의 한국어 PRD 5건을 사용한다. 파일은 저장소·40자 커밋·경로·SHA-256으로 고정하며 원문은 저장소에 복사하지 않는다.
- 각 원문은 100,000바이트 이하 UTF-8이어야 한다. 평가 전에 민감 정보와 기존 튜닝 코퍼스의 중복 여부를 확인한다.
- 모델 결과를 보기 전에 사람이 문서를 읽고 필드별 값·원문 인용·미정 항목을 기록한다. 인용은 원문에서 정확히 한 번 나타나야 한다. 미평가 필드와 계획·미결정 항목은 별도로 표시한다.
- 정답표와 평가 계획을 먼저 커밋한다. 첫 모델 호출과 그 시점의 커밋·설정·결과 해시를 기록한 뒤 해당 코퍼스는 `tuning`으로 바꾼다. 이후 재실행을 독립 평가로 부르지 않는다.

## 평가

- 현재 운영 기본 경로와 선택형 확인 질문 경로를 같은 고정 문서에 실행한다. 각 구성은 평가 전에 고정하고 문서별 최초 결과를 별도로 보관한다.
- 값의 오확정, 근거 위치, 누락, 확인 질문 전환, 실패, 지연, 모델 호출 횟수를 각각 집계한다. 정답이 일부만 있는 필드의 결과는 전체 정확도로 환산하지 않는다.
- API 키·원문·원본 모델 응답은 평가 산출물과 Git에 기록하지 않는다.
- 출시 판단은 오확정의 심각도와 실제 사용자 확인 흐름을 함께 본다. 공개 PRD 평가만으로 Spring 저장·UI·운영 전체를 검증했다고 주장하지 않는다.

## 수용 기준

- 5개 고정 소스의 다운로드·해시·인코딩·크기 검증이 통과한다.
- 모델 호출 전에 정답표가 커밋돼 있고, 모든 정답 인용의 유일성과 미정 판단이 검토돼 있다.
- 최초 결과는 문서와 구성별로 안전한 집계값만 남기고, 커밋·설정·시간을 추적할 수 있다.
- 독립 평가 이후 partition을 변경하고 결과의 한계 및 다음 개선 대상을 기록한다.
