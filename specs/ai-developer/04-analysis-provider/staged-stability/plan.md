# 계획
1. v12 실패 입력/출력 경계를 재현한다. 핵심 필드만 기존 none vs low를 비교해 추론 설정의 영향인지 확인한다. 생산코드 변경 전 로컬 실험.
2. 단계는 분리했으나 두 요청의 시스템 프롬프트가 동일하여 다른 단계 지시와 전체 예시를 포함한다. 먼저 단일 변수 진단으로 이 영향과 추론 설정을 구분한다.
3. 근거가 있는 최소 수정만 TDD로 구현. 외부 Profile/호출한도/검증기를 완화하지 않는다.
4. 고정 전체 평가. 게이트가 충족되면 종료; 실패 시 추측성 프롬프트 누적 대신 진단과 남은 과제 기록.
5. 문서/변경 검토와 비밀값 비노출 확인 후 scoped commit/push. 합성자료와 내용제외 요약만 Git.

## 진단 후 결정
none/low 및 단계 전용 지시를 비교했으나 low는 timeout/응답잘림을 유발해 채택하지 않음. 공식 Upstage API에서 frequency_penalty 기본1.1 확인. 0 명시와 번호 원문은 핵심4건 중3건 통과(이름/DB/HandOff). AgentFit AI 후보 오판이 남음.
선택: profile-v13, 기존 none/40초/4096토큰/최대3호출 유지, frequency_penalty=0 명시, 원문을 [L번호] 줄로 전달. 공개Profile과 근거 위치 유지.
기술 필드의 상태 단어 값과, 인용한 모델의 평가+운영채택 검증후결정 구절만 명시적 미확정 가드로 거부. 기존1회수정으로 넘기고 자동으로 null로 바꾸지 않는다. 모든 한국어 의미를 검증한다고 주장하지 않는다.
