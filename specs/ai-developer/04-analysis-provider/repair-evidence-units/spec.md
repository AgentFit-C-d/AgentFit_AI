# 수정 근거 단위 세분화 — 사용자 승인 완료
## 확인된 문제
같은 이름이 개발 문장과 운영 문장에 반복되면 수정 모델은 quote가2번 포함된 원문 전체를 context로 반환한다. 명시적 예시 보완 후에도3회 모두 SOURCE_REPAIR_INVALID였다. 서버의 모호한 근거 거부는 유지해야 한다.
## 제안
초기 후보 추출용 구역은 유지하고, 원문 수정 요청에서만 원래 구역을 줄 경계 및 문장 끝 구두점 뒤 공백에서 세분화한다. 각 하위 단위에 서버가 순서 ID와 정확한 원문 오프셋을 부여한다. 전체 문서와 상위 제목 문맥은 계속 제공한다. 모델은 해당 하위 unitId의 정확한 quote를 고르고 서버는 기존 규칙으로 검증한다.
새 응답 필드는 만들지 않는다. 공개 Profile, role/status, 최대6회60초는 유지한다. 기본False opt-in 실험이다.
## 불변 조건
- 모든 원문 문자는 원래 순서와 오프셋을 유지한다. 삭제·재작성·의미에 따른 필터링 금지.
- 서로 다른 문장의 동일 이름은 각 단위에서 유일해질 수 있다. 같은 단위 안에서 반복된 값은 기존 context 요구 및 모호성 거부 유지.
- 문장 분리는 의미 판단이 아니다. URL/소수점처럼 뒤 공백이 없는 마침표는 분리하지 않는다. 약어처럼 공백이 있는 경우 과분할 가능성을 검증한다.
- 단위 사이를 가로지르는 값은 임의 합성하지 않는다. 검증 실패를 성공 처리하지 않는다.
- 입력 길이 제한은 유지하며 하위 단위400개를 넘으면 원문을 버리지 않고 명시적 실패한다.
## 영향과 위험
원문 수정에 전달하는 unitId와 텍스트 범위가 바뀌는 내부 근거 계약 변경이다. 하위 단위 증가에 따른 토큰/지연, 과분할로 인한 누락, 문맥 부족이 위험이다. 원문 전체 및 상위 제목 제공은 유지하지만 성능을 보장하지 않는다.
## 대안
1. 문맥 선택 프롬프트만 강화: 변경 작으나 이미 유사 오류 반복.
2. 수정 근거 단위 세분화(권장): 이름 반복을 구조적으로 줄이며 응답 형식 유지.
3. occurrenceIndex 추가: 일반적 위치 선택 가능하지만 응답 계약 변경과 모델의 등장 순서 계산 오류가 추가됨.
