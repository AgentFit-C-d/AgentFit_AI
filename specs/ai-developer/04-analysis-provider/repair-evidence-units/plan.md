# 구현 계획 — 사용자 승인 완료
1. 기존 구역에서 손실 없이 하위 span을 만드는 순수 함수와 회귀 테스트 작성.
2. 실제 quote 위치/중복/CRLF/URL/소수점/약어/다중 문장/400개 제한 검증.
3. source_repair opt-in 경로의 요청 units와 apply_repairs mapping만 같은 하위 단위로 교체. 초기 추출과 공개 응답은 보존.
4. 승인 시 고정한 상태 판단 프롬프트로 현재13건3회와 별도 새 문맥/부재/양성 대조 세트를 비교. 같은 간격과 호출/시간 상한 사용.
5. 기존 전체12건3회, 근거검증100%, 추가 잘못된확정0, 실패 포함 품질·지연 기록. 전부 양호해도 독립 문서와 사람 수정 부담 검증 없이는 실사용 완료 처리하지 않음.
6. 실패는 근거를 보존하고 기본값 승격 없이 결과를 보고.

## 판단 품질 분리 진단
none 추론의 수정에서 세분화만으로 S02는 중복 선택, S10은 잘못된 추가 선택이 남았다. 현재 unit 및 state v2를 고정하고 T07/S02/S03/S10에서 추론none→low만 바꿔 진단한다. 4096토큰 및40초는 유지한다. 전부 통과할 때만 동일13건 반복 비교를 확장한다. 이는 기본 서비스 설정 변경이 아니다.

## 효과 분리와 새 대조 세트
단위 분리+low의 성능 향상이 추론 변경 때문일 수 있다. 동일low/상태v2에서 기존 구역과 하위 단위를 비교한다. 별도 새9건을 사전 고정했으며 반복 이름·미정·부재·부분 부정·CRLF/제목·URL형 이름·약어 포함 제품명을 포함한다. U06의 Dr. Atlas는 승인 명세에서 예고한 과분할 위험을 직접 검증한다. 기본값을 바꾸지 않으며 유리한 결과만 선택하지 않는다.

## 비교 후 전체 흐름 후보 선택
새9건의 기존구역+low는9/9였다. 분리 방식은 U06에서 INCOMPLETE_RESPONSE를 반환했고, Dr. Atlas가 서로 다른 단위로 갈라져 정상적인 전체 이름 인용이 불가능한 구조도 확인했다. 응답 미완료의 내부 원인을 단정하지 않는다. 따라서 분리 방식은 채택하지 않고 기존구역+상태v2+low 수정으로 전체12건을 검증한다. 첫 전체 실행이 모두 통과하면3회까지 확대하고, 실패하면 해당 결과를 보존하며 기본값 승격을 보류한다.
