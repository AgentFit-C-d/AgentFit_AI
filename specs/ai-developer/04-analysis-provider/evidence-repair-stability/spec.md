# 근거 수정 안정화 명세

## 배경

새로 승인된 비식별 실문서 세 개는 기본 Solar 분석에서 모두 Profile을 반환하지 못했다. 전체·개별 호출 시간을 늘린 진단에서도 세 건 모두 `INVALID_EVIDENCE`로 끝났다. 기존 안전 진단은 단계만 기록해 어떤 공통 근거 규칙이 실패했는지 구분하지 못한다.

## 요구사항

- 기존 `safe_evidence_failure`만 사용해 필드·근거 오류 사유·항목 인덱스·일치 개수를 결과에 남긴다. 원문·인용·값·응답·키는 기록하지 않는다.
- 이미 승인된 세 문서의 원본 해시와 비식별 텍스트 해시 및 고정 골드는 바꾸지 않는다. 재평가는 오류 분류용이다. 모델 결과를 보고 골드를 수정하거나 이 문서 전용 지시를 넣지 않는다.
- 원인을 확인한 뒤 동일 오류를 재현하는 합성 입력에서 실패 테스트를 먼저 작성한다. 수정은 공통 근거 계약을 지키고 오류를 조용히 허용하지 않는다.
- 공개 Profile·Spring 계약·기본 분석기의 호출 및 시간 상한을 유지한다. 새로운 수정 경로가 필요하면 기본 동작에 즉시 섞지 않고 선택형으로 비교한다.
- 합성 회귀와 독립 평가를 분리하고, 잘못된 자동 확정·올바른 결과 거절·지연·추가 호출을 집계한다.

## 확인된 실패와 선택형 보완

비식별 재평가에서 H01은 `features/QUOTE_NOT_FOUND`, H02는 `external_integrations/CONTEXT_NOT_FOUND`, H03은 `features/VALUE_NOT_IN_QUOTE`였다. 모두 수정 호출 후의 실패다. 세 사례는 원인 조사에 사용했으므로 이후 개선의 독립 holdout으로 간주하지 않는다.

선택형 실험은 모델이 제시한 값 또는 인용이 **원문에 정확히 한 번** 등장하는 경우에만 서버가 인용 위치를 복구한다. 찾을 수 없거나 반복되면 원래 오류로 실패한다. 원문에 없는 값 생성, 공백 정규화, 임의 등장 선택은 하지 않는다. 변경된 후보는 기존 의미 검토를 그대로 통과해야 한다. 복구 횟수와 원인을 안전한 숫자·코드로 기록한다. 효과가 없거나 미확정 값을 통과시킬 위험이 드러나면 서비스 코드에서 제거하고 진단 결과만 보존한다.

## 완료 조건

1. 세 실문서 실패의 안전한 근거 오류 분류를 확인한다.
2. 재현되는 공통 원인에 대한 수정 또는 구조적으로 안전한 대안을 실험하고, 실패하면 채택하지 않는다.
3. 기존 합성·서비스 테스트와 Linux CI를 통과한다. 새 실문서가 계속 실패하면 그대로 보고하고 실사용 가능이라고 선언하지 않는다.
