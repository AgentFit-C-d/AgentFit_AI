# 근거 수정 안정화 조사 결과 (2026-09-30)

## 안전한 실패 분류

승인된 비식별 세 문서의 원본·비식별 해시와 19개 골드는 바꾸지 않았다. 전체 600초, 필드 호출 120초 진단에서 모두 `INVALID_EVIDENCE`였다.

| 문서 | 실패 필드 | 마지막 실패 이유 | 단계 |
|---|---|---|---|
| H01 Markdown | features | `QUOTE_NOT_FOUND` | repair |
| H02 DOCX | external_integrations | `CONTEXT_NOT_FOUND` | repair |
| H03 PDF | features | `VALUE_NOT_IN_QUOTE` | semantic_repair |

이 원인 확인으로 세 문서는 더 이상 독립 holdout이 아니며, 이후 실험의 튜닝 입력으로 분류한다. 모델 응답이나 Profile 값은 저장하지 않았다.

## 정확한 값 기반 인용 복구 실험

- 원문에서 값 또는 인용이 정확히 한 번 등장할 때만 서버가 근거를 복구하는 선택형 코드를 만들고 합성 테스트를 실행했다. 기본 서비스 설정은 변경하지 않았다.
- 비식별 실문서 3건의 첫 비교와 미확정 표현 방어 후 재비교가 모두 **Profile 완료 0/3**이었다. 복구된 항목이 있어도 다른 항목의 근거 오류가 이어졌다. 19개 골드는 두 비교 모두 채점할 수 없었다.
- 합성 테스트에서 `검토 중`인 값을 좁은 인용으로 복구하면 자동 확정 경로가 열릴 수 있음을 발견했다. 일부 미확정 표현을 회피하는 규칙만으로 일반적인 의미 안전성을 증명할 수 없다.
- 따라서 이 복구 코드는 서비스와 실험 API에서 제거했다. 원문에 없는 인용·문맥, 인용 밖의 값은 계속 실패 처리한다. 안전한 오류 사유 요약만 평가기에 남겼다.

## 다음 구조

현재 값·인용·문맥을 모델이 함께 작성하고 사후 수정하는 흐름의 추가 미세 조정을 중단한다. 다음 실험은 원문 후보 위치를 먼저 고정하고 모델은 후보 ID의 필드·확정 여부만 판단하며, 서버가 근거와 누락을 확인하는 구조로 진행한다. 신규 구조는 별도 feature 브랜치에서 기본 분석기와 분리해 평가한다.
