# 추출 실패 진단

## 변경
기존 평가 결과에 안전한 후보 요약과 차원별 비교를 추가했다.
정확한 값으로만 대응하며, 같은 값의 중복 후보는 다중집합으로 비교한다.
원문·인용·후보 값·응답 원본은 기록하지 않는다. 후보 위치와 허용된 분류값으로 합성 fixture와 대조할 수 있다.
서비스, 프롬프트, 채점 함수 및 fixture는 변경하지 않았다.

## 해석 규칙
- missing_exact/extra_exact는 정확 값의 미대응이다. 의미적 누락/환각의 확정 판정이 아니다.
- 같은 값 묶음의 차원별 최소 불일치 수를 계산한다. 차원별 개수는 중복될 수 있고 합산하면 안 된다.
- 값이 다르면 역할 비교 대상에서 제외된다. 역할 0이 올바른 분류를 보증하지 않는다.
- 차원별 분포가 같아도 후보 간 조합이 틀릴 수 있다. 최종 합격은 기존 튜플 score만 판단한다.
- context 불일치는 값/역할 불일치와 함께 발생할 수 있어 순수한 위치 오류 개수가 아니다.
- 부분 정답은 미정의 차원을 평가하지 않는다. expected의 unassessed는 모델 출력이 아니다.
- 부재 정답은 필드로 대응하므로 missing_exact/extra_exact도 필드 미대응 개수다.
- 구조 실패는 후보 비교 불가로 별도 보고한다.

## 확인된 오류와 평가 문제
| 사례 | 관찰 | 해석 |
|---|---|---|
| Q-001 | none에서 2개 사용자 기능 정확 추출 | 이전 0/6과 달라 반복 변동이 존재함 |
| Q-002 | 짧은 후보 대신 사용자 요청/운영자 처리 문장 단위를 추출 | 정확 값 기준 실패. 기능의 의미를 전부 놓쳤다고 단정 불가 |
| Q-003 | 개발 전용 설명을 features로 추출 | 기능 후보의 포함 여부 판단 문제. client라는 임시 정답 자체도 원문 명시 여부 검토 필요 |
| Q-004 | none에서 미사용 문장을 confirmed로 분류하고 null로 만들지 않음 | 명시적 부정/부재 판단 오류 |
| Q-005 | 회의 시간 문장을 기능 후보로 추출 | 현재 fixture의 제품 요구사항 범위와 불일치 |
| Q-006 | none에서 값·필드는 맞고 role이 product_fact | 역할 분류 오류 |

Q-002의 두 정답을 동일한 '회원 승인'으로 두는 것이 제품에서 원하는 표현인지 검토가 필요하다.
사용자 요청/운영자 처리를 구분한 표현이 유용할 수 있다. 점수를 높이기 위해 이 실행의 정답을 수정하지 않았다.

## 권장 다음 변경
1. 후보 포함 여부: 개발 작업·회의 메타정보·제품 요구사항 구분을 별도 평가 기준으로 고정한다.
2. 부재 표현: 대상 후보와 부정 범위를 묶어 판단하는 계약을 검토한다. 단순 부정 키워드 규칙으로 여러 후보를 일괄 삭제하면 안 된다.
3. 표현 범위: 기능의 표준 표시값과 원문 근거를 분리할 필요를 검토한다. 기존의 value+quote 분리 실패를 반복하지 않도록 서버가 관리하는 근거 ID 등의 대안을 먼저 작은 사례로 검증한다.
공개 계약 변경은 이번 작업에 포함하지 않는다. 어느 하나가 모든 오류를 해결한다고 단정하지 않는다.

## 실제 검증 결과
- none: 의미 1/6, 구조 6/6.
- low: 의미 0/6, 구조 5/6. Q-001은 INCOMPLETE_RESPONSE로 후보 비교 불가.
- low의 Q-004는 미사용 문장을 features로, Q-005는 회의 시간을 frontend로 분류했다.
- 이전 실험과 fixture·프롬프트·채점 revision·토큰 제한 해시/설정 동일 확인.
- 총 12회 실제 합성 호출. 각 설정 1회이며 변동이 있어 성능 개선으로 해석하지 않는다.
- 원문 관련 키 미포함 검사 통과. 전체 단위 테스트 220/220 통과.
- 진단 도구의 구현 완료이며 모델 품질 개선 완료는 아니다.
