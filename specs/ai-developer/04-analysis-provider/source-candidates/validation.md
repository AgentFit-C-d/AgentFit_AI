# 원문 후보 ID 선택 실험 결과
날짜: 2026-09-25. 브랜치: feature/source-candidate-selection. 최종 profile-v23.

**구조 검증은 개선됐지만 의미 품질은 후퇴했다. 운영 적용이나 main 병합을 권장하지 않는다.**

## 구현 범위
서버가 원문 단어/문장부호/일부 한국어 어절 경계에 전역 ID와 Unicode codepoint 좌표를 부여한다. 모델은 lineId/startId/endId/role을 선택하고, 서버가 원문에서 기능명과 근거 위치를 복원한다.
quote/occurrence 생성은 제거했다. 같은 문구가 반복돼도 ID로 구간을 특정한다. 잘못된 ID/순서/줄/역할/추가 키/중복/200자 초과/30개 초과는 거절한다.
12,000개를 넘는 후보는 잘라내지 않고 API 호출 전에 SOURCE_CANDIDATE_LIMIT으로 실패한다.
한국어 경계는 형태소 분석기가 아닌 제한된 어절 끝 분리 규칙이다. 고유어 안에서도 경계가 생길 수 있으나 원문을 삭제하거나 바꾸지는 않으며, 모델이 인접 후보를 함께 선택할 수 있다.

공개 Profile, Solar Pro4, 원문 근거 검증, 2회 추출+최대1회 수정, 네트워크 무재시도, 실패 응답 보관 정책은 유지한다. 후보표는 기능을 포함한 호출에만 제공한다. 분석기 재사용 시 문서별 후보와 스키마 상한이 섞이지 않는 것을 테스트했다.

## 단위 검증
전체 110/110 통과. 새 모듈 미구현 상태의 실패를 확인한 뒤 구현했다. 후보 수 제한 진단 코드도 실패를 확인한 뒤 허용 목록에 추가했다.
추가 11건은 Unicode/CRLF 좌표, 반복 문구, 빈 입력 후보, 후보 수 제한과 호출 차단, 잘못된 ID·순서·줄·추가 키, 중복/길이 제한, 요청별 후보표·수정 스키마, 문서별 격리, 진단 코드 전달을 검증한다.
기존 내부 응답 테스트는 새 계약으로 옮겼으며, 고정 실호출 입력과 정답은 수정하지 않았다.

v21은 이전 실행의 고정 기준 결과다. v22/v23은 각각 40건이며 실패를 빼거나 재시도하지 않았다. 별도 원인 진단용 합성 2건은 점수에 합산하지 않았다.
두 ID 버전 모두 최종 구조 검증 40/40, 기능 단계 최초 검증 40/40을 통과했다. README는 core의 deployment 근거 수정이 각 1회 필요했다.
구조 오류가 관측되지 않았다는 결과는 의미 정확성이나 이후 요청의 무오류를 보장하지 않는다. 표본이 작고 제공자 응답은 같은 설정에서도 달라진다.

## 확인한 실패 원인
- 합성 진단에서 짧은 기능명 대신 주어·서술어를 포함한 문장 전체 ID를 선택했다.
- 연동 제공자 확정 문장을 사용자 기능으로 분류했다. v23에서 이 규칙을 보완했지만 목표 기준을 충족하지 못했다.
- README는 필수 개념 포함 검사만 보면 기능이 있는 것으로 집계된다. 수동 확인에서는 여러 동작을 한 문장으로 묶고 개발·시연·연결 확인 작업까지 포함했다. 기능 품질이 해결됐다고 주장하지 않는다.
- README 전체 점수는 외부 연동의 미언급/없음 오판으로 두 번 모두 실패했다. core는 이번에 변경하지 않았다.
- v23 기존 실제 문서는 HandOff 2건 통과, AgentFit 2건 모두 database 오판으로 실패했다.
- 원문 ID를 정확히 골라도 범위와 역할이 잘못되면 구조 검증은 통과한다. ID 방식만으로 의미 판정을 해결할 수 없었다.

## 비용·한계
v23 기능 호출의 입력 토큰은 README 9,010, HandOff 21,158, AgentFit 37,079였다. 후보표를 포함해 원문을 중복 표현하므로 긴 문서의 비용과 지연이 늘어난다.
후보 수 12,000개 제한은 기존 글자 수 제한 안의 일부 입력도 거절할 수 있다는 호환성 제한이다. 사용자-facing HTTP 계약은 아직 없으며 새 진단 오류를 문서화했다.

## 보관과 판단
보고서 profile-v22-*.json / profile-v23-*.json에는 점수·해시·안전한 호출 진단만 기록했다. 실제 문서 본문, 전체 Profile, API 키, 응답 원본은 Git에 포함하지 않았다.
v22 코드와 v23은 기능 의미 범위 규칙만 다르며 plan.md에 변경 이유를 기록했다. 추가 튜닝이나 새로운 모델 비교는 수행하지 않았다.
이 실험은 채택하지 않는 것이 현재 근거에 맞다. 다음 설계는 v21과 비교하며 짧은 기능 후보의 의미 분류를 별도로 검증해야 한다. 실패를 감추기 위한 정답 완화나 자동 잘라내기는 하지 않는다.
