# 전체 후보 근거 평가 명세

## 목적

Docling·LangExtract·모델 분류·규칙 검증의 실험은 사례마다 지정한 후보 하나만 채점했다. 모델이 같은 문서에서 추가로 자동 허용한 후보가 잘못됐는지 확인하기 위해 문서별 전체 후보를 평가한다. 이 실험은 서비스 승격의 근거를 강화하지만 공개 Profile이나 기본 FastAPI 경로를 변경하지 않는다.

## 입력과 정답

- 반복 이름, 부정 범위, 검토안과 확정 기능, 제목·표를 가진 새 합성 PDF 네 문서를 고정한다. 문서마다 자동 허용해야 할 **모든** `(인용, 고유 문맥, 필드)`를 골드로 작성하고 모델 호출 전에 파일 SHA-256을 고정한다.
- 나머지 언급은 자동 허용 대상이 아니다. 한 문서 안의 같은 이름이 여러 번 나타나면 고유 문맥으로 특정한 등장만 골드가 될 수 있다. 골드 인용의 위치가 중복되거나 페이지를 가로지르면 모델 호출 전 실패한다.
- 실제 사용자가 제공한 PDF는 로컬 변환 회귀 확인에만 쓴다. 모델에는 고정 합성 문서만 보낸다.

## 전체 후보 점수

1. PDF를 선택한 입력 경로에서 변환하고 LangExtract가 모든 후보를 추출한다. 별도 Solar 호출이 각 후보의 필드와 확정·부정·검토 상태를 골드 없이 분류한다.
   필드 지시문은 `database`를 데이터 저장 엔진·DB 제품, `features`를 제품 기능·동작으로 정의하고 표의 기능 이름을 각 후보별로 독립 판단한다.
2. 서버가 후보 인용과 문맥을 정규 텍스트의 코드포인트 구간에 매핑한다. 모호·중복·페이지 경계 오류는 자동 허용하지 않는다.
3. 분류 상태가 확정이고 필드가 허용 필드일 때만 기존 `guard_candidate`를 적용한다. 자동 허용 후보는 해당 페이지의 정확한 근거 구간이 있어야 한다.
4. 자동 허용 `(구간, 필드)`가 골드에 없으면 오확정, 골드가 자동 허용되지 않으면 허용 누락으로 센다. 같은 구간의 중복 후보를 둘 다 허용하지 않는다. PDF·모델·분류 실패는 해당 문서의 실패로 남기고 0점 성공처럼 집계하지 않는다.
5. 결과에는 문서·범주별 건수, 오확정, 누락, 정확 근거, 실패 코드만 저장한다. 원문·인용·모델 응답·키는 파일과 일반 로그에 남기지 않는다.

## 승격 관문

- 오확정 0과 모든 자동 허용의 정확 근거가 필수다. 4개 합성 문서 통과만으로 실사용 가능을 선언하지 않는다. 새 실제 문서의 독립 골드, Profile 전체 필드, Spring 연동, PDF 시간·메모리 예산은 별도 관문이다.
- `--live`와 고정 fixture 해시가 확인되기 전에는 키를 읽지 않는다. 모델 출력 형식·수량이 잘못되면 보수적으로 실패한다.
- 이 평가셋의 필드는 `database`와 `features` 두 종류다. 공개 Profile의 나머지 필드 전체 정확도는 여기서 검증되지 않는다. 원인 조사나 지시문 수정에 사용한 합성셋은 독립 최종 검증셋으로 부르지 않는다.
