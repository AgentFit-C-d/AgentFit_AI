# 검증 결과
## 수정 호출만 분리한 고정 비교
기존 실패2건과 새12건을 사전 고정했다. 새12건은 전체10필드 양성 각1건과 부재/미정을 포함한다. 같은 null 초안과 고정 이슈를 주며 gold는 전송하지 않았다. Mini4/none/4096토큰/40초, 각 조건1회다.

| 조건 | 통과 |
|---|---:|
| 기존 수정 프롬프트+기존 예시 | 6/14 |
| 최종 값 경계 명확화 v1 | 12/14 |
| 스칼라 규칙/예시 포함 v2 | 14/14 |

v1의 스칼라 실패2건만 다시 진단했을 때 domain은 정답 앞7자/뒤2자까지 포함했고 deployment는 정답으로 변했다. 이는 과도한 인용과 실행 변동의 증거이며, 두 오류가 항상 재현된다는 뜻은 아니다.

## 새 합성8건 전이 비교
v2를 고정한 후 별도로 작성한 합성8건에서 v1 5/8, v2 7/8이었다. v1은 domain/deployment 및 부분 연동 부정 사례에서 실패했다. v2는 이3건을 통과했으나 T07에서 회귀했다.
T07은 개발용 모델만 명시하고 운영 제공자는 미정인데, 잘못된 missing 이슈를 강제로 준 통제 사례다. v2는 null을 유지하지 못했다. 이 결과를 숨기거나 부재/unknown의 정답 기준을 바꾸지 않는다. 기본 설정 승격 근거로 사용할 수 없다.

## 코드 검증 및 범위
구현 전 옵션 회귀 테스트 실패; 구현 후 전체 unittest279건 통과. repair_value_boundary의 기본값은 False이며 source_repair가 켜져 있어야 활성화한다. 공개 Profile·호출 한도·원문 검증 판정은 유지한다. 프롬프트 버전과 해시를 기록한다.
평가에는 성공 원문/추론 내용/키를 저장하지 않는다. fixture는 합성 자료이며 예약 공개 문서 및 실제 문서를 이번에 전송하지 않았다.
단일 단문에 대한 전체10필드 양성 관측은 다양한 실제 문서의 필드별 정확도/재현율을 대신하지 않는다. 사람 수정 시간과 독립 문서 검증은 미완료다.

## 전체 흐름 반복
같은 고정 합성12건을 동일 옵션으로 3회 실행해 **12/12, 12/12, 12/12**로 끝났다. 총36회는 서로 다른36문서가 아니다. 기존 동일 세트 직전10/12와 비교해 이번에는 기능·모델 값 범위 오류가 관측되지 않았다.
- 시간 중앙값 8.95초, nearest-rank p95 23.62초, 최대 27.03초.
- 이번 관측의 최대 호출 수 5회. 실제 복잡한 문서의 호출 수/시간을 증명하지 않는다.
- 공개 Profile 근거 검증 및 외부 gold 일치를 모두 통과했다.
- 같은 노출 자료 반복이며 독립 문서 평가가 아니다. T07의 수정 단독 회귀는 여전히 남는다.
- 다음 작업: 잘못된 missing 지시를 받은 개발 전용/운영 미정/부분 부정 원문에서 범위·상태를 먼저 판단하는지 고정 대조로 검증한다. 현재 설정은 기본값으로 승격하지 않는다.
