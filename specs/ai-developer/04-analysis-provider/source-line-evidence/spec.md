# 원문 줄 ID 기반 근거 계약 실험

## 문제와 목적

새 공개 PRD 5건의 사전 고정 평가에서 기본 Solar 5건과 문맥·병렬 Solar 5건 모두 자동 완료가 0건이었다. 첫 core 또는 features 추출에서 원문에 없는 인용·문맥을 생성한 사례가 반복됐고, 수정 호출은 40초 안에 완전 복구하지 못했다. 수정 단계의 문맥 선택지보다 앞선 최초 추출의 정확 인용 부담을 줄이는 것이 목적이다.

## 내부 계약

- 선택형 `line-evidence-v1`은 서버가 원문을 손실 없이 줄로 나누고 `[L번호]`를 붙여 모델에 보낸다. 모델은 확정 필드마다 `value`·`lineId`·`role`만 반환한다. `quote`·`context`·문자 오프셋·등장 순서는 생성하지 않는다.
- `value`는 선택한 줄의 정확한 연속 문자열이어야 한다. 서버는 해당 줄에서 값이 정확히 한 번 나타날 때만 그 구간을 근거 span으로 계산한다. 없거나 반복되면 해당 필드를 오류로 보류하고 임의의 위치를 고르거나 유사 문자열로 보정하지 않는다.
- 미언급·미정·후보·상충은 `null`이다. 배열 필드의 명시적 없음은 `absent`와 원문 줄 ID로만 표현한다. `role`은 기존 필드별 허용 역할을 그대로 적용한다. 전체 Profile·의미 검토·복구형 확인 질문 계약을 유지한다.
- 최초 core/features와 오류 필드 수정 모두 이 계약을 사용한다. 기존 기본 분석기와 기존 근거 계약은 변경하지 않는다. 호출 최대 6회, 분석 전체 60초, 평가 내부 40초를 유지한다.
- 진단에는 계약 버전과 필드·안전 오류 코드·시간만 남긴다. 원문·값·키·모델 원본은 성공 로그에 저장하지 않는다. 실패 원본 7일 정책은 기존 구현을 따른다.

## 검증

- 값이 줄에 없음, 한 줄에 동일 값 반복, 잘못된 줄 ID·역할·상태, 배열 중복, CRLF·Unicode·긴 줄, 가상 예시, 명시적 없음의 단위 테스트를 작성한다.
- 선택형 전체 흐름에서 기한·호출 수·보류 질문·기본 분석기 불변을 확인한다.
- 이미 평가에 사용한 PRD 5건은 `tuning`으로만 재실행한다. 동일한 고정 정답으로 상태·일치·누락·근거 오류·미정·시간을 기록하되 확률적 별도 실행을 인과 비교나 독립 검증으로 주장하지 않는다.
- 자동 완료나 누락 감소가 확인되지 않거나 구조 오류·지연이 늘면 운영 기본값으로 적용하지 않는다. 새 독립 문서와 Spring 확인 후 저장 E2E는 별도 출시 조건이다.
