# 구역별 기능 의미 검토 설계

## 목적과 근거

원문 선택자 분석의 기능 검토는 Campfire PRD 547줄·20,471자 전체를 한 요청에 넣을 때, 묶음당 4,096과 8,192 출력 토큰 상한에 차례로 도달했다. 제목 32개와 제목 사이 최대 99줄이므로 서버가 문서의 모든 줄을 120줄 이하의 6개 구역으로 분할할 수 있다. 사용자는 시간보다 정확도를 우선하고, 최대 12호출의 선택형 구역 검토 실험을 승인했다.

목표는 기능 누락 탐색을 원문 전체에 걸쳐 유지하면서 한 번의 기능 검토 입력을 줄이는 것이다. 검토되지 않은 줄이 하나라도 있으면 자동 완료하지 않는다.

## 선택한 구조

- `section_feature_review=False`가 기본이다. 선택형 원문 선택자 분석기에서만 기존 3묶음 검토 중 A/B는 유지하고, C(`features`)를 결정적 원문 구역별 검토로 대체한다. 기본 Solar·FastAPI·공개 Profile은 바꾸지 않는다.
- 서버는 `source_lines(document)`의 줄 ID 1..N을 Markdown `#`~`###` 제목 경계로 나누고, 인접 구역을 순서대로 합쳐 최대 120줄의 검토 청크를 만든다. 120줄 초과 단일 구역은 줄 단위로 나눈다. 제목 없는 문서도 같은 줄 상한을 적용한다. 빈 줄·마지막 줄도 정확히 한 청크의 커버 범위에 포함한다. 원문 범위의 합집합은 1..N, 교집합은 공집합이어야 한다.
- 현재 문서가 7개 청크를 초과하면 모델을 호출하기 전에 안전하게 보류한다. 최대 2회 추출+1회 구조 수정+2회 A/B 검토+7회 기능 청크 검토=12호출이다. 더 긴 문서에서 부분 결과를 자동 완료로 사용하지 않는다.
- 각 기능 청크 요청은 그 구역의 원문 줄과 필요하면 상위 Markdown 제목을 읽기 전용 문맥으로 받는다. 문맥용 제목이 구역 밖에 있더라도 출력 가능한 근거 줄 ID는 해당 청크의 커버 범위만 허용한다. 현재 Profile의 `features` 중 근거가 구역에 걸친 항목만 전역 ID와 값·해당 구역의 근거 줄로 전달한다. 여러 구역에 근거가 있는 항목은 각 구역에서 검토하되, 구역 밖 항목을 `unsupported`로 판정하지 않는다.
- 모델은 그 구역의 현재 제품 기능 누락과 해당 구역에 속한 초안 기능의 의미 오류를 짧은 `issues`로 반환하고, 정확한 구역 ID·범위를 `checkedRange`로 재확인한다. 기존 항목 오류의 targetId는 그 구역에 포함된 항목의 전역 ID여야 하며, missing은 targetId=null과 구역 내부 원문 줄 ID를 포함한다. 서버는 구역·ID·근거·종류·응답 내 중복을 검증한다. 여러 구역의 동일 targetId 오류는 같은 종류일 때 하나로 합치고, 종류가 충돌하면 보류한다.
- 모든 A/B 및 기능 청크 응답이 유효하고 청크들이 모든 줄을 정확히 덮고 이슈가 없을 때만 자동 완료한다. 어느 한 응답이 미완료·형식 오류·시간 초과이거나 의미 이슈를 반환하면 자동 완료하지 않는다. 유효 이슈가 있으면 모든 성공 청크를 모은 뒤 해당 필드를 확인 필요로 처리하고, 이 선택형 모드에서 의미 수정·재검토를 하지 않는다.
- 기능 청크마다 출력 상한은 기존 묶음 검토와 같은 8,192토큰이다. 실험용 호출 상한은 정확히 12회이고 전체 기한은 평가 전용 600초다. 호출 상한에 걸리거나 청크 수가 7개를 초과하면 기존 복구 초안의 `needs_confirmation` 또는 안전 실패로 처리한다. 진단에는 원문·응답 원본·키·Profile을 남기지 않는다.

## 대안과 결정 이유

- 기능 묶음의 출력 상한만 더 높이면 이미 4K→8K에서 병목이 다음 묶음으로 이동했고 8K 기능 검토는 미완료였다.
- 검색 상위 구역만 검토하면 누락된 기능의 위치를 모르므로 자동 완료의 커버리지 근거가 약해진다. 모든 줄을 결정적으로 덮는다.
- 다른 모델로 전체 파이프라인을 바꾼 GLM/Kimi 한 건씩의 결과는 추출 모델도 달라 기능 검토 모델만의 효과를 분리하지 못했다.

## 검증과 승격 조건

- 오프라인 테스트는 제목/비제목/긴 구역/빈 줄/끝줄의 정확한 커버리지, 최대 7청크, 구역 밖 이슈·대상 ID·근거 줄 거부, 마지막 청크 실패의 자동 완료 금지, 최대 12호출, 기본 경로 불변을 증명한다.
- 이미 튜닝에 사용한 Campfire 1건을 먼저 시험한다. 모든 청크가 유효하고 의미 이슈·부분 정답·미평가 값을 평가할 수 있을 때만 고정 튜닝 PRD 5건으로 확대한다. 실패하면 기본값으로 승격하지 않는다.
- 새 독립 실제 문서의 사람 검토와 Spring/Frontend 사용자 확인 전 저장 금지 E2E 없이는 실사용 가능 판정을 하지 않는다.
