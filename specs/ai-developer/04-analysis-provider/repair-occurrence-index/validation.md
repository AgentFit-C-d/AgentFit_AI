# 검증 결과
## 구현
원래 구역에서 quote의 비중첩 등장 순서를 서버가 찾아 전역 오프셋으로 변환한다. index 범위·정수 타입·실제 존재·중복·역할·상태 검증을 유지한다. context와 occurrence 계약은 opt-in으로 분리하며 기본 분석 경로를 바꾸지 않았다. 문장 분리와 동시 사용은 거부한다. 기존 호출6회/60초는 유지한다.

## 부재 근거 판정
O08은 context/none과 occurrence/low 모두 현재 정책의 접두사까지 포함한 동일 start24/end50을 선택했다. 값 ai=[]는 맞았고 독립 검토에서 유효한 근거로 판단했다. 고정 정답34/end50보다 넓다는 이유로 strict 점수에서는 실패다. 결과 파일과 고정 정답은 바꾸지 않았다. 같은 판정을 양쪽 조건에 적용하면 의미상 유효한 건은 각각9/14,12/14이나 사후 판정이므로 사전 고정 게이트 통과로 보고하지 않는다.
후속 평가에서는 같은 현재 문장 안의 유효 경계를 사전 허용해야 한다. 단순한 gold 포함 조건은 예시/과거/문서 전체까지 허용할 수 있어 금지해야 한다.

## 남은 문제와 결정
occurrence/none은 잘못된 등장 순서·중복·상태 판단 오류를 남겼다. low는 일부 개선됐지만 O09/O12가 각각40초에 PROVIDER_TIMEOUT이었다. 모든 관문을 통과하지 못했으므로 전체12건3회 확대는 수행하지 않았고 기본값을 승격하지 않았다.
서버의 위치 계산은 검증됐지만 모델이 올바른 등장을 지정하는 것은 아직 신뢰할 수 없다. 모델이 순서를 계산하는 대신 서버가 후보 위치를 먼저 열거하고 모델은 ID를 선택하도록 하는 접근을 후속 검토할 필요가 있다. 이는 별도의 계약/흐름 설계 검토가 필요한 제안이며 아직 구현하지 않았다.

## 코드 검증
전체 unittest299건 통과. 신규 검증기 테스트가 미구현 상태에서 실패한 뒤 구현 후 통과했다. 기존 context 경로, 원래 units, 약어·CRLF·Unicode·비중첩 인용·부재·엄격한 숫자·잘못된 근거 위치 채점을 확인했다. 독립 검토 P2를 고정 위치 정답과 재실행으로 보완했다.
예약 공개 문서는 읽거나 전송하지 않았다. 실사용 목표의 독립 문서 품질과 사람 수정 부담은 미검증이다.
