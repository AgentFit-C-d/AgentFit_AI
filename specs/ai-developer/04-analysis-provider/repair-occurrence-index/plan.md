# 구현·검증 계획 — 사용자 승인 완료
1. 별도 repair-occurrence-index feature 브랜치에서 opt-in schema/검증기 및 분석기·평가기 옵션을 추가한다. 기본 context 경로는 유지한다.
2. 실제 인용 목록 계산, 경계값·비정수·존재하지 않는 등장·중복·약어·Unicode 전역 오프셋 테스트를 먼저 작성한다.
3. 값/역할/상태뿐 아니라 기대 evidence span을 포함한 새 합성 대조 세트를 API 실행 전에 확정한다.
4. Pro4/none에서 기존 context 대비 새 계약을 비교한다. 13건 기존 세트와 새 위치 대조를 모두 측정하고 실패·지연도 기록한다.
5. 첫 관문 통과 시 전체12건3회 및 새 대조 반복을 수행한다. 6회60초 초과·잘못된 근거 위치는 실패로 집계한다.
6. 기본값 승격 없이 실험 코드와 결과를 commit/push한다. 독립 실제 문서·사람 수정 부담 검증이 없으면 목표 달성 처리하지 않는다.

## 검토 반영: 기존 상태 세트 위치 정답
최초13건은 이전 평가와 같은 값 정답만 사용했다. 이 결과를 근거 위치 해결 증거로 쓰지 않는다. 기존 cases.json은 보존하고 state-evidence.json에 위치 정답을 별도 고정했다. S02는 운영 문장에 있는 두 번째 Seabird가 정답이다. 이를 적용한 별도 재평가 결과와 기존 결과를 구분한다. 부재 사례는 명시적 전체 부재 문장 전체를 정답 span으로 둔다.

## 위치 정답 평가 후 추론 대조
새14건에서 기존context/none은8/14, occurrence/none은7/14였다. occurrence는 잘못된 위치 선택, 중복·과거 사실 채택이 드러났다. Pro4 모델과 프롬프트·스키마·정답·4096토큰·40초를 고정하고 occurrence/low를1회 평가한다. 정확도뿐 아니라 timeout도 실패로 센다. 전부 통과하지 않으면 전체 흐름3회 관문은 수행하지 않는다. none 위치 정답을 사후 수정하지 않는다.
