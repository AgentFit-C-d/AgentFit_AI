# 대표 기능 그룹의 한 차례 복구

## 목표와 근거

실사용 가능한 기획서 분석을 위해 미포함 기능을 확인 필요로 표시하는 데서 더 나아가, 원문 후보를 활용해 잘못된 대표 그룹을 복구한다. 사용자는 설계·계획·실행의 자율 진행과 기능별 feature 브랜치 push를 승인했다. 기존 작업 폴더를 재사용하고 base는016c954다.

H02의 고정 분할은 관계 검토를 개선한 뒤에도 원래 분할에서6개, 역순 분할에서23개가 미포함으로 남았다. 앞단의 대표 제안이 바뀌지 않으면 관계 검토만으로 해당 기능을 대표 목록에 복구할 수 없다. 소스 후보의 누락·오분류 및 다른9필드의 오류는 별도 문제다.

대안은 미포함 각각을 독립 대표로 승격, 전체 그룹 재제안, 임의 요약문 생성이다. 일괄 승격은30개 제한과 중복을 해결하지 못하고, 새 요약문 생성은 공개 근거 계약까지 바꾼다. 기존 검토의 미포함 ID와 전체 후보를 주고 한 번 재제안한 뒤 새 관계를 모두 검토하는 방식을 선택한다. 이미 포함으로 판단한 관계도 고정하지 않는다. 이전 판단이 틀렸을 가능성 때문이다.

## 계약

1. `repair_feature_curation(document,frozen,reviewed_labels,curation,key,*,model=MODEL,transport=None,call_trace=None)->dict`를 새 `candidate_feature_regrouping.py`에 구현한다. 기존 옵션·문서·후보·curation을 먼저 검증한다. 원본 인수는 수정하지 않는다.
2. 검증된 미포함 집합은 `unrepresentedIds`와 `uncoveredIds`의 합집합이다. 빈 집합이면 API0회로 독립 사본을 반환한다. 반환 uncoveredIds는 입력 후보 순서의 합집합으로 정규화한다.
3. 미포함이 있으면 전체 확정 features 후보, 원문, 이전 `groups/unrepresentedIds/uncoveredIds`를 전달해 새 전체 분할을1회 제안받는다. 이전 검토는 수정할 지점을 알려주는 자료이며 정답 강제 지시가 아니다. 후보·대표는 기존ID만 사용하며 새 기능이나 근거 위치를 만들지 않는다.
4. 기존 엄격 분할 검증과 동일 문구 대표 정규화를 재사용한다. 모든 후보는 그룹 또는 미대표에 정확히1회 배정돼야 한다. 최대30대표, 대표 원문200code point 이하, 서로 다른 대표 값이다. 강제로 묶어 제한을 채우지 않는다.
5. 정규화 후 후보→대표의 배정과 미대표 집합이 이전과 같으면 추가 의미 검토 없이 기존 curation 사본을 반환한다. 그룹/구성원/미대표 나열 순서만 달라지는 경우도 같다. 같은 답의 재검토로 우연히 미포함을 지우는 반복을 피한다.
6. 배정이 바뀌면 `review_feature_relations`로 새 비자기 관계를 모두 최대1회 검토한다. 새 대표의 자기 포함·미대표는 서버가 계산한다. 검토 결과가 이전보다 나쁘더라도 개수만으로 이전 판정을 복원하지 않는다. 새 uncovered는 그대로 보존하며 추가 복구를 반복하지 않는다.
7. 분할·검토의 구조 오류 또는 공급자 실패는 예외를 전달한다. 실패한 제안을 완성 curation으로 반환하거나 원래 결과로 숨기지 않는다. 정상 재검토의 미포함/불확실은 기존 finalize의 확인 필요에 남는다.
8. 기존 `curate_reviewed_features`는 첫 제안·검토 뒤 이 복구를 한 번 연결한다. 전체0~4호출, 복구0~2호출, 재시도0이다. 처음부터 검토 완료면 기존 최대2호출, 기능 고유값30개 이하는 기존0호출/None을 유지한다. HTTP/기본 분석기는 아직 이 실험 경로를 사용하지 않는다.
9. 기존4키 curation·공개Profile·다른9필드·검토된 labels·기존 확인 필요 사유는 유지한다. 입력순서 미포함 목록을 보존한다. 대표 자신 미포함은 계속 거절한다.

## 구현 범위와 상한

- 기존 제안 코드만 `_propose_feature_partition(document,candidates,key,*,model,transport,call_trace,previous_curation=None)`로 추출한다. 첫 제안의 입력·스키마·프롬프트·진단은 유지한다. 재제안의 schema name/stage는`agentfit_feature_regrouping`/`feature_regrouping`이다.
- 재제안에서는 대표 value의 범위를 주변 다른 동작으로 확장하지 않는 검증된 일반 문맥 규칙을 사용한다. 특정 문서명·후보ID·정답을 프롬프트에 넣지 않는다.
- 문서100,000code point, 후보240개, 대표30개/200code point, 출력8192토큰, 호출별timeout600초, 기존 Solar/NVIDIA 허용 모델을 유지한다.
- 진단은 기존 공급자 메타데이터와 안전한 개수/오류/stage만 기록한다. 원문·키·응답 전문·추론·자유 사유를 저장하지 않는다. 실제 평가 드라이버와 ID 결과는 로컬tmp에 둔다.

## 수용 기준

- 새 배정과 모든 새 관계가 실제로 재검증되고, 재구성이 처음의 미포함을 되살릴 수 있다.
- 기존 포함 관계가 새 검토에서 미포함으로 바뀌어도 보존하고 자동 완료하지 않는다. 불확실·미대표도 누락하지 않는다.
- 0호출/동일 분할1호출/수정 분할최대2호출/전체최대4호출이 테스트된다. 더이상 재귀 재시도가 없다.
- 입력 오류는 전송 전에, 잘못된 재제안은 관계 검토 전에 실패한다. 같은 문구 다른 위치는 정규화 뒤에도 의미 검토한다. 모델 위장·length·전송 실패와 민감 진단도 검증한다.
- 관련 테스트, 전체 회귀, 독립 코드 리뷰1회, push와 정확한 Linux CI를 확인한다.
- 실측은 H02의 완료v2 두 curation을 고정해 복구만 각최대2호출,총최대4회 실행한다. 후보/분류/첫제안은 다시 호출하지 않는다. 먼저 해시·라벨·완료 상태를 확인한다. H02는 튜닝 자료다.
- 이전 36쌍 점수는 새 배정의 정확도로 재사용하지 않는다. 새 대표와 새 비자기 관계를 로컬 원문으로 전수 감사한다. 미포함 개수 감소만으로 성공 선언하지 않으며 허위 포함·누락·새 오판을 함께 기록한다. 다른9필드/labels 불변을 확인한다.

다문서·반복 재현성, 좋은 대표 문구 선택, 선행 누락·오분류, HTTP/Spring 확인·저장 통합은 전체 실사용 목표에 남는다. 이 기능만으로 목표를 완료하지 않는다.
