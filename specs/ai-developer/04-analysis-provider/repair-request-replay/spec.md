# 실제 수정 요청 재현
목적: 전체 흐름 N-004와 단독 평가의 입력 차이를 확인하여 미완료 실패를 진단한다.
전체 분석을 기존 설정(statev2/valuev2/low/4096/원래구역)으로1회 실행한다. source_repair payload는 프로세스 메모리에서만 복사하고 기존 전송은 그대로 수행한다. 그 요청을 그대로3회 단독 재생하여 전송·근거 검증·정답 일치를 측정한다.
비교: 단독 평가가 구성하는 document/requestedFields/previous/issues/units와 실제 요청의 동등 여부를 필드별 bool로 남긴다. system prompt 및 schema 동일성도 확인한다. 해시/성공 여부/토큰/시간/고정 오류코드만 보관하며 요청·응답·추론 원문은 파일에 저장하지 않는다.
범위: 고정 합성 N-004 전용 CLI. 서비스 경로 변경 없음. 전체 분석6회60초는 그대로이며 별도 재생3회는 연구 호출로 구분한다. 서비스 재시도 정책으로 도입하지 않는다.
