# 기본 Solar 분석의 복구형 초안

## 배경과 범위

현재 서비스 Worker의 `SolarAnalyzer`는 의미 검토 시간 초과 등으로 실패하면 근거 검증을 이미 통과한 초안도 버린다. 기존 Anchored 복구형 분석기는 성공 경로 오확정과 시간 한계가 남아 있어 그대로 기본값으로 승격할 수 없다. 이번 기능은 현재 Solar 분석의 성공 경로를 유지한 선택형 `analyze_recoverable()`만 추가한다. 서비스 Worker 연결은 별도 기능에서 검증한다.

## 결과 계약

- 기존 분석 성공은 `complete`와 기존 Profile을 그대로 반환한다.
- 실패 전에 **전체 필드의 구조·근거 검증을 통과한** Profile이 없으면 `failed`와 안전 오류 코드만 반환한다. 필드별 격리 검증 결과나 부분 원본 모델 응답은 초안으로 사용하지 않는다.
- 첫 의미 검토가 완료되지 못한 경우 검증된 값은 `suggested`로 유지하되 **각 제안 필드에 `REVIEW_UNAVAILABLE` 확인 질문**을 붙인다. null 필드는 `unknown`으로 두고 일괄 질문하지 않는다. 후속 UI는 unknown 필드도 편집 가능하게 보여 주고, suggested 값은 명시적 확인 전 저장하지 않아야 한다. 이를 자동 확정으로 취급하지 않는다.
- 의미 검토가 구체적 오류를 지적한 뒤 실패하면 지적된 필드 값을 제거하고 `REVIEW_ISSUE` 질문을 붙인다. 나머지 구조 검증된 값은 제안 상태로 남긴다.
- 모든 초안은 공개 Profile 검증을 다시 통과해야 한다. 검토 이슈 필드 제거 **후** 값이 하나도 없으면 확인 질문만 보내지 않고 `failed`로 반환한다.
- 원문, API 키, 모델 원본 응답, 임의 예외 문자열을 결과에 넣지 않는다. 최대 6회 호출과 기존 분석 기한을 유지한다.

## 수용 기준

1. 검토 시간 초과에서 제안 값과 명시적 질문이 함께 나오며, 원문·키가 오류나 질문에 섞이지 않는다.
2. 검토 오류가 지적한 필드는 제거되고 질문이 생긴다. 정상 성공은 기존 Solar Profile과 같다.
3. 구조 검증 전 실패와 값 없는 초안은 `failed`다.
4. 동시 호출 간 임시 초안이 섞이지 않는다. 전체 단위 테스트와 제한된 실제 모델 평가로 미검토 제안의 정오를 별도 기록한다.
