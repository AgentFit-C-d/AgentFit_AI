# 검증 기록

## 자동 테스트

- 구조 검증 전 실패, 검토 시간 초과, 검토 이슈 필드 제거, 제안 값 0개 처리, 제안별 질문, 기존 초안 기본 동작, 동시 요청의 초안 분리를 회귀 테스트로 검증했다.
- AI 서비스 전체 단위 테스트는 최종 수정 후 다시 실행한다.

## 실제 모델 평가

- 수정 전 로컬 합성 20건: `complete` 12, `needs_confirmation` 7, `failed` 1. 실패에서 보존한 제안 값 18개, 질문 70개. 제안 값 0개인 `needs_confirmation` 3건이 결함이었다. 완료 건의 관측된 오확정은 0건이지만, 제안 28개와 의미 근거 35개는 독립 채점되지 않아 평가 게이트가 실패했다.
- 이번 수정은 제안 값 0개면 `failed`로 돌리고, 미검토 null 필드는 `unknown`으로 유지한다. 수정 코드의 실제 Solar 20건 재평가는 **미실행**이다. 합성 문서 20건의 Upstage API 전송이 자동 승인 검토에서 차단되어 구체적 승인을 기다린다. 수정 전 실행 수치를 수정 후 성능으로 간주하지 않는다.

## 적용 범위와 남은 문제

- `RecoverableSolarAnalyzer`는 선택형 내부 실험이다. 기본 Worker, FastAPI, Spring 저장 경로에 연결하지 않았다.
- 미검토 `suggested`는 반드시 사용자 확인을 거쳐야 한다. `unknown`은 후속 UI에서 편집할 수 있어야 한다. FastAPI의 현재 확인 응답 검증과 Spring 저장 계약은 별도 연동 작업이 필요하다.
- 합성 20건은 튜닝에 사용한 자료다. 독립 실제 문서 검증과 제안·의미 근거의 사람 채점 없이는 실사용 준비 완료를 선언할 수 없다.
