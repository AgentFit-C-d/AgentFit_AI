# 전체 분석 60초·120초 비교 결과

## 조건

기존 ID별 후보 opt-in 분석을 같은 Solar Pro4·v2·의미 검토 설정으로 합성 20건에서 교차 실행했다. 두 조건의 후보·판단·의미 검토 **개별 호출 상한은 동일하게 40초**로 고정했다. 전체 제한만 60초와 120초로 바꿨다. 정답은 API로 전송하지 않았다.

독립 코드 검토에서 최초 집계가 정확도 회귀, 전체 제한 오류 단계, 60초 실제 경과 초과를 놓치는 문제를 찾았다. 사례별 실행 결과는 그대로 보존하고, API 재호출 없이 [수정된 사례 결과](results/run1/results-reviewed.json)와 [수정된 집계](results/run1/summary-reviewed.json)를 생성했다. [최초 계획](results/run1/plan.json)의 평가기 해시는 실행 당시 코드를 가리키고, 수정 집계에는 별도 `aggregation_sha256`을 기록했다. 최초 `summary.json`은 최종 판정에 사용하지 않는다.

| 지표 | 전체 60초 | 전체 120초 |
| --- | ---: | ---: |
| 전체 Profile 완전 일치 | 5/12 | 6/12 |
| 전체 Profile 필드 일치, 실패 0점 | 50/120 | 60/120 |
| 다구역 최종 성공 | 0/8 | 0/8 |
| 다구역 지정 사실, 실패 0점 | 0/27 | 0/27 |
| 제공자 호출 시간 초과 | 6건 | 4건 |
| 전체 분석 제한 초과 | 0건 | 0건 |
| 검증·의미 오류 | 9건 | 10건 |
| 잘못된 확정 | 0건 | 0건 |
| 최대 호출 수 | 6회 | 6회 |
| 다구역 지연 중앙값 | 50,109.5ms | 50,765.5ms |
| 다구역 관측 p95 | 60,063ms | 78,047ms |

120초에서 추가로 성공한 사례는 짧은 Q-002 한 건이다. 양쪽 모두 성공한 전체 Profile 5건은 각각 50/50 필드 일치로 동률이었다. 다구역 문서는 어느 조건에서도 최종 결과를 내지 못했다. 60초의 제공자 시간 초과 6건은 모두 의미 검토 단계였고, 120초의 4건은 의미 검토 2건·재검토 2건이었다. 후보·판단 호출 또는 전체 제한 초과는 관측되지 않았다.

## 판정과 한계

- 완전 일치 1건 증가와 시간 초과 2건 감소는 관측됐지만, 전체 제한 초과가 **0건**이므로 전체 예산 60→120초가 직접 원인이었다고 볼 수 없다. 호출당 40초 시간 초과와 모델 응답 변동이 혼재한다. 각 조건 한 번씩 실행했으며 사례는 기존 튜닝 자료다.
- 검증·의미 오류가 9→10건으로 늘었고, 다구역 성공은 0/8 그대로다. 사전 관문의 `validation_errors_no_increase`가 실패했다.
- 60초 조건에서 실제 경과가 60,063ms인 호출이 있었다. 블로킹 네트워크 호출이 경계를 조금 넘을 수 있어 엄격한 60초 반환 관문도 실패했다. 120초 조건의 실제 경과는 120초 이내였다.
- **결론:** 전체 제한만 120초로 늘리는 방안은 기본 서비스에 적용하지 않는다. 다음 병목은 의미 검토 호출의 지연·형식 오류와 후속 의미 병합 실패다. 120초 결과로 실사용 가능성을 주장할 수 없다.

## 검증

기본 60초·선택형 120초, 공통 호출 상한, 잘못된 오류 단계 방지, 정확도 회귀 관문 테스트를 포함한 전체 회귀 테스트를 실행했다. 평가 결과에는 사례 ID·안전한 점수·오류 코드·호출 수·지연만 남기며 문서 원문·인용문·키·모델 원본 응답은 저장하지 않았다.
