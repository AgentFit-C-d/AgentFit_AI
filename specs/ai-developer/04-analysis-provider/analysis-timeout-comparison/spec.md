# 전체 분석 60초·120초 비교 명세

## 목적

ID별 후보 분석에서 전체 60초 제한을 120초로 늘렸을 때, 최종 Profile 성공률과 정확도가 실제로 개선되는지 확인한다. 시간 부족으로 실패한 건과 근거·의미 판단 오류를 분리해 다음 보완 우선순위를 결정한다.

## 실험 계약

- 기존 opt-in ID별 후보 분석 경로를 사용한다. 동일한 Solar Pro4, 프롬프트, 판단·검토 설정과 합성 20건을 60초와 120초로 교차 실행한다. 문서별 두 조건의 순서를 번갈아 바꾼다.
- 두 조건 모두 후보·판단·의미 검토의 개별 호출을 최대 40초로 제한한다. 전체 제한만 60초와 120초로 달리한다. 최대 6회 호출은 유지한다.
- 전체 Profile 12건은 10개 필드의 값·미정·부재를, 다구역 8건은 지정 사실 27개와 배제 사실을 기존 비교와 같은 채점기로 평가한다. 실패 건은 0점으로 포함하고 양쪽 모두 성공한 쌍도 별도로 보고한다.
- 호출 단계별 제공자 시간 초과와 전체 제한 초과, 후보·병합·의미 검토 실패를 구분한다. 사례 ID, 코드·자료 해시, 안전한 점수·오류 코드·호출 수·지연만 저장한다. 문서 원문, 인용, 키, 모델 원본 응답은 저장하지 않는다.
- 기본 서비스의 60초 제한과 호출별 동작, 공개 Profile은 변경하지 않는다. 120초는 평가 전용 opt-in이다.

## 사전 판정 기준

1. 두 조건 모두 20건을 시도하고 각 조건 최대 6회 호출을 지킨다. 실제 경과가 120초를 넘는 호출은 별도로 보고한다.
2. 120초의 최종 성공·정답이 60초보다 증가하는지, 오확정·검증 오류가 늘지 않는지 확인한다. 제공자 시간 초과와 후속 의미 오류의 변화를 분리한다.
3. 120초가 개선돼도 기존 합성 튜닝 자료만으로 실사용 가능 또는 기본 제한 변경을 결정하지 않는다. 오확정 증가, 정확도 회귀 또는 과도한 지연은 적용 보류 사유다.

## 비목표

모델·프롬프트 튜닝, 후보 계약 변경, 새 실제 문서 수집, 기본 서비스의 시간 제한 완화는 이번 비교에 포함하지 않는다.
