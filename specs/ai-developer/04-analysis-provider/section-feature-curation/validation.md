# 구역 핵심 기능 선택 검증

## 구현·코드 검증

- 기능 후보가 30개를 넘을 때만 Solar가 고정 ID를 선택한다. 서버는 ID 중복·범위·개수를 검증해 원래 selector 항목을 원문 순서로 투영한다. 후보가 30개 이하면 기존 호출 수와 결과를 유지한다.
- 기본 서비스, 공개 Profile, 18호출 구역 추출 모드는 변경하지 않았다. 선택형 모드만 최대 19호출·전체 1,200초다.
- Windows 로컬 전체 `unittest discover -s tests -q`: 683건 통과 (2026-09-29). 독립 리뷰에서 선택 ID의 유니코드 숫자 수용·예외 누출과 제목 후보의 이전 형제 제목 문맥을 발견했다. 두 경우를 회귀 테스트로 재현한 뒤 수정했다. 최종 Linux CI는 완료 후 기록한다.

## 실제 튜닝 문서 1건

Campfire PRD(547줄)를 Solar Pro 4로 한 번 실행했다. 안전 결과는 ignored 로컬 `tmp/section-feature-curation-campfire-20260929-1/{plan,results,summary}.json`에 있다. 원문·키·원본 응답·Profile 내용은 저장하지 않았다.

| 항목 | 결과 |
|---|---:|
| 구역 후보 / 정확 중복 / 고유 | 128 / 0 / 128 |
| 선택한 대표 기능 | 30 |
| 제공자 호출 / 실행 시간 | 10/19 / 152,343ms |
| 최종 상태 | `needs_confirmation(INCOMPLETE_RESPONSE)` |
| 부분 정답 일치 / 누락 | 7/7 / 0 |
| 잘못된 근거 | 0 |
| 미평가 값 | 33 |
| 명시적 미정 필드 | 1개 null 유지 |

선택 요청은 8번째 호출에서 형식 검증을 통과했다. 첫 번째 의미 검토는 이슈를 보고했고, 두 번째 묶음(`ai`, `database`, `deployment`, `external_integrations`)은 출력 8,192토큰 상한에 닿아 응답이 미완료였다. 기능 구역 검토는 시작되지 않았다. 자동 완료를 반환하지 않은 것은 안전한 결과지만, 30개 대표 기능 자체의 의미 정확도는 검증되지 않았다.

부분 정답 7개 중 기능 정답은 1개이고, 나머지 33개 값에는 사람 판정이 없다. 이전 구역 추출은 30개 초과로 채점 자체가 불가능했고 그보다 앞선 구역 검토의 2/7 결과는 별도 모델 실행이다. 따라서 이번 7/7을 일반 정확도나 인과적 개선량으로 해석하지 않는다.

## 적용 판단

선택형 실험으로 유지한다. 다음 관문은 의미 검토를 완주시키고, 대표 기능 30개와 정답 밖 값의 사람 검토에서 오확정·누락을 확인하는 것이다. 독립 신규 기획서와 Spring/Frontend 확인 후 저장 E2E가 없으므로 실서비스 기본값으로 승격하지 않는다. 나머지 공개 문서 4건 전송은 이전 자동 승인 검토의 확대 조건을 충족하지 못해 시도하지 않았다.
