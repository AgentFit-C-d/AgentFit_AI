# 기능 경계 조사 계획

직접 순차 실행한다. 사용자 목표 내 설계·실험 자율 권한을 적용한다. 제품 기능 변경 없이 원인 가설을 검증하는 spike다. SDD 요청에 따라 명세와 실행 계획을 남기며, 제품 코드를 보존하는 구현 계획으로 오해하지 않는다.

1. 완료: 새 합성 20사례·정답·범주를 먼저 고정한다. 10개 유지/10개 제외, 반복 등장 위치와 현재/향후 범위를 점검한다.
2. 완료: 기존 검토 요청을 API 없는 capture로 만든 뒤 원문·후보·설정 동일과 추가 규칙만의 차이를 검증한다. 양 모델의 정답 모의 응답이 원래 파서/계약을 통과하는지도 확인한다.
3. 완료: fixture/spec/plan을 커밋으로 고정하고 최대4회 실제 호출한다. 프로세스 handle을 기록하며 관측 timeout에 재시작하지 않는다.
4. 완료: 종료·호출 한도·입력/코드 해시·분모·오제외/오유지·실패 미채점을 감사한다. 정답을 결과에 맞춰 바꾸지 않는다.
5. 결과 문서 완료, 원격 확인 단계: 결과와 다음 행동을 기록·feature push하고 정확한 최종 HEAD의 CI를 확인한다. 제품 코드 변경이 없으므로 관련 없는 전체 로컬 테스트를 추가 반복하지 않는다. 최종 원격 근거는 work/harness/operation-boundary-probe/REMOTE.md에 기록한다.

## 검토 기준

- 모의 응답 통과를 실제 모델 품질로 계산하지 않는다.
- 합성 사례를 독립 실문서 검증 또는 전체 문서 분석 성공으로 취급하지 않는다.
- baseline이 19/20 이상이면 재현 실패로 기록하고 추가 실제 문서 호출·프롬프트 반영을 하지 않는다.
- 사용자 원문·기존 비공개 정답을 합성 fixture에 복사하지 않는다.
