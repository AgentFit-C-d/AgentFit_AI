# API 계약 진단 결과 (2026-09-26)

## 확인된 사실
- 요청 모델을 `solar-mini4-260922`로 지정한 최초 32회는 모두 PROVIDER_REQUEST였다.
- 별도 1회 진단: HTTP 400, invalid_request_body, 모델 미지원 메시지.
- 별칭 `solar-mini4` 진단 1회는 성공했고 반환 모델은 `solar-mini4-260922`였다.
- 별칭으로 본 실험 32회를 다시 실행했다. 모든 응답 모델이 동일했다.
- 기존 평가기는 이미 별칭을 사용했다. 이번 식별자 문제로 과거 의미 오류를 설명할 수는 없다.
- 공식 문서는 스냅샷 요청을 열거하지만 이번 실제 요청 결과와 차이가 있었다.
  [공식 API 문서](https://console.upstage.ai/api/chat)

## 고정 최소 사례: 4개 × 2회
| 설정 | 전체 정답 | 구조 / 인용 / 상태 | 반복 일치 | 지연 중앙값 |
|---|---:|---:|---:|---:|
| schema + none | 7/8 | 각 8/8 | 3/4 | 454ms |
| enum 역순 + none | 6/8 | 각 8/8 | 4/4 | 407ms |
| JSON object + none | 6/8 | 각 8/8 | 2/4 | 445ms |
| schema + low | 8/8 | 각 8/8 | 4/4 | 6,539ms |

오류는 역할 분류에 있었다. 순서 역전과 스키마 제거의 개선은 확인하지 못했다.
low는 이 표본에서 1건 개선됐지만 생성 토큰 합계는 249에서 4,293으로 늘었다.
표본이 작고 반복 변동이 있으므로 통계적 우월성이나 일반 모델 성능으로 해석하지 않는다.
반복 일치는 정답과 별개이며, 잘못된 응답이 반복돼도 일치로 집계한다.

## 기존 추출 과제로 후속 검증
기존 quote-extraction 6사례, 동일 프롬프트·정답·채점 revision 2·토큰 제한 사용.
none을 먼저 6회, low를 다음 6회 실행했다.

| 설정 | 구조 통과 | 의미 전체 정답 |
|---|---:|---:|
| none | 6/6 | 0/6 |
| low | 6/6 | 0/6 |

low의 최소 사례 개선이 실제 추출 계약으로 이어지지 않았다. 6/6 기준에 미달해 전체 문서로 확대하지 않았다.
각 1회이며 순서 효과와 응답 변동을 분리하지 못한다.
추출 평가 로그는 개별 의미 불일치의 세부 원인을 저장하지 않아 어느 필드가 원인인지는 이 결과만으로 확정할 수 없다.

## 변경 및 검증
- 독립 API 비교 도구와 고정 합성 사례, 한 변수 비교·채점·오류 집계 테스트.
- 기존 추출 평가기에 --reasoning none|low 옵션 추가. 기본값 유지.
- API 응답 원문 및 reasoning 미보관. 실제 문서 외부 전송 없음.
- 단위 테스트 211/211 통과. 이는 모델 품질 통과를 뜻하지 않는다.
- 유효 비교 44회, 스냅샷 거절 32회, 원인 확인 2회: 총 78회 요청.

## 판단과 후속 과제
설정 변경만으로 추출 품질을 해결했다는 근거는 없다. 서비스 기본 설정은 변경하지 않았다.
다음 진단은 기존 추출 실패를 누락·불필요 후보·필드·역할·상태·범위별로 구분하는 안전한 비교 지표를 먼저 확보해야 한다.
그 결과를 바탕으로 가장 큰 오류 유형 하나를 수정하고 같은 채점 기준으로 검증한다.
현재 자동 확정 서비스 품질은 여전히 미확보다.
