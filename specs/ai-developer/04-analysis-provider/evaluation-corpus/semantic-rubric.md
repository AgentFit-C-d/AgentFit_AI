# 의미 채점 기준 v1 초안

## 평가 층 분리
기존 quote-extraction revision2 점수는 중간 후보 집합과 정확 문자열의 일치를 측정한다.
이를 최종 Profile 정확도나 모든 내용이 틀린 비율로 해석하지 않는다. 기존 점수는 보존한다.
최종 초안은 field + 대상 제품 + 행위자/행동/대상 + 채택 상태 + 근거를 기준으로 평가한다.
모델이 제외 후보를 출력하지 않았다는 이유만으로 최종 초안을 오답으로 만들지 않는다.
표현 허용 목록은 실제 응답을 보기 전에 고정한다. 애매한 표현은 자동 동의어 확장 없이 검토 보류.

## 기존 튜닝 사례에 적용할 의미 기준
| 사례 | 최종 초안에서 요구하는 의미 | 중대 오류/불필요 출력 |
|---|---|---|
| Q-001 | 사용자의 장소 확인, 후보 선택 두 행동 | 개발 작업으로 처리하거나 누락 |
| Q-002 | 사용자의 승인 요청, 운영자의 승인 처리 구분 | 요청/처리를 합쳐 하나로 표현, frontend/backend로 분류 |
| Q-003 | 개발 테스트 도구는 운영 AI로 확정하지 않음. 운영 AI는 미정 | NovaClient를 운영 AI로 채택, 미정을 명시적 미사용으로 바꿈 |
| Q-004 | 외부 연동 명시적 미사용 | 외부 서비스 채택으로 표시 |
| Q-005 | 요구사항 없음 | 회의 시간을 기능/스택/제품명으로 출력 |
| Q-006 | 사용자의 일정 추천 행동 하나 | '필수 사용자 기능' 같은 제목을 별도 기능으로 추가 |

Q-003의 이름만 보고 client라는 종류까지 확정하는 기존 부분 골드는 최종 Profile 기준으로 쓰지 않는다.
Q-002의 '회원 승인'만으로 두 행동이 구분되는지는 사용자 표시값과 근거를 함께 검토한다.
이 기준은 개발자 초안이며 아직 독립 사람 검토를 받지 않았다. 이전 실패를 소급 통과 처리하지 않는다.

## 채점 증거
TP는 사전 골드 의미 단위와 일대일 대응하고 정확 근거가 있어야 한다.
후보가 잘못된 필드/상태/제품으로 이동하면 FP+FN. 중복은 FP. 미정으로 회피하면 해당 확정 골드는 FN.
확정할 수 없는 사실을 unknown으로 두는 것은 출력 오류가 아니지만 명시적 부재와 혼동하면 상태 오류다.
최종 공개 계약에서 부재와 unknown이 구분되지 않으면 UI나 API를 임의 변경하지 않고 표현 제약으로 보고한다.
