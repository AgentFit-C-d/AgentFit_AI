# 검증 후보 문서 및 의미 기준

## 목적
튜닝 노출 자료와 신규 평가 후보 분리. 새 공개 자료의 점수를 고객 기획서 일반 성능으로 과장하지 않는다.

## 확보 기준
공식 서로 다른 프로젝트 저장소의 README 10개를 Git commit과 SHA256으로 고정했다.
본문은 로컬 output/public-corpus-reserved-v1에만 보관한다. Git에는 출처/버전/해시 metadata만 보관한다.
본문/정답은 아직 검토하지 않았다. Solar 미전송. 사전학습 포함 여부는 알 수 없다.
Documenso 등 검색 결과 일부 요약은 자료 발견 과정에서 노출됐다. 프롬프트 예시나 튜닝에 사용하지 않았다.
reserved는 최종 holdout 인증이 아니다. 내용 검토 후 적합성·중복·언어·10필드 커버리지를 평가한다.
36,808자 Cal.com README는 현재 24,000자 실험 한도를 초과한다. 임의로 잘라 성공률을 계산하지 않는다. 길이 정책 또는 대체 문서의 사전 기준이 필요하다.
공개 README는 제품 소개·설치 설명이 섞여 있어 실제 한국어 초기 기획서와 다르다. 이 한계는 최종 보고에 남긴다.
원문 저작권/라이선스 표기는 API metadata일 뿐 문서 전체 이용 범위를 인증하지 않는다. 원문 재배포는 하지 않는다.

## 다음 절차
1. 튜닝은 기존 문서와 합성 자료만 사용.
2. 최종 분석 경로와 설정을 먼저 고정.
3. 후보 적합성 검토, 골드 작성 및 검토자 확인, 문서 계열 중복 검사.
4. 모델 응답 전에 corpus/gold/config 해시 고정.
5. 문서별3회 평가. 결과를 보고 수정할 경우 노출 세트는 튜닝으로 이동.
6. 사용자 수정량/시간은 별도 측정. 공개 자료 자동 점수로 대체 금지.
