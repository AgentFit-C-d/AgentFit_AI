상태: **계획·정답 초안만 작성. 실행 미승인/미실행. 큰 goal paused.**

## 목적

동일한 저장 후보와 전체 원문으로 현재의 다축 의미 역할 분류(A)와 출력 필드를
직접 판단하는 방식(B)을 비교한다. 역할/필드 모순으로 정상 정보를 보류하는 비용과
브라우저명을 외부 연동으로 제안하는 오확정을 분리해 관찰한다.

이번 요청은 CI 확인 및 비교 계획 작성까지다. CI 성공을 확인했으므로 코드 수정은 없다.
분류기·평가 도구 구현, 새 모델 호출, 재추출, 서비스 연결 및 배포를 하지 않는다.

## 비교 설계

| 항목 | A — 현재 방식 | B — 직접 필드 판단 |
| --- | --- | --- |
| 입력 | 전체 원문 + 동일한68개 후보 | A와 동일 |
| 출력 | field, modelStatus, mentionKind, 5개 의미 축, conflictsChecked, support/counterEvidence | id, field, status, support/counterEvidence |
| 의미 판단 | 축·역할을 각각 출력한 뒤 필드와 일관성 검사 | 원문을 읽고 최종 필드·상태를 직접 선택 |
| 서버 판단 | 현재 의미 admission 규칙 그대로 | 정확한 근거·상충 근거·필드/상태의 최소 일관성 검사 |
| 불확실성 | needs_confirmation | needs_confirmation |
| 사용자 확정 | 부여하지 않음 | 부여하지 않음 |

B는 검토해야 하는 의미 조건을 없애지 않는다. 대상 프로젝트, 현재 시점, 부정,
검토/계획, 개발 도구와 실제 구현 기술, 연동 대상과 지원 플랫폼, 상충 근거를 같은
기준으로 읽되 각 조건을 별도 enum으로 출력하지 않는 실험이다.

두 방식 모두 원문에 이름이 있다는 이유만으로 confirmed를 부여하면 오답이다.
모델이 작성한 새 값·새 후보·위치 수정은 허용하지 않는다. 분류 결과는 사용자의
승인이나 저장 완료와 다르다. B를 A의 필수 의미 축 값으로 채워 서비스에 넣지 않는다.

## 판단 기준

[gold-review.md](gold-review.md)를 사람이 먼저 검토해야 한다. 기존 gold.json은
human_reviewed=false인 과거 임시 기준이며 그대로 보존한다. 새 기준은 아직 승인되지 않았다.

주 평가: 요청한6사례 + 정상/음성 대조4사례, 총10개 anchor occurrence.
전체68개 입력은 유지한다. 주 정답 밖58개는 별도 점검 대상으로 기록하며 정답으로
자동 인정하지 않는다. 원래 후보에 없는 확장 기능은 분류 방식 개선으로 복구할 수 없다.

완료 판정은 오확정·정상 누락·보류·호출·시간 각각의 변화로 한다. 하나의 종합 성공률로
합치지 않는다. 전부 보류하면 정상6개 누락6 및 불필요 보류6으로 남아 채택 기준을 실패한다.
