# 의미 역할 원인 분석 계획 — 2026-10-03

## 이번 범위

사용자가 지정한 두 실제 AgentFit 실행의 원문·저장 요청·원시 분류·서버 판단·후속 검토/최종 출력을 연결한다. 현재 10필드×6역할의 표현 가능성을 합성 입력으로 검사한다. 제품 코드/프롬프트/스키마/골드/복구 도구는 수정하지 않는다. 모델 호출0, 큰 Goal paused. 이전 외부 전송 중단 상태를 유지하고 로컬 feature 브랜치에만 기록한다.

## 순서

1. 실제 전달된 지침과 스키마를 현재 코드와 대조한다.
2. 두 실행에서 이름·지원 Client·인증 제공자의 원시 응답을 기존 validate_assessments로 재검증한다. 유효 인용과 인용 실패를 분리한다.
3. 정상10필드의 표현, 역할 불일치 보류, 대상/다른 프로젝트·Client/서비스·같은 이름의 다른 관계·부정/미정/상충을 오프라인 테스트한다.
4. 저장 응답의 의미상 실패는 expectedFailure로 별도 고정한다. 이는 과거 오류 재현용이며 제품 수정 후 통과해야 하는 release gate가 아니다. 저장된 오답 자체는 프롬프트 변경으로 바뀌지 않는다.
5. 기존 역할이 충분하면 지침 한 곳의 명확화만 제안한다. 합성 검사 통과를 모델 개선으로 계산하지 않는다.
6. 고정8후보·전체 원문으로 추후 A/B 최소2호출 계획과 추가 대조 사례를 작성하고 종료한다. 이번에는 실행하지 않는다.
