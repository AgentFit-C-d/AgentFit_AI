# 구현 계획

1. FastAPI·HTTPX·Uvicorn 의존성을 고정하고 `create_app` 팩토리로 테스트 가능한 내부 경계를 만든다.
2. 서비스 인증과 헤더 검증 후 스트리밍 body를 상한 내에서 읽는다. Content-Length가 틀린 경우에도 실제 byte 수로 판단한다.
3. 기존 `extract_document`와 Solar 분석기를 연결한다. 요청마다 분석기를 생성하고 초안 후보만 반환한다. 실제 분석에는 40초 분석기 기한을 둬 PDF 추출 15초와 함께 60초 목표에 여유를 남긴다.
4. 추출·분석의 알려진 오류와 예상 밖 예외를 안전한 코드로 매핑한다. 앱은 원문을 파일/DB/일반 로그에 저장하지 않는다.
5. TestClient 단위·통합 테스트를 먼저 작성해 실패를 확인하고, 구현 후 전체 테스트와 로컬 HTTP smoke를 실행한다.

이 구현은 내부 계약의 AI 측 제안이다. Spring 연동과 품질 게이트 통과 전까지 실서비스 준비 완료로 표시하지 않는다.
