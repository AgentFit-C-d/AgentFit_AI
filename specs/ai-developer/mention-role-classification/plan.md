# 한정 구현 계획

1. 기존 응답·모델 코드를 변경 전 기준으로 보존, 분류 기준과 고정 평가 세트 확정.
2. TDD: 역할-필드 불일치/정상/불명확/다른 이름·순서/기존 응답 호환성/질문 보존을 검증.
3. 첫 분류 prompt와 opt-in 의미 분류의 mentionKind 검증만 수정. 저장 metadata는 기존 선택적 확장 검증으로 전달.
4. 로컬 고정 응답 비교. 실제 비교는 무료 승인 유효 시 DeepSeek 4.1 Flash만, 최대24회/재시도0/호출당180초/전체30분. 무료 확인 실패·한도/인증/공급자 실패 시 중단하며 유료 대체 없음. 기준/후보/코드 고정 후 같은6문서로 변경 전 기본/변경 후 기본/변경 후 opt-in을 구분해 비교. 추가 튜닝 반복 금지.
5. 전체 로컬 unit/contract, diff 확인, 기능 브랜치 commit/push, 결과·한계 기록 후 종료. 큰 goal은 재개하지 않음.

## 검토 반영

- 기본 prompt 실험은 오확정/애매한 후보 유실이 남아 채택하지 않는다. 역할 정보와 질문 보존 계약을 갖춘 기존 선택형 경로에만 수정 반영.
- 독립 리뷰에서 지적한 수동 metadata 주입 테스트의 한계를 보완: 실제 분류 함수→분석 pipeline→확인 초안까지 고정 모델 응답으로 검증한다. 분류 결과/outcome/unresolved를 테스트에서 덧씌우지 않는다.
- 새 역할 metadata의 HTTP→mock 저장 유지도 기존 계약 테스트에 추가. 실제 Spring은 미검증.
- 평가 코드·정답·실제 응답은 동결 후 보존. 채택하지 않은 prompt 실험 코드도 별도 보존하고, 채택한 구조화 runtime의 해시 및 공용 함수 AST가 실험 때와 동일함을 확인한다.
