# 후보 역할과 출력 필드 분리

사용자 요청: 의미 역할/필드 혼동 한 원인만 수정·검증하고 종료. 큰 goal은 paused 유지. 공개 Profile/서비스 경계/저장 계약은 변경하지 않는다.

## 분류 기준

- external_service: 대상 제품이 연동하는 구체적 외부 제공자/서비스 자체. external_integrations에 대응한다. 이름이 일반 단어여도 원문이 서비스라고 명시하면 인정한다.
- product_operation: 대상 제품이나 사용자가 수행한다고 명시된 동작. features에 대응한다.
- role_description: 도구의 용도/역할을 설명하는 표현. 외부 제공자 이름이 아니다. 설명만으로 독립 제품 기능이 명시됐는지 불명확하면 확인 필요다.
- description: 수식·효과·홍보 설명. 서비스명이나 제품 동작으로 자동 확정하지 않는다.
- unclear: 역할 불명확. 후보/근거를 보존하여 확인 필요로 남긴다.
- other: 위 역할 분류의 대상이 아닌 기존 다른 Profile 필드. 이 값이 features/external_integrations의 확정 근거를 대신하지 않는다.

첫 의미 분류 payload에 이름/행동/설명의 관계 지침을 추가한다. 기존 opt-in 의미 분석기의 모델 응답에는 mentionKind를 먼저 판단하도록 추가하며, 서버는 역할-필드 불일치와 불명확한 역할을 needs_confirmation으로 보류한다. field를 임의 교체하거나 확정으로 승격하지 않는다. 기존 저장 응답은 이전 형식으로 계속 읽고 새 실제 응답에는 역할 정보를 요구한다.

### 평가 후 적용 결정

일반 id/field/status 분류기의 prompt만 변경한 실험은 domain 오확정 1건과 애매한 후보 유실 1건이 남았다. 이 경로의 prompt 변경은 철회하고 실험 코드를 결과 폴더에 보존한다. 실제 반영은 기존 `semantic_assessment=True` 선택형 분류기의 첫 의미 분류 및 역할-필드 검증에 한정한다. 기본 경로의 기존 보류 후보 유실은 이번 수정으로 해결됐다고 주장하지 않는다.

기본 분류의 prompt 개선과 opt-in 구조 검증은 효과를 분리해 측정한다. 새 구조 검증을 기본 HTTP 분석기로 승격하지 않는다. 서비스명·후보 ID·특정 문구·대문자/어휘 목록을 이용한 규칙은 금지한다.

## 검증 범위

이미 승인된 '제공자 이름과 결제 역할은 다르다'는 기준 및 명시적인 외부 연동/사용자 동작을 사용한다. 동일 관계의 이름·언어·문장 순서를 바꾼 사례와, 일반 단어를 실제 서비스 이름으로 명시한 정상 사례를 포함한다. 셀프호스팅·Vikunja Pro는 세트에 넣지 않는다.

원래 Stripe/Payments 문맥에서는 Payments가 외부 제공자가 아님은 확정 기준으로 검사한다. 그 단독 용도 표현을 독립 기능으로 확정할지는 이번 정상 정보 분모에 강제하지 않는다. 이 부분은 not_external 제약으로 검사하고 보류 건수는 숨기지 않는다. 명시적인 결제 기능 사례는 반드시 정상 정보 분모에 포함한다.

평가 파일의 `not_external`은 이름이 좁지만 사전 고정된 채점은 'features 이외 필드로 confirmed 금지'다. domain 등으로 잘못 확정한 것도 오확정에 포함한다. 평가 후 채점이나 정답은 변경하지 않고 보고에서 이 정의를 명시한다. 보류 의무가 명시된 unclear 1건의 유실과, 용도·설명 6건의 제외를 별도로 보고한다.

고정 응답은 모델에 정확한 역할을 주입한 서버 계약 검증임을 명시한다. 실제 모델의 역할 식별 성능으로 오해하지 않도록 실제 호출 비교와 분리한다. 동일 세트에서 오확정·정상 누락·확인 필요 수를 모두 기록하며 전부 보류는 실패다.
