# 후보 의미 역할 분류 — 2026-10-01 결과

## 결론과 적용 범위

기존 `semantic_assessment=True` 선택형 경로의 **첫 의미 분류**에 후보의 역할(`mentionKind`)을 추가했다. 외부 제공자·제품 행동·용도 설명·수식 설명·불명확·기타 필드를 구분한 뒤 출력 필드와 맞는지 검사한다. 불명확하거나 역할과 필드가 충돌하면 원문·모델 판단을 보존하고 `needs_confirmation`으로 남긴다. 서버가 필드를 바꾸거나 확정으로 승격하지 않는다.

- 채택: 구조화된 역할 판단 및 서버의 역할-필드 일관성 검증.
- 미채택: 기존 일반 분류기의 프롬프트만 변경하는 실험. 다른 문장 순서에서 오확정이 남아 코드를 되돌렸다. 실험 당시 파일은 별도 보존했다.
- 기본 분석기 전환·배포는 하지 않았다. 일반 경로의 애매한 후보 유실은 아직 미해결이다.
- 큰 goal은 `paused` 유지. 이번 원인 하나의 수정·검증 후 종료한다.

## 최초 오류와 분류 기준

기존 `output/semantic-confirmation-guard-v2/actual-readme-baseline-0.json`의 C073은 원문의 `Payments`를 `external_integrations/confirmed`로 분류했다. 원문 후보의 위치는 맞았지만 **첫 의미 분류에서 도구의 용도를 외부 제공자로 판단**했다. 사용자 확인이나 저장에서 최초 발생한 오류가 아니다.

| 의미 | 판단 기준 | 처리 |
|---|---|---|
| 외부 서비스 | 대상 제품이 연동하는 제공자·서비스 자체 | `external_integrations`와 일치해야 함 |
| 기능/행동 | 대상 제품 또는 사용자의 동작이 원문에 명시됨 | `features`와 일치해야 함 |
| 용도 설명 | 해당 도구를 어디에 쓰는지 설명 | 제공자 이름으로 확정 금지; 기능 성립이 불명확하면 보류 |
| 수식 설명 | 효과·수식·홍보 문구 | 서비스/기능으로 자동 확정 금지 |
| 불명확 | 역할을 원문으로 판단하기 어려움 | 필드 미정이어도 원문과 확인 질문 보존 |

서비스 이름·문구·후보 ID의 하드코딩은 운영 코드에 없다. 특정 단어를 차단하지 않으며, 일반 단어를 실제 서비스 이름으로 명시한 정상 사례도 포함했다. 기존 모델 판단과 사용자 확정의 분리도 유지된다.

## 2. 실제 모델 호출

현재 계정에서 무료 사용이 확인된 NVIDIA Build의 `deepseek-ai/deepseek-v4.1-flash`만 사용했다. 6개 입력 × 3경로 × 1회, **18회 완료**, 재시도 0, 유료 전환/대체 0. 공급자 호출 소요 합계 약 199.3초. 최종 보고 준비 중 추가 호출은 하지 않았다.

| 지표 | 기존 일반 분류 | 프롬프트만 변경 — 미채택 | 역할 구조화·검증 — 채택 |
|---|---:|---:|---:|
| 오확정 | 2 | 1 | 0 |
| 정상 정보 누락 | 0 / 11 | 0 / 11 | 0 / 11 |
| 확인 필요 후보 | 0 | 0 | 2 |
| 명시적 불명확 후보의 확인 의무 유실 | 1 | 1 | 0 |

- 이번 실행에서 기존 경로의 오확정 2개는 결제 용도를 `domain/confirmed`로 분류한 경우다. 프롬프트만 바꾼 경로의 1개도 같은 종류다. 외부 서비스 오분류 2→0이라고 해석하지 않는다.
- 원래 Stripe/Payments 입력은 이번 재호출에서 기존 경로도 오확정을 재현하지 않았다. 과거 174개 전체 후보와 이번 2개 선택 후보의 문맥 조건이 다르다. 해당 1건의 실시간 재현 수정 성공으로 주장하지 않는다.
- 채택 경로: 12개 supported(정상 11개 + 기능으로 허용한 용도 1개), 2개 needs_confirmation(Payments, 역할 미정 Relay), 4개 excluded(용도 설명 3개 + 수식 설명 1개). 18개 모두 판단과 원문 위치가 metadata에 남는다.
- 기존/프롬프트 경로의 `irrelevant`는 각각 5/6개다. 위의 ‘정상 누락 0’은 확정된 정상 정보 11개만 센다. 용도 설명의 제외나 애매한 Relay의 유실을 이 수치가 보장하지 않는다. 이 때문에 유실 지표를 따로 보고한다.
- 확인 필요 후보 증가는 **0→2 / 18개(11.1%)**다. 실제 UI 질문 개수는 필드별 병합과 정상 제안 확인 때문에 이 수와 다를 수 있다.
- 이는 일반 경로와 구조화 경로의 단일 실행 비교다. 이전 구조화 경로와 수정 후 구조화 경로를 같은 조건으로 실제 재호출한 A/B는 아니다. 역할 정보 추가만의 인과적 향상률이나 새 문서 일반화 성능을 뜻하지 않는다.
