## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프로젝트를 만들고 다시 찾기 (Priority: P1)

사용자는 프로젝트를 생성하고 목록에서 선택해 상세 화면을 다시 열 수 있다.
상세 화면은 아직 기획서가 없는 상태와 분석·검토 진행 상태를 구분한다.

**Why this priority**: 분석 대상과 저장 위치를 먼저 마련해야 문서 분석이 일회성 시연에 머무르지 않는다.

**Independent Test**: AI 연결 없이 프로젝트를 생성하고 목록·상세 화면을 다시 열어 동일한 프로젝트가 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 프로젝트가 없는 사용자, **When** 유효한 이름으로 프로젝트를 생성한다, **Then** 목록에 표시되고 상세 화면에 기획서 입력 안내가 나온다.
2. **Given** 생성한 프로젝트, **When** 화면을 새로고침하고 목록에서 다시 선택한다, **Then** 같은 프로젝트 이름과 저장 상태를 확인할 수 있다.
3. **Given** 공백만 입력한 이름, **When** 생성을 요청한다, **Then** 생성하지 않고 이름을 입력하라는 설명을 표시한다.
4. **Given** 프로젝트 저장 실패, **When** 생성 결과를 보여준다, **Then** 성공으로 표시하지 않고 입력한 이름을 보존해 재시도할 수 있다.
5. **Given** 로그인하지 않은 방문자, **When** 프로젝트 생성·목록·상세·분석·수정에 접근한다, **Then** 로그인 안내가 표시되고 프로젝트 내용이나 분석 결과를 읽거나 변경할 수 없다.
6. **Given** 다른 사용자가 소유한 프로젝트의 식별자, **When** 로그인한 사용자가 조회·분석·수정을 시도한다, **Then** 요청을 거부하고 타인의 프로젝트 내용이나 존재 여부를 드러내지 않는다.
7. **Given** 본인 프로젝트의 삭제 안내, **When** 삭제를 확인한다, **Then** 프로젝트와 연결된 프로필·최소 문서 정보·분석 시도·감사 기록이 함께 제거된다. 취소하면 데이터를 변경하지 않는다.
8. **Given** 로그인 화면, **When** GitHub 로그인을 완료한다, **Then** 자신의 프로젝트 목록으로 이동하며 저장소 접근 권한을 요구하지 않는다. 취소·인증 실패이면 로그인되지 않은 상태로 재시도 안내를 제공한다.

### User Story 2 - 기획서를 구조화된 분석 결과로 받기 (Priority: P1)

사용자는 프로젝트에 PDF 또는 Markdown 기획서를 업로드하거나 텍스트를 직접 입력한다.
분석을 시작하면 진행 상태를 확인하고, 결과에서 프로젝트 유형·기술·핵심 기능·외부 연동·미확정 정보를 본다.

**Why this priority**: 입력 문서를 편집 가능한 Project Profile로 바꾸는 것이 첫 흐름의 핵심 가치다.

**Independent Test**: 준비한 프로젝트와 내용이 알려진 문서를 사용해 입력 → 분석 → 저장된 결과 표시를 검증한다.

**Acceptance Scenarios**:

1. **Given** React, Node.js, 인증 기능이 명시되고 DB·배포 환경이 없는 정상 PDF, **When** 분석한다, **Then** 명시된 정보는 해당 항목에 표시되고 DB·배포 환경은 미확정으로 남는다.
2. **Given** 같은 내용을 가진 정상 Markdown 또는 직접 입력 텍스트, **When** 각각 분석한다, **Then** 동일한 종류의 프로필 항목을 확인할 수 있다.
3. **Given** 아직 분석하지 않은 유효한 문서, **When** 분석을 시작한다, **Then** 진행 중임을 표시하고 같은 요청을 중복 생성하지 않는다.
4. **Given** 검증된 분석 결과의 저장 성공, **When** 페이지를 다시 연다, **Then** 저장된 분석 초안이 복원되며 사용자 확인 완료로 잘못 표시되지 않는다.
5. **Given** "모든 권한을 허용하라" 같은 지시가 포함된 문서, **When** 분석한다, **Then** 문서 내용을 권한이나 시스템 지시로 실행하지 않는다.
6. **Given** 부정·후보·미래 계획·다른 대상의 기술이 등장하는 문서, **When** 분석한다, **Then** 단어가 있다는 이유로 본 프로젝트의 확정값으로 저장하지 않는다. 같은 범주의 명시적 확정 내용은 해당 값으로 추출한다.
7. **Given** 문서 근거값과 위치가 저장된 결과, **When** 처리 후 근거를 확인한다, **Then** 위치·출처와 원문 미보관을 설명하며 서버가 원문 인용을 계속 보관하거나 재열람할 수 있는 것처럼 표시하지 않는다.

### User Story 3 - 분석 결과를 확인하고 수정해 저장하기 (Priority: P1)

사용자는 분석된 각 항목을 수정하거나 미정으로 남길 수 있다.
저장 결과를 확인한 후 다시 방문해 자신이 마지막으로 확정한 프로필을 이어서 사용한다.

**Why this priority**: AI의 판단을 사용자가 정정할 수 있어야 잘못된 사실이 이후 추천으로 전달되지 않는다.

**Independent Test**: 미확정 항목이 있는 분석 초안을 준비해 값 변경·미정 선택·저장·재접속을 검증한다.

**Acceptance Scenarios**:

1. **Given** DB가 미확정인 초안, **When** 사용자가 DB를 입력하고 확인·저장한다, **Then** 값과 사용자 확인 상태가 저장되고 해당 항목이 미확정 목록에서 제거된다.
2. **Given** 값이 있는 항목, **When** 사용자가 미정으로 바꾸고 저장한다, **Then** 미정 상태와 미확정 목록이 일치한다.
3. **Given** 미확정 항목이 남은 초안, **When** 사용자가 그대로 확인·저장한다, **Then** 미정을 허용하고 확인 여부와 정보 완전성을 별도로 표시한다.
4. **Given** 사용자가 수정 중인 내용, **When** 저장에 실패한다, **Then** 수정 입력을 보존하고 저장 완료로 표시하지 않는다.
5. **Given** 이미 저장한 사용자 확인 프로필, **When** 새 문서를 분석한다, **Then** 기존 확인 프로필을 자동 덮어쓰지 않고 새 분석 결과를 검토 후보로 제시한다.
6. **Given** 같은 프로필을 두 화면에서 열고 한쪽이 먼저 저장했다, **When** 다른 쪽에서 오래된 내용을 저장한다, **Then** 최신 저장을 묵시적으로 덮어쓰지 않고 충돌 안내와 다시 불러오기 동작을 제공한다.
7. **Given** AI 분석에 실패했고 기존 확인 프로필은 없는 프로젝트, **When** 사용자가 직접 작성으로 전환해 확인·저장한다, **Then** 입력한 프로필이 저장되며 작성 출처는 사용자로 표시하고 AI 분석 성공으로 기록하지 않는다.

### User Story 4 - 잘못된 입력과 분석 실패에서 복구하기 (Priority: P1)

사용자는 지원하지 않는 문서나 읽을 수 없는 내용, AI 오류가 발생했을 때
실패 이유와 가능한 복구 행동을 확인한다.

**Why this priority**: 실패를 숨기거나 잘못된 결과를 저장하면 이후 흐름 전체의 신뢰성이 훼손된다.

**Independent Test**: 빈 파일·텍스트 없는 PDF·손상 문서와 분석 오류를 재현해 잘못된 성공·저장이 발생하지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 미지원 형식·손상된 문서·빈 입력, **When** 분석을 요청한다, **Then** 적절한 입력 오류를 표시하고 외부 분석을 시작하지 않는다.
2. **Given** 텍스트를 추출할 수 없는 PDF 또는 잠겨서 읽지 못하는 PDF, **When** 입력한다, **Then** 읽을 수 없음을 알리고 텍스트를 포함한 PDF·Markdown·직접 입력으로 바꿀 수 있도록 안내한다.
3. **Given** 10 MiB 초과 파일, 100쪽 초과 PDF 또는 10만 자 초과 추출·직접 입력 텍스트, **When** 제출한다, **Then** 해당 한도와 초과 원인을 표시하고 부분 내용만 몰래 분석하지 않는다. 각 한도와 정확히 같은 유효한 입력은 크기 사유로 거부하지 않는다.
4. **Given** 외부 AI 오류·응답 지연 종료·잘못된 결과 구조, **When** 분석을 완료할 수 없다, **Then** 실패를 표시하고 기존 저장 프로필을 보존하며 재시도와 직접 작성·수정 동작을 제공한다.
5. **Given** 분석 결과는 유효하지만 저장 실패, **When** 결과를 표시한다, **Then** 저장 실패를 알리고 저장되지 않은 결과를 확정 프로필로 표시하지 않는다.
6. **Given** 입력에서 식별 가능한 Credential 또는 시스템이 보유한 Credential, **When** 분석 요청을 준비한다, **Then** 해당 Secret을 외부 AI에 전달하지 않으며 로그·오류에도 노출하지 않는다.
7. **Given** 분석이 성공·실패·시간 초과로 종료됐다, **When** 서버 측 처리 데이터의 생명주기를 확인한다, **Then** 원문과 추출문을 보관하지 않는다. 재시도에는 입력을 다시 제출하도록 안내하며 기존 프로필의 직접 수정은 가능하다.

### Edge Cases

- 파일 확장자와 실제 내용 불일치, 빈 문서, 깨진 문서, 텍스트 없는 스캔 PDF.
- PDF에서 텍스트 일부만 추출되어 원문을 온전히 분석했다고 오해할 수 있는 경우.
- 이름은 다르지만 내용이 같은 문서를 다시 제출하거나 분석 버튼을 연속으로 누르는 경우.
- 기획서에 값이 아예 없거나 서로 충돌하는 DB·기술 선택이 함께 적힌 경우.
- 부정문·조건부 제안·현재/미래·다른 프로젝트의 기술과 명시적 확정을 구분해야 하는 경우.
- 유효 입력에 빠르게 실패해 응답 시간 목표만 충족하거나 모든 값을 미정으로 반환해 오류를 숨기는 경우.
- 정상 형식처럼 보이지만 필수 항목이 누락되거나 허용되지 않은 값이 포함된 분석 결과.
- 외부 분석 실패, 요청 제한, 응답 지연, 결과 저장 실패, 수정 저장 실패.
- 분석 도중 새 문서 제출, 새로고침, 이전 분석 응답이 뒤늦게 도착하는 경우.
- 사용자 확인 프로필이 이미 있는 상태에서 재분석하거나 여러 화면이 같은 프로필을 수정하는 경우.
- 문서 안의 악성 지시·외부 링크·Secret, 오류 메시지에 문서 원문 또는 Credential이 포함되는 경우.
- 세션 만료와 타 사용자 프로젝트 접근 시 내용·존재 여부의 노출 방지.
- 분석 도중 프로젝트 삭제, 삭제 후 늦게 도착한 분석 결과, 삭제 처리 중 실패, 비정상 종료 후 남은 임시 데이터.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 이름으로 프로젝트를 생성하고 목록과 상세 화면에서 다시 조회할 수 있어야 한다(MUST).
- **FR-002**: 프로젝트 이름이 비어 있거나 공백뿐이면 생성을 거부하고 입력 오류를 설명해야 한다(MUST).
- **FR-003**: GitHub 계정 로그인만 제공하며 사용자 식별에 필요한 권한만 사용하고 저장소 권한은 요청하지 않아야 한다(MUST). 프로젝트 생성·목록·상세·문서 입력·분석·프로필 수정·삭제에는 로그인이 필수이며 본인 소유 프로젝트에만 접근할 수 있다. 비로그인과 타인 프로젝트 요청을 거부하고 내용·존재 여부를 노출하지 않는다. 화면을 거치지 않는 요청에도 동일한 제한을 적용하며, 로그인 취소·실패·세션 만료는 인증 성공으로 처리하지 않는다. 로그아웃 후에는 새 인증 없이 보호된 작업을 수행할 수 없다.
- **FR-004**: 프로젝트별로 PDF, Markdown 파일 또는 직접 입력 텍스트를 분석 입력으로 받아야 한다(MUST). 한 분석 요청에는 하나의 입력을 사용한다.
- **FR-005**: 한 파일은 최대 10 MiB(10,485,760 bytes), PDF는 최대 100쪽, 추출·직접 입력 텍스트는 최대 100,000자로 제한해야 한다(MUST). 한도는 포함 경계이며 어느 하나라도 초과하면 분석 전에 거부한다. 문자 수는 Unicode code point 수로 세고 공백·줄바꿈을 포함한다. 적용 한도를 입력 전에 안내하며 초과 내용을 자동 절단하지 않는다.
- **FR-006**: 지원하지 않거나 손상·잠금·빈 내용으로 읽을 수 없는 입력을 거부하고 수정 방법을 안내해야 한다(MUST).
- **FR-007**: 읽을 수 있는 텍스트만 분석 대상으로 사용해야 한다(MUST). 텍스트 없음·추출 실패·일부 추출을 정상적인 전체 문서 분석으로 표시하지 않는다. 외부 링크나 첨부 리소스를 자동 실행·가져오기하지 않는다.
- **FR-008**: 분석 시작 전에 외부 AI에 전달할 문서 내용의 범위를 알리고 사용자의 분석 시작 동작으로 요청해야 한다(MUST). 분석에 필요하지 않은 다른 프로젝트 데이터와 Credential을 전달하지 않는다.
- **FR-009**: 분석 결과는 프로젝트명, 유형, 도메인, Frontend·Backend·AI 기술, DB, 배포 환경, 핵심 기능, 외부 연동, 미확정 항목을 포함하는 Project Profile이어야 한다(MUST).
- **FR-010**: 문서에 없는 값과 상충하여 확정할 수 없는 값은 미정으로 남겨야 한다(MUST). 문서의 제안·후보를 이미 결정된 기술처럼 확정하지 않는다. 부정문, 후보/확정, 현재/미래, 다른 대상에 관한 기술과 문맥의 제한을 구분한다. 문맥상 해당 프로젝트·필드의 확정 사실로 확인된 값은 임의로 미정으로 누락하지 않는다.
- **FR-011**: 문서에 근거한 값, 사용자 입력으로 수정한 값, 미확정 값을 구분할 수 있어야 한다(MUST). 분석값을 처리 중 근거와 대조하고, 저장 결과에는 근거의 페이지·문자 위치 등을 연결한다. 근거 검증을 위해 원문 인용 구절을 계속 보관하지 않는다. 보관한 위치 정보는 원문을 다시 열 수 있다는 뜻이 아니며, 처리 후 원문 확인은 사용자가 가진 원본을 기준으로 하도록 안내한다.
- **FR-012**: 분석 결과를 저장하기 전에 구조, 값의 유효성, 미확정 필드의 일관성을 검증해야 한다(MUST). 해석할 수 없는 응답이나 구조 위반 결과를 성공으로 저장하지 않는다. 구조 유효성·근거 문자열 존재·의미 정확성을 구분한다. 원문의 값이 해당 프로젝트·필드의 확정 내용인지 검증하고 불확실하면 미정으로 남긴다.
- **FR-013**: 분석 진행·분석 초안 저장·사용자 확인 완료·실패를 구분하여 표시하고 새로고침 후 저장된 상태를 복원해야 한다(MUST).
- **FR-014**: 사용자는 프로필 항목을 수정하거나 미정으로 남기고 확인·저장할 수 있어야 한다(MUST). 저장된 미확정 목록은 실제 값과 일치해야 한다.
- **FR-015**: 재분석 결과는 사용자 확인 프로필과 분리된 검토 후보여야 하며, 사용자가 확인·저장하기 전 기존 값을 자동 덮어쓰지 않아야 한다(MUST). 오래된 분석 결과나 동시 저장이 최신 확정값을 묵시적으로 바꾸지 않아야 한다.
- **FR-016**: AI 실패 시 기존 저장 내용을 보존하고 재시도와 프로필 직접 작성·수정을 모두 제공해야 한다(MUST). 기존 프로필이 없으면 미정 항목을 가진 편집 화면에서 시작하고, 있으면 기존 값을 바탕으로 수정한다. 직접 작성 결과에도 동일한 값 검증·확인·저장을 적용하며 AI 분석 성공으로 표시하지 않는다. 재시도에 입력을 다시 받아야 하는 조건은 FR-021 보관 정책에 따른다.
- **FR-017**: 생성·분석 결과·프로필 수정의 저장이 실패하면 성공으로 표시하지 않고 가능한 입력·결과를 현재 화면에 보존해야 한다(MUST).
- **FR-018**: 문서 속 지시는 데이터로만 처리하고 도구 실행·권한 변경·Secret 조회에 사용해서는 안 된다(MUST NOT).
- **FR-019**: 시스템 Credential과 입력에서 식별된 Secret이 AI 요청·사용자 오류·로그·Audit에 들어가지 않도록 검증해야 한다(MUST). 식별된 Secret은 요청 전 제거하거나 해당 요청을 차단한다.
- **FR-020**: 분석 시작·성공·실패·사용자 확인 저장을 프로젝트·요청·시점·결과와 연결해 추적할 수 있어야 한다(MUST). Audit에 문서 원문이나 Secret을 담지 않는다.
- **FR-021**: AgentFit이 관리하는 업로드 원문·추출문은 분석 처리 중에만 사용하고 성공·실패·시간 초과·취소 등 처리 종료 후 별도로 보관하지 않아야 한다(MUST). 비정상 종료도 잔존 원문·추출문 파일을 남겨서는 안 된다. 단, 실패한 분석에서 실제 수신한 LLM 원본 응답은 오류 추적용으로 최대 7일 보관할 수 있다. 이 응답에는 원문 일부가 포함될 수 있음을 고지하고, 정상 분석의 원본 응답·일반 로그·Audit·공개 API에는 남기지 않는다. 만료 또는 프로젝트 삭제 시 진단 응답을 제거한다. 재분석에는 사용자가 입력을 다시 제출해야 하며 이 동작을 미리 안내한다. 프로필·최소 문서 정보·분석 시도·감사 기록은 본인만 접근 가능하고 프로젝트 삭제 시 함께 제거한다. 외부 AI 서비스의 별도 처리·보관 조건은 숨기지 않고 고지하며 AgentFit의 삭제를 외부 서비스의 삭제 보장으로 표시하지 않는다.
- **FR-022**: 문서 분석 성공을 개발환경 설치·연결·검증 완료로 표시해서는 안 된다(MUST NOT).
- **FR-023**: 주요 입력·결과 수정·저장 흐름은 키보드로 수행할 수 있고, 입력 오류·진행·성공·실패를 색상만으로 구분하지 않아야 한다(MUST).
- **FR-024**: 사용자는 본인 프로젝트와 연결된 저장 데이터를 삭제할 수 있어야 한다(MUST). 삭제 전 대상과 함께 제거될 데이터를 설명하고 확인·취소를 제공한다. 완료된 삭제 뒤 늦은 분석 결과가 프로젝트·프로필을 되살려서는 안 되며, 삭제 실패를 성공으로 표시하지 않는다.

### Key Entities *(include if feature involves data)*

- **User**: GitHub 로그인으로 식별되는 사용자. 같은 GitHub 계정의 재로그인은 같은 사용자로 연결한다. 소유 프로젝트에만 접근하며 타인과 데이터를 공유하지 않는다.
- **Project**: 사용자가 만드는 분석 대상. 식별자, 이름, 소유 사용자, 생성·수정 시점, 현재 진행 상태를 가진다.
- **ProjectDocument**: 프로젝트에 제출된 입력의 최소 정보. 입력 유형, Secret을 제거한 표시 이름, 크기 또는 길이, 제출 시점, 처리 상태를 보관한다. 원문·추출문·인용 구절은 처리 후 저장하지 않는다.
- **AnalysisAttempt**: 특정 입력에 대한 한 번의 분석 시도. 연결된 프로젝트·입력, 진행·성공·실패 상태, 실패 분류와 시점을 기록한다.
- **ProjectProfile**: 구조화된 프로젝트 정보. 분석 초안과 사용자 확인 프로필을 구분하고, 필드의 값·출처·미확정 상태 및 마지막 저장 상태를 가진다.
- **AuditEvent**: 분석과 사용자 확인 저장 등 중요한 사건의 최소 추적 정보. 사용자 또는 요청과 연결하되 원문·Secret을 포함하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 정상 PDF·Markdown·직접 텍스트 각 유형에서 프로젝트 생성 → 분석 → 결과 확인 → 수정 → 저장 → 재접속 흐름을 모두 완료할 수 있다.
- **SC-002**: 검증용 문서에서 명시되지 않은 DB·배포 환경은 100% 미확정으로 남고, 사용자가 값을 입력하거나 미정으로 바꾼 뒤 저장하면 미확정 목록과 100% 일치한다.
- **SC-003**: 사전 정답을 정의한 검증 문서 최소 9개(입력 유형별 3개)의 명시된 프로필 사실 중 90% 이상이 올바른 항목에 추출된다. 틀린 값과 근거 없는 값은 정답으로 세지 않으며, 정답표는 AI 출력에 맞춰 수정하지 않는다.
- **SC-004**: 저장에 성공한 사용자 수정값은 새로고침·재접속 후 100% 유지되고, 재분석·실패·오래된 저장 시도로 자동 변경되지 않는다.
- **SC-005**: 정의된 입력·분석·저장 실패 사례에서 실패를 성공으로 표시하는 경우가 0건이며, 각 사례에 이유와 복구 행동이 있다. AI 실패 사례에서는 재시도와 직접 작성·수정 경로를 각각 완료할 수 있다.
- **SC-006**: 준비된 Secret·문서 지시 주입 검증 사례에서 Secret의 외부 전달·로그 노출과 문서 지시에 따른 권한 변경·도구 실행은 각각 0건이다.
- **SC-007**: 사전 기능 설명 없이 첫 흐름을 시도하는 개발 초보자 5명 중 4명 이상이 진행자 개입 없이 입력부터 확인·저장까지 완료한다.
- **SC-008**: 지원 한도 내 대표 입력의 95%는 분석 시작 후 60초 이내에 결과 또는 명시적 실패 안내를 받는다. 정상 외부 서비스 조건·입력별 표본·측정 방법은 Plan에서 정의하며 외부 장애를 성공으로 집계하지 않는다. 성공 분석 지연과 실패 안내 지연을 별도로 보고하고 이 기준을 정상 입력 성공률 SC-012의 대체 지표로 사용하지 않는다.
- **SC-009**: 비로그인 접근과 사용자 A의 프로젝트에 대한 사용자 B의 조회·분석·수정 검증에서 타인 데이터 조회·변경 성공이 0건이다.
- **SC-010**: 정상·실패·시간 초과·비정상 종료 검증에서 AgentFit이 별도로 보관하는 업로드 원문·추출문 잔존은 0건이다. 실패 건에만 허용된 진단용 LLM 원본 응답은 7일 만료 또는 프로젝트 삭제 후 0건이며, 삭제 완료된 프로젝트의 연결 데이터와 지연 응답에 의한 복원도 0건이다.

- **SC-011**: 부정, 후보와 확정, 현재와 미래, 다른 대상의 기술, 상충 정보, 문맥의 제한이라는 6범주별 최소 2개(총 12개) 정답 사례에서 필수 대상 필드값과 미확정 구분이 모두 정답과 일치한다. 세 입력 유형을 모두 포함하고 확정값을 반환해야 하는 대조 사례도 둔다. 원문에 문자열이 존재한다는 이유만으로 정답으로 인정하지 않는다.
- **SC-012**: 정상 외부 서비스 조건에서 지원 정책을 만족하는 독립 정상 문서 최소 30개(입력 유형별 10개)의 95% 이상이 첫 요청으로 유효한 분석 초안을 저장·표시하고 사전 필수 사실 검토를 통과한다. 실패·시간 초과·재시도 결과는 첫 요청 성공으로 세지 않는다. 성공률과 성공 분석 지연·실패 안내 지연을 따로 보고하며, 데이터·기대값·측정 조건을 결과 확인 전에 고정한다.

## Assumptions

- 첫 Feature의 범위는 개인 프로젝트 생성·목록·상세·삭제와 문서 분석·검토·저장이다.
  Foundation 기반 코드는 없으므로 선행 의존성으로 함께 계획한다.
- PDF·Markdown과 함께 직접 텍스트 입력도 첫 Feature에 포함한다. 이는 인수인계의 명시된 입력 방식이며 파일 처리 실패 시 사용 가능한 경로다.
- 재분석과 프로필 충돌 방지는 이 Feature의 데이터 보존에 필요한 범위로 다룬다. 모든 프로필 이력의 비교·복구 UI는 포함하지 않는다.
- OCR, 이미지·표의 시각적 의미 해석, 여러 문서의 병합 분석, Team 협업은 이 Feature 범위 밖이다.
- Developer·Environment Profile, Capability, Tool Catalog, 추천, Permission Manager의 제품 UI,
  Config 생성·Preview·다운로드, Browser Directory 적용과 Local CLI는 후속 Feature다.
  다만 이 Feature 자체의 접근 통제·Secret 격리·입력 보안 요구는 적용한다.
- FR-003·FR-005·FR-016은 2026-09-07 사용자 응답으로 확정했다.
  문자 계산의 모호성을 없애기 위해 code point·공백 포함 기준을 명시했다.
  FR-021의 보관 정책도 같은 날짜의 사용자 응답으로 확정했으며, 선택한 데이터 삭제를 가능하게 하는 최소 프로젝트 삭제 동작을 포함한다.
  GitHub 로그인만 제공하도록 확정했으며, 저장소 접근은 범위 밖이다. GitHub 로그인에 필요한 애플리케이션 등록·Credential 설정은 Plan의 외부 준비 조건으로 기록한다.
- SC-003·SC-007·SC-008의 수치는 명세 초안의 검증 목표다. 실제 측정 결과가 아니며
  목표 변경은 구현 결과에 맞춘 사후 조정 대신 요구 변경으로 기록한다.
- Framework·Database·Validation·AI Provider·저장 방식·테스트 도구는 Technical Plan에서 결정한다.
  외부 AI의 실제 연결과 승인된 테스트 입력을 준비해야 하며 Mock만으로 첫 흐름 완료를 선언하지 않는다.
